**Disposition:** focused source/design review. Not Part V acceptance,

## R4 preservation

- Preserve a concise, Clojure/Hiccup-friendly authoring surface.
  Views own text, visual status, CSS, keyboard/ARIA and layout;
  authoritative operation legality and choreography remain model/
  application owned.
- Preserve exact semantic operation identity through binding, plan
  selection, renderer, transport and protected model invocation.
  The source's compact `gesso/action` example is an illustrative
  API, not an assertion that this exact function ships in v1622.
- Preserve the R4 prohibition on silent fallback from incomplete
  managed Claim to naked `hx-post`. An *explicitly* ordinary HTMX
  interaction remains valid on its own route under ordinary model
  authentication and protection.
- Preserve the separation between prepared view affordance and
  a trusted execution capability. A client-supplied observation
  basis, command ID, opaque binding or previous rendering cannot
  confer principal identity or current authorization.
- Preserve pre-serve whole-application closure and precise
  diagnostics rather than generic malformed-HTML failure.
  Rendering of a provisional state is not proof of command
  incorporation or completed authoritative adoption.
- Preserve typed unavailability and independently expected
  positive product capabilities; missing realization must not
  disappear behind hidden markup.

## Focused semantic corrections

1. **Physical request closure:** a Hiccup node marked with
   `:choreo/op` may still emit conflicting physical actions.
   The admitted correspondence is over actual method, route,
   submitter/form overrides, target and transport, not merely
   semantic metadata. Extra `hx-get`/`hx-put`, duplicate
   string/keyword request attrs, or alternate native form paths
   are not exempt because the node carried a canonical mark.
2. **Constructed availability is not a generic fallback:**
   only a semantically declared policy-unavailable/deferred
   state with complete non-executable rendering may be
   displayed as unavailable. Missing required plan, artifact,
   route or binding is a typed construction defect. Reassign's
   complete input-collection entry is distinct from its
   final, helper-selected mutation.
3. **Untrusted rendered bytes:** in-process Hiccup metadata
   can support a pre-serialization check, but does not become
   authoritative HTML/client metadata or a server execution
   credential. Trusted server principal, public model guards
   and disclosure remain independent.
4. **Raw HTMX correctness:** ordinary HTMX remains a supported
   interaction; it may not target an assembled semantic route
   to bypass the associated protocol. A protected server write
   remains protected regardless of the client realization mode.
5. **Accessibility and status truth:** pending/busy/disabled
   appearance cannot assert settlement, adoption, deduplication
   or authority. Eligible entry actions require their complete
   keyboard/form/accessibility realization.
6. **Dynamic and deployment coverage:** check the *actual*
   rendered occurrence before serialization under the current
   ApplicationAssembly, but do not claim all Clojure branches,
   manually pre-serialized HTML or alternative deployed
   entrypoints were inspected.
7. **Public/private errors:** include expected and observed
   semantic/physical edge in repair diagnostics, but disclose
   only authorized status/reasons to the requesting user.
8. **Positive/adverse test pairs:** exact managed method/route
   versus alternate physical request; ordinary HTMX versus
   semantic-route collision; Reassign entry/final construction;
   accessible provisional status versus false incorporation;
   dynamic pre-serve render check versus deployment bypass.

## Gesso code and tests actually inspected

At `michaelmrose/gesso` `application-assurance`
`1b5e10e7` (v1622):

- `src/gesso/live/ui.clj` exposes `post-button`,
  `with-optimistic-operation-capabilities`, inert optimistic
  annotation, and in-process semantic affordance metadata.
  `resolve-post-button-optimistic` resolves `:choreo/op`
  through an operation-keyed capability registry and rejects
  conflicting `:optimistic`/binding declarations.
- `src/gesso/live/optimistic/capability.cljc` derives closed
  operation-keyed capabilities from current browser plans,
  checks exact requested identity and intentionally treats
  the result as configuration rather than authorization.
- `src/gesso/live/application_preflight/affordance.clj`
  rejects anonymous physical method/path matches with
  registered semantic routes and alternate physical requests
  on an already-marked canonical Choreo node.
- `src/gesso/live/application_preflight/rendered_request.clj`
  enumerates explicit Hiccup HTMX/native-form request
  coordinates; it rejects duplicate string/keyword spellings
  of request-relevant attrs rather than trusting an ambiguous
  browser outcome.
- `src/gesso/live/application_preflight.clj` documents and
  implements a current `check-rendered-surface` and a
  canonical pre-serialization handler wrapper. Its guarantee
  is limited to inspected Hiccup on the installed path.
  Alternate Biff startup, later handler replacement, manually
  pre-serialized HTML and unexamined rendering branches
  remain explicit correspondence/deployment obligations.
- Source-inspected tests:
  `test/gesso/live/ui_optimistic_test.clj` checks exact
  capability-to-Choreo resolution, no conflicting declarations,
  malformed metadata, and the canonical post-button path;
  `test/gesso/live/application_preflight_test.clj` tests
  wrong method/path, ambiguous trusted routes, operation
  outside assembled scope, and malformed source metadata.

This demonstrates meaningful v1622 enforcement while leaving
the full future `:needs-input`/deferred view availability
contract, all intended HumanHelp capabilities, and installed
deployment/non-bypass certification open. No Gesso source or
test was edited. **No JVM, Node, Chromium, XTDB or proof
test was executed in this documentation revision.**
