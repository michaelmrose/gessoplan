## R4 preservation

- Retain exactly one portable semantic meaning in the shared
  execution core, rather than independently written JVM, Node and
  browser branch machines. Production executes the same admitted
  projected plan under host-specific effects.
- Keep the global semantic core and role-local projected machine
  distinct but corresponding. Projected operations preserve
  `:local`, `:authoritative`, `:branch`, `:send`,
  `:receive`, `:await`, and `:return` as declared; the
  global `:communicate` event and endpoint send/receive are not
  interchangeable with host-local events.
- Preserve R4's source-sensitive normalization: raw HTMX,
  EventSource, timer, DOM and browser events are not evidence
  of authority, principal identity or execution ownership.
- Preserve one declared owner each for execution trajectory,
  adapter-wide target arbitration/requirements and imperative
  physical handles. A leftover handle after retirement is
  cleanup debt, not a living semantic execution.
- Preserve total outcomes for supported event/state cases and
  typed rejection of unknown, malformed or version-incompatible
  inputs. A host exception is not a domain rejection.
- Preserve the proof/runtime split: the executable semantic core
  is permanent; optional verifier, proof graph and diagnostic
  sidecar are not production runtime authorities.
- Preserve R4's JVM/Node/Chromium conformance aspiration with
  explicit numeric, equality, collection, error and protocol
  compatibility; source sharing and finite parity are not
  universal equivalence proofs.

## Focused corrections

1. **Portable value meaning:** cross-host identity, equality,
   numeric precision, serialization, collection membership,
   missing-versus-nil and basis comparison must not alter
   branch selection or effects. Unsupported classes are
   rejected instead of silently interpreted differently.
2. **Trust versus normalized shape:** participant messages,
   authoritative results, observations and environment
   completions have distinct source admission. The same
   keyword or a tagged wrapper is not transferable proof.
3. **Physical effect race:** register/buffer or serialize an
   immediate completion so `:await` cannot miss it; a
   requested effect is never classified physically completed
   just because the host issued it.
4. **Totality and exception semantics:** supported events are
   admitted, stale/duplicate, stuttering, recovery-producing,
   or typed faults. Malformed/unknown cases cannot fall
   through to imperative branches; unexpected host exceptions
   invoke the runtime failure contract, not model rejection.
5. **Retirement and correlation:** E2 may inherit specifically
   handed-off obligations, but never E1's timer/DOM/transport
   callback identities or role-local knowledge. Current
   execution IDs cannot be read during callback to relabel
   an earlier physical event.
6. **One checked plan:** exact semantic production path
   differs from a separately written "reference" machine;
   diagnostic/proof output does not influence semantics.
7. **Five paired positive/adverse cases:** portable branch,
   source-qualified receive, immediate installation,
   late E1 callback, and typed event/fault handling.

## Current Gesso implementation inspected, not executed

Gesso `application-assurance` was checked at
`1b5e10e7` (v1622).

- `src/gesso/choreo/semantics.cljc` defines the portable
  global semantic vocabulary and source-sensitive events.
  Global `:communicate` has one atomic semantic meaning,
  while projected send and receive live in role-local
  realization. A same-named environment event does not
  substitute for a participant message.
- `src/gesso/choreo/machine.cljc` implements a portable
  role-local `ExecutablePlan` machine and separately
  suspends on local, authoritative, send, receive and
  environment boundaries. It does not touch DOM, HTMX,
  XTDB, timers or network APIs.
- `src/gesso/live/browser/adapter.cljc` is a pure portable
  browser coordinator with documented
  `AdapterState × NormalizedEvent -> AdapterState × AbstractEffects`
  transition, ownership/generation checks and distinct
  authoritative swap admission. It invokes, rather than
  redefines, the portable role-local machine.
- `src/gesso/live/browser/refinement.cljc` supplies a
  separate source-derived refinement candidate/checker
  boundary; a canonical observation candidate is not by
  itself an admitted global event or proof of physical
  host emission.
- `test/gesso/live/browser/refinement_node_parity_test.cljc`
  and `refinement_exploration_parity_test.cljc` contain
  JVM/Node stable cross-host corpora. Their docstrings
  expressly limit results to exercised pure semantics and
  bounded choice-relative exploration rather than actual
  Chromium/DOM/XTDB behavior or universal global proof.
- `test/gesso/choreo/semantics_test.cljc` tests message
  versus environment classification, closed semantic data,
  unexpected events, and distributed observation
  separation at the portable source boundary.

**No code or test was changed in Gesso. No JVM, Node, Chromium,
XTDB, Python assembler or formal verification test was run
during this documentation-only revision.** The candidate is a
timeless finished-system specification, not an assertion that
the current implementation already meets every host-parity,
effect-admission and actual physical correspondence guarantee.
