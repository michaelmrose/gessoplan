# R5.1 Part V — 05.10 R4 preservation and implementation correspondence

**Baseline:** `gessoplan/main` R4 Part V, `One portable semantic
machine, several execution environments`, `Portable execution owns
semantic state, not the browser shell`, `Runtime inputs are normalized
before semantic interpretation`, `Runtime state transition functions
are total over the supported event vocabulary`, `Test execution and
production execution use the same plan`, `Verification does not ship as
a browser prerequisite`, and `Portable representation version and
semantic compatibility are explicit`.
**Candidate:** `r5.1` section `05.10-execution-boundaries-and-deployment.org`,
joining accepted Parts I–IV and reviewed Part V 05.01–05.09.
**Disposition:** bounded source-informed specification revision, not
whole-Part-V acceptance, a verified browser build or formal proof.

## R4 preservation and supersession

- Preserve one shared portable semantic machine rather than a
  separately handwritten browser interpreter of the same business
  and projected event transitions.
- Keep portable projected state, shared adapter state and opaque
  physical DOM/HTMX/timeout resources in distinct owner domains.
  An orphan physical handle is cleanup debt, not a living execution.
- Normalized HTMX, timer, EventSource and DOM callbacks remain
  representations awaiting source/owner/contract admission. In-process
  wrappers and serialized fields are not authenticators.
- The supported state/event relation is explicit; stale, duplicate,
  unknown, malformed and fault cases do not silently fall through
  to ad-hoc browser branch decisions.
- Production tests and runtime execute the canonical plan with the
  actual semantic core. Diagnostic/proof metadata is optional
  explanatory data, never a secret transition authority.
- Parsing a plan version is not proof of semantic, protocol, assembly,
  physical handler or suspended-continuation compatibility.
  Recovery must not silently resume an incompatible execution.

## Focused improvements

1. **Effect-instance admission:** bind action/event schema, exact
   issued effect generation, owner/target incarnation, completion
   source and interpretation version. Distinguish missing output,
   present nil and false; a later omission never inherits an old
   output by accident or silently opens a closed output schema.
2. **Source classification:** value shape, qualified provenance,
   authentication/visibility, resource owner and physical
   completion are independent checks. A copied in-process
   token cannot manufacture a participant message, trusted
   server result or after-swap completion.
3. **Totality versus fault:** explicit step classifications
   do not become Claim acceptance or physical installation
   evidence. Supported semantic transition commits before
   effect interpretation/reentrant completion; synchronous
   faults and rejected Promises retain separate recovery.
4. **Cross-host and packaged execution:** JVM/Node/Chromium
   conformance applies to named exercised cases, exact plan,
   effect interpreter and asset. An equal source or copied
   stamp cannot certify the shipped browser entrypoint or
   arbitrary runtime behavior.
5. **Four compatibility predicates:** format parsing,
   semantic operation/interface, host protocol/handlers,
   and currently suspended continuation are separate.
   A recognizable incompatible plan causes semantic
   retirement followed by fallible cleanup/recovery.
6. **Retained obligations across reload:** an unknown C42
   command, independently acquired but uninstalled card,
   Live/Refresh requirements and physical repair can be
   transferred only to qualified successor owners. Retiring
   E42 is not terminal C42 rejection, and a new current
   card does not prove C42's historical disposition.
7. **Five paired positive/adverse cases:** stale optional
   output, event-source impersonation, incompatible-plan
   recovery, reentrant effect completion/fault isolation,
   and exact served-artifact/deployment correspondence.

The R5.1 additions strengthen the finished-system contract
without forcing a universal proof for every arbitrary Clojure
callback or demanding proof metadata at production runtime.

## Actual Gesso implementation inspected

At `michaelmrose/gesso` `application-assurance`
`1b5e10e7` (v1622), read as implementation context:

- `src/gesso/choreo/machine.cljc` delegates canonical
  `ExecutablePlan` classification to projection and
  distinguishes `:compatible`, recognizable
  `:incompatible` and malformed `:invalid` plans.
  Current `:await` event contracts validate required/
  optional fields and closed/open event data.
- `src/gesso/live/browser/adapter.cljc` rejects unknown
  event classes and unallowed event keys and checks state
  invariants. Distinct effect, request, timer and target
  generations constrain callback admission.
- `src/gesso/live/browser/choreo.cljs` handles a recognizable
  incompatible plan by first attempting semantic retirement,
  then calling the configured authoritative reconstruction
  handler. It explicitly refuses to continue the old
  suspended plan; failed physical cleanup is separately
  diagnosable. This is a concrete narrower recovery seam,
  not proof that all unknown commands and pending product
  obligations are durably recovered across every reload.
- `src/gesso/live/browser/shell.cljs` installs the
  next portable adapter state before interpreting physical
  effects, allowing a synchronous reentrant callback to
  see new ownership. Shell effects may still fail after
  transition and require bounded recovery.
- `src/gesso/live/browser/runtime.cljs` checks one shared
  runtime composition and exact handler ownership.
  Stop/start failure semantically retires the runtime
  before best-effort physical cleanup and detachment.
  These composition checks do not certify every asset
  and server entrypoint of an actual deployment.
- Source-inspected tests in
  `test/gesso/live/browser/adapter_test.cljc` include
  closed event vocabulary, stale timer/effect generations,
  optimistic retirement and concurrent request tests;
  related `gesso/choreo` tests cover plan format and
  environment event contracts. Source inspection does not
  mean these tests were run.

No Gesso runtime source was changed and no JVM/Node/Chromium,
XTDB, asset deployment, Python assembly or formal proof
tests were executed.

## Cross-part residual obligations

- **05.11–05.13:** emitted canonical plan identity,
  exact sidecar-to-plan matching, packaged-asset closure,
  location/proof identity separation and diagnostic
  noninterference must bind the same actual runtime.
- **Part IV:** current actor authorization, durable
  command-history readback, qualified scoped observation
  and completed adoption remain independently established.
- **Part VI:** source-normalized physical callbacks, real
  HTMX after-swap and DOM ownership, interruption,
  release and reentrant physical effects require
  browser-host correspondence evidence.
- **Part VII:** actual served routes, preflight wrappers,
  runtime artifacts, asset manifests and deployment
  entrypoints need change-sensitive assembly admission.
- **Part VIII:** independent HumanHelp Claim/Reassign,
  creator-local update and one-Refresh product behavior
  must be exercised, not inferred from abstract dispatch.
- **Parts IX–X:** cross-host parity and a typed source
  report are bounded evidence, not general kernel
  soundness, trustworthy provider execution or physical
  implementation certification.

The original Part V `CUSTOM_ID` identifiers remain stable;
all 13 numbered source files must reconstruct the published
