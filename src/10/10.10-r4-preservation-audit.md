## Editorial synthesis

Keep R5's natural staged formalization plan and R4's explicit tool-independent, source-derived semantics. Make the first formal theorem concrete and falsifiable without implying that Gesso already has an externally verified kernel. Its proof language contains the seven admitted rules, and its semantic theorem quantifies over all supported derivations and Boolean interpretations of opaque atoms. But *soundness of the mathematical derivation calculus* and *soundness of the current Clojure parser/normalizer/checker and issuer* are different theorem targets; the external proof does not complete the latter by sharing a source label.

The external formal mechanism remains optional at the framework/tool level but required for a selected *strong assurance profile* only when that profile actually demands it. This retains the Clojure-first authoring promise while allowing fully machine-checked evidence for supported closed fragments. An unsupported or over-budget checker is an incomplete result or a typed admission failure, not a silent trust upgrade.

## R4, R5 and accepted-part preservation decisions

1. **Small first theorem rather than whole-Clojure verification.** Prioritize the kernel's seven-rule calculus; do not start by encoding arbitrary ClojureScript, XTDB, browser, HTTP, full HumanHelp policy or multi-node execution as one unverifiable monolith.

2. **Seven inference rules preserved exactly.** Premise, truth introduction, implication reflexivity, conjunction introduction/elimination, implication elimination and disjunction introduction remain the initial complete admitted rule inventory. Existing formula connectives do not imply additional proof rules.

3. **Source/derived proof distinction.** Formal proof subjects and derivations derive from the admitted Gesso source. A second handwritten Lean/Quint/TLA+/Recife HumanHelp application does not automatically correspond to the runtime model.

4. **Opaque Boolean atom semantics are deliberate.** Propositional soundness assumes an arbitrary valuation of each original atomic declaration. It does not establish the truth of a typed business predicate, current Membership, Request status or arbitrary host Clojure code.

5. **Used open premises remain open.** The entailment is conditional on the actual step-inherited Gamma; a checked premise introduction does not discharge it. The source checker may impose the stricter discipline that every declared premise/step participate. Neither fact is an unrestricted hypothetical-context discharge rule.

6. **Truth of `Gamma |= P` is not application nonvacuity.** A contradictory Gamma can make an entailment vacuous. Satisfiable supported initial states, valid source operation catalog and positive eligible HumanHelp operations remain separate requirements.

7. **Rule-schema soundness has a universal quantifier.** The formal proof must cover supported formula trees, all appropriate arities, indices, reference layouts and valuations, not only each rule name's presence in one test.

8. **Derivation-system soundness needs induction over proof order.** The theorem's step relation and exact inherited named premises must preserve entailment from each valid prior step through the final goal.

9. **Mathematical rules and Clojure implementation are not equal.** Even a perfect proof of the seven rules does not prove that the deployed Clojure parser, proposition normalizer, binder, checker and admission call follow those rules for every supported input.

10. **Original-source normalization is in scope.** The checker must preserve the exact typed proposition, subject, atom identity, premise context and supported connective tree from original source, not merely accept a correct theorem about a different normalized subject.

11. **Typed-atom truth requires its own bridge.** The actual typed-rule evaluator, allowed reader footprint, nominal type, present-nil/absent distinction, input environment, errors and authorized model context are distinct from arbitrary Boolean atom valuations.

12. **Finite oracle is evidence for its tested domain.** Exhaustive valuations for one bounded set of opaque atoms or a bounded typed input corpus are useful adversarial evidence, not a universal kernel metatheorem or live production correctness.

13. **Production acceptance is directional.** Prove or qualify that every supported concrete derivation the actual trusted admission boundary accepts maps to a logically valid formal derivation, not merely that both reject a few invalid examples.

14. **Soundness and completeness are different.** A bounded checker may reject valid but too-large proofs and remain sound. Legitimate supported positive constructions still need a nonvacuous usability/acceptance contract; rejecting every operation is not completed Gesso.

15. **Evidence mechanism and claim type are explicit.** Rule theorem, source-check report, checked derivation, finite diagnostic, issuer certificate, installed artifact proof and runtime guard are not interchangeable labels. One can be established while a downstream one is still open.

16. **No hidden theorem by proof tool branding.** Lean (or another proof assistant) can play the role, but the evidence names the actual statement, axioms, checker/kernel, toolchain and what it checks. A clean exit code or unverified label is not a proof.

17. **Importer and currentness are a trust boundary.** Proofs bind exact original source, canonical encoding, dependency/issuer closure, admitted checker semantics and supported artifact/current generation. Changed axioms, parser, dependencies or runtime implementation re-open the affected claims.

18. **Proof sidecars do not alter runtime transitions.** A required construction gate may stop a new application admission, but a proof cache, diagnostic sidecar or proof handle cannot confer principal authorization, a command retry, a browser resource lease or an SSE read grant.

19. **No silent downgrade.** Unsupported proof form, unavailable checker, malformed evidence, timeout, budget exhaustion, stale subject or missing bridge remain explicit; a stricter selected profile may not fall back to trusted/opaque output without a separately selected and accurately recorded weaker claim.

20. **External tool implementation can be incremental.** Subsequent targets include typed evaluation, guarded transitions, source-complete induction, projection, provenance, progression and browser refinement as independently scoped theorem families; one verified primitive does not automatically cover every host-language use.

21. **Common-mode bug risk remains visible.** Shared parser/normalizer logic between formal and production implementations can hide errors; independent interpretations and systematic mutation tests are valuable but separately qualified by their domains.

22. **Physical realization stays outside the initial kernel theorem.** Real XTDB serializability, guard coverage, direct physical writers, effective actor authorization, loaded browser assets and correct DOM effects remain the 10.04–10.09 transfer obligations even if the pure rule calculus is formally proved.

## Actual Gesso v1622 source and limitations

- `src/gesso/assurance/proof/kernel.clj` implements the restricted seven-rule, original-source, closed propositional derivation checker. It re-parses typed propositions against the same subject/context, rejects incorrect step dependencies and retains declared premises. It explicitly disclaims atomic truth, hypothetical discharge, SMT arithmetic, certificate issuance and metatheoretic soundness. Its bounded parser/checker accepts source, not cached reports.

- `src/gesso/assurance/proof/propositional_semantics.clj` defines an independently written Boolean reference interpretation over the admitted connective tree and distinct opaque atomic declarations. Its exhaustive entailment routine is finite/budgeted; it does not authenticate typed atoms, concrete runtime subjects, large unbounded formulas or any certificate.

- `src/gesso/assurance/proof/propositional_rule_schema_audit.clj` audits a finite catalog or one original rule *instance* by exhaustive Boolean valuations under a bounded independent semantics, with separate hypothetical counterfactuals. Its `:universal-schema-soundness` field is explicitly `:not-established`, and it does not check a general proof assistant theorem.

- `src/gesso/assurance/proof/propositional_kernel_correspondence.clj` reruns the production kernel on original source and independently reconstructs each rule's sources, local consequence and inherited premises. It detects source-step correspondence errors within its finite audit, but is not a proof of the Clojure normalizer, universally sound kernel or physical runtime correctness.

- `src/gesso/assurance/proof/propositional_normalization_audit.clj` independently reconstructs source/canonical proposition trees and checks opaque-Boolean preservation under explicit valuation bounds. It explicitly leaves typed-rule denotation equivalence and universal normalization correctness unestablished.

- `src/gesso/assurance/proof/propositional_derivation_soundness.clj` provides a compositional *source-relative* argument by induction over one finite source derivation: its selected local premises and conclusions are audited, then its source-reconstructed premise inheritance is composed. This does not independently prove every Clojure checker path, all rule schemata in an unbounded language, semantic truth of typed atoms or physical XTDB/CLJS execution.

- `src/gesso/assurance/proof/propositional_soundness.clj` independently truth-table audits a bounded original derivation and each purported step, while retaining opaque atom semantics and refusing admission authority. Its maximum-atom/valuation-work limits matter to the scope.

- `src/gesso/assurance/proof/typed_proposition_bridge.clj` enumerates original input bindings over declared finite domains, independently checks typed atoms and compares connective evaluations. It does not prove universal typed-rule meaning, authenticate actual bindings, discharge open premises or issue certificates.

- `src/gesso/assurance/proof/certificate.clj` admits source-rechecked restricted proof kinds as *process-local, opaque JVM handles*; its current source explicitly retains checker meta-soundness and unrelated production correspondence as open obligations. A valid handle is not a signed transferable theorem or runtime permission.

- `test/gesso/assurance/proof/recife_finite_correspondence_test.clj` illustrates independent bounded Gesso abstract transition and Recife/TLC exploration for two operations, including deliberate mutations; its namespace documentation disclaims universal soundness, XTDB refinement, deployment, fairness and certification. It is a test source, not evidence an external small-kernel proof was completed or a test newly passed in this turn.

- Relevant test sources include `kernel_independent_soundness_test.clj`, `kernel_normalization_semantic_preservation_test.clj`, `kernel_systematic_mutation_test.clj`, `propositional_rule_schema_audit_test.clj`, `propositional_kernel_correspondence_test.clj` and `typed_proposition_bridge_test.clj`. These furnish useful regression and mutation targets; they were not executed for this editorial revision.

These source facts show substantial implemented *precursors* toward S0–S4. In the inspected state, no independently completed universal external small-kernel metatheorem, proven concrete Clojure checker implementation correctness, unrestricted typed-atom correspondence, complete production physical refinement or HumanHelp product acceptance was established by these files. The normative future target is not weakened to the present diagnostic implementation.

## Sixteen positive/adversarial acceptance pairs

1. **Premise:** An admissible named premise yields a derivation that retains its open assumption; removal of the premise may not produce an unconditional theorem.
2. **Truth/reflexivity:** Proper premise-free truth and implication reflexivity succeed for supported syntax; a forged arbitrary atomic truth axiom is rejected.
3. **Conjunction:** Correct ordered n-ary introduction and indexed elimination succeed; arity/index/order mutations fail.
4. **Implication:** Correct implication plus antecedent derives consequent; swapped or unrelated antecedent and altered consequent do not.
5. **Disjunction:** Embedding exactly the cited proposition at its declared index succeeds; wrong injected atom/position fails.
6. **References:** Prior valid source steps can be cited; forward/circular references and forged previous conclusions cannot pass.
7. **Normalization:** Original typed source and normalized connective/atom tree retain stated semantics; atom/context/premise mutation breaks correspondence.
8. **Finite scope:** Exact bounded opaque-Boolean valuation supports a local rule instance; incomplete/exhausted enumeration never claims universal schema proof.
9. **Metatheorem:** A valid formal proof covers the seven schemata with quantified parameters/valuations; a sample catalog masquerading as the theorem is rejected.
10. **Production checker:** Every accepted concrete derivation maps to the formal derivation relation; deliberately faulty parsing/normalization/step enforcement invalidates this soundness transfer.
11. **Typed atoms:** Correct finite source bindings agree with their typed evaluator; opaque Membership or Request truth is not inferred universally.
12. **Issuer:** Current original-source obligation closure and checked derivation justify the scoped handle; copied report/stale certificate does not mint another admitted proof.
13. **External evidence:** Exact theorem/axiom/checker version and qualified proof import passes; forged proof, shifted axiom or exit-code-only success fails.
14. **Physical seam:** A formally sound Claim remains conditional on actual current model guard/writer correspondence; an unguarded real physical writer does not inherit the theorem.
15. **Browser privilege:** A real current resource owner may apply permitted effect; a reused DOM ID and stale certificate cannot grant effect-time authority.
16. **Nonvacuous product:** Real eligible Claim and other required HumanHelp lifecycle actions remain executable and independently testable; reject-all cannot pass product acceptance.

For each pair record original source, exact formal meaning/quantifier, genuine positive, injected mutant, first checking or enforcing boundary, current evidence class, real effect observer if applicable and remaining premises. Abstract source rejection does not certify that an uninspected physical bypass was prevented. A formal theorem or tool execution not actually observed must not be reported as having run.
