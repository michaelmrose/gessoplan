**Normative source:** `r5-source/10/10.14-enforced-qualification-and-runtime-trust.org`.
**R4 baseline:** `main` Part X, “Trusted computing base, security boundaries, and failure modes,” especially the certificate/authorization, hash, shared-bug, forgery, circular-trust, assertion-inflation, fingerprint, sidecar and qualified-verification subsections.
**Preferred predecessor:** R5/initial R5.1 10.14, preserving conditional backend qualification, true runtime authority, exact artifact/assembly identity, noninterference and mandatory admission gates.
**Accepted cross-part architecture:** R5.1 Parts I–IX and Part X 10.01–10.13. 10.13 owns the claim-specific trusted-base inventory and actual-backend qualification contract; 10.15 owns real execution of mutation/fault-injection and independent physical oracles.
**Gesso reference:** `michaelmrose/gesso` `application-assurance` v1622, commit `1b5e10e71c00e7784b019dee7dc1198a96fd03f6`.
**Disposition:** 10.14 substantively reviewed and tightened as the *finished-system* normative design candidate. This is not an assertion that its required physical enforcement is implemented or certified.
**Execution:** No new JVM, XTDB, CLJS, Chromium, HumanHelp or external formal-checker run was performed for this editorial revision.

## Editorial decision

Preserve R5's sharper separation of selected backend qualification, production admission, untrusted browser inputs, source/asset/assembly compatibility and optional sidecars. Restore R4's concrete stale-artifact example, unforgeable checked-value discipline, qualified proof evidence vocabulary, shared-bug/circularity counterexamples, fingerprint positive and negative controls, and noninterference requirements. Make the first actual enforcing boundary and the aftermath of an uncertain physical submission explicit. The plan does not make certificates, hashes, passive reports or post-effect observers into runtime authority.

## R4/R5 preservation decisions

1. **Qualified backend evidence is scope-bound.** A known failed or stale selected provider premise invalidates dependent current applicability, not the timeless conditional abstract theorem.
2. **Fail closed under mandatory profiles.** If a required claim is unsupported, stale, contradicted or unqualified, new affected admissions/effects cannot proceed under the same strict claim; safe unaffected operations may remain available under their own premises.
3. **No silent downgrade.** Reclassifying a strict claim as merely `tested` or `asserted` without a new requested profile is forbidden.
4. **Enforcement is time- and path-specific.** Startup checks, dependency snapshots and post-dispatch observers do not substitute for the first live gate that must block a forbidden physical effect.
5. **Configuration changes invalidate selectively.** Backend, adapter, codec, semantic source, handler, plan, certificate dependency or deployment change must recheck the affected qualified closure; the whole DAG need not be discarded for independently irrelevant edits.
6. **Incident response retains history.** Blocking new mutations does not undo committed effects or turn uncertain/in-flight command outcomes into rejection; recorded command resolution and disclosure retain separate current authority.
7. **Untrusted browsers can forge data.** Browser-provided semantic IDs, command ID, roles, principal, basis token, DOM, JavaScript, plan-looking values and certificate fields cannot authorize a protected server read or write.
8. **Trusted principal and binding admission.** Current session authentication, operation/subject/argument/command association and actual authoritative guard are independently required at their enforcing boundaries.
9. **Replay is distinct from incorporation.** Historical compatible command resolution requires current disclosure; revocation cannot mint permission to retry or erase prior committed history.
10. **Protected reads/subscriptions are live authority boundaries.** A valid Choreo projection or checked rendering cannot grant permission to see protected data.
11. **Threat model remains scoped.** Opaque JVM-local handles, captured function identity and weak issued registries prevent accidental substitution among cooperating code; they do not sandbox privileged reflection or direct XTDB credentials.
12. **Persistence does not preserve issuance.** A cached certificate/report reenters as untrusted data and must be rechecked. Garbage collection does not define semantic revocation or retirement.
13. **Hash identity is not proof truth.** Independently recomputed canonical bytes/content can show scoped identity under stated assumptions, whereas a copied digest is unverified metadata; neither proves the proposition.
14. **R4 stale-artifact counterexample retained.** Equal-looking digest claims with Membership M18/H42 versus M19/H43 are insufficient for current proof/assembly transfer. The restored pure Clojure example explicitly proves only data comparison.
15. **Directional compatibility is separate from byte identity.** A new compatible artifact may reuse abstract theorems with checked dependency closure; an unchanged asset may have stale policy evidence.
16. **Generated/installed output needs real binding.** The browser build receipt and current manifest/served bytes, emitted plan registry, compiler assumption, actual handler adoption and deferred response emission are distinct contracts.
17. **No forged certified API values.** A user map with `:semantic-id` and `:valid?` is not a checker-issued proof; public APIs must not permit fabricated map shape to issue an operation or permission.
18. **Independent proof and production checks remain distinct.** The derivation checker, original source and independent correctness obligations are rechecked; a copied report or same-bug wrapper cannot be treated as soundness.
19. **No self-justifying proof graph.** An operation cannot prove its own implementation by assertion. Cyclic proof dependencies reject unless a sound explicitly admitted fixed-point/induction rule covers the recursion.
20. **Assertions cannot substitute for mandatory proofs.** `:asserted` is a legitimate open premise; its transitive impact remains on root reports and cannot erase required kernel or physical obligations.
21. **Fingerprint under/over approximation tested.** Semantic changes must invalidate affected claims; harmless refactors/formatting may preserve valid interfaces under checked canonicalization.
22. **Optional sidecars do not change transitions.** Trace/proof/report generation must not change admitted state machine semantics, physical effect identity, payload or settlement; failure cannot create a second write.
23. **Required gates remain effective.** Optional reporting independence does not excuse bypassing mandatory admission, current authorization, disclosure or required publication/audit semantics.
24. **Finite oracles and qualified evidence only.** Paired positive/adversarial cases remain future verification obligations, not evidence that Gesso, XTDB or HumanHelp has passed them.
25. **Arbitrary Clojure stays explicit.** Formal proofs target the admitted semantic subset; unchecked JVM callbacks are opaque and retain conformance/testing/trust assumptions.
26. **User-facing language stays Clojure/Gesso.** Proof checker, backend or evidence representation are behind the framework; downstream authors do not maintain a Quint/TLA/Recife application replica.

## Gesso v1622 source correspondence and nonclaims

- `src/gesso/assurance/proof/kernel.clj` rechecks a closed seven-rule propositional derivation from original source and returns a copyable *unadmitted* result; it does not issue a certificate or establish independent meta-soundness.
- `src/gesso/assurance/proof/certificate.clj` admits only its supported conditional proof kinds through JVM-local opaque handles and checked dependency graphs. It explicitly does not provide signed persistence, proof of arbitrary Clojure/XTDB/CLJS effects, universal original-source closure or deployed writer coverage.
- `src/gesso/assurance/proof/compose.clj` checks a bounded conditional composition and witness; `:atomic` is a requested mode, not established physical atomicity.
- `src/gesso/assurance/proof/application_assurance_report.clj` recomputes source-based conditional views, is copyable and nonauthoritative, and leaves kernel soundness, installed adoption, physical writer completeness and browser/XTDB refinement open.
- `src/gesso/assurance/subject.clj` computes canonical structural identity of pure bounded EDN-like interfaces. A digest is not denotational equivalence, deployment proof or original implementation correspondence.
- `src/gesso/live/browser/build.clj` binds emitted bytes to a manifest/receipt under its supported build boundary; arbitrary custom emitters, trusted compiler correspondence and actual deployed byte usage require separate justification.
- `src/gesso/live/application_preflight/biff.clj` installs a checked Biff handler in a supplied system map but does not establish that a deployed server uses that final handler or that raw-response bypasses are absent.
- `src/gesso/live/application_preflight/assurance.clj` explicitly describes open rendered-surface and installed-handler obligations; descriptive reports confer no admission or deployment certificate.
- `src/gesso/assurance/proof/xtdb_gateway_biff_request_mediation.clj` provides a scoped Biff mediator around locally issued writers, but cannot attest deployed handoff, all privileged entrypoints, actual authentication or universal XTDB refinement.
- `src/gesso/assurance/proof/xtdb_gateway_biff_writer_assembly.clj` checks a host-local route/writer join and post-dispatch observation. It cannot prevent a write already made or prove all real backend writers are confined.
- `src/gesso/assurance/proof/conditional_single_node_refinement_evidence.clj` composes bounded caller-reported single-node observations and is explicitly not a production authority/certificate.
- `src/gesso/assurance/proof/xtdb_gateway_command_outcome_bridge.clj` v1622 binds local one-shot readback and a disclosure-gated *caller-reported* outcome; it cannot authenticate the principal/arguments/Biff response or infer causality/retry authorization.

These are substantial conditional mechanisms, but NOT a finished enforced qualification lifecycle, authenticated production adoption of every server/DB boundary, universal Clojure formal verification or proven Gesso application.

## Paired positive and adversarial acceptance controls

| # | Positive admitted witness | Forbidden or adversarial witness |
|---|---------------------------|----------------------------------|
| 1 | Current qualified provider admits supported Claim | Known revoked qualification blocks new dependent physical effect before submission |
| 2 | Unaffected safe read remains authorized after unrelated provider fault | Guard failure for one operation must not falsely authorize another |
| 3 | Compatible historical committed command resolves under disclosure | Provider fault, lost reply or unknown status must not turn it into rejection or an automatic retry |
| 4 | Current trusted principal/operation binding admits a real request | Forged browser principal, role, certificate map or stale token cannot authorize the request |
| 5 | Protected result is disclosed only under current policy | Revocation/account switch cannot reveal historical command record or private SSE contents |
| 6 | Real route invokes current installed checked handler | Older captured handler and unchecked raw path cannot inherit route certificate |
| 7 | Authentic source derivation and valid issued certificate is checked | Same-shaped `{:valid? true}` or copied report cannot mint an issued proof |
| 8 | Compatible actual source dependencies remain current | Changed Membership M18->M19 invalidates related Claim despite same digest-looking artifact |
| 9 | Current actual JS bytes match receipt and emitted manifest | Copied digest and arbitrary emitter's manifest claim cannot prove JS implementation |
| 10 | New semantically compatible asset preserves reusable theorem | Formatting-only source edit does not automatically invalidate all abstract meaning |
| 11 | Checker rejects unsupported malformed derivation | Two certificates that justify each other cannot create an axiom by circular reference |
| 12 | Source-complete mandatory proof obligation remains visible | Marking required kernel obligation asserted or removing a source operation cannot pass |
| 13 | Independent positive and negative checker tests expose rule errors | Two wrappers around shared faulty predicate cannot count as two independent proofs |
| 14 | Optional trace collection reports original outcome | Throwing diagnostic after possible commit cannot change unknown into rejection or cause second submit |
| 15 | Optional sidecar removed leaves same state/effect transition | Telemetry code cannot alter guard, payload, effect ordering or settlement semantics |
| 16 | Required construction/runtime gate blocks invalid action | “Sidecar noninterference” does not justify skipping certification/auth |
| 17 | Required durable audit/dispatch obeys operation failure contract | Silently dropping it as optional telemetry fails dependent guarantee |
| 18 | Approved lower profile declares its own bounded claims | Strict profile cannot silently downgrade to `tested` under a missing provider premise |

These are normative prospective controls; *none was run in this document revision*. The independent physical mutation, concurrency and browser failure-window program belongs to section 10.15.

## Boundary and next revision

Sections 10.13–10.14 together preserve the full R4 trusted-computing-base, hostile-browser, certificate-forgery, shared-bug, circular-trust, hash, assertion and sidecar requirements, while keeping R5's stronger selected-provider and current installation semantics. 10.15 must challenge the actual pre-effect guards and post-submission failure windows in physical environments. 10.16–10.20 retain multi-node topology, durable rendezvous, outbox and deployment application/assurance contracts.

Part X whole-part reconciliation must cross-check all of these joins independently. Editorial acceptance is not runtime proof.
