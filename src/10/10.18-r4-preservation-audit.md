## Editorial decision

Retain the R5 split between authoritative state, advisory debt, explicit user grant, coherent acquisition and installed adoption. Restore R4's demonstrable cross-host Claim/result/Refresh failure meaning and give negative races concrete observable outcomes. Part VIII's settled explicit-Refresh policy controls even already-visible remotely changed cards; own-command and local conflict recovery are narrowly scoped exceptions. Preserve the original application semantics while tracing them through distinct real hosts, provider snapshots, HTMX OOB batch and current browser resource ownership.

The R4 example's =choreo/admit-command=, =board/read-authoritative= and adjacent names are schematic contracts, not evidenced current Gesso APIs. This audit references the *behavior*, not a mistaken assumption that R4's illustration already compiles. The ephemeral typing-message half is preserved for review in 10.19, not inserted into 10.18.

## Thirty preservation and strengthening decisions

1. **Part VIII's explicit:** Part VIII's explicit remote Refresh applies both to remote Create and already-visible lifecycle changes.
2. **Application UI policy:** Application UI policy is distinct from generic Gesso choreography and physical hosting.
3. **An advisory is:** An advisory is possible-change debt, never a protected read or installation grant.
4. **The user's own:** The user's own qualified command result can selectively adopt only its correlated outcome and membership effect.
5. **A local rejection/unknown:** A local rejection/unknown recovery read may update the affected Request, not silently expand unrelated cohort membership.
6. **Current Request truth:** Current Request truth and attribution of an unresolved command are independent claims.
7. **Stale visible Claim:** Stale visible Claim buttons remain safe only under transaction-current trusted domain admission.
8. **Initial page load,:** Initial page load, own command, command-recovery read and explicit Refresh have separate grant origins.
9. **One issued Refresh:** One issued Refresh authorizes one board acquisition; in-flight new advisory does not auto-schedule another.
10. **An already pending:** An already pending sufficiently newer qualified observation can discharge additional *covered* debt.
11. **Scoped/incomparable progression requirements:** Scoped/incomparable progression requirements cannot be merged by selecting numerically larger tokens.
12. **Search, sorting, mine-first,:** Search, sorting, mine-first, terminal visibility and card expansion stay local to adopted cohort.
13. **Board collection membership:** Board collection membership cannot be inferred from individual-card or partial/truncated query success.
14. **Common coherent read:** Common coherent read context is required for Request, assignment and permitted User projections.
15. **Lagging node C:** Lagging node C must return insufficient progression rather than echo a requested frontier.
16. **HTTP success or:** HTTP success or received OOB markup is not physical batch adoption.
17. **Toolbar/collection OOB installation:** Toolbar/collection OOB installation must account for partial failure and controlled repair.
18. **Resource replacement, delayed:** Resource replacement, delayed callbacks and failed aborts cannot install retired observations.
19. **Current authorization/scope changes:** Current authorization/scope changes retire old protected projections rather than waiting for Refresh.
20. **Already disclosed offline-client:** Already disclosed offline-client bytes cannot be retroactively erased; new disclosure gates remain real.
21. **Outbox distribution acceptance,:** Outbox distribution acceptance, SSE delivery, browser debt, acquisition and adoption are separate stages.
22. **Host A crash:** Host A crash before submit, after possible submit and after known commit imply distinct participant knowledge.
23. **Lost command response:** Lost command response does not authorize new command identity or automatic resubmission.
24. **Host C's current:** Host C's current Request read cannot identify which of Alice's earlier commands incorporated.
25. **Command historical replay:** Command historical replay requires exact binding, retention, qualified read and current disclosure.
26. **Lost/duplicated advisory and:** Lost/duplicated advisory and registration/router gaps preserve coverage uncertainty without silent adoption.
27. **Multi-node test requires:** Multi-node test requires two actual independent processes, provider and authentic browser/transport evidence.
28. **The HumanHelp response-flow:** The HumanHelp response-flow product contract remains unresolved independently of the Claim/Refresh slice.
29. **Gesso v1622's browser:** Gesso v1622's browser physical shell and bounded command evidence do not imply installed HumanHelp multi-node certification.
30. **Unconditional safety is:** Unconditional safety is distinguished from eventual recovery requiring retention, availability, authentication and explicit user action.
