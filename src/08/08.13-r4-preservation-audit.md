## Preservation and editorial decisions

1. **R4's malformed fixtures use real production construction.** Rather than recreating the illustrative R4 `gesso.application/normalize` / `gesso.application/check-operation` pseudocode as if it were the current API, the finished specification requires a controlled change to the actual HumanHelp `application-preflight` source graph, followed by the actual Gesso preflight. A hand-made “bad application” or altered final status field cannot certify that the real production constructor rejects defects.
2. **Every negative has an eligible positive.** R4 explicitly rejects the vacuous strategy of disabling Claim, failing every startup or treating all malformed inputs as success because every request is rejected. The paired correct path must reach the same enforcing boundary and proceed into real authorized Request/assignment truth and user-visible settlement.
3. **Route- and protocol-bound protection is two-sided.** R4 requires anonymous lifecycle-form/HTMX production to be rejected before serialization *and* a malformed or retargeted command to fail at the trusted HTTP boundary. The revised plan distinguishes the protected output producer from untrusted external clients, with exact route-selected operation/subject identity and no silent downgrade.
4. **Structural versus runtime authority remains separate.** R4's static plan/route/capability checks cannot decide the future Request/assignment and Membership/Organization prestate. This revision places current policy rejection at the actual trusted model/XTDB guard and treats it as legitimate domain behavior, not an assembly error.
5. **R4's startup gates remain physical.** Correct application module, source-owned startup, generated browser artifact and actual handler installation precede Aleph service. Merely rechecking a report or constructor function is insufficient if another handler is installed.
6. **R4's concrete render defects remain required.** Missing basis, conditional buttons, native forms, inherited HTMX, duplicated request attributes, unsupported raw/deferred responses and anonymous route collision are assigned precise physical/output scopes instead of an unjustified universal HTML/JavaScript claim.
7. **R4's malformed command tests preserve exact actor and subject trust.** A forged client `:principal` cannot become the authenticated production User. Testing a malformed plan does not by itself test identity forgery; the latter requires a separately otherwise-valid command and distinct eligible principals.
8. **Failure after commit is not precommit rejection.** The same valid Request write may commit before rendering, Live or delivery fails. The negative oracle must distinguish blocked invalid output from preservation of committed Request authority and truthful recovery.
9. **Dynamic failure completeness survives.** Static preflight must demand a declared recovery/continuation for submitted-unknown, acquisition failure, disclosure denial, obsolete plan/target, lost SSE, exhausted retry and unavailable provider without pretending it can predict their occurrence.
10. **No second authority from an inspection report.** Report fields, copied stamps, valid-looking maps and matching descriptors are non-authoritative. Semantic admission must remain tied to original sources, checked artifacts, actual callable/host binding and protected physical effects.
11. **Physical writer coverage is qualified.** A declared or Biff-enumerated list cannot certify arbitrary outside XTDB capability. Unknown, raw, external and background write paths remain explicit coverage premises or require enforced restriction.
12. **Independent product obligations remain independent.** A reduced model/Choreo catalog missing Reassign is not accepted because the remaining operations pass every structural check. Gessoplan 08.03 and 08.12 supply the separate positive lifecycle and board requirements.

## Gesso implementation evidence and its explicit limits

- `src/gesso/live/application_preflight.clj` assembles browser, operation, trusted execution, publication, route and acquisition evidence; it offers `check-rendered-surface`, `checked-rendered-response!`, `application-handler-module` and `start-biff-application!`. Its namespace documentation expressly limits the guarantee to the canonical Gesso HTML response/start path and does not promise coverage of pre-serialized Ring responses or handler replacement.
- `src/gesso/live/application_preflight/biff.clj` recognizes the exact canonical `application-handler-module`, requires exactly one object with the stable qualified module ID in the modules Var, verifies a sequential qualified start-order beginning with that ID, and installs a `:biff.ring/handler` wrapper. Direct unchecked `biff.core/start`, later replacement and a server that ignores that handler key are explicitly outside the claimed guarantee.
- `test/gesso/live/application_preflight/biff_test.clj` has focused checks for spoofed assemblies, wrong module count/identity/order, invalid Ring handler, guard behavior on canonical HTML, and the explicit exclusion of raw Ring HTML. These are test designs inspected in source; this editorial revision did not execute them.
- `src/gesso/live/application_preflight/rendered_request.clj` enumerates canonical Hiccup HTMX method/path requests, native form owner/action/method and submitter overrides. It rejects duplicated keyword/string spellings of request-relevant HTML attributes rather than arbitrarily choosing one. Its inspection scope is supplied structured output; it does not prove arbitrary later DOM or JavaScript requests.
- `test/gesso/live/application_preflight/rendered_surface_test.clj` includes paired canonical versus anonymous/native POST cases, submitter override, ambiguous attrs, unknown operation, mismatched plan/path and contaminated surfaces. `test/gesso/live/application_preflight_test.clj` checks source-shaped assembly/render closure, malformed metadata and report/assembly tampering. They do not establish the actual HumanHelp production deployment uses every covered guard.
- `src/gesso/http.clj` supplies a dynamically scoped canonical HTML response pre-serialization guard. It cannot attest to deferred work after the dynamic scope ends or manually prebuilt HTML not passed through it.
- `test/gesso/assurance/proof/physical_writer_capability_coverage_test.clj` explicitly includes an unobserved hidden writer, raw XTDB writer marked read-only, copied report/claim, changed callables, ambiguous source and metadata. It treats host-observed registration as bounded evidence, not proof that all physical writers are mediated.
- Browser-plan and artifact checks elsewhere in Gesso bind manifest/receipt/byte identity under a named supported build path. Neither a correct label nor matching hash alone proves all transitive deployed assets or actual browser semantics.

## HumanHelp source and test correspondence

- `src/net/humanhelp/example/application_preflight.clj` composes exact production Request Choreo browser plans, six operation-to-concrete-route mappings, prepared trusted server, compiled Live graph, acquisition and selected generated browser artifact. It explicitly avoids a second operation/plan/route registry.
- `test/net/humanhelp/example/application_preflight_test.clj` uses the canonical constructor and tests deletion of a production operation, physical route or managed fragment realization. This is real source-level fail-closed coverage, not full installed-host or every advertised negative defect.
- `test/net/humanhelp/example/app_test.clj` tests exact lifecycle operation/Request binding, malformed Request IDs and missing/unreadable wire protocol, plus presentation-only settlement handling. These are trusted HTTP/command seam tests, not proof of user-generated browser commands.
- `test/net/humanhelp/example/optimistic_test.clj` checks route/command compatibility, canonicalized authenticated model identity, use of production Request choreography and refusal to use browser arguments as authenticated principal.
- `test/net/humanhelp/example/chromium_acceptance.clj` exercises genuine rendered lifecycle commands and reload persistence for the major positive operations, but not every structural defect nor all two-client board/recovery cases.
- `src/net/humanhelp.clj` currently calls `application-preflight/start-biff-application!` with a modules Var lacking Gesso's canonical `application-handler-module` and with a component-function sequence used where the current Gesso startup requires a qualified module-ID start order. Compared to v1622 Gesso source, this is a concrete source-level mismatch requiring rejection/fix; **the test and actual running-start behavior were not executed in this editorial revision**.
- The HumanHelp positive test ladder and source mismatch are distinct observations. We must not infer “production startup is proven broken” or “full structural acceptance passed” solely from either one.

## Paired positive/adversarial evidence obligations

1. Valid source-owned Claim/route/plan/admitted artifact succeeds; missing plan and wrong route/executor fail without fallback.
2. An otherwise valid actor/Request command reaches current production model; forged browser identity cannot switch actor or Request.
3. Correct native form/HTMX affordance is admitted; same effective protected route without semantic metadata fails before serialization and at the receiver.
4. Qualified rendered observed basis permits Claim; absent basis chooses admitted unavailability or rejects without fabricated authority.
5. Valid generated browser bytes and correct served asset pass; copied receipt, mismatched bytes, stale A assets or unsupported producer fail at their actual boundary.
6. Correct Biff/Aleph module and installed handler serve an eligible real page; missing module, forged identity, wrong start order and later handler swap fail installation/assurance.
7. Real valid Create/Claim transaction persists; a postcommit render failure cannot convert commit into rejection.
8. Recoverable unknown C42 remains uncertain and has bounded requery; incompatible binding reuse is typed rejection without result disclosure.
9. Genuine permitted remote Refresh adopts only justified authority; an advisory, duplicate token, or stale Live callback cannot grant it.
10. Current authorized target T2 remains installed; retired T1 callback cannot install or roll back obsolete state.
11. Covered Request writer commits according to the selected policy; unknown or raw XTDB writer invalidates a stronger physical-writer closure claim.
12. An enabled Reassign target selector and model operation work in an eligible case; removing it from derived catalogs still fails independent product acceptance.
13. Missing initial acquisition/recovery is rejected before managed service; actual dynamic lost acquisition uses the declared repair path rather than an invented terminal outcome.
14. Typed diagnostic is present at the *first actual enforcing boundary* and redacted for recipient, without misleading claims about earlier/later steps.
