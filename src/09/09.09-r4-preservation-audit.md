## Governing reconciliation

Preserve R5's coherent source-relative issuer, independent obligation
checking, typed issued artifacts, process-local handle registration,
durable-package rechecking and scoped reuse. Recover R4's complete
construction and public-category discipline, precise claim semantics,
source-derived completeness, non-vacuous positive controls and
consumer-selected currentness. Do not mistake an architectural future
requirement for existing v1622 proof or installed-app conformance.

## R4 preservation decisions

1. **Original-source provenance:** R4 requires certification to follow
   actual declared source into downstream uses. Source selected by an
   attacker is not proof about the application that was constructed.
   Standalone abstract certificates remain explicitly source-relative.
2. **Coherent construction generation:** Stage checks may be cached or
   parallel, but a new model, old rule and replaced browser artifact
   must not be issued as a single checked subject.
3. **Nine independent pipeline responsibilities:** Source admission,
   normalization, elaboration, obligation derivation, evidence checks,
   required dependency closure, premise accounting, issuance and
   consumption all remain specified; their runtime implementation
   need not use nine separate passes.
4. **Derivation completeness:** An elaborator cannot certify the
   obligation list that it merely chose to emit. An independent
   rule/category specification derives all required cases from
   original source and the selected claim/profile.
5. **Structural versus required closure:** A valid declared DAG
   that omits an operation or invariant is not a complete source
   certification. Source closure and real physical installed writer
   coverage are distinct questions and evidence families.
6. **Separate proof and authority:** A typed conditional rule is
   not a current actor grant, actual transaction incorporation,
   accepted HTMX installation or permission for a browser effect.
7. **Non-vacuity:** Uninhabited initial states and reject-all
   operation coverage cannot satisfy a profile requiring usable
   HumanHelp Create/Claim and positive transition witnesses.
8. **Proposition-specific admission:** Each certificate binds its
   exact theorem, original subject, checker rule, required
   dependencies, premises and requested claim profile. An
   artifact-wide boolean is insufficient.
9. **Conditional is not partial:** Mandatory local checks must all
   pass. Permitted open assumptions remain visible; missing
   derivations cannot be relabeled as legitimate premises.
10. **No self-certification:** Copied checker reports, forged
    semantic IDs, user-submitted success maps and reciprocal
    proof-DAG cycles do not establish valid checked conclusions.
11. **Raw/structural/certified/installed products differ:**
    Public APIs reject same-shaped data and stronger-category
    substitutions; a weaker artifact must be returned explicitly.
12. **JVM-local handles have limited threat scope:** Identity-
    registered unforgeable-through-public-API objects protect
    cooperating code, not hostile same-JVM reflection or
    arbitrary changed trusted Vars. Weak registration does
    not implement revocation or deployment freshness.
13. **Persisted packages re-enter as data:** Exact bounded decoding,
    semantic/checker versions, original evidence, dependency
    closure and policy must be checked. Signatures establish byte
    authenticity, not theorem truth.
14. **Trusted consumer obtains current source:** Checking an old
    graph against old source is not freshness. On change, reuse
    requires exact applicable identity or a separately checked
    compatibility bridge, with coherent hot-reload generation.
15. **Boundary-specific enforcement:** Per-build source checking,
    per-installation actual assets/handlers, per-invocation
    principal/current state and per-effect resource/write
    authority cannot be collapsed into one static stamp.
16. **Ordinary Clojure authoring survives:** Gesso generates
    proof obligations and dependent artifacts from source-owned
    declarations. Developers do not hand-author TLA+, Quint,
    Recife, proof DAGs or copied semantic identifiers.
17. **Product paths survive proof abstraction:** Real Claim
    needs current Membership/Organization and guarded writer,
    exact command-specific historical outcome; creator-local
    Create and one user-authorized remote Refresh retain
    their distinct display and acquisition policies.
18. **Diagnostics identify ownership:** Failure reasons point
    to the first semantic, source, dependency, proof,
    installation or physical gate actually responsible.
    Abstract proof checking is not credited with physical
    defects it has not observed.

## Gesso v1622 correspondence and limitations

- **subject.clj** supplies bounded canonical, pure-data semantic
  identity; its report disclaims behavioral proof of a Clojure function.
- **admission.clj** issues identity-registered structural handles from
  a private WeakHashMap. A copied map or manually created handle cannot
  obtain live admission through the supported API. The checked
  categories are structural rather than universal proof.
- **dependency.clj** verifies node identities, edge fingerprints,
  source-relative graph structure, roots, acyclicity and freshness.
  It does not derive complete physical application dependencies.
- **proof/certificate.clj** currently issues only three restricted
  kinds: propositional, guarded-transition and conditional-induction.
  The issuer reruns original source checks, matches the dependency
  root, requires exact open-obligation sets and registers a
  CertificateHandle only after success. describe-certificate returns
  copyable non-authoritative data; require-current-certificate!
  rechecks supplied source and current dependency graph. The module
  itself says a caller-selected graph proves only its selected
  abstraction, not currently installed application correspondence.
  Checker meta-soundness, arbitrary implementation equivalence,
  full physical writer coverage and runtime authority remain open.
- **proof/application_dependency.clj** independently derives a
  complete ledger/graph for an original declared abstract induction
  catalog. It expressly disclaims an independently authenticated
  installed writer inventory or application proof.
- **live/application_preflight.clj** and inductive_policy.clj supply
  selected assembly/startup gates and source/operation coverage
  reports; they are not general issued certificates of deployed
  browser, XTDB or arbitrary business-policy conformance.
- **test/gesso/assurance/proof/certificate_test.clj** contains
  adversarial cases for forged reports, unissued handles, omitted
  obligations, wrong roots, stale proof and graphs, and preserved
  conditional abstract premises. Source inspection is not an
  executed test result in this review.

The working implementation contains real, useful precursor
boundaries. None establishes a general original-source-to-installed
application theorem, a sound fully independent proof kernel
metatheorem, automatic opaque-Clojure effect coverage or
physical end-to-end certification. R5.1 retains those future
requirements without claiming they are currently discharged.

## Positive/adversarial verification obligations

1. Genuine issuer-registered conditional proof is admitted;
   copied describe-certificate output is not.
2. Original source derives its obligation manifest;
   precomputed caller :checked-result is rejected.
3. Declared induction catalog contains every invariant,
   initializer and operation; omitting one cannot pass via
   a structurally valid reduced DAG.
4. Consumer rechecks actual current source; caller-selected
   stale source+stale graph cannot claim currentness.
5. Hot reload installs one wholly admitted new generation;
   old proof/new writer/new client bundle mixing is rejected.
6. Local checks pass with exact allowed open premises;
   omitted required proof step is not excused as assumption.
7. Inhabited initial state and valid positive operation
   meet the selected non-vacuity gate; impossible Init
   or reject-all construction does not.
8. Independent writer/route inventory establishes its
   named coverage; a dynamic omitted writer cannot be
   certified by a hand-written declaration.
9. Real handle passes the proper category;
   same-type forged object and serialized handle fail.
10. Valid inert durable package is rechecked;
    reader execution, unknown tag, stale signature,
    missing evidence and unsupported version fail.
11. Compatible, unchanged abstract semantic contract
    may reuse its proof; changed implementation cannot
    reuse an old physical correspondence unexamined.
12. Authorized real Claim has command-specific historical
    readback; HTTP 200 or card view is not an outcome.
13. Exactly one user-authorized remote Refresh may
    perform its named acquisition; queued second
    request cannot consume the original grant.
14. Current actor/Membership/Request state must be
    checked at the mutation boundary; static proof
    does not cache current domain authorization.
15. Independent proof kernel/dedicated checker accepts
    an actual derivation; fabricated proof rule/result
    cannot mint a new theorem.
16. Unsupported strong profile fails explicitly;
    no transparent downgrade to unchecked execution.
17. Retired incompatible source/plan/resource loses
    effect rights even if an abstract certificate remains;
    durable command recovery has a separate contract.
18. Valid practical HumanHelp Create/Claim/response
    control must succeed when eligible; a reject-all
    checker is not sufficient positive product evidence.

The expected result and first responsible checking/physical
boundary must be recorded before running each mutant.
A counterexample about an abstract model is not itself
an authenticated trace of the deployed browser or XTDB.

required-obligation completeness, conditional claims,
non-vacuity, typed category separation, coherent issuance,
consumer freshness, durable imports and stage-specific
runtime enforcement explicit while retaining R5's
efficient issuer/handle architecture.
