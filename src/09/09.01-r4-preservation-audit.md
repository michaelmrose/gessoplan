## Governing design judgment

Preserve the preferred R5's **one executable semantic core, separate small
proof kernel and dedicated semantic checkers**, with shared canonical
terms but no parallel runtime semantics. The finished Gesso user
writes normal Clojure application/model operations, typed rules where
the supported reasoning fragment applies, and explicit contracts
only where real application truth or opaque effects cannot be inferred.
Gesso generates routine obligations and derivations; it does not
require HumanHelp developers to maintain TLA+, Quint or Recife
proof source by hand.

This revision strengthens a proposition-scoped rather than
artifact-scoped assurance model. An independent current runtime
authority check is never implied by a proof digest, checked
abstract proposition, generated JavaScript stamp or good Clojure
namespace name. The design remains *aspirational where needed*:
the installed Gesso source is implementation evidence, not
the upper bound of the timeless contract.

## R4 preservation decisions

1. **Dependency invariant / no proof by reputation.**
   Retained from R4 lines 14–235: every exported guarantee
   needs a checked justification appropriate to its evidence
   class, with explicit original-source subject, dependencies,
   scope and still-open assumptions. An upstream status label
   cannot satisfy a missing downstream proposition.
2. **Executable and proof DAG are different products.**
   Retained from R4's runtime/certificate parallel paths:
   checked proof sidecars may govern build admission but
   cannot alter an already admitted operation's transitions,
   authorize current User or create XTDB transaction facts.
3. **No accidental raw-to-certified substitution.**
   R4 lines 455–488 and 2502ff specify checked constructors/
   opaque handles instead of untrusted =:valid?= flags;
   the revision states this as a public-interface behavioral
   property, not an impossible security promise against
   arbitrary trusted JVM reflection or raw lower-level writes.
4. **No self-certification, copied identity, or proof cycles.**
   R4 lines 489–556 retain independence of proof checker
   from elaborator, an acyclic certificate justification
   graph, explicit fixed-point/induction for legitimate
   recursion, and distinction between structural fingerprint,
   proof evidence and physical implementation identity.
5. **Fail-closed without useless reject-all.**
   R4's stronger certified construction requires no
   certified artifact after a failed required check.
   Narrower operational/conditional profiles remain
   explicit legitimate products; a requested stronger
   build cannot silently downgrade. Every negative
   test requires a related genuine admissible positive.
6. **Full-language Clojure remains available.**
   R4's certified construction and R5 full-language
   principle survive without a second programming
   language. Unsupported arbitrary code is a named
   opaque conformance or runtime premise and cannot
   be mislabeled as proof; surrounding independent
   facts can still be checked when unaffected.
7. **Correctness-relevant semantic-policy surface.**
   R4 lines 1419–1544 retain explicit coverage for
   authorization, ownership, assignment, disclosure,
   state transition, command incorporation and
   related semantic choices. A detected escape in an
   inspected subset must be reported. No escape found
   in a closed rule AST does *not* prove that arbitrary
   uninspected Clojure branches are irrelevant.
8. **Finite, conditional, formal and physical limits.**
   An exact finite-model result, conditional abstract
   derivation, runtime enforcement and browser test
   remain different evidence classes. No bounded
   trace proves all backend writers or an unbounded
   theorem without an explicit abstraction/refinement.
9. **Source and coverage completeness are independent.**
   All submitted derivations may be valid while
   obligations, operations, true product requirements
   or physical writers are missing. Coverage is
   relative to a declared inspected surface and
   independently named product obligations.
10. **Error location, applicability and change impact.**
    The first boundary with the necessary evidence
    rejects with a structured diagnostic. Fresh trusted
    consumers recheck source/dependency/generation
    applicability instead of trusting yesterday's
    report or a copyable certificate summary.

Detailed rule syntax and opaque normalization belong to 09.03–09.04;
judgment and proof-kernel schemata to 09.05–09.07; certificate
issuance and identity/DAG to 09.09–09.11; actual
source/XTDB/browser correspondence to 09.12; HumanHelp root
pilot to 09.13; coverage diagnostics and mutation suites

## Gesso v1622 correspondence: concrete partial implementation

- `src/gesso/assurance/subject.clj` computes bounded, versioned
  *structural identity* for pure declared interfaces. Its own
  contract denies that structural fingerprints prove behavioral
  equivalence, original Clojure source fidelity or admission.
- `src/gesso/assurance/rule.clj` parses bounded, data-only rule
  syntax and exact reader declarations; its returned report
  is copyable and unadmitted. It cannot observe all hidden
  arbitrary Clojure policy branches.
- `src/gesso/assurance/proof/kernel.clj` checks a small closed
  propositional derivation from re-parsed original source;
  the output remains descriptive, conditional on any open
  premises, and is not transaction authority.
- `src/gesso/assurance/proof/certificate.clj` admits restricted
  propositional, guarded-transition and conditional-induction
  evidence to opaque, process-local registered handles.
  Its source documents open premises including original
  abstract/physical relation, complete writer catalog,
  original state validity and unproved checker meta-soundness.
- `src/gesso/assurance/proof/compose.clj` conditionally composes
  two abstract operations with a specified intermediate
  state relation; structural compatibility does not prove
  executable sequencing, actual atomicity or HTMX/XTDB
  effect correspondence.
- `src/gesso/assurance/report.clj` produces a source-bound,
  *copyable reporting object*, explicitly neither proof
  kernel nor authenticated test-run evidence nor a
  deployment/certification or authorization gate.
- `src/gesso/live/application_preflight/certified_contract.clj`
  checks an in-process binding from actual issued semantic
  executor to Ring handler and route table; its own
  documentation excludes unknown handler replacement,
  independently deployed router and opaque request/response
  callback correctness.
- `src/gesso/assurance/proof/physical_writer_inventory.clj`
  documents a host-observed writer enumerator that cannot
  prove enumerator completeness or absence of outside raw
  XTDB writers.
- `src/gesso/assurance/proof/propositional_derivation_soundness.clj`
  supplies a conditional source-specific soundness argument
  but does not certify the universal implementation body
  or transitive model-to-physical refinement.
- `test/gesso/assurance/proof/certificate_test.clj` and
  `test/gesso/assurance/proof/application_assurance_invalidation_test.clj`
  include positive admission and adversarial copied/stale/
  assumption scenarios. They were inspected, *not executed*.

These are meaningful source-level precursors. There is no
basis from this inspection to declare universal proof-kernel
soundness, all original-source/issuer-to-deployed links,
complete physical writer confinement, full compiler
correctness, or complete HumanHelp product acceptance.

## HumanHelp and cross-part correspondence

- Accepted R5.1 Parts I–III own semantic ontology, type
  meaning and source-to-participant choreography.
  Parts IV–VI own current Request transaction/command
  authority, browser physical effects, progression and
  knowledge. Part VII owns whole-application source
  closure and actual production-path enforcement
  requirements. Part VIII owns independent HumanHelp
  product intent and real-browser/XTDB acceptance.
- The HumanHelp Claim exemplar requires a manager/helper
  distinction, complete guarded Request/RequestAssignment
  effects and current Organization/Membership eligibility;
  a source-derived conditional proof cannot authorize
  a stale Claim or certify unqualified absence of an
  active primary assignment.
- The required HumanHelp Reassign and one-use Refresh
  capabilities remain independent product oracles:
  deleting them from the declared graph does not
  establish semantic or product completeness.
- Historical command C42, current Request R17,
  actor/session authority, browser target T1,
  issued plan identity and Live advisory debt have
  separate subjects. A certificate that checks one
  cannot silently provide the others.
- The Part VIII independent editorial acceptance
  did not assert that the current HumanHelp app has
  passed its full runtime and product gates. This
  Part IX review likewise does not.

## Concrete positive and adversarial obligations

1. A valid, source-owned Claim rule and admitted
   opaque Organization policy permit the compatible
   profile and separately retain open premises.
2. A valid theorem/proof source admits only the
   precise, scoped abstract conclusion it establishes;
   proof kernel and current runtime authority remain
   distinct.
3. Forged `:verified?` map, copied certificate
   description or matching subject digest cannot
   substitute for a fresh admitted upstream value.
4. An inferred dependency edge missing from the
   source-declared catalog blocks the requested
   stronger profile rather than silently passing.
5. A source change to Membership, Claim guard,
   route, execution/callback or browser artifact
   invalidates affected conclusions at trusted
   consumption while preserving unrelated checks
   where compatible.
6. An unsupported proof syntax cannot run arbitrary
   host code, silently become an assumption, or
   downgrade the user's requested strong profile.
7. A discovered authorization/policy branch omitted
   from the inspected semantic subset is diagnosed
   as an escape; uninspected Clojure remains
   explicitly outside completeness claims.
8. A cyclic certificate chain cannot establish
   its own premise; a genuinely supported
   inductive/fixed-point rule is treated separately.
9. Removing HumanHelp Reassign from both the
   source and generated model still fails its
   independent positive capability acceptance.
10. A hidden raw XTDB writer or opaque callback
    leaves physical correspondence open rather
    than being falsely reported proved.
11. After abstract certification, an invalid
    current actor, failed guard or retired browser
    target still cannot perform the protected
    physical action.
12. Test a real valid candidate alongside every
    malformed candidate; rejecting everything
    is never a certified-construction success.

## Editorial checks and limitations

This revision changes only the numbered 09.01 Org
source, its audit, the derived canonical Part IX
publication, and the Part IX README. The other
15 numbered Part IX sources remain unchanged.
The exact publication must reassemble from all
16 sources at the committed GitHub HEAD, retain
all eight original Part IX `CUSTOM_ID` anchors
and both original cross-part links, and keep
Org example/source blocks balanced.

**Not run:** local complete checkout
`python3 script/assemble_r5.py --check`,
Gesso/HumanHelp JVM, XTDB, Playwright/Chromium,
Recife/TLC or production deployment checks.
Source review and a GitHub document equality
check are not a physical certification.
