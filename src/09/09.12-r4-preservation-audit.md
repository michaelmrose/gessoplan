## Governing reconciliation

Keep R5's stronger explicit directional realization edges, issuer
ownership and physical evidence limits. Recover R4's complete
root application chain, executable/manifest/rendered-surface
categories, source-to-host binding and non-HTTP writer coverage.
Make actual *causal* command provenance, transaction-internal
prestate, independent provider observation, loaded browser
bytes, installed target completion and bounded versus
universal claims explicit. Preserve timeless finished-system
requirements, placing current implementation evidence and
nonclaims in this audit rather than in the normative Org text.

## R4 preservation and design decisions

1. **The hierarchy extends past ExecutablePlan.**
   Original model/rule/operation, admitted Choreo, projected
   plan, assembly, emitted assets, installed routes, model writer,
   live output and actual physical effect are separately
   required links for appropriate root profiles.

2. **Each correspondence edge has a proposition.**
   Source/target, abstraction mapping, observables,
   hidden steps, failure treatment, trust/issuer,
   quantifier, applicability and generation must be named.
   Matching a stamp is identity evidence, not proof of
   translation correctness or physical installation.

3. **Source-owned callables reduce drift but are not proof.**
   Actual issued handler/plan correspondence needs
   source-rechecked construction. Installing or invoking
   it is a separate trusted host event; copied reports
   and route inventories do not establish adoption.

4. **Input conversion is security-sensitive.**
   Ring/Biff request-to-input mapping must bind the real
   trusted principal and tenant, canonical operation,
   command ID, state/input and anti-forgery requirements.
   An attacker-supplied principal or a mapping error
   defeats an otherwise verified rule.

5. **Response conversion is security-sensitive.**
   Final outcome, actor disclosure, status mapping,
   HTMX transport semantics and recovery must be
   checked at the source-owned response boundary.
   HTTP success does not certify domain incorporation.

6. **Per-request provenance is essential.**
   Independent simultaneous requests require
   independent stable command, execution, physical
   node, authorization and result evidence.
   Global single-request fixtures and second
   diagnostic submissions do not prove concurrency.

7. **Effect inventory is not route inventory.**
   Non-HTTP writers, initializers, background work,
   imports, migrations, raw XTDB bypasses and
   external processes must be covered or explicit
   premises. Comparing a host list to itself
   does not prove the list exhaustive.

8. **Atomic prestate belongs to the transaction.**
   Candidate pre-read eligibility is not proof
   of the actual transaction-internal guard.
   A selected profile must authenticate guarded
   source/serialization/recomputation or leave
   exact protected writer semantics open.

9. **Post hoc comparison cannot prevent an effect.**
   A later discrepancy may diagnose/reject
   assurance but cannot undo unauthorized
   incorporation. Required strong prevention
   must act at the actual pre-effect boundary.

10. **Co-observation is not causality.**
    Matching public TransactionKey, system ledger,
    domain poststate and command record at a pinned
    basis is valuable bounded evidence but can
    arise from other writers unless authentic
    same-execution causal binding is independently
    established. Unknown after submission
    must not trigger a second write.

11. **Stable historical commands survive recovery.**
    C42's incorporated past is distinct from
    current Request status and H1/H2 transport
    attempts. Replay checks actual original
    command binding and current disclosure,
    not a fresh new-command guard.

12. **Four domain outcomes remain distinct.**
    Committed, rejected, already-incorporated
    and commit-unknown are not a Boolean
    success/failure split; presentation
    accepted/rejected/unknown has its own
    mapping and source evidence.

13. **Outbox/invalidation and browser adoption are
    later evidence subjects.** Atomic write,
    durable intent, publication, fanout,
    acquisition and completed installation
    cannot be collapsed into one commit stamp.

14. **Browser build correctness is conditional.**
    Manifest, deterministic emission and asset
    digests bind only their actual inspected
    source/build. Common-mode compiler/checker
    bugs remain trusted unless independently
    checked. The real server and browser must
    select the corresponding bytes/plan.

15. **Concrete rendering needs concrete output.**
    Checking one Hiccup tree cannot prove
    all possible deferred/streamed/cache/error
    responses. Actual affordances/HTMX
    requests and serialization need their
    own declared coverage and first gate.

16. **Physical adoption is target/owner scoped.**
    Admitted source, authorized acquisition,
    effective actual target, effect resource
    instance and completed swap are distinct.
    Partial OOB and superseded continuity
    rights remain real obligations.

17. **Proof quantifiers must not change silently.**
    One controlled trace is scoped evidence.
    Exhaustive finite-model checks are
    model-bounded; universal physical
    refinement requires a simulation/abstraction
    argument with trusted observation,
    writer-coverage and environment premises.
    Safety and liveness are separate.

18. **Positive HumanHelp controls remain independent.**
    Correct eligible Claim, Create, manager
    Reassign, user-granted Refresh, creator-
    local visibility, remote advisory,
    continuity and response behavior
    need actual execution paths; reject-all
    certification cannot substitute.

19. **No silent downgrade.** A missing
    physical guard, uninstalled handler,
    unknown writer or unsupported host
    prevents stronger admission rather
    than allowing a raw HTMX request
    to impersonate a Choreo operation.

20. **First actual enforcement and origin**
    govern failure attribution. A static
    checker may discover a declared
    mismatch but must not claim to
    have caught physical violations
    it cannot observe.

## Source correspondence: Gesso application-assurance v1622

The source corpus contains important
partial implementations but does not
support a whole-production theorem:

- `src/gesso/live/application_preflight/inductive_contract.clj`
  joins an original abstract induction catalog with current
  issued-handler semantic routes, explicitly leaving actual
  router adoption, physical writer completeness, initializer
  correspondence and abstract-to-physical transition semantics
  unestablished.

- `src/gesso/assurance/proof/issued_executor_physical_plan_correspondence.clj`
  freshly issues a controlled one-shot handler and observes
  actual adapter-call operations from the same synchronous
  invocation. It is not the already installed production route;
  its callback, XTDB API/node, atomic prestate and other writers
  retain open obligations. The closely related
  `issued_executor_ledger_join.clj` avoids a second diagnostic
  transaction and uses a pinned ledger readback, while leaving
  physical payload authentication and production origin open.

- `src/gesso/assurance/proof/installed_route_physical_correlation.clj`
  binds a controlled Ring invocation and adapter-call
  observation with in-process source/handler evidence, but
  does not establish that the running production server
  adopted this route. The
  `installed_route_guarded_correspondence.clj`
  module expressly refuses to treat separate caller-supplied
  prestate data as evidence about the executed handler.

- `src/gesso/assurance/proof/physical_writer_inventory.clj`
  asks a host enumerator to inspect registered writer paths.
  Its own documentation says this cannot prove that the
  enumerator found every raw/external/hidden writer or
  that observed writers refine the abstract operation.

- `src/gesso/assurance/proof/physical_xtdb_transition_observation.clj`
  classifies one controlled XTDB transition and its distinct
  observation phases, without authenticating production
  handler or universal writer coverage. Some controlled
  collectors actually submit transactions; diagnostics are
  restricted to a controlled test node and must never
  auto-retry after uncertain submission.

- `src/gesso/assurance/proof/xtdb_gateway_atomic_readback.clj`
  observes canonical domain/command/ledger records at a
  pinned basis but warns explicitly that matching all
  three does not prove causality.
  `xtdb_gateway_command_outcome_bridge.clj` (v1622)
  joins an issued plan-bound atomic submission, exact
  in-process result, pinned readback, canonical command
  reconciliation and caller-reported request outcome.
  The reported outcome, disclosure predicate, principal,
  node and installed plan are not independently
  authenticated, so this is bounded value agreement,
  not Ring causality, authorization or browser settlement.

- `src/gesso/assurance/proof/xtdb_gateway_biff_parallel_request_context.clj`
  provides opt-in Biff request-local writer registries,
  concurrent request support, source-bound issuance and
  atomic command/update/readback options. Its own contract
  disclaims completeness of bypass writers, actual
  deployed adoption, principal correctness, domain-target
  truth and universal execution refinement.

- `src/gesso/live/application_preflight/rendered_surface.clj`
  enumerates concrete supplied Hiccup surfaces and
  effective request coordinates but does not prove
  all possible render states or streamed and deferred
  output paths. Browser shell source
  `src/gesso/live/browser/shell.cljs` explicitly owns
  physical transport/continuity resources and translates
  lifecycle effects; semantic source verification
  and actual browser install remain separate concerns.

- `src/gesso/assurance/proof/transaction_outcome_progression_correspondence.clj`
  classifies one physical outcome/durable resolution/
  progression report, while retaining nine explicit
  physical refinement obligations. It distinguishes
  reconciliation from new incorporation and
  does not equate an unknown exception with rejection.

Representative test sources include
`test/gesso/assurance/proof/installed_route_physical_correlation_test.clj`,
`test/gesso/assurance/proof/physical_writer_inventory_test.clj`,
`test/gesso/assurance/proof/xtdb_gateway_atomic_readback_test.clj`,
and `test/gesso/assurance/proof/xtdb_gateway_biff_source_return_readback_test.clj`.
These were inspected for inventory, not executed in
this revision; they are not proof of deployment.

## Positive/adversarial conformance cases

1. Valid source/issued handler and actual host route
   coincide; a copied name or replaced callable does not.
2. Trusted principal and canonical Request input
   reach the actual guarded writer; caller-supplied
   principal or stale pre-read does not.
3. One request/transaction carries its own source,
   node and outcome; another request or diagnostic
   transaction cannot donate evidence.
4. Genuine guarded atomic incorporation satisfies
   its protected dependencies; post hoc
   comparison alone cannot prevent a bad write.
5. A controlled real submission and matching
   pinned domain/command/ledger readback
   are reported at their *bounded* class;
   an unrelated co-write cannot be
   misreported as causal proof.
6. Known incorporated C42 replay uses original
   binding and current disclosure; a new
   write/guard on replay is rejected.
7. Exact command outcome remains distinct
   from HTTP/presentation success and
   current Request status.
8. A qualified real writer/initializer
   inventory covers required effects;
   hidden raw/external paths are not
   certified by self-reported host lists.
9. Source/plan/manifest/generated bytes
   match at the actual build boundary;
   copied manifest stamps or wrong
   bundles do not establish execution.
10. Actual browser load is compatible
    with served plan and installed
    application generation; a suspended
    tab or substituted asset is rejected.
11. Valid concrete rendered Hiccup
    affordance binds a real operation;
    unseen deferred/error response
    does not inherit its coverage.
12. Authorized target-specific HTMX/OOB
    installation completes before
    adoption is claimed; partial swap
    or retired resource does not.
13. Local Creator Create remains visible
    without unrelated whole-board
    refresh; remote advisories cannot
    manufacture Refresh permission.
14. Qualifying user Refresh grants
    exactly its scoped read and
    adoption; second ungranted
    acquisition cannot borrow it.
15. One controlled physical trace
    may support a bounded witness;
    it is not a theorem over every
    deployed possible execution.
16. A successful actual eligible
    Claim/Create path passes an
    independent product oracle;
    reject-all construction does not.
17. Changed handler, writer, provider
    or asset generation invalidates
    the affected physical claim while
    leaving unrelated abstract proof
    potentially reusable.
18. Missing physical provenance or
    current installed enforcement
    rejects a strong profile rather
    than silently downgrading.
19. Correct response mapping and
    historical command disclosure
    succeed; mapping HTTP 200 or
    a fresh current-card read into
    fabricated commit success fails.
20. Real application audit attributes
    each failure to its first actual
    source, checker, assembler,
    runtime gate or observation
    boundary, never imaginary
    cross-layer evidence.

The corpus must predeclare source, claim,
expected result, evidence origin and
first enforcement boundary. A structural
checker cannot be credited for observing
a physical defect that only an independent
host witness could establish. Positive
cases and deliberate negative neighbors
are both mandatory.

## Editorial outcome

09.12 now binds the proof hierarchy to
actual source-owned issued execution,
Ring/Biff and physical XTDB guard
requirements, command-specific history,
non-HTTP write coverage, emitted and
loaded browser artifacts, real target
installation and scoped refinement
quantifiers. It retains R5's strong
architecture and R4's whole-application
and browser/report requirements.

The finished-system design requires
these relationships; the v1622 source
supports narrower, well-documented
precursors, not end-to-end deployed
correctness. The separation is
deliberate and must survive later
Part IX whole-part reconciliation.

**Nonclaims:** This audit does not
claim any newly run tests,
formal theorem, deployed Gesso
installation certificate, universal
physical refinement or accepted
production HumanHelp pilot.
