## Central editorial decision

R4 rightly used *one evolving* original Claim instead
of eighteen parallel demonstrations. It also made
important negative assertions: illustrative API-shaped
calls do not implement a checker, a printed certificate
is not proof/authority, and a browser-provided
`:principal`/`:role`/`:basis` cannot authenticate
the model actor. Those requirements remain. R5's
data-first, runtime-neutral boundary table is clearer
and more durable than reproducing R4's extensive
fictional call sites. The new 12.12 restores **all
eighteen stage joins** with exact actual evidence
subjects, while keeping the example explicitly
contractual rather than claiming current APIs exist.

The entire example uses one eligible human helper
Alice, one independent remote viewer Bob, one Request
R, a separate active-primary RequestAssignment,
one original C42 logical command and a different
identity for each attempt, browser resource, installed
generation and backend observation. Neither a toy
`:request/helper-id` nor a fabricated Claim-only
business rule is accepted as an implementation.
Reassign and Unclaim remain relevant to invariant
catalog coverage; the complete HumanHelp product
requires their actual independently eligible paths,
and Response remains separately unselected.

A newly committed C42 can have an unknown client
outcome after network loss. A later authorized
historical resolver does not rerun a now-false
new-Claim guard; if command-specific evidence
is unavailable, the current claimed R does not
prove the identity or result of the old command.
The original R4 multi-node observation retained
this distinction, as do the revised R5.1
command semantics. Publication can be owed even
when its dispatcher dies, with durable intent
selected and atomically recorded where the
strong profile requires it. A delivered advisory
does not create Bob's one-use Refresh grant.

A pre-read and an emitted XTDB ASSERT/PUT do not
automatically attest transaction-internal
prestate, actual uniqueness, full frame or all
external writers. Similarly a checked application
assembly, build manifest or local Ring wrapper
does not show the active host served those bytes
or installed handler. Each now has a separate
physical evidence slot; source-checking without
actual correlation remains conditional or
explicitly open.

## Bounded Gesso v1622 implementation evidence

The following real source namespaces were inspected.
They establish meaningful mechanisms, not this
entire HumanHelp execution or a stronger formal
or production certificate:

- `src/gesso/model/core.clj` builds Malli-derived
  single-document Graph/FX/Biff plumbing;
  domain complex relationships remain
  application-owned and generic model
  generation alone is not HumanHelp Claim.
- `src/gesso/model/tx.clj` combines
  `:commands`, `:guards`, `:assertions`
  and `:changes` for generic atomic plans.
  The guard keys are not a complete
  independent authorization proof, and
  the ordinary Live after-commit seam is
  not an atomic multi-host durable outbox.
- `src/gesso/model/command_resolution.clj`
  supplies experimental same-plan command
  record creation and exact replay under
  application-supplied trusted binding,
  guards, authorization and disclosure.
  Its namespace explicitly leaves real
  XTDB contention, retention, complete
  domain guards and lost-response
  liveness outside its checked scope.
- `src/gesso/choreo/project.cljc`
  projects closed roles, communication,
  environment await and authoritative
  operations, with scoped local knowledge
  but no proof that a browser-originated
  label can authorize the server.
- `src/gesso/live/browser/adapter.cljc`
  owns the pure =AdapterState × Event →
  State × Effects= transitions, stale
  target/effect control, opaque basis,
  optimistic settlement and logical
  Live refresh debt. It does not
  prove physical HTMX installation
  or HumanHelp one-use Refresh policy.
- `src/gesso/live/application_preflight.clj`
  checks selected source-derived
  operation/route/plan/artifact/
  acquisition and canonical rendered
  HTML seams, while explicitly not
  establishing actual arbitrary
  installed Biff handler use,
  all external writers or every
  pre-serialized response path.
- `src/gesso/assurance/proof/certificate.clj`
  admits restricted source-relative,
  JVM-local proof kinds, not a
  signed portable credential, a
  meta-sound kernel or XTDB
  execution refinement.
- The accepted 12.10/Part X source
  comparison also records bounded
  experimental XTDB prestate and
  scoped one-shot command-outcome
  observations. Those cannot
  identify the fully authenticated
  cross-host physical C42 history
  in this hypothetical schedule.

Source inspection is not a substitute
for executable product or formal
evidence. No new JVM, XTDB, Biff,
Playwright/Chromium, multi-host
failure, generated formal backend
or external theorem checks were
run during this editorial revision.
