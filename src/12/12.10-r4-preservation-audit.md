## Editorial findings and preserved design freedom

Preferred R5's improvement is retained. Gesso generates
formal subjects from the original admitted semantic
machine and transfers evidence through precise, separately
qualified correspondence relationships. A mathematical
theorem can remain true while its physical implementation
premise fails. Admission soundness, completeness,
physical execution safety refinement, progress transfer
and reverse traceability are *different judgments*.
The last is a mapping of assumptions to production
obligations, not an automatically proven reverse
simulation relation.

The strong production safety direction is concrete to
abstract: each relevant admitted physical execution
under a justified initial and step relation has an
allowed abstract behavior, accounting for permitted
internal stuttering. The existence of a matching
formal operation name or synthetic example does not
prove this simulation. A finite enumeration cannot
supply universal abstraction or physical refinement
unless closure and the transfer theorem are independently
established. Progress additionally needs actual fairness,
availability, retention, continued authority and
appropriate HumanHelp user action.

R4's original Stage 17 correctly insists on a bridge
from every formal assumption back to the *production
enforcing boundary*, preservation of original/source
requirements, genuine generated-backend counterexamples,
deterministic artifacts and actual release freshness.
The new section makes those obligations more explicit
without claiming that current v1622 XTDB readback,
snapshot tokens or one-shot receipts authenticate
transaction-internal prestate, full writer causality
or all deployed browser effects.

For Stage 18, R4's several-process realization is
not a replacement distributed business model.
Part X establishes one semantic machine across
placement changes. The revised roadmap recovers the
essential durable changes, command result, cross-host
replay, late interest and router failover failure cases.
In particular an outbox need not know all live current
subscriber interests at the moment of original write,
and a router's incomplete interest filter must not
be used as proof that a missed notification is
impossible. Fence/replay/gap/authorized reacquisition
are explicit. Duplicate advisory redelivery is
permitted and can avoid expensive per-recipient
completed-delivery tracking, but requires selected
acknowledgment meaning, scope/disclosure and bounded
work. No particular hierarchy, broker or Rust
implementation is mandated.

The HumanHelp choice remains remote advisory-only,
including lifecycle changes to already visible
Requests; Bob's one-use explicit Refresh is a
distinct permission. With no user Refresh,
automatic visible convergence is *not* the intended
liveness guarantee. Initial/authorized acquisition,
unresolved notices, scope-qualified progression
and actual physical DOM adoption are independent.

## Bounded actual Gesso v1622 implementation correspondence

The `application-assurance` branch currently resolves to
`1b5e10e71c00e7784b019dee7dc1198a96fd03f6`,
with source inspected via GitHub. It provides
well-scoped precursors rather than completed
distributed assurance:

- `src/gesso/assurance/proof/kernel.clj` checks seven-rule,
  original-source propositional derivations, not external
  meta-soundness or S2 implementation refinement.
- `src/gesso/assurance/proof/finite_model_oracle.clj` is a
  separate bounded data-only oracle over a declared finite
  transition universe; its enumerated integer/identity
  representatives do not prove unbounded policy safety
  or physical execution.
- `src/gesso/assurance/proof/xtdb_internal_prestate_capability.clj`
  records version-specific XTDB 2.2.0-beta1 transaction
  API and earlier bounded prestate experiments. It
  explicitly rejects a public snapshot token or
  `xt.txs` row as an authenticated internal DML
  guard/prestate witness.
- `src/gesso/assurance/proof/xtdb_gateway_command_outcome_bridge.clj`
  is an opt-in, read-only join of exact process-local
  submission return, pinned local readback, canonical
  command reconciliation and a *caller-reported*
  request result. It does not authenticate installed
  server handler use, physical causality, current
  principal authority, safe cross-host retry or
  Live/browser settlement.
- `src/gesso/live/invalidation.clj` expands
  declared primary changes to invalidation scopes,
  retaining exact trusted progression metadata;
  it neither inspects real DB writes nor emits
  SSE/cross-host notices and cannot guarantee
  durable outbox or registration coverage.
- `src/gesso/live/progression.cljc` preserves
  orderless opaque authority bases, allowing
  only exact equality and externally supplied
  progression evidence, rather than deducing
  order from integers, timestamps or host arrival.
- `src/gesso/live/application_preflight.clj`
  and the Biff preflight modules (previous
  sectional source audits) provide selected
  canonical assembled/HTML boundary checks
  without independently proving the actual
  deployed handler and external writer inventory.

These files are concrete implementation evidence
of the *vocabulary* and bounded mechanisms, not
a general distributed routing service, strong
outbox-failover implementation, source-to-XTDB
universal refinement or independent formal proof.
No Clojure test suite, embedded XTDB probe,
two-host crash, Chromium/HTMX or external formal
checker was executed during this editorial edit.
The fact that source docstrings name earlier tests
is not evidence of a newly run test.
