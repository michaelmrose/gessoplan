## Requirements preserved from R4

1. **Mandatory production-path checking, not an optional ritual.**
   R4 requires the supported managed startup to perform structural
   preflight before external service, and actual render/operation
   boundaries to reject protected contradictions when knowable.
   A checker test that directly invokes a validator does not prove
   the deployed application adopted it. 07.04 now places assurance
   policy at candidate admission, installation, activation,
   invocation and post-execution observation, each with its
   separate claim.
2. **Canonical production assembly.** R4 rejects a test-only route,
   registry, browser artifact or mock handler masquerading as
   production evidence. 07.04 uses source-owned catalogs and actual
   issued/installed realizations; a copied report or equal operation
   name cannot transfer authority.
3. **Strict current authorization still belongs to the model.**
   Preflight can establish trusted route and principal-binding
   structure, not that a particular helper is currently permitted
   to Claim a particular Request. The real guard and transaction
   boundary must check current Request, RequestAssignment,
   Membership/Organization and trusted principal.
4. **Required dynamic handling and positive paths.** Runtime
   rejection, unavailability, unknown command attribution,
   authoritative reacquisition and genuine user operations retain
   distinct obligations. Structural green checks cannot make
   HumanHelp Create, Claim, Unclaim or manager Reassign usable.
5. **Independent effect providers and trusted capabilities.**
   Clock, transaction, authoritative observation and other required
   providers must be real compatible bindings; a capability name
   does not confer authorization. The actual
   `:biff.fx/now` value needed by an FX integration remains a
   concrete correspondence requirement at execution.
6. **Production enforcement differs from test or observer success.**
   Controlled defects must reach the actual protected path and
   be rejected before the prohibited effect/output where the
   relevant information is available. Post-commit detection is
   diagnosis, not rollback or prevention.
7. **Server and non-server operations have legitimate coverage.**
   The whole application cannot restrict its correctness argument
   to Choreo-annotated browser controls or the currently rendered
   subset; raw XTDB and other effects touching protected state
   must be accounted for within their claimed profiles.

R4 does not have a single section with exactly the later R5 07.04
table of finite/inductive coverage categories. The above R4
obligations were preserved from their corresponding original
preflight, trusted execution, runtime and acceptance sections,
not falsely presented as already proved or fully deployed.

## R5 improvements preserved and sharpened

The strong R5 starting point already had one construction owning
the semantic catalog and checking products, distinct finite
operation/rule/outcome coverage, conditional induction, original
source/evidence provenance, route plus non-route writer coverage,
request- and work-owned effect capabilities, and the crucial
difference between a pre-effect gate and post-execution observation.

This revision:
- Makes selected assurance policy a set of proposition-specific
  requirements and lifecycle *enforcement boundaries*, not one
  green Boolean, late checker or implicit automatic downgrade.
- Distinguishes disabled, enabled-but-rejected, committed and
  rejected modeled attempts, and counts scoped to actual finite
  principal/argument choices. Positive and rejected modeled
  outcomes are separately requireable; neither implies production
  behavior or complete domain coverage.
- States the abstract invariant preservation obligation over
  *every* relevant admitted transition and initial state; a
  never-enabled operation is vacuous safety, not completed
  manager Reassign functionality.
- Requires an explicit abstract-to-physical bridge for state
  mapping, transaction-internal guards, concurrency, all writers
  and real XTDB effects. Conditional induction and finite checks
  alone do not prove physical deployment refinement.
- Expands writer coverage to physical capability/target and
  mutation shape, including full-document replacement and
  non-route background/initializer/migration paths.
- Keeps host-enumerated registrations, declared write footprints
  and source-derived ID equality as bounded diagnostic evidence,
  not a proof that raw/hidden XTDB writers are excluded.
- Requires per-request/per-work capabilities with isolation for
  concurrent valid attempts, fresh invocation/transport resources
  and stable logical command identity across compatible retries.
- Keeps post-execution observation useful but incapable of
  vetoing or undoing an already committed transaction.
- Supplies fourteen positive/adverse acceptance histories that
  independently test real Claim, concurrent users, operation
  nonvacuity, declared-versus-actual writer gaps, opaque evidence,
  stale reports, pre/post guard order and checking budgets.

## Source correspondence with Gesso v1622

- `src/gesso/live/application_preflight/inductive_policy.clj` is an
  explicitly **opt-in** strict source-relative startup-eligibility
  gate with mandatory source-bound conditional induction and exact
  issued handler/plan binding. `:disabled` is a separate
  compatibility mode. It **does not** establish physical writer
  completeness, deployed router adoption, independent checker
  soundness or automatic enforcement on every startup. The target
  managed-by-default policy in 07.04 is a *finished design* rather
  than a claim this optional module is already universal.
- `src/gesso/live/application_preflight/operation_family_coverage.clj`
  requires exact operation-ID coverage for a current assembly's
  route-exposed registry before finite exploration. It explicitly
  does not establish correspondence of supplied modeled callbacks
  to the registered executable functions, completeness of physical
  writers or unbounded invariant preservation.
- `src/gesso/live/application_preflight/relational_definition.clj`
  contains optional `:require-exercised-rule-ids`,
  `:require-attempted-operation-ids` and
  `:require-operation-outcomes` gates, with modeled disabled,
  attempted, committed and rejected counts, private admitted
  construction, bounded transition trees and redacted explanations.
  The tests under `test/gesso/live/application_preflight/relational_definition/`
  distinguish disabled families, rejected attempts and unexercised
  rules; no fresh pass was run during this editorial revision.
- `src/gesso/assurance/proof/application_writer_coverage.clj`
  joins source-derived declared, independent and issued operation
  identity sets plus host-observed entries. Semantic source and
  installed physical equivalence, inventory exhaustiveness and
  actual transaction refinement remain explicitly unestablished.
- `src/gesso/assurance/proof/physical_writer_inventory.clj` and
  `physical_writer_capability_coverage.clj` account for
  host-enumerated path callables, declared potential target scopes
  and mutation kinds. Their outputs cannot authenticate hidden
  writer absence, callable-to-physical-sink equivalence or
  production enforcement; registered lists are not capability
  sandboxes.
- `src/gesso/assurance/proof/application_assurance_report.clj`
  composes conditional source-derived summaries while explicitly
  issuing no certificate, application admission or transaction
  authority.
- `src/gesso/live/application_preflight/authoritative_coverage.clj`
  compares host-supplied entrypoint snapshots with declared
  semantic routes; it preserves physical-exhaustiveness and
  router-adoption as unestablished.
- `test/gesso/live/application_preflight/relational_definition/operation_exercise_test.clj`,
  `outcome_exercise_test.clj` and `rule_exercise_test.clj`
  are relevant scoped tests. These source files were inspected
  locally; Gesso JVM/browser/XTDB/formal suites were **not run**.

## Cross-part obligations / boundaries

- Parts I–III: no checker self-certificate, semantic catalog or
  choreography translation may silently infer original business
  policy correctness, full external environment or new authority.
- Part IV: real Request/RequestAssignment guards, atomic XTDB,
  command deduplication, historical incorporation and scope-aware
  progression remain authoritative.
- Parts V–VI: an HTTP attempt/physical effect must respect its
  original issued source and resource owner; retiring browser/
  work contexts and Refresh grants are scoped to their actual
  lifetimes. Unknown delivery does not manufacture rejection.
- 07.01–07.03: accepted candidate source ownership, qualified
  physical/semantic coverage, non-circular edge evidence.
- 07.05–07.15: route and provider identity, rendered output,
  actual serving and worker lifecycle, machine-checking receipt
  applicability, fault injection and positive user acceptance
  must be joined to the real admitted generation.
- Parts VIII–XII: HumanHelp product behavior, compositional kernel
  claims, physical correspondence, multi-node boundaries, release
  and universal invariants remain separately evidenced.
