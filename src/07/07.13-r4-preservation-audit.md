## R4 requirements preserved

1. **Structured, stable error kinds rather than parsed prose.**
   A diagnostic answers what failed, which subject/operation
   it concerns, where its required condition came from,
   what was expected and actually supplied/observed,
   which source owns the correction, where checking
   occurred and which exact generation/asset applies.
   A public diagnostic schema may choose names distinct
   from the R4 sample, but cannot erase those questions.
2. **Missing versus incompatible, ambiguous or unverified.**
   A route absent from a registry, a route with wrong
   method/protocol, an overlapping route with ambiguous
   precedence and an unadopted local handler are different
   failures. Likewise a missing clock differs from a
   present provider with an incompatible value shape;
   unknown and contradicted evidence remain distinct.
3. **Unknown operation and no fuzzy execution.** R4's
   `:request/claime` example must report the unrecognized
   source/view and may show `:request/claim` as an
   optional diagnostic near match. The application never
   auto-corrects operation identity for execution or
   grants authority from a suggestion.
4. **Missing browser plan.** The operation can be
   semantically valid while its projected executable
   plan or current manifest is incomplete. Report
   only the invalid realization relation, without
   claiming the model operation was rejected.
5. **Stale generated artifact.** Verify exact
   manifest/byte/receipt and, if applicable, source
   map or diagnostic sidecar identity before
   presenting source coordinates. Filenames,
   timestamps and similar operation names do
   not establish correspondence.
6. **Anonymous protected semantic route.** A
   concrete rendered method/path can match a
   semantic operation despite missing metadata;
   the diagnostic identifies the source control,
   effective action and protected route rather
   than silently downgrading to ordinary HTMX.
7. **Provider and acquisition failures.** An
   operation needing `:biff.fx/now` sampled Instant
   cannot use an unrelated `:clock` function.
   A managed fragment without initial authority
   or a permitted reread must report logical
   owner, projection, progression and missing
   trigger/route, not merely "invalid button".
8. **Static construction versus dynamic authority.**
   Current Membership or Request state may
   correctly reject a Claim even though the
   assembly is still valid. A rejected
   domain command is not automatically
   application-preflight corruption.
9. **Repair is source-local, optional and
   separately authorized.** R4 required
   diagnostics to suggest mechanically known
   alternatives without automatically editing
   source, replacing handlers or dispatching
   a nearby operation. Changes require new
   admission, artifact building and
   verification of affected dependencies.
10. **Disclosure and evidence honesty.**
    Sensitive principal, Request, session,
    command history, model and executor
    values follow privilege scope. A
    copied report cannot claim new
    provenance, a projected value cannot
    prove opaque implementation behavior,
    and redaction is not absence.

R4 did not demand the exact current diagnostic
API shapes. The revision retains the R5 source-
and obligation-specific architecture while
restoring R4's detailed error counterexamples
and security boundaries as normative behavior.

## Strengths of R5 and R5.1 additions

The preferred R5 already identified the phase,
operation, assembly, violated edge, expected/
actual values, stable diagnostic families,
typed assurance status, owner and safe repair
suggestions. This revision adds:

- First-blocker semantics with deterministic
  priority *and* a separately complete scoped
  open-obligation/dependency view. One
  first error does not prove there are no
  other failures.
- Exact diagnostic source/generation,
  evidence/checker, runtime-effect and
  deployment applicability; a local
  Biff-system check cannot masquerade as
  production server adoption.
- Operation/command-specific recovery and
  loss semantics: a failed render after
  committed Claim is not a failed commit.
- Direct R4 missing-plan, stale-asset,
  wrong-route, anonymous HTMX and missing
  clock/authoritative acquisition examples.
- Explicit source-correction and re-admit
  workflow for human and agent tooling;
  suggestions cannot gain executable or
  transaction capability.
- Versioned vocabulary, redacted public
  versus privileged internal diagnostics,
  exact sidecar correspondence and
  browser observer noninterference.
- Eighteen positive/adversarial histories
  designed to reject copied green
  reports, fake near-match execution,
  unsupported proof promotion and
  unsafe automatic domain compensation.

## Actual Gesso code and honest limits

- `src/gesso/assurance/diagnostic.clj` has
  a versioned `gesso.assurance.diagnostic/diagnose!`
  original-source entrypoint. Its supported
  `:kind` choices are induction,
  inductive-report, application-induction,
  observed-correspondence and finite-model.
  It rechecks original sources rather than
  accepting caller-supplied proof reports,
  verifies public upstream checker Vars
  have not been substituted, and emits a
  deterministic `:first-blocker` plus
  `:open-obligations`, source fingerprints,
  evidence class and explicit nonclaims.
  Its output is always a copyable
  `:blocked`, `:diagnostic-only`
  explanation with `:authority :none`;
  it is **not** a general whole-application
  repair engine, certificate or admission
  path.
- `test/gesso/assurance/diagnostic_test.clj`
  tests this first-blocker source
  contract, supported diagnostic classes
  and authority boundaries with real
  source-relative fixtures. Source and
  tests were inspected, not newly run.
- `src/gesso/live/application_preflight.clj`
  and `src/gesso/live/application_preflight/assurance.clj`
  expose typed application errors/issues,
  `operation-summary`, `open-obligations`,
  and current-report explanation.
  Their issue vocabulary is scoped to the
  actual declared assembly, artifact and
  supplied rendered surfaces. They do
  not independently authenticate all
  host routes, served assets or external
  writers. Biff adoption remains a
  separately qualified deployment fact.
- `src/gesso/live/application_preflight/affordance.clj`
  identifies rendered unknown semantic
  operations and anonymous protected
  route collisions for the supported
  simple route-template vocabulary,
  retaining source/surface paths.
  The module explicitly does not
  implement arbitrary router semantics.
  `src/gesso/live/application_preflight/rendered_surface.clj`
  limits its diagnostics to actually
  supplied Hiccup and supported effective
  requests; it is not a census of all
  possible dynamic rendered responses.
- `test/gesso/live/browser/diagnostic_noninterference_test.cljs`
  compares one real projected plan's
  semantic transitions, effects, state,
  resources and completion with/without
  a diagnostic observer, including
  one that throws. Its bounded positive
  case supports noninterference for
  that runtime profile, not a universal
  theorem for every third-party adapter
  or logging implementation.
- No current inspected Gesso code was
  found establishing a universal
  automatic source-repair planner,
  arbitrary HTML/router diagnostics,
  guaranteed production-adoption
  attestation, all-writer coverage or
  generalized source-to-physical
  proof. These remain end-state
  obligations where required.

No fresh Gesso JVM, XTDB, Chromium,
ClojureScript or formal tests were run
in this GitHub-only editorial revision.
