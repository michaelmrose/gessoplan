## Preserved R4 requirements

1. **Whole-application construction is a first-class correctness
   boundary.** Locally valid Choreo, model, browser, route, and
   rendering components can form an application that cannot
   successfully execute an eligible operation.
2. **No second choreography.** The global machine governs
   admitted distributed behavior; projection derives local
   execution; application assembly checks compatible *real*
   implementation and trusted/physical edges for the
   selected construction. Correct routes cannot legitimate
   invalid semantic trajectories.
3. **Missing-edge examples remain positive requirements.**
   Missing browser plan, stale generated artifact, missing
   trusted command route, absent required execution
   capability, successful command with no acquisition,
   Live subscription with no initial knowledge, and
   managed-to-raw silent downgrade remain explicit
   failures requiring a compatible repair/blocked path.
4. **R4's three assurance claims remain independent.**
   Declared graph closure, actual production-path
   enforcement and independently specified behavioral
   completeness cannot prove one another.
5. **Precise evidence vocabulary.** Preflight-closed or
   assembly-verified is not automatically formally proved.
   A browser test is behavior under its tested profile;
   a runtime guard is actual enforcement; trust in model
   or provider code stays a named premise.
6. **Positive user controls matter.** No amount of
   structural consistency can supply a missing
   required HumanHelp Claim or Reassign affordance.
   Testing by manually injecting the intended command
   does not verify the rendered control.
7. **Actual source ownership matters.** A separate
   test-built operation registry or browser surrogate
   cannot certify a different production assembly.

The preferred R5 structure remains the principal
normative text. This revision does not import R4's
illustrative imperative helper implementations as an
independent runtime, nor require every application
function to become a Choreo operation.

## Focused improvements

- Added an explicit *effect-sensitive* scope for
  managed browser commands, server/background work,
  ordinary HTMX reads, local draft controls and
  non-Choreo state-changing endpoints.
- Named the difference between a missing declared edge,
  incomplete source inventory, a trusted external
  premise, a dynamic current-world condition and
  positive behavior omitted from product intent.
- Required evidence about *actual* installed/served
  production paths when claiming enforcement,
  rather than a static snapshot or valid assembly
  being promoted to a runtime/deployment attestation.
- Preserved legitimate ordinary Clojure, CLJS and HTMX
  without permitting raw writes to invalidate the
  protected model claims made elsewhere.
- Added direct links from missing plan/provider/route
  to the specific current lifecycle or transaction
  gate that must detect it. An unknown user, target,
  current Claim winner, or SSE arrival remains a
  dynamic fact, not a statically guessed result.
- Explicitly required acquisition/installation,
  startup interest/fence and recovery joins on
  *successful* authoritative operations, not
  just negative checks on malformed input.
- Restored precise distinctions among preflight,
  production, model runtime, behavior, finite proof,
  unestablished and contradicted reports.
- Added ten paired eligible/adverse histories so a
  reject-all, synthetic command, orphan route or
  missing physical browser edge cannot count
  as full-application acceptance.
- Kept this section as an *opening scope and
  assurance contract*. The concrete assembly data,
  registration graph, route binding, browser manifest,
  lifecycle and diagnostics remain in 07.02–07.15.

### Explicit limits established by the inspected source

ApplicationAssembly by itself does not prove
that an application used Gesso's canonical Biff
startup; that a later module did not replace
=:biff.ring/handler=; that the server actually
consumes that handler key; or that hand-built
pre-serialized Ring HTML passed through
=gesso.http/html-response=. Those are
explicit production/deployment escape paths.
Optional rendered Hiccup snapshots do not
enumerate arbitrary Clojure branch outcomes.
The named dynamic wrapper closes its
selected *canonical* response boundary,
not all possible output producers.

The source lists trusted assumptions for
authenticated-principal binding, public-model
operation contracts, XTDB transactions,
published model declarations, trusted
command/acquisition routes, and the actual
compiled browser entrypoint. These source
assumptions cannot be promoted to universal
backend or host proof through their inclusion
in a valid preflight map.

The assembled report warns about unhandled
published change topics and static affordance
snapshot coverage separately from hard
structural invalidity. Those warning/open
classifications cannot be silently treated
as fully discharged Live continuity or
mandatory application product requirements.
Future strict assurance profiles may reject
conditions whose unresolved status violates
their particular declared promise.

## Current-source versus finished-design gap

The actual Gesso application-preflight
backbone and canonical HTML guard are
substantial structural and dynamic-enforcement
precursors. The finished Part VII additionally
requires a complete assurance argument for
the selected actual deployment, model writers
outside canonical HTTP, authority provider
bindings, served/loaded browser and extension
profiles, correct subscription baseline/recovery,
and nonvacuous positive application behavior.
Those are *still owed* where current source
and tests do not establish them. They are
not reasons to weaken 07.01's normative text.

The absence of a complete proof for a generic
opaque effect or third-party writer does not
forbid the use of Clojure. It requires the
result's correct evidence scope and a
declared noninterference/trust contract
whenever a stronger application claim
depends on that effect.
