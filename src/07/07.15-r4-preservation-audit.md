## R4 requirements preserved, with R5's stronger architecture

1. **Structural admission is not current model authorization.**
   R4 explicitly required the trusted server to authenticate the
   principal and the public model to check current Request,
   Membership/Organization, RequestAssignment and guarded XTDB
   facts, regardless of whether a browser supplied a well-formed
   action or the assembly once passed preflight.
2. **Browser metadata is always untrusted for authority.**
   A forged user ID, operation, Request selector,
   `ApplicationAssembly`, source receipt, certificate, command
   bytes or basis must not bypass trusted server dispatch,
   current model guards, disclosure or physical target checks.
   The browser may carry an *intent*, not a new capability
   for server-side protected effects.
3. **Artifact stamp and preflight reports are bounded evidence.**
   R4 explicitly distinguished a current BrowserArtifactStamp,
   an assembly-like metadata value and a successful preflight
   report from authentication, allowed operation, command
   freshness, guarded transition or permission to disclose
   data. R5's separate issued handle, actual production
   adoption and proof/physical correspondence classes are
   preserved without authority promotion.
4. **Exact realization preserves semantic identity.**
   R4's final construction invariant required no silent
   erasure or substitution of Choreo operation through
   generated browser plan, exact compiled artifact, HTMX
   transport, trusted route, public model, settlement,
   progression and authoritative reacquisition. A known
   structural mismatch rejects rather than downgrades.
5. **Biff startup precedes protected external application
   behavior.** R4's mandatory preflight-before-Aleph
   requirement remains. R5.1 makes the actual Biff 2
   all-init-before-start hazard explicit: start ordering
   alone does not fence prior initializer side effects,
   and protected writers/workers also need the
   admitted activation boundary.
6. **Static future handling and dynamic authority coexist.**
   R4 demanded structurally checked handling paths for
   required supported conditions, while not predicting
   future Membership, network loss or unbounded liveness.
   A command possibly committed remains participant-unknown
   until admissible historical evidence settles it.
   A postcommit render error cannot undo the effect.
7. **Live is advisory, acquisition separately authorized.**
   An initial observation or permitted acquisition, scoped
   progression, fence/replay/reacquisition through
   subscription gaps and one-Refresh user grant remain
   separate from receipt of an SSE advisory or current
   permission to disclose protected state.
8. **Three independent application claims survive.**
   R4's structural closure, *actual production-path*
   enforcement and independent *positive* behavioral
   completeness are separate. A fully coherent but
   permanently disabled Claim or missing manager Reassign
   still fails HumanHelp acceptance.
9. **Actual threat scope must be declared.** A closed
   route registry and source-relative host inventory do
   not sandbox untrusted code within a compromised JVM,
   erase external XTDB writers or establish universal
   implementation refinement. The finished specification
   distinguishes accidental cooperating-code bypass,
   adversarial clients, and stronger hostile-host
   isolation requiring separate mechanisms.
10. **One qualified invariant, not a self-issued proof.**
    The original R5 end-state quote is preserved intact.
    Seven explicit interpretation conditions now identify
    the source catalog, real physical/effect closure,
    current guarded permission, publication/disclosure,
    change impact and product acceptance obligations
    required to claim that invariant in any real
    application generation.

The R4 final construction-invariant text is not
reproduced verbatim because R5 has a clearer, source-owned
whole-application formulation. Its material security
prohibitions, acquisition and Biff/HTML behavior, and
the three-claim separation remain explicit and operational.

## Strong R5 improvements retained and sharpened

- One admitted semantic/physical source subject and selected
  assurance policy; construction, artifact, installation,
  invocation and physical-completion facts remain distinct.
- No report, stamp, certificate or process-local handle
  silently gains another layer's execution authority.
- Coherent generations throughout build, serving, concurrent
  requests, async completion, hot reload and retirement,
  with cross-generation command resolution.
- Explicit no-sandbox threat model and physical writer
  completeness premises alongside concrete source/model
  implementation correspondence.
- Server-side historical command binding and current
  disclosure are separate from new invocation permission;
  missing record is not automatically rejection.
- Advisory Live, user-acquisition permission, physical
  DOM adoption and no-gap multi-node interest recovery
  retain different evidence claims.
- Sixteen adversarial/positive falsification histories
  challenge forged client identity, substituted sources,
  raw writers, stale assets, startup exposure, unknown
  commits, repeated Refresh, router failover and
  product completeness.

## Source correspondence to Gesso v1622

The following Gesso source files were inspected directly
from the `application-assurance` branch:

- `src/gesso/live/application_preflight/assurance.clj`
  declares canonical Biff/HTML enforcement *available*
  on the selected startup path, while explicitly leaving
  deployment installation proof and some static/dynamic
  rendering completeness open. It creates explanation
  vocabulary, not a portable source certificate.
- `src/gesso/live/application_preflight/biff.clj`
  implements the canonical Biff 2 module, current assembly
  check and wrapped `gesso.http/html-response` guard;
  arbitrary raw Ring responses, later handler swaps and
  independently deployed router adoption remain outside
  that bounded guarantee.
- `src/gesso/live/application_preflight/certified_contract.clj`
  checks an exact issued Ring handler against an issued
  certified-plan executor *in process*, while leaving
  trusted input conversion, actual deployment adoption,
  current authorization, transaction atomicity and
  external writer coverage as explicit premises.
- `src/gesso/assurance/proof/executed_guard_authorization_correspondence.clj`
  checks one bounded original abstract guard reader-to-
  physical callback/attempt correspondence. It expressly
  does not prove true domain policy, transaction-internal
  prestate, complete refinement or independent
  guard-checker soundness, and issues no certificate.
- `src/gesso/model/command_resolution.clj`
  can construct a canonical same-plan command record
  and reconcile a correctly bound, authorized result.
  It explicitly does not authenticate principal,
  grant permission to replay a new domain effect,
  infer rejection from missing records or provide
  a production executor by itself.
- `src/gesso/live/optimistic/capability.cljc`
  produces inert view-side optimistic operation bindings,
  explicitly **not** server authorization; the trusted
  server must authenticate, resolve, reread and guard.
- `src/gesso/assurance/proof/application_assurance_report.clj`
  produces a conditional, non-authoritative source-relative
  assurance summary while retaining complete writer
  coverage, installed handler equivalence, XTDB refinement,
  kernel soundness and browser correspondence as open.

Code inspection does not establish a fresh passing test
suite, whole-deployed HumanHelp acceptance, universal
Gesso certified security or backend proof. No JVM,
Chromium, XTDB, formal or local Gessoplan Python
assembler tests were run during this sectional revision.
