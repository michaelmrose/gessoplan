## R4 preservation obligations

1. **Separate checking from production-path enforcement.**
   A validator can be perfectly correct and never called by
   the installed listener. R4 required actual managed Biff/Aleph
   startup, checked browser build, route, trusted handler and
   final response boundary. The revision distinguishes exact
   local system-map wiring from observed listener adoption,
   runtime effect and deployment traffic under named premises.
2. **Observable negative control.** Removing or miswiring
   *the actual* guard must cause a production-integration
   test to fail. Supplying a second test-only guard,
   edited fixture registry or checker-only assertion
   does not demonstrate runtime enforcement.
3. **Fail at the earliest legitimate physical boundary.**
   Structural errors prevent activation, malformed effective
   actions prevent checked output delivery, selector/provider
   mismatches prevent protected invocation, and transaction
   guard failures prevent forbidden domain effects.
   A postcommit contradiction does not retroactively veto
   earlier authority or physical output.
4. **Use canonical source-owned construction.** R4 rejected
   independently typed test registries. Tests preserve
   exact semantic source, plan/artifact, installed executor,
   route, model, publication/acquisition and generation
   correspondence. Matched labels alone are insufficient;
   cross-product substitutions must be rejected.
5. **Start real browser acceptance from rendered controls.**
   A lower-level test may construct ideal protocol messages.
   An end-to-end test must click the generated real control
   with the actual compiled runtime, HTMX, route, model,
   settlement, SSE/acquisition and DOM adoption. Injecting
   a valid command cannot repair a missing button binding.
6. **Separate evidence mechanisms and limits.** Biff module
   start, Ring call, loopback HTTP/SSE, real Chromium
   integration, guarded XTDB observation and public deployment
   each establish different scope. A fake committed response
   is not independent evidence of a database mutation.
   Neither abstract model checking nor a process-local
   issued handler proves universal deployed correspondence.
7. **Retain error/unknown classification.** A malformed
   response after successful Claim blocks the HTML but
   cannot erase incorporation. A lost settlement or unknown
   command needs its declared resolver. Broad browser error
   suppression would hide failures the test is meant to
   detect; deliberate fault diagnostics are asserted
   specifically.
8. **Actual repeated/concurrent request operation.** R5's
   stronger architecture requires later valid requests,
   concurrent contexts and out-of-order completion to
   preserve independent command/owner/target rights.
   A single consumed process-wide request slot is not
   a credible general serving path, although an explicitly
   bounded serial profile may be qualified separately.
9. **Independent positive product capability acceptance.**
   R4 explicitly distinguished structural closure, actual
   production enforcement and positive behavior. Deleting
   manager Reassign may leave a smaller coherent graph,
   but must fail HumanHelp product acceptance. Fake
   buttons, forever-disabled capabilities, test-only model
   stubs and direct injected protocol commands are not
   substitutes for working controls.
10. **Real defect campaigns remain safely isolated.**
    Twenty-two positive/adversarial histories cover actual
    managed startup, guard omission, early Biff init
    side effects, handler substitution, copied local host
    maps, stale asset bytes, cross-product swaps,
    conditional HTMX defects, parameter mismatch,
    wrong time provider, forged physical commit,
    postcommit render failure, historical settlement
    uncertainty, Live inception gap, one-use Refresh,
    retired response, unknown writer, repeated invocation,
    missing manager capability, browser injection and
    precisely asserted network-loss diagnostics.
    Tests use disposable source-owned state and real
    qualified effect/output boundaries, not live user data.

R4's illustrative accepted operation maps, old
`gesso.application/*` helpers and generic HTTP status
examples are retained as *behavioral* requirements,
not asserted to be currently shipped public APIs.
The preferred R5 source-specific evidence vocabulary
and whole-application closure layering remain intact.

## Strong R5 architecture retained and clarified

The R5 predecessor already required observing concrete
startup, route/effect/output seams, controlled real defects,
a corresponding successful control, exact failure
diagnostics, generated browser runtime, repeated/concurrent
requests and causal physical installation.

The revision strengthens that core by:
- defining source-to-physical evidence provenance rather
  than just listing a collection of integration checks;
- requiring mutation of the *actual enforcement connection*
  and observational independence from the checker oracle;
- distinguishing pre-effect prevention, post-effect
  detection and truly unobserved physical outcome;
- retaining host/deployment premises and source/asset/
  observer scope when joining local Biff with loopback
  browser and actual XTDB evidence;
- making product acceptance sensitive to removal of
  required HumanHelp capability even where smaller
  application remains internally consistent;
- making request-local concurrency and postcommit unknown
  recovery observable as physical acceptance cases;
- retaining twenty-two positive/adversarial histories
  as counterexamples to false claims of universal proof.

## What Gesso v1622 implements and does not

- `src/gesso/live/application_preflight.clj` and
  `src/gesso/live/application_preflight/biff.clj`
  have a canonical checked ApplicationAssembly,
  browser-artifact checks, checked render response
  wrapper and a Biff module/start function.
- `src/gesso/live/application_preflight/assurance.clj`
  defines the actual assurance vocabulary:
  local backbone and supplied-rendered-surface
  closure, conditional canonical Gesso/Biff HTML
  enforcement and explicit escaped paths.
  Direct Biff start, later handler replacement,
  server ignoring `:biff.ring/handler` and raw
  pre-serialized HTML remain open deployment
  integration boundaries. A source-derived report
  is not an independently issued certificate.
- `test/gesso/live/application_preflight/lifecycle_integration_test.clj`
  exercises actual Biff module start, checked
  system-map handler identity, malformed-affordance
  rejection before HTML serialization and a
  later module observing the wrapped handler.
  It does not independently authenticate a real
  network server adopting that system map.
- `test/gesso/live/application_preflight/physical_request_integration_test.clj`
  exercises detached form owners, browser button
  defaults, string/keyword request attributes,
  multiple physical actions and failure before
  rendering on supported Hiccup. It does not prove
  arbitrary client JavaScript or all unsupplied
  document context behavior.
- `test/gesso/live/application_preflight/contradiction_integration_test.clj`
  and `cross_product_integration_test.clj`
  cover mismatched browser plans, capabilities,
  settlement, route, acquisition, artifacts and
  independently valid but incompatible product
  substitutions. They remain source-relative
  assembly/integration tests.
- `src/gesso/assurance/proof/checked_biff_host_adoption.clj`
  constructs an opt-in actual checked Ring router
  module and locally checks the resulting Biff
  system handler slot using an issued handle.
  Its own contract explicitly leaves real server
  handler consumption, caller-provided startup
  order, later replacement, external writers,
  authenticated requests, physical transaction
  correspondence and universal refinement open.
  `test/gesso/assurance/proof/checked_biff_host_adoption_test.clj`
  checks forged/copied handles and system maps,
  source substitutions and reentrant startup
  failure. This is not public deployment
  attestation.
- `test/gesso/assurance/example/physical_single_node_http_test.clj`
  uses a disposable embedded XTDB/Biff/Ring
  reservation proving fixture with actual guarded
  readback and explicit negative routing tests.
  Its source explicitly notes that a forged
  `:committed` result can produce HTTP success
  without a write; it does not claim certified
  plan issuance, authenticated authorization,
  network deployment or all-writer completeness.
- `test/gesso/assurance/example/physical_single_node_live_chromium_integration.clj`
  provides a dedicated real Chromium/Playwright,
  loopback HTTP and actual EventSource/HTMX
  exercise for the *example reservation fixture*,
  including two browser contexts. It is
  deliberately separate from normal
  `*_test` discovery, and its source does not
  establish HumanHelp end-to-end acceptance or
  production deployment verification.
- Gesso's proof/physical source contains many
  source-bound reports and controlled physical
  observation steps. Their presence and test
  files are useful evidence of progress, not
  a universal source-to-XTDB/HTTP/browser
  refinement theorem for arbitrary applications.

No fresh Gesso JVM, Chromium, XTDB or formal
tests were run for this editorial revision.
The code was inspected in its supplied local
v1622 checkout. The finished normative contract
remains ahead of what these bounded interfaces
currently establish.
