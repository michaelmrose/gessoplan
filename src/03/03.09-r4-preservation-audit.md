# R5.1 Part III — 03.09 Operation Interface and External Commitments

**Baseline:** R4 `main`, Part III “Operation contracts export a semantic
interface” and “External commitments versus derived structure.”
**Candidate:** `r5.1` source unit 03.09.
**Status:** focused preservation review, not Part III acceptance, current
proof-kernel soundness or certified physical operation implementation.

## R4 requirements retained

- A normalized operation interface exports only the semantic facts that
  downstream reasoning may rely on: input and entry knowledge, provenance,
  roles, authority, model operations, semantic outcomes, produced facts,
  resources, provisional permissions, settlement, continuation compatibility,
  named guarantees and assumptions.
- Arbitrary Ring/Reitit/DOM/XTDB class or bundle offsets are physical
  realization coordinates, not semantic identity or default typed exports.
- An operation's external declaration states commitments that cannot safely
  be inferred; the choreography body supplies branch/continuation/value
  flow. Redundant manually synchronized metadata is not a source of truth.
- The R4 example's illustrative =:confirmed= and =:reconciled= labels
  do not force all models to implement those as durable dispositions.
  Model truth, participant-relative uncertainty and presentation outcome
  are different semantic layers.
- A known Request status after a successful Claim does not mean a
  compatible replay was newly rejected. Current disclosure remains a
  separate authorization contract.
- A result's nominal identity or recorded outcome must not replace
  source-owned truth/implementation premises.

## Superior R5 design retained

- The canonical Claim command-resolution categories separate
  =:committed=, =:rejected=, compatible =:already-incorporated= and
  epistemic =:commit-unknown=, with explicit mapping to presentation
  =:accepted= / =:rejected= / =:unknown=.
- Read/progression scope, command identity and source/model contract
  version remain attached to imported premises, without granting
  authoritativeness to HTTP callbacks or summary fingerprints.
- Derived structural, knowledge, projection and finite proof facts
  remain distinct from physical enforcement, opaque model rules, and
  installed application/handler correspondence.

## Changes in this revision

1. Require source-owned subject, version and premise provenance for
   exported commitments; neither a matching name nor a copyable summary
   authenticates a rule or physical implementation.
2. Correct a misleading phrase: the four Claim categories are
   *boundary-facing command-resolution* categories, not four distinct
   durable model/database outcomes. =:commit-unknown= is observer
   uncertainty, not a database status.
3. Keep compatible replay tied to the exact command binding, recorded
   result and current disclosure; uncertainty requires reconciliation
   instead of fabricating rejection or new command identity.
4. Specify four intended evidence classes (derived, imported,
   runtime-required, assumed/open) without claiming the current
   product uses those exact record tags.
5. Require compositional interfaces to retain each original operation's
   guard/invariant premises and source attribution, without treating
   possible interference as a proof of commutativity or serial execution.
6. Add seven counterexamples covering available-but-unproved branch
   semantics, HTTP callbacks, mismatched replay, historical resolution,
   indeterminate delivery, operation interference and opaque rule names.

## Correspondence to Gesso application-assurance

- `gesso.choreo.verify` checks definite values, role-local knowledge,
  and declared-authoritative must-analysis for the supported portable
  language. It expressly does not establish actual principal
  authentication, authoritative provenance truth, runtime resource
  ownership, physical browser execution or arbitrary liveness.
- `gesso.choreo.proof` checks five finite structural/compiler projection
  properties but explicitly excludes all-schedules projected-step
  simulation, trace refinement, authority authenticity and physical
  distributed execution.
- `gesso.assurance.proof.operation-interface` derives source-bound
  *conditional abstract* operation interfaces from the live declared
  dependency catalog, retaining the original guard, state/input types,
  read/write/frame footprint, conditional preservation and un-discharged
  proof/physical premises. It does not issue admission or a certificate.
- `gesso.assurance.proof.operation-interface-composition` combines
  alternative abstract operations over one common state schema and
  identifies potential interference. It neither serializes transitions
  nor proves physical writer coverage or concurrency refinement.
- `gesso.live.application-preflight.semantic-audit` retains a trusted
  public-model contract premise while reporting actual Clojure guard
  predicates and dynamic transaction dependencies as uninspected.
- `gesso.model.command-resolution` builds a guarded command-record
  create in one model transaction plan and can compare compatible
  recorded bindings; it remains explicitly experimental and assumes
  correct trusted authentication, underlying domain plan, disclosure
  and XTDB behavior.
