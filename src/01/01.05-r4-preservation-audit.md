# R5.1 Part I — section 01.05 R4 preservation audit

Baseline: canonical R4 (`main`). Candidate: R5.1, 01.05.
Scope: machine-checked semantic judgments, proof strength, and correspondence
limitations. This review is normative editing, not proof or test evidence.

## R4 obligations retained

- All fourteen candidate judgment families remain: typed rules, knowledge,
  provenance, authority, message closure, branch knowledge, projection,
  resources, progression, browser transitions, retirement, dependencies,
  executable provenance, and certificate consistency.
- Runtime authentication and commit-time authorization remain separate from
  a static non-escalation/knowledge judgment.
- Closed semantic message payloads do not gain facts or authority from raw
  transport metadata or untrusted maps.
- Resource lifetime, scope, effect ownership, safe retirement, and
  browser-adapter implementation-correspondence limits survive.
- R4's finite versus unbounded proof limitations, abstraction soundness,
  retained data dimensions, and conformance-vector limitations survive.
- Claim subject, quantification, assumptions, semantics, refinement,
  tool/subject identities, and implementation applicability remain mandatory.

## Specific improvements

1. The earlier wording implied that an opaque call, relationship predicate,
   or case expression belongs directly to the Part IX closed rule grammar.
   Part IX's baseline has only a small reader-based AST and no host evaluation.
   The revised text distinguishes its supported rule typing from *separate*
   typed interfaces, checked elaboration, and conditional opaque premises.
   This retains R4's relational/case well-formedness ambitions without
   inventing baseline syntax or asserting an existing elaborator.
2. Knowledge entailment is made explicitly conditional on the runtime
   acquisition, entry, and communication premises. Static checking cannot
   authenticate the actual physical event or observation.
3. Behavior-sensitive branch knowledge now preserves the identity and scope
   of the relevant historical decision. A same-looking current status is
   not proof of which prior command or branch produced it (Part III).
4. Projection preservation now states its refinement direction, observable
   and internal-step relation, and separately names liveness/fairness
   and adversarial browser realization obligations (Part X).
5. Kernel acceptance of one derivation is distinguished from a universal
   soundness theorem for the kernel implementation. Finite source-instance
   truth-table checking does not establish that theorem (Part X).

## Deferred work and review limits

Parts II, III, V, IX and X own the full executable specifications and proof
transfer. No R4 requirement was intentionally discarded. The existing proof
kernel or syntax checker is not claimed to have universal soundness merely
because these candidate requirements are now clearer. Other Part I sections
and the whole R5.1 cross-part audit remain open.
