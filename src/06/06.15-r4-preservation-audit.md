## R4 obligations preserved

- **One semantic owner, physical interpreter:** production
  browser execution derives semantics from the admitted
  portable plan and adapter; HTMX owns supported native
  requests/swaps and the shell handles concrete effects.
  A second callback interpreter must not invent branch,
  authorization or recovery meaning.
- **Authoritative data and physical installation differ:**
  authorized observations, attached representations,
  issued permits, actual host completion, scoped adoption
  and discharged obligation debt have distinct sources
  and postconditions. No HTTP 200 or copied basis proves
  an entire board installed.
- **Retirement makes callbacks powerless before cleanup:**
  exact E42 generation/resource rights are revoked
  semantically; late timers, HTTP requests and observers
  cannot mutate current E43/B2 even if physical abort
  fails. Shared coordinator and independent command
  resolver rights survive only through their own owners.
- **Adversarial server protocol:** arbitrary syntactically
  representable client requests, forged local actor
  claims, proof artifacts, command IDs and plan state
  cannot authorize an illegal trusted operation or
  protected observation. Model/XTDB/authentication
  assumptions must be named rather than hidden in
  a browser correctness theorem.
- **Qualified physical host:** the selected HTMX
  version/configuration/extensions and actual loaded
  application assets must preserve required
  pre-mutation gates, OOB/response effects and
  correlation. Unsupported paths cannot be
  admitted by a generic afterSwap report.
- **Conditionally layered assurance:** portable
  invariants, checker/finite reference, actual
  adapter transition, independent host/backend
  witness, qualified runtime profile and
  deployed application certificate are
  different proof subjects.
- **Conformance with real positive controls:**
  failing all requests is not compliance.
  Eligible Create, Claim, Reassign, authorized
  read and real physical installation must
  succeed before negative adversarial cases
  can establish the intended rejection
  and recovery properties.

R5's compact installation/resource table,
adversarial boundary, conformance cases
and assembly/final invariant are retained
as the editorial structure. The revision
adds explicit closure requirements and
actual acceptance controls without
restoring R4 example-only helper functions
as a competing implementation.
