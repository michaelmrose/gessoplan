## Preserved R4 requirements

- **One semantic authority:** projected role-local Choreo trajectories
  and adapter-owned browser coordination compose in one executable
  interpretation. A second listener, shell, store or diagnostic
  simulation must not independently select the controlling branch or
  create competing authority over the same target.
- **Pure step and narrow effects:** plan/state/event inputs yield
  next state and abstract effects; physical DOM, clock, timers,
  transport, cancellation and callbacks remain in an imperative
  boundary. Unknown opaque operations have explicit contracts and
  accepted premises, not implicit proof.
- **Synchronous semantic gate:** protected HTMX actions must be
  admitted before a forbidden physical request or mutation occurs;
  HTMX retains its ordinary declarative lifecycle. The required
  hook coverage depends on the actual supported HTMX version and
  modes rather than an invented universal before-swap guarantee.
- **Installed correlation and event-source distinction:** resource
  identity is attached at registration and carried opaquely, not
  rediscovered from mutable DOM, URL or currently-active globals.
  Shared scoped invalidations are not execution-private callbacks.
  Parsed event fields are not authenticated owner/source evidence.
- **Stale safety:** semantic retirement revokes callback rights
  before best-effort physical cleanup; cancellation alone is not
  a correctness guarantee. A provisional rollback does not override
  a newer authoritative installation.
- **Adversarial browser:** copied client plan/correlation fields,
  DOM presence, or self-asserted proof never authorize a server
  Request/RequestAssignment mutation or a protected read.

The original long R4 Claim/listener examples are not mechanically
restored as a second normative implementation. Their essential
admission, source, ownership, before-effect, unknown-outcome and
physical-completion obligations are retained under the improved
R5.1 architecture. Later Part VI sections carry the precise
transport/Claim and scoped installation contracts.

## Changes and reasoning in 06.01

1. Resolved a possible ambiguity in `one executable semantic core`:
   role-local choreography state and browser coordination are
   composed responsibilities, not independent competing machines.
   This retains R4's explicit state-owner split and R5's permanent
   executable semantics plus separate checker/proof kernel.
2. Qualified the displayed `adapter/step` inspection map.
   Current v1622 `adapter/step` actually returns a pair
   `[next-state effects]`. The R5 example is expressly
   illustrative; an optional transition locator must be bound
   to the *selected actual step*, not invented by diagnostics.
3. Made reentrant dispatch ordering explicit: semantic next state
   and old-owner retirement are committed before interpreting
   effects; an immediate host callback sees that state. Where
   concurrent hosts could dispatch, an actual serialization
   contract is required.
4. Separated event payload parsing from source and authority
   admission. Client-carried owner IDs and signed-looking
   envelopes do not themselves authenticate a real physical source,
   current resource instance or trusted model fact.
5. Made distinct proof subjects explicit: emitted allow/cancel
   disposition, HTTP response, physical DOM mutation, adopted scope,
   historical command result and current model state cannot be
   inferred from each other.
6. Preserved plain HTMX for supported normal behavior and scoped
   pre-mutation intervention for Gesso-owned invariants; no HTMX
   reimplementation or unexamined OOB/alternate-host bypass is
   implicitly authorized.
7. Distinguished optional diagnostic observation from
   mandatory assurance/admission. Observer noninterference
   requires a stated bounded failure/isolation mechanism.
8. Added paired positive/adverse acceptance histories for
   reentrant callbacks, rollback against newer authority,
   shared invalidation versus private callbacks, physical
   adoption and observer failure. They cannot pass merely
   by displaying a fabricated data map.

## Inspected Gesso implementation (not run)

Inspection source: the supplied Gesso archive at
`application-assurance` v1622,
`1b5e10e71c00e7784b019dee7dc1198a96fd03f6`.

- `src/gesso/live/browser/adapter.cljc` implements a portable
  `adapter/step` returning `[next-state effects]`, checks state
  invariants, and distinguishes semantic effects from
  `:diagnostic/ignored`. Its closed event vocabulary covers
  commands, HTMX lifecycle, timers, invalidation, continuity,
  optimism and retirement. It documents source/trust limitations.
- `src/gesso/live/browser/shell.cljs` holds one mutable adapter
  state plus opaque physical handles, calls `adapter/step`,
  `reset!`s the state **before** effect interpretation, and
  translates effect outcomes back into normalized events. A
  reentrant callback therefore sees the committed state. It
  separately classifies handlers that must synchronously fail
  closed and handlers that observe diagnostics.
- `src/gesso/live/browser/refinement.cljc` and
  `observation.cljc` derive conservative observations from actual
  step histories/effects. They explicitly decline to certify
  global choreography, physical transport, browser host effects
  or XTDB commits from that local record.
- Source-inspected test files include
  `test/gesso/live/browser/adapter_test.cljc`,
  `test/gesso/live/browser/shell_test.cljs`,
  `test/gesso/live/browser/fx_conformance_test.cljc`
  and `test/gesso/live/browser/diagnostic_noninterference_test.cljs`.
  Their fixtures exercise specific pure/host integration
  assumptions; none was executed for this revision.

These observations support feasibility and sharpen the normative
boundary. They do **not** show that every HTMX response/OOB mode
has a protected gate, every registered host handler is safe under
reentrancy, every opaque observer is isolated, the full deployed
browser assets match the inspected code, or HumanHelp passes all
production RequestAssignment acceptance cases. The current
adapter API is not forced to grow an unneeded `:transition-ref`
field solely to match a schematic example.

## Independent positive/adverse and cross-part obligations

- **06.02–06.04:** verify exact command, execution, transport,
  resource and source lifetimes; synchronous HTMX decisions,
  response/OOB behavior and protected Claim/acquisition flow.
- **06.05–06.07:** require current-target physical installation,
  partial-effect evidence, scoped progression, retained advisory
  debt, one user Refresh and subscription-gap recovery.
- **06.08–06.11:** preserve plan compatibility, late callbacks,
  immediate reentrancy, effect cancellation versus semantic
  invalidation, and unique event-source admission.
- **Parts IV–V:** do not substitute command incorporation for
  installation, an authoritative card for historical C42
  attribution, or local provisional display for a trusted
  RequestAssignment guard. Continuity capture cannot authorize
  an obsolete restoration.
- **Parts VII–X:** require actual protected routes/assets,
  independent positive HumanHelp capabilities, finite versus
  universal proof boundaries and physical refinement evidence.
  A source-only test or sidecar cannot establish installed
  application closure.
