# R5.1 Part VI — 06.10 R4 preservation and Gesso correspondence

**R4 baseline:** Gessoplan main Part VI, *Browser managed
effects*, *One effect scope per active execution*, *Effect
category affects legal cleanup*, *Rollback rights expire*,
*Catastrophic cleanup preserves the original semantic
failure*, *Cleanup is idempotent*, *Physical remnants are
observable debt, not hidden success*, and *Shared resources
require an explicit shared ownership class*.
**Preferred starting point:** Gessoplan r5 Part VI.
**Reviewed unit:** r5-source/06/06.10-managed-effects-and-resource-lifetime.org.
**Disposition:** one substantive sectional review, not
whole-Part-VI acceptance or runtime/physical conformance proof.

## Preserved R4 guarantees

- The pure adapter chooses one semantic owner and abstract
  effect lifecycle; the imperative browser shell stores opaque
  physical handles and executes effects without becoming a
  competing interpreter.
- One root effect scope belongs to each active execution, with
  explicit child scopes and separately named coordinator/shared
  resource owners. Every Gesso-managed effect is reachable
  through its current owning resource instance.
- Resource, reversible, authoritative, async and ephemeral
  describe independent cleanup/semantic properties. Cleanup
  may release or compensate only while the corresponding
  current owner and legal restoration right still exist.
- Semantic retirement revokes callbacks before physical
  timer abort, listener removal or provisional cleanup.
  Physical cancellation may fail; a late callback never
  resumes the old execution through an equivalent selector.
- Best-effort catastrophic cleanup continues through other
  independent permitted releases when one throws, preserves
  the original failure F with subordinate cleanup CA/CC,
  and does not undo an authoritative install.
- Idempotent cleanup applies to *the same issued resource*,
  not to whichever new resource occupies the same key.
  Lingering physical remnants remain observable, bounded
  or handled by a declared unavailable/resource policy.
- Shared SSE interests and coordinator resources have
  explicit sharing/detach/last-reference behavior; retiring
  one execution must not terminate other valid owners.

The preferred R5 emphasis on effects as independently
classified contracts remains intact. The revision does not
restore R4's long illustrative implementation as a second
runtime or claim that current Gesso already closes every
physical resource race.

## Focused improvements

1. Bound each effect to semantic purpose, host footprint,
   exact owner/instance/generation, issue/commit/completion,
   retry, compensation, evidence and declared host premises.
2. Made registration-before-physical-issue precise for
   synchronous callback-before-handle and nested
   retirement-before-handle. Late physical handles must
   be released, not unconditionally registered as live.
3. Required rechecking the current owner/target permit
   before every remaining effect in a reentrant batch;
   rejecting only a later completion does not stop
   an obsolete physical DOM mutation.
4. Distinctly handled local once-only effects and
   remote C42/H1/H2 idempotent command replay.
   A single DOM installation says nothing about
   exactly-once HTTP delivery.
5. Required owner/incarnation-based CSS and DOM cleanup.
   Matching =min-height= strings do not distinguish a
   newer owner that wrote the same value.
6. Qualified exact-resource shared-interest detachment,
   duplicate attachment, resource budgets and
   remnant backpressure separately from logical
   one-active coordinator bounds.
7. Preserved continuity capture's implementation/restore
   contract, mandatory pre-swap preparation, delayed
   frame cancellation and optional post-install
   restore failures as browser-local outcomes.
8. Separated original semantic/physical fault F,
   subsequent cleanup failures and command-history
   unknown results, without blind effect-batch replay.
9. Added nine positive/adverse physical histories
   for synchronous timers, reentrant effect batches,
   recycled IDs, same-value CSS, rollback/resolver
   lifetimes, shared SSE, failure causality, optional
   continuity and physical resource leaks.

## Gesso v1622 implementation observations (source-inspected)

The user-provided Gesso application-assurance archive at
1b5e10e71c00e7784b019dee7dc1198a96fd03f6
was inspected at its browser source/test boundaries.

- src/gesso/live/browser/adapter.cljc makes one
  portable transition and issues abstract effects;
  retired execution/target/timer generations lose
  semantic rights. It models current generation
  and scoped optimistic/continuity lifetimes.
- src/gesso/live/browser/shell.cljs keeps one mutable
  adapter state and opaque timers, transports,
  continuity and optimistic handles. dispatch!
  resets the semantic state before interpreting
  effects, so synchronous callback reentry sees
  the committed adapter transition. shutdown!
  retires adapter-owned executions and fragments
  before best-effort physical release.
- In that shell, interpret-timer-start! calls
  :set-timeout! and only then associates its
  returned handle into :resources :timers. Its
  callback removes the resource and dispatches
  :timer/fired. Under an immediate/synchronous
  scheduler seam, the callback can therefore
  finish or retire T1 *before* the outer call
  stores the returned handle. The finished
  protocol requires a checked post-return
  admission and cleanup path; the inspected
  function does not demonstrate that path.
  This is a concrete source-level gap to
  investigate/test, not a claim that normal
  native setTimeout always fires synchronously.
- src/gesso/live/browser/continuity.cljs has
  release-height-lock! comparing the installed
  :applied minHeight string with the current
  DOM style before restoring :previous. This
  avoids overwriting many different-value
  later edits, but cannot distinguish a
  newer owner that wrote the *same* value.
  Strong owner-relative CSS release requires
  a separate ownership/incarnation mechanism
  or a documented exclusive physical premise.
- src/gesso/live/browser/shell.cljs uses exact
  continuity slot resource keys and routes
  failed restoration via adapter events.
  Its release handler removes the slot and
  attempts optional physical cleanup; the
  source alone does not certify every late
  host callback or arbitrary third-party writer.
- Source-inspected tests include
  timer-replacement-cancels-only-old-generation-and-late-old-fire-is-harmless-test,
  synchronous-local-completion-reenters-after-transition-state-is-installed-test,
  continuity-release-uses-only-exact-slot-owned-resource-test,
  late-continuity-restore-rejection-after-retirement-is-stale-and-does-not-double-release-test,
  and release-revokes-delayed-restore-before-any-late-mutation-test.
  Their tested fixtures do not by themselves
  establish the late-handle/same-value-owner
  cases added in this revision. None was run.

The inspected source supplies meaningful one-state-owner,
generation-gating, continuity and cleanup groundwork,
but it does not prove every physical host permit,
reentrant batch, same-value cleanup, third-party
noninterference, native resource bound or
durable command recovery. These remain named
implementation correspondence obligations.
