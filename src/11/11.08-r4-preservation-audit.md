## Editorial decision

Preserve the strong compact R5 matrix instead of mechanically reverting
to R4's generic N/N+1 sketch. Restore R4's explicit four identity
coordinates, finite overlap and important possibility of retiring old
execution while retaining command-specific recovery. Strengthen actual
reachability analysis: sticky routing is not a tested exclusion when
failover, stale assets or direct endpoints can expose the other
direction. Qualify each client/server operation and protocol separately,
and forbid both proof-by-label and silent fallback. Make first-real-
boundary denial and permitted positive operation independent tests.

An immutable semantic contract is neither a physical installed
handler/decoder nor current principal authority. A historical command
resolution path can outlive permission to execute the earlier writer.
The completion state of the browser, XTDB, cross-host delivery and
user-selected adoption are different subjects. The proposed system can
support a small ordinary overlap without promising arbitrary history
migration, a universal broker or globally atomic host activation.

## Thirty-two R4/R5 preservation and strengthening decisions

1. Preserve R4's independent operation/plan semantic identity.
2. Preserve exact client/server artifact and protocol identity.
3. Preserve admitted assembly and concrete activated-host identity.
4. Preserve a directional compatibility/adaptation relation as a
   distinct subject, not a fourth version number.
5. A committed build, a prepared candidate and an activated
   predecessor are different states.
6. Never infer compatibility from Git ancestry, elapsed time or
   successive integer generations.
7. Retain a declared finite, bounded baseline A/B overlap.
8. Other finite windows require their own explicit admitted scope.
9. Third-generation activation does not revoke sleeping browsers by
   arithmetic; explicit expiration/recovery remains mandatory.
10. A/A pairing requires continuing qualification of old installation.
11. B/B pairing requires actual new installation and asset applicability.
12. A/B old-to-new is independent of B/A new-to-old.
13. Compatibility is operation-, envelope- and continuation-specific.
14. Mutating commands, protected reads, reconciliation and advisory
    Live use can have separately qualified directions.
15. A route exclusion is a proved or qualified physical guard, not
    sticky-session configuration asserted from one request.
16. Host failover, reconnect, redirects, CDN/proxy and direct paths
    can make otherwise excluded pairs reachable.
17. Browser/sleeping client references and assets are real sources
    of old-generation traffic after new activation.
18. A schema/operation name or copied compatibility digest proves
    neither installed route adoption nor decoder behavior.
19. Complete normalized semantics may justify conservative equality,
    while the physical realization still needs independent evidence.
20. Directional adaptations carry explicit representation/refinement
    premises; unsupported handwritten flags cannot prove them.
21. Mismatch stops before first privileged data, authoritative effect
    or browser-owned installation.
22. Typed retirement/recovery and explicit refusal are allowed;
    anonymous HTMX fallback and silent feature downgrade are not.
23. Positive valid traffic must succeed under the same actual gate
    that rejects the negative cross-generation control.
24. Actual guarded writer/origin attribution is not established by
    an earlier test wrapper rejection or HTTP success.
25. Existing requests keep their owned generation and current
    runtime/authorization obligations across activation.
26. An inherited assembly identity never freezes Membership, tenant
    disclosure, credential validity or browser resource ownership.
27. Unknown incorporation is not rejection; no fresh command ID
    is created because a response was lost during upgrade.
28. Qualified historical read-only reconciliation can outlive the
    supported old mutation plan.
29. One coherent local host switch does not prove globally atomic
    rolling activation.
30. Revocation/retirement is a safety obligation; claimed eventual
    completion remains conditional on fairness and availability.
31. Release policy determines mandatory directions before execution;
    unsupported strict checks do not silently turn into exclusions.
32. Ownership remains with 11.08 for the reachability matrix, 11.09
    for continuation/retention and 11.10 for recovery/adoption.

R4's N/N+1/N+2 example is retained semantically as a finite
activation-order example, not a numeric assembly ID. The original
specific command C42 and Request recovery rules remain in their
owning sections rather than being duplicated into a second
reconciliation algorithm. No essential R4 release/skew requirement
was deliberately removed.

## Actual Gesso v1622 implementation correspondence

Source was examined through the application-assurance GitHub branch
at the exact v1622 commit; it was not executed in this editorial pass.

- src/gesso/live/application_preflight/biff.clj describes a local
  Biff 2 application-handler lifecycle. Its actual-function and
  handler/start checks concern a current ApplicationAssembly and
  system-map boundaries. Its own contract excludes later handler
  replacement or a server ignoring :biff.ring/handler. This is
  not evidence of arbitrary multi-host rolling compatibility.
- src/gesso/live/application_preflight.clj contains whole-application
  preflight and actual render/handler guards, but explicitly does not
  prove deployed server adoption from the presence of checked
  :biff.ring/handler or build metadata.
- src/gesso/live/browser/build.clj binds exact generated asset bytes,
  manifest stamps and receipts under selected build assumptions;
  it does not establish which asset a remote sleeping browser
  actually loaded after a mixed-generation deployment.
- src/gesso/assurance/proof/installed_route_provenance.clj checks a
  narrow local in-process Ring dispatch witness. The namespace
  explicitly leaves deployed server adoption, credential authority,
  full physical writer coverage and dynamic-route correlation open.
  It cannot certify A/B or B/A reachability and effect boundaries.

These modules support a source-relative, bounded set of individual
physical facts. No complete distributed generation registry,
externally authenticated release routing exclusion, old/new
directional continuation checker, installed multi-host traffic
attestor or sleeping-browser release-compatibility proof is inferred.
The plan deliberately specifies those future obligations without
calling them implemented.

No JVM, XTDB, browser, Biff deployment, actual HTTP listener,
HumanHelp, source-to-physical failure injection or multi-host
test was executed in this 11.08 editorial revision.

## Eighteen paired future conformance cases

| # | Positive case | Adversarial near miss |
|---|---------------|-----------------------|
| 1 | A/A retains valid old rights | A unsafe old writer outlives revocation |
| 2 | A/B Claim envelope and effects match | Stripped metadata bypasses B's current rules |
| 3 | B/A separately qualified | A/B success is incorrectly made symmetric |
| 4 | B/A excluded through actual failover guard | Sticky route looks safe but failover reaches A |
| 5 | Current B/B serves B assets | Old JS is served using a new manifest label |
| 6 | Old origin may perform compatible read | Old writer is erroneously allowed to mutate |
| 7 | Same semantics requalify changed physical adapter | Old provider test reused because ID matches |
| 8 | Deferred A response retains A context | Callback imports B's mutable provider |
| 9 | Current principal gates old-origin operations | Historical Membership is treated as authority |
| 10 | Incompatible transport gets typed retirement | Unmarked HTMX downgrade occurs |
| 11 | Real physical guard blocks wrong pairing | Test wrapper rejects but production writer accepts |
| 12 | Positive valid Claim still executes | Reject-all implementation passes negative tests |
| 13 | Unknown C42 resolves through admitted lookup | Old response loss produces new C43 |
| 14 | Current DOM resource owns browser effect | Retired A callback installs into B page |
| 15 | Actual host failover and reconnect tested | One healthy endpoint sample counts as closure |
| 16 | Third activation retires A and recovers safely | Indefinite old plan from N/N+1 arithmetic |
| 17 | HumanHelp remote adoption awaits Refresh | Upgrade reconnect auto-imports remote rows |
| 18 | Unsupported strict direction blocks release | Mandatory evidence silently recast as optional |

The examples are future test specifications, not results. Their
physical/effect oracle must observe the actual protected gateway,
absence of prohibited effects and legitimate positive behavior;
their formal scope must not be promoted to system proof.
