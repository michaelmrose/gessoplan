Accepted R5.1 context: Parts I–X, with Part XI 11.01–11.10 already

Implementation correspondence baseline: Gesso application-assurance

## Editorial judgment and rule of interpretation

Preserve R5's economical organization while recovering useful specificity
from R4, especially that application authors are not required to write
proof-assistant scripts, that domain revisions/actor knowledge and provider
progression are distinct, and that release retirement cannot secretly
override HumanHelp's Refresh policy. Make each non-goal conditional on
the actual application source: it removes a *universal architecture
requirement*, not an obligation selected by a model, release profile
or original independent product specification.

This also prevents a subtle error: "No universal event log" must not
be used to erase the command record/outbox a particular operation
requires. "No proof of browser internals" does not eliminate the
actual browser test/qualified shell premise. "No global participant
fabric" does not license dropped invalidations. "No arbitrary Clojure
proof" does not permit an unsupported opaque callback to satisfy
a mandatory theorem by assertion.

## Thirty-two preservation and strengthening decisions

1. No universal persisted fact DAG; authoritative model/backend state
   and selected durable histories remain real owned effects.
2. Proof/assembly dependency graphs are evidence structure, not
   a second system of record for business facts.
3. No universal Git-style branch/merge ancestry or three-way merge.
4. Event sourcing, CRDTs and custom conflict strategies remain valid
   domain choices with typed interfaces and current authorization.
5. Model-specific conflict interpretation is not chosen by optimism.
6. No one scalar collapses provider basis, model revision, valid time,
   causal command identity and participant knowledge.
7. Provider comparison and scoped progression have declared meanings.
8. Different actors may legitimately possess different relevant
   authorized projections; convergence is scoped.
9. No universal actor-to-host global directory or direct message fabric.
10. A required direct/durable participant protocol still specifies
    explicit receipt, owner, retries and failure conditions.
11. No universal persisted server/browser suspended workflow engine.
12. Multi-node extends single-node semantics without a second
    mutation or Live/adoption authority model.
13. No universal arbitrary stale-plan migration; checked bounded
    compatibility and authorized recovery remain mandatory.
14. Retired callbacks/DOM rights cannot be reanimated by copying state.
15. Semantic command uncertainty may survive execution retirement.
16. An old version or current Request snapshot does not establish
    historical command incorporation.
17. No arbitrary host-language type theorem from invoking a callback.
18. Closed checker unsupported cases remain explicit, not promoted
    to proof or ruled out as valid application programming.
19. Application authors do not manually write TLA+, Quint, Recife,
    Lean or internal proof-kernel terms for ordinary use.
20. Generated formal work and source-derived obligations preserve
    their original business owner, not a second policy catalog.
21. No unconditional proof of JVM, JS engine, browser, HTMX, Biff,
    XTDB, network, operating system or arbitrary dependency.
22. Each relied-on external premise or physical implementation
    has a stated evidence/qualification scope.
23. Product requirements and independently selected user behavior
    are not inferred from a well-typed implementation subset.
24. No replacement of runtime authentication/authorization or
    effect/DOM resource validation by a proof certificate.
25. No replacement of actual physical browser/backend/failure
    conformance by abstract proofs or caller-reported tests.
26. No unconditional progress across dead clients, unavailable
    network and expired evidence or retention.
27. No mandate that every role know or be allowed to read all facts.
28. Source, semantic, assembly, byte artifact, issuer and effect
    identities remain distinct; a digest is not an authority.
29. Optional proof/debug sidecars remain nonsemantic; mandatory
    gates and durable audit/publication effects are still binding.
30. No mandatory database neutrality; qualified XTDB-specific
    mechanisms can be primary, with honest provider boundaries.
31. Non-goal exceptions cannot be applied after a failing mandatory
    gate to preserve the same requested release claim.
32. Stronger optional machinery is supported where selected and
    appropriately admitted; the default framework need not
    impose it on every small application.

All R4 non-goal families survive, with related entries grouped
under semantic owners. R5's more accurate conditional trust and
application-defined recovery model is retained. No essential
earlier requirement or illustrative negative scenario was removed.

## Implementation correspondence and nonclaims (v1622)

The actual connected GitHub branch was inspected for this revision.

- src/gesso/assurance/proof/certificate.clj issues narrow, process-local,
  source-relative checked handles for distinct restricted proof kinds.
  Its namespace contract rejects treating an accepted handle as runtime
  authorization, arbitrary host-language proof, authenticated durable
  certificate, complete application enumeration or physical execution.
- src/gesso/assurance/proof/application_assurance_report.clj computes
  nonauthoritative source-linked structural summaries with explicitly
  open proof, hidden-writer, XTDB and browser correspondence obligations.
  A copied report cannot certify an installed release.
- src/gesso/assurance/report.clj reports conditional assurance
  classifications and explicitly does not authenticate caller-provided
  external test execution or make the report a deployment gate.
- src/gesso/live/application_preflight.clj constructs a bounded
  ApplicationAssembly with route/render and generated browser-asset
  checks. Its declared open obligations include arbitrary/opaque
  implementation and actual installed serving-path behavior.
- src/gesso/live/browser/adapter.cljc owns a pure Clojure/CLJS
  semantic browser transition/effect interface; its domain model
  is intentionally separate from actual HTMX, DOM, timer and
  transport implementation in the physical shell.

These sources show deliberately bounded *current* proof and
application-preflight machinery. They do not demonstrate
arbitrary Clojure correctness, comprehensive application
certification, a universal runtime actor directory, portable
all-database qualification, complete actual multihost Live
recovery, or real HumanHelp product acceptance. Those are
separate selected future claims and validation subjects,
not results inferred from these namespace docstrings.

No JVM, XTDB, Chromium, installed Biff/Aleph, real multihost,
external formal verifier or HumanHelp tests were executed for
this editorial revision. The presence of source/tests alone is
not an executed assurance result.

## Positive/adversarial design freedom acceptance

| Selected ordinary or stronger design | Invalid waiver or overreach |
|--------------------------------------|-----------------------------|
| Simple Claim uses model-owned XTDB transactions and a bounded C42 record | A universal second fact DAG is demanded without a semantic need |
| Domain with genuine merge policy selects CRDT/three-way strategy | Default optimistic overlay silently chooses a domain merge |
| Tenant-scoped observation compares only soundly related basis tokens | One integer is treated as causality, valid time and actor knowledge |
| Multi-node invalidations use qualified discovery/fencing/recovery | No universal message fabric is cited as permission to miss updates |
| Long-running workflow opts into admitted durable owner | Every short Choreo is forced into permanent suspended actor storage |
| Retired page preserves explicit route/draft intent | Old DOM, callback and authority bytes are replayed as a current plan |
| C42 remains unresolved through browser retirement with valid recovery | Old execution loss is treated as rejection or new command identity |
| Opaque Clojure implementation is admitted under a permitted premise | Mandatory proof is silently replaced by assertion |
| Generated proof obligations originate in domain rules | Application developer must manually maintain a second Quint policy |
| Selected kernel theorem is conditional on implementation/host premises | The entire JVM, browser, XTDB and network are declared proven |
| Current Membership guards a previously checked operation | Old certificate is mistaken for runtime permission to disclose |
| Actual browser/XTDB/host tests challenge the deployed path | Passing static derivations are treated as sufficient end-to-end results |
| Canonical HumanHelp product capabilities are independently checked | Coherent Claim fixture causes missing Reassign/Response to vanish |
| Explicit limited progress assumptions are maintained | Network outage is represented as guaranteed eventual recovery |
| Two authorized actors see different relevant projections | Every role must acquire all facts to claim consistency |
| Exact browser asset and semantic operation retain different identities | Copying the correct asset hash is taken as a proof of execution |
| Optional diagnostic view is passive while required guard enforces | Copied report becomes authority to mutate protected state |
| Qualified XTDB adapter is selected without universal portability | A similarly named unqualified backend is treated as equivalent |
| Required C42/outbox evidence is durably retained by its owner | No universal event log is cited to discard necessary history |
| Small server-rendered app selects only needed strong mechanisms | Optional formal/multinode machinery is forced into every route |
| Strict selected profile fails when proof obligation is unsupported | Non-goal becomes a post-failure permission to downgrade the claim |

These are prospective independent positive/adversarial controls.
A non-goal is an architectural exclusion from *default
requirements*, not observed test evidence and never a replacement
for a model obligation, actual protected boundary or admission
profile. Positive paths must remain usable alongside rejection
of precisely the unsupported stronger claims.
