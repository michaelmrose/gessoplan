## Editorial judgment

Retain R5's concise table and R4's explicit failure inventory.
Qualify every item with a physical source, installed subject,
failure schedule and independently observed success/absence-of-
effect oracle. Reconcile the entire target with Part X's
stronger recent model: source-derived durable notices cannot
depend on a writer knowing all live recipient interests;
router-filter replicas can be stale even when healthy; and
a registration/replay fence must close the initial and
reconnect gaps without fabricating current knowledge.

The *semantic machine is one* across one node and many.
Routers, brokers, coarse/hierarchical filters, redundant
placements or an eventual alternate implementation language
can be chosen independently provided their actual
failure, authorization, progression and publication
contracts are qualified. Do not mandate one product,
broker, routing engine, permanent per-recipient send ledger
or application-authored second distributed policy.

## Thirty-two R4/R5 preservation and strengthening decisions

1. Multi-node is a realization of the original single-machine
   authority, operation, knowledge and adoption semantics.
2. A role, actor, principal, authority and physical process
   have distinct identities and ownership.
3. Two actually isolated processes and their installed path
   are required for multi-node physical correspondence.
4. Source completeness includes alternative HTTP, admin,
   migration and background privileged writer entrypoints.
5. One real selected shared backend/adapter must qualify
   atomic, visibility, progression and contention behavior.
6. Stable original logical command binding survives A-to-C
   retry and separate transport attempt identities.
7. Current authentication and model guards are rechecked
   at every host's trusted command boundary.
8. Same-command competing submissions do not manufacture
   independent mutations or two primary assignees.
9. Current Request state alone does not causally attribute
   an uncertain C42 to the first host.
10. Deduplication retention/expiry is an enforced protocol;
    missing historical record cannot mean automatic new intent.
11. Failure before or after possible submission, commit,
    publication, dispatch acknowledgment and response
    delivery have different expected outcomes.
12. Required command outcome and durable publication intent
    are atomically coupled to an authoritative write where
    promised, or justified by an equivalent recovery mechanism.
13. A model writer's required notification purpose is
    source-derived, not erased by the writer's lack of
    a live global subscriber list.
14. A durable outbox is not an SSE delivery receipt.
15. Dispatcher ownership and crash recovery can cause
    duplicate notice attempts without duplicate domain
    effects or lost required intents.
16. At-least-once dispatch is scoped to the actual named
    acknowledged broker/router/recipient boundary;
    browser delivery requires separate evidence.
17. New-subscription interest acquisition and authoritative
    read must be fenced to avoid a silent initial gap.
18. Router failover must account for an outdated surviving
    filter, not merely the death/health of a process.
19. Filter replication, coarse routing, conservative
    authorized overdelivery and bounded redelivery are
    eligible alternatives to per-recipient success logs.
20. Cross-tenant notice routing, disclosure metadata and
    current subscription scope remain protected.
21. Replay expiry, missed gap and insufficient basis
    are exposed as typed blocked/recovery debt, not
    silently reported as current state.
22. Read progression must use actual qualified observed
    provider evidence, not reflected caller tokens.
23. Transport, authorization, acquisition, DOM install
    and advisory adoption are different checked stages.
24. HumanHelp remote lifecycle stays advisory to Bob
    until permitted explicit user Refresh.
25. Direct participant typing has its own ephemeral
    delivery contract; it is not a durable Request event.
26. Rolling A/A, A/B, B/A, B/B exposures include actual
    host failover, retained assets, migrated state
    readers/writers and compatible retirement.
27. Concurrent deferred work carries correct assembly,
    resource and principal context; one-shot authority
    cannot leak across requests.
28. Real fault injection must exercise independently
    isolated host/router/backend failures, not labels
    or staged status fixtures.
29. Resource and capacity claims state queues, filters,
    debt, retention, overload, backpressure and their
    actual bounds and operating conditions.
30. Conditional liveness names backend/network availability,
    qualified replay, fairness and explicit user action;
    safety and nondisclosure hold when liveness is blocked.
31. Root evidence names physical topology, selected
    trusted premises, real positive/negative traces,
    original-required denominator and open gaps.
32. A two-host prototype is useful partial feedback,
    never complete production or general formal
    certification merely from its topology.

R4's required host-loss, publication-loss, duplicate/reorder,
cross-host retry, reconnect, authorized Refresh, load/fault,
deployment-compatibility and release-report checks all
remain. R5's clearer bounded claim/evidence categorization
is preserved. No essential prior requirement is dropped.

## Inspected Gesso v1622 implementation correspondence

Reviewed the pinned application-assurance source:
- src/gesso/live/core.clj composes model invalidation rules,
  async dispatch, a local hot source/flow, SSE transport,
  per-client event filtering, and app-facing XTDB
  consistency/progression helpers. It does not itself
  attest a durable multi-node router or host-failover
  subscription recovery.
- src/gesso/live/invalidation.clj expands *declared primary
  changes* into app-level invalidations and preserves
  attached authoritative progression. It deliberately
  does not inspect database writes or infer old/new
  state from XTDB.
- src/gesso/live/dispatch.clj supports bounded queued
  local expansion work with configurable overflow and
  errors; the in-process worker pool is not a durable
  distributed outbox acknowledgment.
- src/gesso/live/consistency/xtdb.clj provides qualified
  XTDB2 query/transaction and progression helpers,
  explicitly without listening to transaction logs
  or automatically publishing live invalidations.
- src/gesso/live/transport/sse.clj owns an SSE response
  frame/stream lifecycle from a per-client flow; an
  emitted frame does not establish remote browser
  receipt, authorized current data acquisition,
  or DOM adoption.
- src/gesso/assurance/proof/conditional_single_node_refinement_evidence.clj
  composes bounded caller-supplied single-node
  diagnostics and explicitly does not authenticate
  physical submission/commit causality, transaction
  isolation, all writers or production refinement.

These are real single-node-oriented building blocks and
conditional diagnostics, not an observed production
multi-host implementation. This source inspection
does not establish that *no* other routing experiment
exists elsewhere, only that the inspected interfaces
do not themselves prove this completion milestone.
The future multi-node plan remains a distinct physical
realization under the same semantic Gesso contract.

No JVM, XTDB, Chromium, real Biff/Aleph host, physical
router, network partition, load, HumanHelp multi-client
or fault-injection suite was executed for this
editorial revision.

## Twenty-four positive/adversarial multi-node controls

| # | Genuine qualified positive | Invalid adjacent counterexample |
|---|----------------------------|---------------------------------|
| 1 | Two independently isolated hosts serve one Claim contract | Two labels share process-local state and report failover |
| 2 | Concurrent helpers satisfy one-primary invariant | Cross-host stale read permits two primaries |
| 3 | C reuses C42 canonical binding or qualified history | C creates C43 after A response loss |
| 4 | Uncertain incorporation remains unknown until evidence | Current Request read or absent record asserted as proof |
| 5 | Required committed outbox intent survives A loss | Sole A callback dies before publication |
| 6 | Dispatcher repeats unacknowledged send safely | Duplicate advisory becomes duplicate mutation |
| 7 | Broker/router receipt reported only for its boundary | SSE write called delivery to every browser |
| 8 | Subscription handshake closes read/registration gap | Change between initial read/interest is dropped |
| 9 | Healthy backup repairs stale filter knowledge | Stale router omits required interested recipient |
| 10 | Conservative redelivery is scoped and bounded | Overbroadcast reveals protected tenant metadata |
| 11 | Replay gap/expiry leads to typed recovery | Stream silence is proof of currentness |
| 12 | Host C uses real sufficient provider basis | Echoed token/lagging snapshot satisfies later basis |
| 13 | C reauthenticates current Membership/result scope | Old A session permits revoked disclosure |
| 14 | Bob waits for one explicitly granted Refresh | SSE reconnect silently adopts unrelated rows |
| 15 | Current browser resource admits authorized new view | Old A callback installs into B DOM |
| 16 | Actual mixed-generation paths satisfy overlap | Sticky route ignores failover to incompatible old code |
| 17 | Rollback checks migrated schema and durable work | Prior successful binary is blindly reactivated |
| 18 | Physical process/router fault actually occurs | No process is killed, but fault test reports pass |
| 19 | Eligible Claim succeeds beside real protected rejection | Reject-all test interceptor appears green |
| 20 | Resource envelope survives declared overload/recovery | Short throughput hides infinite queue growth |
| 21 | Ephemeral typing respects current recipient scope | Typing message counted as durable Request update |
| 22 | Report lists genuine physical premises and open gaps | Copied success map certifies universal topology |
| 23 | Qualified progress occurs with fairness/user action | Offline Bob with no Refresh is claimed converged |
| 24 | Revoked principal receives safe nondisclosure | Historical result is replayed to old session |

These are prospective physical acceptance histories, not
newly executed test results. Positive and negative
oracles must touch the actual host, backend, router,
protected read/writer and browser delivery boundary
they claim to check. An independently observed
two-host experiment is still narrower than an
unspecified all-topologies theorem.
