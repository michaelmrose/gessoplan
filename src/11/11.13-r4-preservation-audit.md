## Primary editorial judgment

R5's milestone is architecturally superior to the original R4
checklist. Retain its exact source/installation, production-model
ownership, six-operation product success, currently selected
advisory-only remote Refresh policy and separately open Response
decision. Recover R4's explicit minimum Biff/XTDB/projection/
Choreo/Live/optimism/continuity construction and generic
adversarial-production tests. Tie all items to the actually
served application and original independent product denominator,
not a favorable generated subset or a passing Claim fixture.

Part VIII's independent editorial acceptance expressly **did not**
select HumanHelp's response-flow product meaning or certify the
current app. The required product decision remains open.
Do not create or assert a messaging provider or claim that Claim
alone fulfills Response. The selected complete operational
milestone requires real product-owner selection and independent
positive and negative acceptance of that flow, including the
actual model or external effect if chosen.

## R4/R5 preservation and sharpening decisions

1. The operational milestone is the *usable installed app*, not
   an abstract theorem or completed documentation review.
2. Original independent HumanHelp capabilities, not exposed
   controls, establish its fixed denominator.
3. Declared closure, actual production enforcement and actual
   usable behavior remain distinct independent claims.
4. Source-derived model/route/plan/render/asset closure is
   required for the actual selected application.
5. Actual Biff serving adoption must use the checked
   handler/response guard and correct lifecycle ordering.
6. Actual JS bytes and qualified loaded browser runtime
   must agree with admitted manifest/build premises.
7. Public production model owners define User, Membership,
   Organization, Location, Request and RequestAssignment truth.
8. Trusted server binding, source-owner authorization and
   actor/target separation cannot come from browser metadata.
9. Protected Request/assignment multi-record guards prevent
   two competing primary Claims.
10. Lifecycle state =:done= and primary responsibility closure
    remain consistent at authoritative commit.
11. Reassign requires eligible distinct target selection and
    real manager authority, not rebranded self-Claim.
12. All six lifecycle actions require eligible positive
    real-control browser cases, not always-disabled buttons.
13. Creator-local Create/visibility stays separately
    permitted without granting unrelated remote collection reads.
14. Remote Create and lifecycle remain advisory until explicit
    user Refresh, subject to narrow own-command/recovery exceptions.
15. One-use Refresh, required coverage, concurrent advisory and
    remaining debt are separately enforced.
16. Search/sort/mine-first/unclaimed-first/terminal options
    operate on actually authorized adopted board information.
17. Detail/selection/scroll/compatible local input continuity
    preserves current browser owner and principal restrictions.
18. Response flow remains a required independent product
    decision and acceptance gate; do not invent its semantics.
19. Production mutation truth is not optimistic card display
    or HTTP 200, and fresh read is conditional on outcome contract.
20. Canonical logical command ID, binding, compatible replay
    and unknown-result reconciliation retain independent truth.
21. Missing readback is not authoritative business rejection
    or permission to submit another command.
22. Durable publication/invalidation and real writer inventory
    remain accepted-source and physical obligations.
23. Real XTDB/provider/configuration, not a fake adapter,
    must satisfy the selected transaction/progression premises.
24. Actual rendered controls and physical browser events,
    not manually fabricated hidden protocol calls, are tested.
25. Distinct authenticated users are needed for multi-client
    acceptance and advisory/authorization races.
26. Controlled defects fail at intended production boundaries
    and eligible nearby positive operations still succeed.
27. Startup/preflight failure cannot leak an unadmitted
    listener or protected background worker.
28. Stale browser resources, lost responses and Live
    interruption need truthful safe recovery, not UI silence.
29. Actual current principal/Organization changes can revoke
    disclosure and effect permissions despite cached state.
30. Ordinary operational completion does not automatically
    claim full compositional certification, external formal
    verification or multi-node production certification.
31. Any stronger assurance profile chosen for the release
    remains mandatory, even if the narrower operational
    milestone would otherwise be satisfied.
32. Partial checkpoints explicitly retain open Response,
    missing product operations and unqualified physical
    correspondence rather than shrinking the target.

No essential R4 lifecycle, UX, real Chromium, controlled-defect,
actual-production-path, or milestone-separation requirement
was intentionally discarded. R5's stronger source-owned
authority and compatibility distinctions remain preserved.

## Implementation and source correspondence: Gesso v1622

Inspected Gesso source at the pinned application-assurance
commit, alongside Part VIII's accepted *specification* and
implementation limits. This is source inspection, not a
new runtime or deployed-app test.

- src/gesso/live/application_preflight.clj defines an
  ApplicationAssembly and source/route/browser/render
  relations, including rendered-surface guard and
  canonical Gesso/Biff startup interface. Its own
  docstring excludes arbitrary deployment startup,
  later handler replacement, raw serialized HTML,
  and a listener ignoring :biff.ring/handler.
- src/gesso/live/application_preflight/biff.clj
  implements the selected local handler module and
  startup preflight/handler checks. It is not an
  attestation that a real production load balancer
  or running deployment uses this route.
- src/gesso/live/browser/build.clj binds
  BrowserAssemblyManifest/stamp and exact generated
  byte receipts under selected emitter assumptions;
  it does not establish what browser clients
  actually loaded or compiler semantic correctness.
- src/gesso/assurance/proof/installed_route_provenance.clj
  checks narrowly scoped in-process Ring route
  dispatch/handler use; it expressly leaves real
  deployed host, caller identity, XTDB effects
  and physical dynamic-route correlation open.
- src/gesso/model/command_resolution.clj
  constructs a canonical command record within one
  abstract model transaction plan and supports
  qualified reconciliation, but does not itself
  prove production XTDB atomicity, current actor
  authentication or disclosed results.

Part VIII's independent accepted-candidate record
explicitly states that its source requirements have
been accepted as a future-system design, **not**
that the app has passed Chromium, multi-client,
real XTDB, completion, security or formal gates.
Its Response interaction product meaning remains
independently unselected; its remote lifecycle
adoption policy is explicitly selected as
advisory-only with user Refresh.

No JVM, XTDB, browser, Biff listener, multi-user,
HumanHelp, production deployment or formal theorem
tests were executed in this editorial revision.
No application/runtime completion certificate is
claimed from inspecting repository source.
