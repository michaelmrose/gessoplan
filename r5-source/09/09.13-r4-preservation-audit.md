## Governing decision

The first pilot must prove meaningful *compositionality*
about the real HumanHelp Request Claim vertical slice:
correct source declarations and public model boundaries
flow into typed proof obligations, Choreo/projections,
issued executors, application assembly and specific
physical/user evidence. Three independent conclusions
must remain independent: source-relative semantic
judgments, actual implementation/host correspondence,
and positive product/browser acceptance.

R5's architectural model is retained. R4's multi-layer
dependency graph, source-mismatch rejection, precise
typed root report and negative mutant oracles return.
Accepted R5.1 Part VIII prevents pilot success from
being mistaken for complete product success or from
inventing business fields, statuses or a response flow.

## R4 preservation and strengthened requirements

1. **A real application vertical slice:** The pilot
   uses public production Request, RequestAssignment,
   User, Membership, Organization and Location
   semantics where required, not example-only policy
   or a test-created Request store.
2. **R4's full DAG extends through the host:** Schema,
   domain, relationships, rules, operation, Choreo,
   both helper/authority projections, executable plans,
   application assembly, browser/route/handler, model
   operation and authoritative reacquisition remain
   visible. Only justification edges form a proof DAG.
3. **No invented model shortcuts:** The production
   active primary assignment is not a persisted
   `:request/helper-id`; canonical lifecycle uses
   `:done`, not a new `:completed` state.
   Organization policy fields are source-derived.
4. **Model-owned cross-boundary policy:** Claim consumes
   the owning public `*.core` contracts and does not
   reimplement private FX/domain/graph authorization
   in the example or browser proof layer.
5. **Complete original-source manifest:** Invariants,
   shared initialization, operation families, model
   guards, proof/Choreo outcomes and installed
   components are independently derived. Removing
   Reassign from both current source and generated
   proof remains an independent product failure.
6. **Actual protected dependency set:** Request state,
   active primary absence/cardinality, authenticated
   actor and selected target helper, effective
   Membership, Organization/Location policy,
   command exclusion and relevant relationship
   facts must be guarded at the actual transaction
   boundary where the production rule requires them.
7. **One-primary safety with real races:** Two eligible
   helpers attempting independent Claims cannot
   create two active primary assignments. A pair
   of clicks or pre-read guards does not establish
   contested atomic incorporation conformance.
8. **Historical C42 is not a current card:** A lost
   response preserves the original command binding.
   An eventual Reassign changes current truth but
   does not erase an earlier Claim incorporation.
   Replay requires declared retention and fresh
   disclosure, never an invented second write.
9. **Four model outcomes and presentation truth:**
   Committed, rejected, already-incorporated,
   commit-unknown remain distinct from
   accepted/rejected/unknown UI. An HTTP 200
   is not a backend incorporation theorem.
10. **Source-owned browser command:** The real rendered
    Claim control must issue its own command and
    target. Constructing the wire envelope in the
    browser test establishes only an integration
    fixture, not the browser-to-command edge.
11. **Authoritative adoption is physical:** Scoped
    permitted card read and actual target completion
    are needed. A provisional badge, received SSE
    or swapped toolbar alone does not establish
    adopted Request/assignment truth.
12. **Selective creation and explicit Refresh:**
    Creator-local correlated S may be installed
    while remote R remains advisory, even for
    already-visible Requests. One user grant permits
    only its scoped authoritative read; automatic
    remote refresh is not a permitted replacement.
13. **No trivial safety/product pass:** All six
    lifecycle operations and real Reassign target
    selection remain separate eligible positive
    gates. Claim proof and a permanently disabled
    UI cannot constitute HumanHelp acceptance.
14. **Response flow remains unselected:** The exact
    response interaction must be decided by
    HumanHelp product authority with its own
    privacy, actor, persistence/recovery and
    positive/negative evidence. A Claim pilot
    cannot silently select it.
15. **Assumption scope survives composition:**
    Opaque Organization policy, checker soundness,
    XTDB guarded-writer/absence semantics,
    physical writer coverage, compiler/HTMX
    behavior and external availability remain
    exact open, discharged or independently
    qualified premises by claim.
16. **Physical source correspondence is separate:**
    Actual handler adoption, model callable,
    protected transaction prestate, pinned
    command record, loaded asset and browser
    install cannot be inferred from a matching
    original-source DAG or caller-stated report.
17. **R4 upstream breakage must stop early:**
    Changed Organization semantic guarantee
    invalidates relying Claim rules and later
    operation/Choreo/plan composition. Valid
    new upstream source is not itself malformed.
18. **Generated root explains rather than acts:**
    The example map is copyable inspection
    output, not certificate input, capability
    or actual application admission. It names
    every used premise and unresolved separate
    product/implementation evidence class.
19. **Actual positive and nearby negatives:**
    Browser, guarded XTDB, adversarial actor,
    wrong target, uninstalled route, broken
    asset, lost outcome and multi-client
    tests have separate real first gates.
20. **Full-plan proof claims remain limited:**
    A Claim slice milestone neither establishes
    universal all-schedules browser/XTDB
    refinement nor accepts fourteen HumanHelp
    product gates or the whole R5.1 document.

## Source evidence in Gesso v1622 — scoped precursors

- `src/gesso/assurance/proof/application_dependency.clj`
  constructs a complete *declared abstract catalog*
  closure and original-source operation/invariant
  ledger. Its live handle is explicitly not a
  physical writer census, deployed-application
  certificate or end-to-end proof; a caller-
  selected catalog cannot authenticate the
  currently installed HumanHelp application.
- `src/gesso/assurance/proof/application_assurance_report.clj`
  recomputes a conditional source-level report
  from the declared catalog, operation
  composition, source provenance and observed
  writer accounting. Its documented permanent
  open obligations include independently proven
  checker soundness, actual installed handler
  adoption, complete physical writer coverage,
  universal physical transition refinement and
  browser/HTMX/SSE correspondence.
- `src/gesso/live/application_preflight/inductive_contract.clj`
  joins original abstract induction IDs to
  source-relative issued handlers and current
  assembled semantic routes. The result is
  a copyable explanation; model/physical
  transition semantics, actual router adoption,
  dynamic writer and initializer coverage
  remain open.
- `src/gesso/assurance/proof/issued_executor_physical_plan_correspondence.clj`
  checks a freshly issued, process-local
  handler and its captured XTDB adapter-call
  plan in *one controlled synchronous
  execution*, not the deployed route or
  actual physical atomic prestate.
- `src/gesso/assurance/proof/physical_writer_inventory.clj`
  gives host-observed possible XTDB write paths
  against a declared operation source. It
  explicitly does not establish the host
  enumerator found all raw/external paths.
- `src/gesso/assurance/proof/xtdb_gateway_command_outcome_bridge.clj`
  (v1622) compares one source-issued,
  process-local atomic submission and pinned
  canonical command readback with reported
  request outcome. The module explicitly
  does not authenticate the reported
  principal/disclosure/installed plan or
  prove Ring causality or Live/browser
  settlement. Its result is bounded
  co-observation and value agreement.
- `src/gesso/live/application_preflight/rendered_surface.clj`
  checks concrete supplied rendered Hiccup
  affordances and effective HTMX coordinates,
  not every potential deferred/error/
  streaming response or a fully observed
  browser-to-command path.

Selected relevant tests, such as
`test/gesso/assurance/proof/application_dependency_mutation_test.clj`
and the XTDB-gateway/installed-route families,
exercise declared-source omission and narrow
controlled physical boundaries. This audit
inspected their existence and/or relevant
source contracts, not test execution.

The Gesso repository does **not** itself
contain the HumanHelp production Request
and RequestAssignment implementation;
the independent Part VIII review used
the HumanHelp `dev` branch as separate,
bounded source evidence. This 09.13
review therefore uses the *accepted
Part VIII normative production contracts*
without claiming to have independently
executed the HumanHelp application
or verified its present deployment.

## Paired positive and adversarial corpus

1. **Public Request truth:** Original production
   Request/assignment contract available.
   Negative: invented helper-id field or
   noncanonical completed status passes
   as if source-derived.
2. **Cross-model interface:** Genuine public
   Membership and Organization commitments
   compose. Negative: private FX or copied
   policy field becomes an admitted shortcut.
3. **Complete catalog:** All original
   relevant invariants and operations present.
   Negative: omitted Unclaim/Reassign still
   yields a vacuously smaller safe DAG.
4. **Stale Organization:** Updated O15 interface
   causes genuine Claim C21 failure and
   checked repair/re-issuance. Negative:
   cached C21/Choreo/plan reused unchanged.
5. **Actor authority:** Alice's authentic helper
   Membership in correct Organization passes
   actual guarded Claim. Negative: revoked
   Membership, wrong actor or browser
   :helper role grants mutation.
6. **Primary safety:** Two eligible real
   competing Claims result in at most one
   newly active primary. Negative: merely
   concurrent clicks or separate pre-reads
   are reported as physical guard proof.
7. **Model consistency:** Successful Claim
   atomically updates Request, active
   primary assignment, command result
   and required publication intent under
   the selected profile. Negative:
   partial assignment or independent
   non-atomic write is accepted.
8. **Stable C42:** Known committed Claim
   replay is attributed under real
   retention/disclosure. Negative: a new
   command or current card is substituted
   for historical incorporation.
9. **Outcome completeness:** Four backend
   outcomes map to justified
   accepted/rejected/unknown presentation.
   Negative: commit-unknown becomes
   rejection or silent success.
10. **Real browser origin:** Actual enabled
    Claim control emits generated protocol.
    Negative: test manually supplies the
    wire command for a broken control.
11. **Trusted host adoption:** Installed route
    calls the issued qualified model op.
    Negative: an in-process handle or
    matching route name is credited
    without deployed server adoption.
12. **Browser asset:** Loaded runtime and
    emitted manifest/plan match current
    installed generation. Negative:
    copied stamp or stale bundle passes.
13. **Physical adoption:** Authenticated
    card query/target installation
    completes. Negative: HTTP 200 or
    provisional DOM alone is accepted.
14. **Creator/local and remote:** Creator
    selectively installs S, remote R
    remains advisory. Negative: local
    Create imports remote whole board.
15. **One Refresh:** Real user authorizes
    one scoped remote board read.
    Negative: SSE or retained debt
    manufactures a second acquisition.
16. **Other lifecycle positives:** Eligible
    Unclaim, Mark on the way, Complete,
    Cancel, Reassign each work and
    preserve model truth. Negative:
    disabled Reassign selector satisfies
    the product's capability gate.
17. **External interference:** Named
    Membership/admin/initializer writer
    effects are covered/qualified.
    Negative: hidden raw XTDB writer
    omitted from physical inventory
    is falsely declared impossible.
18. **Fault after commit:** Real Claim
    incorporates; render/OOB/Live
    delivery fails and recovery remains
    truthful. Negative: postcommit
    output failure is classified as
    transaction rejection.
19. **Root report:** All checked abstract
    claims, conditional premises, host
    bindings and product gaps appear.
    Negative: a forged :accepted map
    or missing physical edge passes.
20. **Response choice:** Clearly selected
    response interaction eventually
    has a separate actor/privacy/positive
    and adverse acceptance. Negative:
    Claim certificate silently selects
    the product response feature.
21. **Independent product gate:** An actual
    authenticated real two-client
    browser scenario follows
    production model readback after
    reload. Negative: one injected
    fixture is declared full
    multiclient product acceptance.
22. **Evidence class:** Finite abstract proof,
    source/route assembly, controlled
    physical observation, installed
    host and deployed browser test
    report their distinct scopes.
    Negative: one bounded local
    observation is called universal
    physical refinement.

Every case records the intended
claim and counterexample oracle
before injection, with source
generation, expected first
enforcement boundary, actual
authority/observation and profile.
An expected unsupported result
must not masquerade as passing
support, and checker silence
about hidden implementation
effects remains unknown rather
than proof of their absence.
