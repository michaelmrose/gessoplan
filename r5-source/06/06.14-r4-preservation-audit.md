# R5.1 Part VI — 06.14 R4 preservation and Gesso correspondence

**R4 preservation baseline:** Gessoplan main Part VI,
especially Mechanical checking and concrete correspondence;
Adapter state has one semantic owner; Semantic admission
precedes physical action; Correlation is installed then
carried opaquely; Stale and duplicate events are modeled;
Cancellation is an optimization; Execution isolation is
intentionally local except for declared shared events;
Runtime/browser guarantees are layered; and the final
Browser realization invariant.
**Preferred architectural source:** Gessoplan r5 Part VI.
**Reviewed source:** r5-source/06/06.14-refinement-traces-and-execution-isolation.org,
joined to accepted R5.1 Parts I–V and reviewed 06.01–06.13.
**Disposition:** substantive section review, not whole-Part-VI
acceptance or universal Gesso implementation/browser refinement.

## Preserved requirements

- A portable semantic adapter is the single owner of
  execution progression and permitted abstract effects;
  the physical shell normalizes real callbacks and
  executes supported effects without a second semantic
  interpreter or rediscovered ownership.
- Actual emitted abstract effects, real physical issue,
  trusted domain/model result, authoritative acquisition,
  physical installation and scoped adoption are different
  evidence subjects and must not all be called success.
- A browser role-local receive can be only a candidate
  global communication absent independent sender,
  delivery and global-schedule correspondence. A local
  completion is not necessarily the global terminal
  outcome, and hidden local work is not invented as
  a trusted operation occurrence.
- Source/effect/owner correlation is installed when the
  physical resource is issued and carried through
  callbacks. Stale or duplicate events remain modeled
  outcomes, not events made impossible by cancellation.
- Semantic retirement revokes old private physical
  rights before best-effort cleanup. A stale old
  callback cannot restore weaker presentation or
  mutate the new owner.
- A shared authoritative invalidation has its own
  coordinator/source scope and may legitimately
  influence another execution; execution isolation
  is therefore explicitly local except for
  permitted shared interactions.
- Protected host actions must be prevented before
  unsafe actuation when intervention is required;
  post hoc trace rejection cannot stand in for
  a real physical gate.
- External host/HTMX, backend/XTDB and
  runtime asset/source premises remain named.
  Real browser tests do not universally prove
  every browser or extension behavior.

This revision keeps the compact R5 structure but
recovers the R4's explicit owner/source/physical
accounting. It does not reintroduce an illustrative
R4 "admit-event" function as a parallel runtime,
nor strengthen current implementation source
observations into fabricated proofs.

## Focused refinements

1. Specified an evidence inventory from actual
   selected adapter step through role-local
   history, physical send, trusted command result,
   acquired observation, target-specific completed
   installation, adoption and concrete witness.
2. Defined a conditional concrete-to-semantic
   forward-simulation obligation with admitted
   internal stuttering, but no hidden protected
   effect, wrong-target mutation or lost obligation.
3. Made liveness/divergence and fairness
   requirements independent of safety stuttering.
4. Required trace matching by exact physical
   *occurrence identity*, source and target,
   prohibiting duplication, omission, fabrication
   or unsupported causal reordering.
5. Qualified weak/commuting witness semantics
   and happens-before preservation rather
   than requiring an artificial total order
   over genuinely independent actors.
6. Required independent sender/delivery/global
   terminal witnesses for role-local Choreo
   candidates; a running browser alone does
   not attest global execution.
7. Distinguished a self-rederived diagnostic,
   exact artifact-bound concrete correspondence
   and independently sourced host/backend
   physical evidence, with complete extractor
   assumptions and proper nonclaims.
8. Specified local execution isolation under
   shared coordinator, authoritative supersession,
   same-target arbitration, shared SSE resource,
   resource pressure and principal changes.
9. Required diagnostic noninterference, failure
   isolation and honest bounded trace capture
   with loss markers, not just a read-only label.
10. Added ten paired eligible/adverse histories
    covering real source/host witnesses,
    replay, matching, weak commutation,
    sharing, physical isolation and observer faults.

## Actual Gesso v1622 implementation source inspected

The user-provided application-assurance archive at
1b5e10e71c00e7784b019dee7dc1198a96fd03f6
contains the following meaningful partial implementations.

- src/gesso/live/browser/observation.cljc:
  step-observed actually calls adapter/step and derives
  one source-relative adapter observation from its
  returned next state and ordered semantic effects.
  observe-transition reruns the actual step and
  rejects substituted successor/effect arrays.
  It explicitly disclaims global Choreo, physical
  transport, XTDB commit and browser-host proof.
- src/gesso/live/browser/refinement.cljc:
  step-projected and trace-projected derive
  conservative mappings from the actual adapter
  and role-local machine history. A role-local
  receive becomes :candidate-only with required
  :sender-emission-witness, :delivery-correspondence
  and :global-schedule-admissibility.
  Local terminal effects remain hidden, and
  imported preexisting role-local history
  is marked unwitnessed. Every returned result
  has :global-trace-admitted? false and
  :proof-authority :none, with persistent
  explicit nonclaims of physical/backend
  and global Choreo correspondence.
- src/gesso/choreo/artifact.clj:
  check-artifact-witness and
  check-artifact-weak-witness require exact
  choreography-to-ExecutablePlan and structural
  certificate agreement before checking one
  concrete lockstep or weak witness. The
  artifact-bound evidence explicitly excludes
  all-executions trace/projection refinement;
  an accepted concrete witness is not a
  quantified general theorem or physical
  host evidence.
- src/gesso/live/application_preflight.clj:
  executor-bound refinement candidate review
  uses issued opaque process-local handles
  for actual selected physical attempt
  observations. It advertises unverified
  selected candidate packages and explicit
  remaining premises, not whole-application
  admission or authenticated backend truth.
- test/gesso/live/browser/diagnostic_noninterference_test.cljs:
  exercises an actual canonical ExecutablePlan
  with and without a diagnostic observer,
  comparing ordered semantic transitions,
  abstract effects, final AdapterState,
  resource counts and physical handler results;
  it includes throwing diagnostic cases.
  The test demonstrates those fixtures,
  not all instrumentations or actual
  physical/browser effects.
- src/gesso/live/browser/shell.cljs:
  commits the next adapter state before
  physical effect interpretation and keeps
  a narrow runtime effect handler contract.
  This supports local reentrant semantic
  ownership, but does not establish a
  general independent physical mutation
  or backend transaction observer.

These sources were inspected, not executed
for this documentation revision. They
support precise, conservative internal
observations and useful artifact-bound
witness checking. They do not establish
full browser-to-global-Choreo refinement,
all physical mutations, trusted XTDB/
RequestAssignment correspondence,
actual deployed handler closure, complete
concurrent fairness, or HumanHelp
positive end-to-end product acceptance.
The finished-system requirements remain
normative rather than falsely described
as already proved.
