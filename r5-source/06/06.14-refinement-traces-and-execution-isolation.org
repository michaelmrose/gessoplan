** Refinement, correspondence, and conformance evidence

The browser refinement claim relates one admitted executable semantic
plan and its source-normalized transition/effect history to the actual
physical behavior of the selected browser, HTMX/SSE integration, backend,
renderers and other installed effects. These are *different subjects*.
A valid role-local adapter transition is not a trusted server commit;
a requested send is not actual delivery; an observed browser receive
does not by itself prove a corresponding sender emitted it; a local
machine finishing does not prove the global choreography terminated.

Gesso's finished assurance pipeline makes these distinctions useful:
the application author declares domain rules, Gesso construction and
the supported physical profile, while the assembly and evidence
pipeline generates, checks and relates its semantic witnesses.
Authors need not manually write Recife, TLA+ or Quint. Generated
evidence does not confer semantic authority on diagnostics or let
an unsupported host action pass a physical gate.

The *object being certified* is always explicit: exact choreography
and projected executable artifact, admitted application/operation
assembly, actual source event or host trace, specified backend
execution, selected release/profile and the claimed safety or
liveness property. A pass over an attractive surrogate does
not establish correspondence of the application that ran.

*** Observe actual adapter transitions and independent physical occurrences

A diagnostic about the browser's internal machine starts from the
*actual* adapter step, not an externally proposed successor that a
report happens to describe. The recorded next state and ordered
abstract effects come from one execution of the admitted portable
transition function against the exact before-state and normalized
event. The observation carries the current execution, owner,
effect and applicable artifact identity and cannot itself create
an installation or command result.

The physical shell and qualified external sources additionally record
or attest the concrete actions to which the guarantee applies.
For each claimed physical step, the evidence names its own producer,
registration, environment/asset profile, observation point,
occurrence identity, effect/target incarnation, and real disposition.
A report that merely restates the adapter's intended effect is
not physical evidence that the effect happened.

| Evidence layer | Proposition it can establish | Proposition it cannot establish alone |
|----------------+------------------------------+---------------------------------------|
| Selected portable adapter step | The real semantic adapter selected this next state and ordered abstract effects for these admitted inputs. | HTMX sent a request, a server committed, or the DOM changed as intended. |
| Role-local projected machine history | This role locally performed or accepted the recorded step under its executable plan. | The global sender, network and other roles actually participated. |
| Abstract =:transport/send= effect | The semantic runtime requested a correlated transport attempt. | The physical browser sent it or the peer received it. |
| Correlated physical host issue/return | The selected host performed the reported issue/completion boundary under its qualified profile. | Domain incorporation or unrelated secondary effects not covered by the observation point. |
| Trusted domain command/result witness | The authenticated model operation or qualified resolver established a particular C42 historical disposition. | Current RequestAssignment/card state or physical presentation adoption. |
| Qualified authoritative acquisition | The trusted provider established stated query/entity/absence, scope, context and progression. | Installation of the representation, or universal ordering of opaque bases. |
| Real scoped physical installation witness | The current permitted effect established its declared target-specific postcondition, including supported OOB/partial behavior. | Another target, the complete board, an unrelated command result or a common backend snapshot. |
| Participant adoption transition | The participant admitted the actual covered installation into its current scoped presentation state. | That every other participant has adopted or that their obligation debt vanished. |
| Checked concrete correspondence witness | A specific independently sourced and bound trace satisfies the stated relation and checker premises. | Every future schedule, all deployments, or correctness of unobserved physical effects. |

For the actual host trace, issue, send, send-failure, receive,
response processing, native swap, OOB target mutation, timer callback,
resource release and completion may be distinct occurrences.
The selected profile says which observations are available and
sufficient for each protected contract. If that profile does not
expose a controllable or observable protected mutation, the
application must reject the strong realization, use another
qualified host contract or explicitly retain the unproved premise;
it cannot obtain a universal witness by giving an unobserved step
the same label as a known one.

An event-source registry and an adapter-created correlation value
help bind an actual callback to issued work. They do not authenticate
arbitrary client-payload claims. Trusted backend/XTDB and command
evidence must be produced at their own authoritative boundary.
An actual physical browser observation cannot be replaced by a
synthetic event sequence merely because the same adapter steps
appear when replayed.

*** Refinement relates concrete traces, not similar-looking outputs

For an admitted initial relation, one may state a conditional
forward-simulation/refinement obligation as follows:

#+begin_example
Assume the named executable, source, backend and host contracts.
Let R(c, s) relate a concrete running state c to semantic state s.

For each actual concrete protected transition c -> c':
  either:
    there is a matching permitted semantic transition s -> s'
    with its required identity/evidence/physical bindings, and R(c', s');
  or:
    the concrete transition is an admitted internal stuttering step
    with R(c', s) and no hidden protected effect or lost obligation.

For every claimed semantic physical completion:
  an appropriately sourced concrete occurrence establishes its
  exact permitted target/effect postcondition.

No concrete protected effect is omitted from the correspondence.
#+end_example

This is a *conditional proof obligation* whose discharge requires
evidence for each supported browser/HTMX profile and deployment. The relation
has to cover source-normalized event admission, current owner and
resource instance, physical commitment points, partial mutations,
runtime faults, recovery obligations, qualified progression, and
observations/authority context. A model containing only successful
send/swap histories cannot refine an implementation with failed
abort, duplicate settlement, OOB changes and stale callbacks.

A concrete step can correspond to zero semantic progress only
if its "internal" status has been justified. A DOM replacement,
unadmitted second request, cross-principal disclosure,
resource-generation change that revives old rights, or loss of
pending O2 debt cannot disappear into an unspecified stutter.
Conversely purely local observer bookkeeping, bounded trace
buffer maintenance or a harmless ignored stale event may
stutter when its noninterference contract really holds.

Safety refinement and liveness are separate. Infinitely many
internal steps can satisfy a naive safety stuttering relation
while preventing an enabled authoritative installation forever.
A stronger liveness conclusion requires an explicit divergence
condition and the fairness, provider, grant, recovery and
physical scheduling premises of 06.13.

The relation need not impose one artificial total order on
independent concurrent operations. A declared weak or commuting
correspondence may account for causally independent steps and
permitted internal actions. It must preserve the actual
happens-before edges, per-resource and per-command order,
server transaction constraints, physical target serialization
and every externally observable effect whose order matters.
Commutation cannot swap a settlement ahead of its issuing send,
a DOM completion before its current permit, or an old callback
past the revocation that makes it powerless.

*** Trace alignment preserves actual occurrence identities and provenance

A concrete trace matcher checks occurrences, not merely
similar maps or eventual output values. It establishes a
declared mapping from each relevant real occurrence to
its role-local/semantic counterpart and verifies that
neither side supplies invented send, delivery,
incorporation, completion or adoption events.

For a supported exact or weak correspondence, the matcher:

1. Binds the exact admitted choreography, projection,
   executable plan and application/assembly subject;
   checks the artifact relation rather than relying
   on a friendly source name or copied plan digest.
2. Binds the concrete trace to its actual executor/
   physical source, runtime/deployment instance and
   declared extraction point. A caller-supplied list
   of plausible observations is not evidence that
   those events happened.
3. Preserves relevant individual occurrence IDs
   and their issued effect, owner generation,
   command, transport attempt, target,
   observation and resource incarnation.
4. Requires every *protected concrete* action
   to be accounted for exactly under its
   permitted semantic or independently
   justified internal classification.
5. Never duplicates one physical send, receive,
   target mutation or completion to satisfy
   two unrelated obligations; never drops
   the inconvenient occurrence and calls
   the remaining sequence aligned.
6. Checks the declared causal and ordering
   relation, allowing only proven
   independent commuting steps.
7. Distinguishes absent physical evidence,
   a reported physical failure, an
   explicitly checked no-op and actual
   successful completion.
8. Carries source/provider trust premises
   forward; a structurally validated
   =:advances= or =:committed= carrier is not
   a self-authenticating authoritative witness.
9. Exposes ambiguous matches and their
   assumptions rather than guessing the
   desired witness from the final state.
10. Rejects traces whose extraction, version
    binding, loss reporting or coverage
    cannot support the requested property.

An effect request and its completion may share a semantic
effect identity but remain *different occurrences*. Multiple
compatible HTTP attempts H1/H2 can share C42 yet retain
distinct physical IDs and possible delivery outcomes.
A trusted command resolver may prove C42's historical
incorporation while the actual H1 receive still lacks
a transport witness. A successful DOM replacement can
be physically observed while an unrelated board
advisory remains outstanding.

The trace extractor is part of the assurance boundary.
It must be sufficiently independent of the semantic
claim it is checking that it cannot silently fabricate
the required fact. For a physical host claim, a reporter
that merely copies =:htmx/allow-swap= into
=:authoritative/installed= is not a witness to a
real swap. For source/backend claims, submitting a
model result as an opaque request's expected value
does not prove the actual transaction followed that
model. The emitted record must identify who/what
observed the actual execution and at which point.

Completeness is relative to the claimed footprint.
An instrumented real Chromium test can establish
one concrete tested lifecycle and admit the remaining
uncovered extension/browser paths as explicit
assumptions or unsupported. It cannot claim complete
physical correspondence if the instrumented hook
does not see mutations from permitted scripts,
OOB processing or another DOM writer.

A digest can bind evidence to exact bytes under its
canonicalization and collision premises; equality
of digests is not admission of the evidence itself.
A diagnostic/proof sidecar is read-only: runtime
operation/branch selection depends on the executable
semantic plan and current admitted inputs, not on
whether a favorable certificate happens to be
attached or can be forged.

*** Global communication and termination need independent witnesses

A browser role-local =:send= is normally hidden from
the distributed-observation alphabet until actual
communication requirements are established. A role
receiving an envelope can produce a *candidate*
distributed communication shape, but cannot prove
from its receive history alone that the expected
sender emitted the same event, that transport
delivery corresponds to that send, or that a
global admissible schedule exists.

The corresponding independent witnesses include:

| Candidate global claim | Required additional evidence |
|------------------------+------------------------------|
| Browser role-local receive corresponds to distributed communication | Sender emission, delivery/correlation and global schedule admissibility under the canonical choreography. |
| Browser role-local terminal outcome corresponds to global return | Global terminal outcome, all-role terminal compatibility and schedule admissibility. |
| Browser local authoritative observation means trusted model step occurred | Authenticated operation/transaction evidence with exact schema, actor, causal operation binding and backend/provider premises. |
| Browser adapter requested transport and therefore remote effect occurred | Actual physical send/delivery plus qualified receiver and operation evidence as appropriate to the claim. |
| Browser installed a view and therefore application reached agreement | Current scoped physical/adopted observation and independent other-participant coverage/adoption where agreement is claimed. |

Importing an already-advanced browser machine at
=:execution/start= cannot attest the steps that
occurred before import. Likewise machine history
erased on retirement cannot be reconstructed as
observed merely because a terminal effect was
emitted. The evidence pipeline records these
unwitnessed intervals and refuses to promote
candidate observations into certified global
facts.

A local execution becoming terminal is not the
global choreography reaching its specified
return outcome; an outer role-local success
envelope is not the trusted final model result.
To establish a global claim, the independent
role/sender/authority evidence is related
to the actual observed schedule with the
declared correspondence checker. This
avoids a self-confirming loop in which the
browser emits both the assertion and the
supposed proof of its truth.

The portable semantic implementation may
have independently checked canonical
choreography-to-projection correspondence
for a selected concrete witness, including
weak/commuting alignment. That evidence is
valuable but still witness-scoped until
a quantified refinement argument or
separately justified complete abstraction
has been established. Linking to the
actual browser host and backend execution
is an additional obligation, not
automatic from projection agreement.

*** Execution isolation is local except for declared shared effects

Execution-private state and effects belong
to their exact owner generation. E42's
timer, transport completion, provisional
rollback, local output and target lease
cannot advance E43 or mutate E43's
private physical target simply because
both executions reference the same Request
or historical command C42. An old
callback may remain physically present
after logical retirement, but it has
lost actuation rights.

The model also admits *intended shared
interactions* through their declared
semantic owners. A current fragment
coordinator may receive a scoped SSE
advisory, adopt an authorized
RequestAssignment observation, revoke
old provisional presentation or
apply a declared resource-pressure
policy while several local
executions are active. Those
operations affect multiple executions
in ways the semantic relation must
represent rather than exclude as
unmodeled interference.

| Interaction | Required isolation/correspondence treatment |
|-------------+---------------------------------------------|
| E42 private callback after E43 starts | Deny E42's progression and stale physical target rights; optional bounded diagnostic only. |
| Current B3 shared advisory during E42 work | Admit under B3's current subscription/interest and applied scope, independent of E42; preserve outstanding debt and selected Refresh policy. |
| Shared authoritative card supersedes E42 provisional display | Revoke only the applicable weaker presentation rights under a real qualified scope/progression policy; retain independent C42 resolver ownership. |
| E42 and E43 attempt to mutate the same DOM target | A current serialization/merge/supersession relation determines the winner; distinct execution IDs alone do not isolate the target. |
| An old owner and new owner share a timer ID or same CSS height value | Exact resource/owner incarnation controls release; old cleanup cannot cancel or restore new owner's physical state. |
| Current whole-board R result overlaps newer creator-local S | Preserve separately qualified card/cohort representation or reacquire the conflict; do not claim an invented single snapshot. |
| One coordinator retires while a shared SSE connection serves another | Detach only its exact interest and revoke its callbacks; preserve other valid owners and their continuity gaps. |
| Deployment/runtime fails and shared capacity is exhausted | Apply declared runtime-wide containment/backpressure and retained debt; do not pretend completely independent progress where shared resources failed. |

An isolation theorem therefore names
the protected state/physical footprint,
allowed cross-owner transitions and
the environmental noninterference
premises. It cannot mean "no
execution ever affects another"
when the application intentionally
coordinates shared authoritative
views. Nor can two execution
names make a common DOM target
or native browser side effect
thread-safe by declaration.

Where one effect interferes with
another, the assembly supplies
an admitted serialization,
supersession, transactional
physical primitive or
scope-aware merge. If a host
reenters during a protected
multi-target action, the
protocol names actual
intermediate states and partial
failure disposition. JavaScript's
event loop alone is not proof
that an arbitrary multi-target
HTML swap is physically atomic.

An actor/tenant change,
permission revocation or
incompatible deployment can
justifiably retire several owners
at once. Each affected resource,
advisory requirement and command
resolution obligation still
requires a current scoped
disposition. The server
independently authorizes reads,
subscriptions and writes against
a hostile client that may ignore
all browser isolation gates.

*** Diagnostics and witness extraction do not alter execution

Observing the execution must
not be a second executable
semantic interpreter.
For the same admitted plan,
event sequence and actual
physical input behavior,
attaching or removing a
read-only diagnostic observer
must not add, remove,
reorder or rewrite semantic
transitions, abstract effects,
command sends, owner state
or authorized completion.

A throwing, malformed, slow
or disabled observer follows
an explicit bounded
failure-isolation policy.
An ordinary in-process
callback without scheduling/
resource isolation can still
block or reenter execution;
calling it "optional" is not
proof of noninterference.
Instrumentation effects and
buffer capacity need a
real contract. A production
certificate cannot depend on
collecting complete traces
from a buffer that silently
drops relevant mutations
without loss markers.

The actual source boundary
and physical capture must
be audited for completeness
and trust assumptions.
The strongest runtime
conformance check may require
dedicated instrumentation
or an external observer
outside the semantic
decision path. The
application's semantic
branch never switches
because a proof report is
present, absent or favorable.

*** Paired refinement and isolation acceptance histories

Every positive test exercises
a real admitted transition,
source, physical effect or
concrete independent witness
as appropriate. Its
adversarial counterpart
reaches the relevant
correspondence boundary,
rather than trivially
rejecting an unrelated
malformed fixture.

| Eligible positive history | Adverse or incomplete history | Required conclusion |
|---------------------------+-------------------------------+---------------------|
| A real adapter step emits a specific ordered effect vector and the observer rederives it from the same state/event. | A caller substitutes a plausible successor, reorders effects or copies a matching-looking report from another step. | The actual step is observed; source-derived equality alone grants no global/physical certificate. |
| E42's role-local receive has matching independent sender, delivery and global-schedule witnesses. | The receiver reports the envelope but sender emission or delivery evidence is absent. | A candidate distributed event is admitted only when all named witnesses are supplied; no invented send. |
| Two roles finish under a globally admissible terminal schedule with an independent global outcome witness. | The browser role alone completes and the report claims the global choreography returned. | Preserve role-local completion versus global terminal correspondence. |
| H1's actual issue and host completion are observed with registered correlation, and trusted C42 evidence is separately acquired. | A requested send is copied as a physical delivery or HTTP 200 is copied as model incorporation. | Distinct source/transport/model evidence remains separately bound. |
| A permitted real HTMX card swap installs B2 and a qualified target-specific postcondition is observed. | A similar =afterSwap= or unexamined OOB mutation is matched to B2 while its actual owner/target differs. | No wrong-target matching or invented physical completion; keep partial repair debt. |
| A weak/commuting witness reorders only proved independent private steps while preserving required causal edges. | It swaps settlement before send, physical completion before permit, or drops a conflicting shared mutation as "stutter." | Trace alignment preserves causality, protected actions and admitted commutation rules. |
| A current B3 shared invalidation coexists with private E42/E43 work and affects only declared scopes. | E42's retired callback is relabeled shared, or a shared coordinator is omitted from the isolation model. | Permit legitimate shared effects without letting private callbacks launder authority. |
| E42 and E43 compete for one target; a qualified supersession policy revokes old rights and preserves newer installed content. | Distinct IDs are treated as proof of physical independence while an old queued effect mutates the successor. | Isolation requires actual target arbitration and last-actuation checks. |
| The same plan and inputs produce identical semantic/effect traces with and without a bounded read-only observer. | The observer changes a branch, throws into the semantic transition or hides a physical fault after buffer overflow. | Observer noninterference and honest trace loss are independently verified. |
| An artifact-bound concrete Choreo witness passes its real checker, and a separately sourced host/backend trace supplies the required physical premises. | The artifact witness alone is called universal browser refinement or the extractor fabricates the expected host actions. | State witness-local conclusion and independent physical/source proof obligations; no circular certification. |
