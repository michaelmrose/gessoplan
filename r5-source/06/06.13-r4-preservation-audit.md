## R4 obligations retained

- **Safety and liveness are not interchangeable.**
  A terminal path from each machine state does
  not prove termination; enabled communication,
  authoritative availability, timers, continued
  execution, actor action and suitable fairness
  are distinct premises.
- **Observer-relative authoritative truth survives
  runtime failures.** A trusted commit followed
  by lost notification remains incorporated.
  An H1 timeout with possible physical send does
  not prove nonincorporation or rejection.
  Browser display/cleanup failures do not alter
  the underlying domain transaction.
- **Unknown versus rejected versus unavailable.**
  A command result, protocol failure, malformed
  host callback, unsupported asset, blocked
  read and capacity exhaustion require distinct
  classification and admissible recovery.
  A recovered current card is not automatically
  historical command attribution.
- **Conditional agreement under quiescence.**
  Actor-local knowledge, provider basis and
  currently installed scopes may differ during
  concurrent writes. A declared covering
  reacquisition can converge without replaying
  every intermediate SSE packet.
- **Selective, nonautomatic adoption.**
  HumanHelp's remote advisory and explicit
  one-user-Refresh require an actual user
  grant, valid provider observation and
  physical adoption. A newer creator-local
  S card must not be regressed by an older
  R board snapshot.
- **Layered assurance.** Pure semantics,
  runtime checks, source/model correspondence,
  real browser/HTMX behavior, trusted XTDB
  operations and environment assumptions
  carry different guarantees.
- **Browser realization invariant.** The
  complete semantic adapter/physical shell
  continues to require owner-relative event
  admission, last-actuation checks, retired
  callback isolation, no false command
  settlement, scoped authority/adoption
  and explicitly conditional liveness.

R5's concise failure table, scoped safety
targets, fairness list and independent
resource budgets remain the preferred
structure. This review preserves omitted
R4 distinctions without resurrecting R4's
large illustrative helper code or
claiming all aspirational properties
already hold in Gesso.

## Improvements made in 06.13

1. Separated failure at pre-send, trusted
   operation, possible-send transport,
   post-commit notification, acquisition,
   installation, stale-plan, cleanup
   and runtime invariant boundaries.
2. Formulated owner-, scope-, resource-
   and command-indexed safety families,
   explicitly qualifying physical
   mutation/response effects and
   provider-proved progression/absence.
3. Distinguished genuine command-result
   liveness from eventual arrival at
   truthful blocked/manual/unknown
   recovery; no fake committed/rejected
   conclusion after retention expiry.
4. Required a named fair scheduler and
   enabled transition, availability,
   grant and user-action premises
   rather than treating a reachable
   terminal as a liveness theorem.
5. Expressed quiescence convergence as
   actual acquisition plus physical
   scoped adoption; not uniform global
   snapshot equality or mandatory
   replay of all historical events.
6. Preserved the one-Refresh budget
   and independent O1/O2 obligation
   discharge, with source-qualified
   subscription-gap recovery.
7. Made logical cycles, queued slots,
   incomparable advisory debt,
   dedup/history, physical remnants,
   retained targets, diagnostics
   and retry/resolver work separately
   budgeted with explicit overflow.
8. Distinguished finite model checks,
   actual adapter-step observations,
   source/executor-bound execution
   evidence, Chromium host traces
   and trusted model/deployment
   certification. An optional
   proof artifact cannot control
   production branches.
9. Added ten eligible/adversarial
   acceptance histories requiring
   real positive HumanHelp operation,
   read, browser and recovery paths.

## Inspected Gesso v1622 source; tests not run

The provided Gesso application-assurance
source archive is at commit
1b5e10e71c00e7784b019dee7dc1198a96fd03f6.

- src/gesso/live/browser/adapter.cljc
  declares an invariant-errors/require-state!
  runtime checker over structural and
  resource invariants. The source
  explicitly describes these as
  runtime checker invariants rather
  than proof of every browser property.
  The adapter uses stale-generation
  rejection and conservative opaque
  queued requirements; an idle
  invalidation starts an automatic
  fragment refresh in the inspected
  implementation, which does not
  establish the HumanHelp one-user-
  Refresh policy.
- The same adapter's finish-fragment-request
  composes failed active requirements
  with *already queued* successor work
  but does not automatically issue a
  retry with no queued successor. Its
  inspected local fragment shape does
  not itself provide a durable independent
  debt ledger for every failed
  adoption-stage obligation. The
  finished plan retains that stronger
  requirement.
- src/gesso/live/browser/shell.cljs
  commits the next semantic state
  before interpreting effects and
  performs best-effort shutdown/
  resource cleanup. The R5.1 06.10
  audit separately records timer
  registration/late-handle and
  same-value CSS owner questions.
  Those are not proven resolved
  by abstract adapter invariants.
- src/gesso/live/browser/refinement.cljc
  conservatively labels mappings
  candidate-only and identifies
  required sender, delivery and
  global terminal witnesses.
  It explicitly disclaims a
  global Choreo trace certificate,
  physical transport/XTDB evidence
  and browser host refinement.
- src/gesso/live/application_preflight.clj
  exposes an opt-in finite Recife/TLC
  diagnostic for exact executor-bound
  observations, with required
  assumptions and nonclaims.
  It records bounded finite-reference
  checks rather than a generic
  inductive theorem, actual XTDB
  refinement, server-browser
  composition or whole-application
  certificate. The ordinary preflight
  path does not run that checker.
- Source-inspected tests in
  test/gesso/live/browser/adapter_test.cljc
  include failed-bound-request-without-queued-work-does-not-manufacture-retry-test,
  failed-bound-request-preserves-unsatisfied-active-and-queued-canonical-requirements-test,
  optimistic-network-failure-does-not-fabricate-trusted-settlement-test,
  stale-optimistic-timeout-is-powerless-test
  and initial-state-satisfies-declared-invariants-test.
  Actual HTMX/Chromium cases appear in
  test/gesso/live/browser/chromium_integration.clj,
  including failed-bound-canonical-refresh-preserves-active-and-queued-authority-test
  and continuity-restore-failure-is-local-and-later-refresh-recovers-test.
  Tests were located and inspected,
  not executed for this documentation change.

These are useful implementation precedents.
They do not certify all physical resource
budgets, durable C42 recovery, sound
requirement compaction, real RequestAssignment
eligibility, actual authority-provider
convergence or a universal browser
safety/liveness theorem. The charter
requires the finished-system document
to retain those guarantees as explicitly
scoped obligations rather than weaken
them to what v1622 already implements.
