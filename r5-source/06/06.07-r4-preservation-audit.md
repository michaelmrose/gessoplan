## R4 requirements preserved

- **Two real obligations through one read:** R4's Bob/Alice
  example requires O1 to be discharged while O2 remains
  when A1's actual qualified observation covers only O1;
  a later sufficiently covering result may discharge both
  without a second read. This review retains the exact
  positive/adversarial distinction and requires the same
  qualified physical installation for adoption-stage debt.
- **Source/progression is not fixture mutation:** R4's
  X18/X21 examples were illustrations, not an assertion
  that changing a token or comparing opaque positions
  numerically proves provider progression or a new
  authorized acquisition.
- **Acquisition is not installation:** a qualified read
  may clear acquisition-stage obligations but cannot
  establish adoption-stage discharge without an actual
  current permitted target postcondition. Partial or
  indeterminate installation retains appropriate debt.
- **A grant is not an endless retry permit:** R4 already
  distinguishes advisory debt from user permission to
  refresh. The 06.06-reviewed exact grant policy is joined
  to O1/O2 and requires a counted physical read, no
  hidden A2, and explicit handling of failure/retry.
- **Stale physical requests cannot adopt:** after A1
  retires, a late physical A1 response does not acquire
  A2's installation rights, even if its apparent provider
  position is stronger.
- **Scoped coexistence:** newer creator-local card S
  survives an older board R adoption under qualified
  provider/representation relations; there is no
  fabricated common backend snapshot.
- **Actual browser and model authority:** qualifying
  request, owner, principal and RequestAssignment
  read permission come from admitted sources and trusted
  model/transport boundaries, not manually edited
  :installed? or basis fields.

R5 introduced the clearer applied-query/local-draft
split and the explicit baseline/subscription continuity
gap. These remain normative and were strengthened rather
than replaced with R4's longer helper pseudocode. The
new section keeps the existing four subsection boundaries
and adds one focused acceptance-history subsection.

## Focused improvements

1. Made G1's one-read budget and captured O1 distinct
   from a concurrent O2, actual returned Q coverage,
   acquired/installed evidence, and successor permission.
   A complete case table considers valid, incomparable,
   partial, failed, stale and independently satisfied outcomes.
2. Applied query Q is defined by authorized cohort,
   principal/Organization, relevant server-side filters
   and temporal/projection semantics; local live search
   and continuity drafts do not retroactively change it.
   Query/authority change requires owner retirement,
   qualified transfer or reacquisition.
3. Strengthened the initial page baseline-to-interest
   race with explicit fence/replay/buffered-subscribe/
   current-read alternatives. Receiving no SSE events
   is never itself evidence of no missed writes.
4. Distinguished events generated then lost (where
   idempotent router redelivery may help) from events
   never generated because the relevant interest had
   not yet been registered or propagated. Redelivery
   alone cannot cover the latter gap.
5. Qualified SSE IDs, XTDB basis values, request
   generations and router epochs as distinct
   provenance and ordering subjects.
6. Separated current-state convergence by a qualified
   reacquisition from durable processing of *every*
   intermediate event, which needs its own contract.
7. Reconnected suspension/reconnect, node/router
   failure, root replacement and shared-interest
   ownership to exact source/target and permit rights.
8. Reconciled user-granted one-Refresh policy with
   mandatory subscription-gap repair: where a read
   is needed for a stronger guarantee, it must have
   its own declared permission or the guarantee is
   weakened/rejected; no hidden consumption of G1.
9. Added nine paired positive/adversarial histories
   covering the named physical and provider boundaries.

## Gesso v1622 implementation source inspected

The supplied Gesso application-assurance archive is
at 1b5e10e71c00e7784b019dee7dc1198a96fd03f6.

- src/gesso/live/browser/core.cljs implements
  managed SSE normalization through HTMX listener
  correlation, decodes canonical progression wire
  values with source consistency checks, and
  dispatches :live/invalidated events. It treats
  :online, persisted :pageshow and foreground
  :visibilitychange as advisory recovery boundaries.
  Its on-sse-open! sends an advisory invalidation
  for a managed fragment. This is a wakeup, not
  source proof that every missing change is covered.
- src/gesso/live/browser/adapter.cljc maintains
  :inflight, :queued-refresh?, request generation,
  physical request ID and :queued-requirements.
  It currently issues :fragment/refresh when an
  invalidation arrives at an idle fragment and
  checks stale request generations before swap/
  completion. This is an automatic-refresh profile,
  not a demonstrated implementation of HumanHelp's
  remote advisory-only one-Refresh grant.
- The same adapter's finish-fragment-request
  path carries opaque failed attempt requirements
  into an already queued successor; when no queued
  refresh is warranted, it does not independently
  preserve the failed attempt's full debt in a
  separate persistent obligations ledger in that
  local state shape. This is a potential
  implementation-correspondence gap for the
  stronger finished contract, not proof that all
  production paths have lost information.
- src/gesso/live/core.clj and
  src/gesso/live/htmx.clj expose progression-aware
  fragment querying/rendering and managed
  fragment refresh trigger construction. A
  decoded browser progression carrier does not
  itself establish trusted authority.
- Source-inspected tests include
  first-invalidation-starts-one-fragment-refresh-test,
  invalidations-during-one-request-coalesce-without-starting-another-request-test,
  explicit-dom-invalidation-without-requirement-remains-advisory-test,
  managed-sse-progression-copies-must-both-be-present-and-agree-test,
  mismatched-managed-sse-listener-fails-closed-before-refresh-test,
  sse-open-refreshes-managed-root-and-ignores-legacy-root-test,
  and queued-refresh-started-during-after-request-is-not-erased-by-old-cleanup-test.
  These names and cases were inspected in source.
  Tests were not executed for this editorial revision.

The implementation has real SSE source normalization,
generation-aware request coalescing and recovery
wakeup infrastructure. These observations do not
establish atomic baseline/interest installation,
durable replay, router failover coverage, every
XTDB provider satisfaction premise, physical DOM
adoption, trusted HumanHelp read authorization,
or full one-Refresh product behavior. The target
design may require those guarantees subject to
named trust and liveness premises.
