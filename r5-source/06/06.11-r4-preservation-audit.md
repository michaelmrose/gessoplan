## R4 preservation and intentional supersession

- Every state-changing callback uses a common conceptual
  owner-relative source/identity/legal-state gate.
  An obsolete execution callback cannot choose a
  different class and be retried as shared.
- E42-private, B3/S9-shared and K8-command-resolution
  owners are distinct. Shared invalidations need no
  invented execution ID; trusted late command evidence
  cannot revive a retired execution.
- R4's key early-message rule is retained: physical
  delivery M1 can be consumed upon observation even
  if the projected machine is not ready to receive,
  preventing the identical M1 from being replayed
  later as newly legal.
- Stale, unknown, malformed, duplicate, incompatible,
  illegal state, unestablished source evidence and
  uncertain host effects remain distinct diagnoses,
  not substitutions for domain command results.
- Terminal settlement/supersession invalidates
  competing presentation timeout rights before
  slow rendering, while separately owned command
  recovery can continue.
- Model/test orderings must cover source generations,
  callback identities, duplicate and conflicting
  evidence rather than assuming lucky JS timing.

R4's lengthy illustrative helper functions and old
single-field Claim fixture are not restored as a
parallel executable admission interpreter. The
finished contract uses R5's portable adapter and
one physical shell and HumanHelp's real
RequestAssignment authority.

## Focused improvements

1. Specified real event source registrations, allowed
   event kinds, host lifecycle, exact owner/resource
   incarnations and scope. Payload class labels
   cannot manufacture their own trust or provenance.
2. Separated source admission from evidence provenance:
   parsing SSE wire fields or matching listener
   roots is not a universal trusted XTDB or
   command-result witness.
3. Distinguished source/owner/effect correlation,
   machine legality, consumption/duplication policy,
   current authority and subsequent last-actuation
   permission as separate checks.
4. Retained the R4 early physical message consumption
   case and qualified class-specific consumption,
   without globally deduplicating on C42.
5. Specified H1/H2 and E42/E43 differences alongside
   B3/S9 shared and K8 resolver owners; stale
   private-to-shared redispatch remains forbidden.
6. Required duplicate payload equivalence/conflict
   diagnostics, bounded tombstone compaction and
   safe resource incarnation separation.
7. Joined physical HTMX/OOB effect admission,
   callback reentrancy, SSE debt and one-Refresh
   grant accounting without claiming a single
   afterSwap callback certifies every physical path.
8. Preserved primary failures versus secondary
   cleanup errors, timer right retirement and
   bounded liveness premises.
9. Added ten independent positive/adverse
   acceptance histories including early replay,
   conflicting settlement, stale subscriptions,
   different transport attempts and authority
   changes.

## Gesso v1622 implementation observations (source only)

The user-provided Gesso application-assurance
snapshot at commit
1b5e10e71c00e7784b019dee7dc1198a96fd03f6
was inspected at its actual browser source/test
boundaries.

- src/gesso/live/browser/adapter.cljc defines a
  closed normalized-event-types set and exact
  event-allowed-keys. The portable adapter/step
  returns [next-state effects] and checks its
  invariants. Expected stale callbacks normally
  produce :diagnostic/ignored; malformed current
  events may fail closed.
- current-execution-or-ignore distinguishes
  missing/retired execution from a mismatched
  generation. Local/transport pending-effect
  generations prevent old completion from
  advancing a newer issued operation.
- deliver-message consumes a physical
  :message-id before machine/accepts? tests the
  projected receive boundary. An early
  unaccepted M1 therefore cannot be replayed
  later when the machine becomes receptive.
- Optimistic settlement permits the same
  repeated observation idempotently but raises
  :conflicting-optimistic-settlement for an
  incompatible repeated value. Timeout and
  authoritative-supersession paths retain
  distinct semantic ownership.
- src/gesso/live/browser/core.cljs correlates
  managed HTMX requests with active request
  IDs and generations, checks managed SSE
  listener/root correspondence, and requires
  copied SSE progression fields to agree.
  It treats online/pageshow/visibility and
  SSE-open as advisory repair opportunities.
  None of those source checks alone certifies
  authenticated provider read/settlement
  or every OOB/extension effect.
- src/gesso/live/browser/shell.cljs commits
  semantic state before effect interpretation.
  Exact physical handle/lifetime and reentrancy
  still carry the 06.10 correspondence
  obligations.
- Inspected test sources include
  consumed-physical-message-id-cannot-satisfy-later-identical-receive-test,
  rejected-early-physical-message-id-is-consumed-and-cannot-be-replayed-later-test,
  optimistic-settlement-cancels-timeout-and-is-idempotent-only-for-identical-observation-test,
  stale-transport-success-cannot-complete-a-retried-send-test,
  and tests of managed SSE progression consistency.
  Tests were inspected, not executed.

This is partial implementation precedent, not
proof of complete source/host provenance,
cross-tab data security, trusted XTDB
evidence, all served browser/HTMX paths,
physical target completion, installed assets
or nonvacuous HumanHelp product acceptance.
