## Governing decision: inventory is not confinement

Retain the preferred R5 architecture. Its authorial contribution is that a physically complete application invariant cannot be inferred from a semantically complete operation catalog or a matching collection of HTTP routes. Make the requirement falsifiable by distinguishing three independent claims: original abstract source coverage, source/host-observed actual entrypoint correspondence, and *enforced* closure over the physical writer universe that can invalidate the property.

A closed-world claim needs a justified deployed universe and a genuinely constraining backend/credential/process boundary, or transparent explicit assumptions about every unresolved path. Host-owned declarations, original source, copied report maps, route names, exact identity sets and bounded observations remain valuable but cannot, singly or jointly, prove no hidden writer exists.

The future finished framework is expected to offer strong forms of this assurance where the deployed environment can enforce them. The present source experiments' deliberately scoped diagnostics are not a reason to weaken the timeless target.

## Preservation and strengthened decisions

1. **Original semantics retain sole authority.** A formal operation catalog covers what it actually declares. A different raw XTDB path can invalidate a physical whole-application theorem without making a correct abstract induction itself false.

2. **R5's explicit extra-entrypoint inventory survives.** The protected universe includes ordinary routes, background jobs, scheduled processes, queues, imports, initializers, migrations, maintenance/admin tools, parallel processes and external services with write-capable credentials; none is silently ignored because it is not an HTTP handler.

3. **Non-HTTP operations are not fake routes.** A scheduled service has a source/operation or operational contract and real installed execution identity without inventing a Ring path. Entry-point identity and semantic operation identity are related but distinct.

4. **Three closure obligations are independently checked.** Original-source obligation completeness; observed entrypoint-to-issued writer/effect correspondence; and actual enforcing physical writer closure each require their own evidence. A clean result at one does not imply the others.

5. **Claims are protected-domain-relative.** The universe records actual documents/tables, relationships, tenant, assignment absence/uniqueness, revision histories, command ledger and other state that can invalidate the specific theorem. It is not automatically “the entire database.”

6. **Guard and physical mutation footprints both matter.** A writer that updates RequestAssignment while the checker inventories only Request status may violate one-primary; a whole-document PUT has a broader physical footprint than a declared narrow field delta.

7. **Host enumeration is a live observed snapshot.** An enumerator must inspect the host's actual known registrations instead of reproducing a hand-authored approved list. Even freshly invoked enumerators cannot establish they discovered every hidden/raw/external physical writer.

8. **No enumeration is unknown, not empty.** Missing, inaccessible or partial writer inventory cannot be transformed into zero writers or zero policy escapes. Summary counts state the actual inspected sources and generations.

9. **Declared capabilities are descriptions.** A host-provided target scope, mutation form or restriction flag is not independent evidence that a physical client cannot execute other operations. Provider-enforced grants or an actual capability restriction must warrant a stronger exclusion.

10. **Actual privileges define possible paths.** The root model accounts for principals and processes with write-capable XTDB credentials, pools, clients and service identities even when no named Gesso operation is invoked.

11. **Operational exceptions are explicit proof subjects.** Admin and break-glass paths name their actor, protected scope, permitted transition, audit and invalidation/requalification. “An admin may write anything” cannot coexist with an unqualified all-writers-preserve-I theorem.

12. **Initializers and migrations affect induction.** A startup or migration outside original transitions may require proof it refines an admitted operation or a new valid initial-state boundary and fresh dependent certificate applicability before stronger claims resume.

13. **The physical enforcement boundary is current.** Startup registry validation, source/handler identity and one observed request do not guarantee a later swapped callback or different deployed server still enforces the constraint.

14. **Cross-process/multi-node does not change the application semantic contract.** It increases host, credential, external writer, durable command and installation scopes. Losing an in-process registry on node failure cannot erase an already submitted transaction.

15. **One-shot submission is not universal writer mediation.** A narrowly checked gateway may prevent a second submission through its own process-local capability while unrelated raw clients still possess physical mutation rights.

16. **All-writer monotonic revisions depend on deployment discipline.** A source-rechecked revision successor does not prove every other worker, migration or node increments it; direct untracked writers invalidate the stronger history/ABA conclusion.

17. **Absence and uniqueness are protected physical predicates.** The writer closure must include every path that can create, activate, reassign or revive a primary assignment, not only writers that update the Request document.

18. **Correct command history is physical and durable.** Transactional C42 incorporation, H1/H2 attempts, outbox publication intent and protected replay rules cannot be proved solely by successful route-to-writer identity joins.

19. **Positive product capability remains independent.** A source-complete reduced application, rejected every-Claim writer or disabled Reassign can be safe in a narrow model but fails full HumanHelp positive product requirements.

20. **After-effect observations have limited authority.** A post-dispatch mismatch can diagnose a path or unexpected mutation but cannot prevent a write that already occurred. A report about one controlled request does not prove all possible route invocations.

21. **Change/release identity matters.** New backend credentials, installed services, route generations, worker schedules, migrations and external provider configurations re-open dependent physical correspondence unless qualified by the selected source/deployment lifecycle.

22. **Failure and non-observation are classified honestly.** Unknown direct writers, inspection timeout, missing credential audit, incomplete runtime capture and uninspectable external service remain open, not successful proof. Conditional, test-only and full-enforcement claims use different qualifiers.

## Paired positive/adversarial conformance obligations

1. **Source coverage:** Independently derived complete original operation/initializer list passes; a pruned Unclaim catalog or caller-supplied smaller induction source fails full source coverage.
2. **HTTP entrypoint:** Real admitted Claim route corresponds to its issued handler/writer; a mismatched or stale handler name cannot inherit correspondence.
3. **Scheduled job:** A legitimate non-HTTP scheduled operation with its own original semantic/operational contract is classified; requiring a fake HTTP route is an incorrect rejection.
4. **Initializer:** An actual startup initializer establishes admitted initial state; an unmodeled initializer writing protected RequestAssignment must reopen the corresponding guarantee.
5. **Migration:** A controlled migration preserves or reestablishes the invariant under checked transition/initial-state evidence; an unapproved revision reset cannot inherit prior certification.
6. **Admin exception:** An authorized, narrowly scoped maintenance writer has an explicit transition and audit; a general unrestricted maintenance client cannot silently count as the safe operation catalog.
7. **External credential:** Actual provider grants exclude a write-only-excepted path where claimed; a host-declared `:read-only` field attached to a write-capable credential does not.
8. **Raw bypass:** Physical confinement prevents a direct raw XTDB write to protected domain; a hidden direct client invalidates an unqualified all-writer coverage claim.
9. **Table scope:** A table-wide write capability is classified as covering all relevant documents; inventing coverage only over enumerated IDs is a false strengthening.
10. **Whole-document footprint:** PUT is treated as all-field replacement; a changed-fields-only summary cannot certify physical frame safety.
11. **Unknown inventory:** Missing enumerator data results in incomplete/unknown; an empty result cannot automatically mean zero relevant deployed writers.
12. **Runtime replacement:** Handler/worker swaps invalidate affected physical generation; an old matching registration report does not prove the new handler was constrained.
13. **Local mediation:** One owned request through final checked Biff handler can be diagnosed at its observed scope; an earlier/direct handler does not inherit that proof.
14. **Parallel requests:** Fresh valid independently scoped writers can execute through compatible current mediation; a single process-global lease is not a necessary semantic operation requirement.
15. **Deferred async:** A worker with its proper service principal and bounded current lease can write; an expired HTTP request-local callback cannot borrow stale authority.
16. **Revision discipline:** All relevant writers actually increment and guard the relevant revision, permitting a history-sensitive claim; an external write without bump defeats that guarantee.
17. **Primary uniqueness:** Real Claim/Unclaim/Reassign and any external writer preserve one active primary; a hidden row-level insert or activation cannot escape the protected predicate.
18. **Command/delivery:** Domain and command record use the specified commit contract while outbox notice can replay safely; a duplicate invalidation cannot create a duplicate Claim or unauthorized remote Refresh.
19. **Independent physical oracle:** Observed forbidden writes are stopped before effect where claimed; postdispatch failure detection is not reported as prevention.
20. **Product nonvacuity:** Eligible Claim, creator-local Create and the independently required lifecycle actions remain operational; reject-all or silently omitted model functionality cannot pass the whole-application product claim.

Each case requires a predeclared original subject, selected profile,
protected state, deployment and writer/credential scope, positive control,
adversarial mutation, first source/host/backend enforcing boundary and
independent physical effect observation when prevention is claimed.
Assertions about an uninspected external process, a different installed
server or a changed provider generation must remain outside the tested
claim's scope.
