## Preservation judgment

Keep R5's strong separation of ephemeral semantic participant receipt from durable authoritative invalidation, while recovering the R4 typing contract as readable schematic Clojure data. Restore the explicit sender/recipient authentication, Document permission, expiry, receipt, retirement, and transport non-equivalence from R4. R4's durable Request half is already preserved across 10.16–10.18; this section covers the ephemeral contrast and distributed acceptance joins.

1. **Direct participant receipt:** Direct participant receipt has different meaning from durable Request invalidation and authoritative reread.
2. **R4's typing contract:** R4's typing contract retains best-effort, ephemeral, duplicates permitted and late-message discard.
3. **R4 sender and:** R4 sender and recipient identities derive from trusted current authentication/collaboration membership.
4. **Browser intent identifiers:** Browser intent identifiers and message content never authenticate the sender or grant read authority.
5. **Choreo global communicate:** Choreo global communicate and role-local send/receive are distinct from physical broker and browser events.
6. **Actual endpoint correspondence:** Actual endpoint correspondence relates projected roles to real host-admitted send/receive effects.
7. **Message ID, execution,:** Message ID, execution, send occurrence, transport attempt, broker ack, recipient receipt and UI effect differ.
8. **Duplicate same-identity delivery:** Duplicate same-identity delivery does not invent additional semantic knowledge or authority.
9. **Distinct messages with:** Distinct messages with equal body are not automatically duplicates of one delivery.
10. **Recipient admission checks:** Recipient admission checks current session, membership, plan compatibility, target scope and resource ownership.
11. **Sender revocation before:** Sender revocation before trusted send and recipient revocation before disclosure retain separately scoped policy.
12. **Late messages cannot:** Late messages cannot restore retired physical browser resources.
13. **Tenant privacy covers:** Tenant privacy covers routing topics, Document presence, recipient selection and typing status.
14. **Clock-based expiry requires:** Clock-based expiry requires offset/skew assumptions; receiver-local expiry has narrower meaning.
15. **Malformed, oversized or:** Malformed, oversized or incompatible envelopes are rejected without alternate authority.
16. **Best-effort loss permits:** Best-effort loss permits missing participant receipt, rather than inventing an authoritative state reread.
17. **Stronger guaranteed delivery:** Stronger guaranteed delivery needs explicit durable storage, acknowledgments, deduplication and replay/retirement.
18. **Broker acceptance and:** Broker acceptance and participant semantic receipt are distinct even if transport is shared with Gesso Live.
19. **Durable business Claim:** Durable business Claim and ephemeral typing are independent semantic contracts.
20. **Application authors remain:** Application authors remain on ordinary Gesso/Clojure declarations; no parallel formal spec.
21. **Source-to-physical proof identifies:** Source-to-physical proof identifies every actual sender, transport, recipient and current resource boundary.
22. **In-memory projected realization/testing:** In-memory projected realization/testing is narrower than cross-host authentication and physical delivery.
23. **Real two-process acceptance:** Real two-process acceptance includes required positive controls and observed fault injection.
24. **Original-source operation/writer/host/participant coverage:** Original-source operation/writer/host/participant coverage is not proven by successful local callbacks.
25. **Cross-host command retries,:** Cross-host command retries, outbox publication, registration gaps and progression remain separate guarantees.

27. **HumanHelp remote lifecycle:** HumanHelp remote lifecycle adoption remains subject to explicit Refresh and local-result exceptions.
28. **Safety during partition/revocation:** Safety during partition/revocation is separate from fairness-dependent liveness and user-enabled adoption.
29. **Suspended choreography stacks:** Suspended choreography stacks remain optional rather than necessary for durable business rendezvous.
30. **Gesso v1622 implements:** Gesso v1622 implements substantial portable Choreo checks, but not a verified deployed cross-node direct router.

## Gesso v1622 source correspondence and limits

- `src/gesso/choreo/knowledge.cljc` records communicated, authoritative, input and asserted knowledge provenance, explicitly without authenticating physical sender or granting authorization.
- `src/gesso/choreo/project.cljc` projects global `:communicate` into role-local `:send` and `:receive` contracts; those contracts are not actual cross-node delivery receipts.
- `src/gesso/choreo/realization.cljc` executes independently projected roles against a **deterministic in-memory queue**, supporting explicit drop/reorder but no browser, network, XTDB, transport or authentication.
- `src/gesso/choreo/verify.cljc` checks value/knowledge availability and declared authoritative provenance in the supported semantic subset; it does not establish actual provider freshness or external message authenticity.
- `src/gesso/live/browser/adapter.cljc` owns portable execution generations and participant-message deduplication/stale-generation behavior, but it does not perform real authenticated cross-host delivery.
- `src/gesso/live/browser/shell.cljs` executes physical effects and reports normalized completion while retaining generation/resource bounds; it is not a distributed router or producer authenticity attestation.
- `src/gesso/live/source.clj` is process-local indexed invalidation, semantically distinct from participant messaging and not a retained distributed message store.
- `src/gesso/live/transport/sse.clj` sends SSE response frames; sending an event is not evidence that a recipient's Choreo machine consumed it.
- `src/gesso/live/optimistic/server.clj` handles trusted optimistic command boundary operations, but delegates model business authorization, actual Live publication and HTTP response emission.
- `src/gesso/live/optimistic/protocol.cljc` validates command/execution/settlement shapes while explicitly declining to authenticate principals, provenance or authority.

The source demonstrates real implementation work but does not establish an installed physically distributed participant-message router, complete recipient current-access assurance, actual broker acknowledgment/receipt provenance, cross-node liveness, all-writer closure, or production HumanHelp adoption. Those remain scoped prerequisites for claimed runtime verification.

## Eighteen paired distributed acceptance controls

| # | Positive physical/semantic boundary | Negative or adversarial case |
|---|--------------------------------------|------------------------------|
| 1 | Valid typing sender/recipient admission | Forged identity or Document access cannot install |
| 2 | Projected send/receive matches one execution | Other execution's same event label cannot satisfy |
| 3 | Current recipient owns typing target | Retired browser resource cannot be mutated |
| 4 | One message delivery ID yields one semantic receipt | Duplicate transport packet is not new knowledge |
| 5 | Current collaboration membership permits receipt | Revoked membership cannot be bypassed by queued broker data |
| 6 | Expired message is safely discarded | Spoofed clock is not authenticated freshness |
| 7 | Best-effort loss is truthfully permitted | Enqueue acknowledgment is not recipient receipt |
| 8 | Guaranteed-message variant replays within declared horizon | Expired replay cannot claim unconditional delivery |
| 9 | Current authoritative Request acquired from shared DB | Typing message cannot act as Request commit |
| 10 | Command resolves after host replacement | Duplicate HTTP retry cannot create another Claim |
| 11 | Outbox intent survives publisher death | Lost callback does not erase committed notification |
| 12 | Subscriber fence closes read/register gap | Stale router cannot silently certify no missed change |
| 13 | Remote lifecycle change waits for user Refresh | Advisory or typing event cannot auto-adopt board |
| 14 | Qualified C read satisfies real progression | Echoed token or lagging read cannot clear debt |
| 15 | Mixed deployment versions validate compatibility | Old unqualified asset/wire cannot inherit authority |
| 16 | Concurrent requests retain independent trusted bindings | Request-local writer or recipient permit cannot leak |
| 17 | Actual process death is survived within premises | Two names for one process cannot count as physical failover |
| 18 | Liveness holds under named availability and explicit Refresh | Partition or no user action cannot be promised convergence |

These are future positive/negative test requirements. A correct abstract transition or in-memory queue success is not a substitute for the actual installed source, authentic host, recipient, transport and browser observations.
