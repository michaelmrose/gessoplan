## Architectural decision

Keep R5's compact canonical Claim structure and its original
three tables. Expand from an abstract/production mapping *description*
to a testable connected vertical slice with distinct sources, original
model relationships, authenticated ingress, physical command/assignment
incorporation, historical outcome, participant progression and real DOM
adoption. The section is a finished-framework assurance target, not
a declaration that Gesso v1622 already establishes all these edges.

The exact same public HumanHelp Request, RequestAssignment, User,
Membership, Organization and Location interfaces used by the
production application must supply the claim's substantive meaning.
Source-relative proof fragments may project a different representation,
but no parallel fake Request model, convenient helper-id persistence,
invented lifecycle state or manually fabricated browser command
stands in for the original model and installed product. A matching
source label does not prove real host adoption or physical causality.

## R4/R5 preservation and stronger decisions

1. **One source/one Claim meaning.** Keep the R4 rule that verified F and executed G must be connected by checked or explicit conditional correspondence, not accepted because both are called Claim. R5 already makes this stronger by choosing the real public model as semantic owner.
2. **Real primary assignment representation.** Active primary ownership lives in RequestAssignment and its actual public relationships. A synthesized helper display projection is permitted only with qualified source mapping and coverage; never invent a persisted `:request/helper-id=` authority field.
3. **Original invariant quantifier.** One-primary means *at most one* active primary per Request under the real model's active/terminal semantics; an open/unclaimed Request may have none. A proof of only new self-Claim does not cover all Reassign, Unclaim, lifecycle, background or migration writers.
4. **Actor, target helper and domain IDs.** Self-Claim equates actor and selected helper only as an admitted local rule. Manager Reassign or assign-for-another operations need distinct actor authority and target helper Membership/eligibility; takeover must not be silently identified with either.
5. **The browser only proposes.** It may send Request and stable command ID, canonical arguments and observed basis; the authenticated principal, current effective Membership, Organization/Location policy, tenant and actual Request state arise from trusted ingress and public model.
6. **Command versus transport identities.** The stable C42 binding is distinct from H1/H2 attempts, HTTP request ID, XTDB transaction receipt, current Request/card, execution/resource identity and proof fingerprint. Every corresponding claim names the identity it actually uses.
7. **Existing command precedes new eligibility.** Compatible C42 history must resolve under current disclosure/retention before fresh-new-Claim eligibility. A previously successful Claim cannot become a “new command rejected because now claimed” merely due to a lost response.
8. **Incompatible reuse is not a lookup capability.** C42 reused with different actor, Request, operation or arguments is a mismatch, and forbidden disclosure does not leak whether another actor has a command record.
9. **Unknown and missing record are not noncommit.** One pinned external read with no matching command row does not necessarily show that H1 will never commit; retention expiration may leave honest indeterminacy.
10. **Atomic multi-record guard.** Current Request openness, helper/actor eligibility, real Membership/Organization/Location associations, active-primary absence/uniqueness and command exclusion require a qualified common commit/conflict mechanism. A pre-read is not an authenticated transaction-internal prestate.
11. **Physical frame includes more than Request status.** RequestAssignment history/activation, command-result storage, required outbox intent and the actual mutation forms must correspond to the abstract guard/frame. A single-document verified gateway cannot automatically establish complete Claim semantics.
12. **Two-helper race is distinct-command contention.** Alice/C42 and Bob/C43 must genuinely contend at the real protected backend so only one new primary wins. A sequential model replay, two UI clicks with no actual commit conflict or reject-all Claim is insufficient.
13. **All four backend dispositions survive.** =:committed=, =:rejected=, =:already-incorporated= and =:commit-unknown= retain source-specific meanings, not generic HTTP statuses or local evidence labels.
14. **Historical recorded rejection replays as rejection.** =:already-incorporated= means the permitted stored disposition, not automatically successful Claim; it may re-present a recorded rejection.
15. **Three presentation statuses remain independent.** =:accepted=, =:rejected= and =:unknown= are participant views; matching HTTP success or received SSE notice is not an XTDB incorporation receipt.
16. **C42 history and current Request differ.** A later legitimate Unclaim/Reassign can change current assignment while leaving the original C42 truth. Command-specific protected reconciliation is independent of card reacquisition.
17. **Physical browser effects require real observation.** The issued browser plan and actual loaded JS/HTMX, real click-originated command envelope, installed route, DOM resource ownership, target-specific completion and permitted acquisition each have separate evidence owners.
18. **Post-write rendering failure is not domain rejection.** Broken HTML, missing OOB target, transport loss, deferred stale callback or absent SSE advisory cannot undo a transaction. They require honest unsettled/partial presentation and safe scoped recovery.
19. **Creator-local Create differs from remote advisory.** The creator can adopt permitted new S locally; other participants receive advisory R until their one user-authorized Refresh. No general remote collection pull is issued by SSE or reconnect.
20. **Installed physical writer universe matters.** A raw/admin/background/migration writer can violate one-primary despite correct abstract induction. Original source completeness, observed paths and actual confinement/qualified exception are distinct gates from 10.07.
21. **Three assurance conclusions must be independent.** Source-relative certification, installed physical realization and independent positive product acceptance cannot be conflated by a common report or high proof percentage.
22. **Full Part VIII remains a separate target.** Claim proof does not make Create, Unclaim, Mark-on-the-way, Complete, Cancel, manager Reassign, rich board, multi-client selective refresh, accessibility and chosen response-flow behavior pass.
23. **Same single-/multi-node Claim.** Topology adds physical routing/command/outbox/frontier/failover evidence but never changes the original protected operation or grants remote read authority.
24. **The accepted Part IX pilot remains the comprehensive owner.** 10.08 specifies a concrete *production-correspondence slice* for Claim; 09.13 owns the complete cross-family compositional source/assembly/evidence DAG. Neither falsely inherits complete acceptance from the other.

## Gesso v1622 source facts and precise limits

- `src/gesso/model/command_resolution.clj` constructs a canonical command-result record inside an already-supplied compatible `gesso.model.tx` plan and checks exact command binding at reconciliation. Its own documentation states that it does not authenticate the principal, verify complete domain guards, qualify the stored outcome, prove XTDB execution or grant a protected disclosure/retry right. It assumes an actual application supplies the real policy and transaction path.

- `src/gesso/assurance/proof/xtdb_gateway_unknown_command_reconciliation.clj` reads one actual canonical command record under a pinned XTDB snapshot and applies command-resolution/disclosure logic, without writes. It expressly distinguishes compatible historical attribution from *which* physical attempt incorporated, and missing record at one basis from definitive noncommit. The redacted result can still be a command-existence oracle to an unauthorized caller.

- `src/gesso/assurance/proof/xtdb_gateway_atomic_submitted_readback.clj` joins a bounded process-local, source/plan-bound atomic domain update plus canonical command CREATE, original return and same-node/single-basis domain, command and ledger readback. Its own contract explicitly declines causality, source-specific authentication, complete writer set, actual installed Biff route and Live settlement. A post-submit observation failure retains unknown outcome.

- `src/gesso/assurance/proof/xtdb_gateway_command_outcome_bridge.clj` (v1622) compares an opt-in plan-bound gateway's exact local return, pinned matched canonical record and *caller-reported* request outcome under an application-supplied disclosure predicate. Source comments label a positive report bounded co-observation, *not* an authenticated Ring response, transaction causality, model-policy authorization, permission to retry or participant settlement. Its process-local callback registration is not a physical deployment certificate.

- `src/gesso/assurance/proof/installed_route_physical_correlation.clj` can invoke a checked handler recorded in a Biff system slot and capture one adapter call-site observation. It is a privileged controlled in-process diagnostic; it does not establish that an actual HTTP server adopted the handler or all other writers route through it. Supplied callbacks may inspect the observer request, so authority/purity remains open.

- `src/gesso/assurance/proof/transaction_outcome_progression_correspondence.clj` classifies one selected controlled physical outcome, command reconciliation and reported authoritative basis independently. The source names nine permanently open physical-refinement obligations, including principal/input authenticity, internal guard prestate, receipt causality, deployed handler, all writer coverage and universal refinement. A returned report is neither proof authority nor browser settlement.

- `src/gesso/assurance/proof/physical_writer_capability_coverage.clj` joins the host-observed inventory with *host-declared* physical target/mutation capabilities, not backend-enforced restrictions. It explicitly disclaims credential confinement, enumerator completeness and unobserved XTDB writers; whole-document PUT remains a potentially broad mutation.

- Current source-level Claim/operation or correspondence fixtures may exercise source/guard and finite physical cases, but the inspected Gesso library is not a deployment of HumanHelp's complete public production model and does not establish the Part VIII fourteen-gate product. No new runtime test was executed for this review.

## Thirteen paired positive/adversarial oracles

1. **Real click:** A loaded issued Claim control generates C42 and H1 and runs a current installed route; a synthetic helper envelope through a route-only fixture is not accepted as an actual browser-positive product witness.
2. **Current helper:** Real Alice with permitted active Membership and matching Request/Organization policy can Claim; revoked Membership or forged browser helper flag cannot authorize the physical write.
3. **Two-helper contention:** Distinct C42/C43 claims for one open Request permit at most one newly active primary at the true atomic boundary; sequential simulation or stale pre-read competing writes does not establish the same property.
4. **Command compatible replay:** H1 incorporated C42 but response vanished; compatible H2 returns permitted historical result without second assignment, and current claimed status does not spuriously reject the prior command.
5. **Incompatible binding/disclosure:** C42 reused for another Request, actor or operation is rejected without leaking another principal's command existence or result.
6. **Missing/expired record:** A missing pinned record or retention expiry is reported as unresolved where still possible; absence of one row does not authorize blind retry or assert original rejection.
7. **Stored rejection:** The command record contains a justified rejection; a compatible historical lookup re-presents that rejection rather than treating every =:already-incorporated= as success.
8. **Target helper:** A manager-selected new primary helper has independently current eligible Membership and actor permission; self-Claim cannot reauthorize a different target.
9. **History/current split:** Legitimate later Unclaim/Reassign changes current RequestAssignment while C42 remains a true earlier incorporation; a card snapshot cannot replace historical command attribution.
10. **Physical transaction:** Real guarded Request/RequestAssignment/command/outbox writes meet the declared atomic and frame contract; a single-document checked gateway does not gain untested multi-document safety by source similarity.
11. **DOM/race recovery:** Authorized target installation completes under current resource ownership; after-effect render failure or retired callback does not rewrite incorporation or claim fully adopted DOM.
12. **Selective multi-client:** Creator-local S is adopted without automatic unrelated R; other user receives R as advisory and one granted Refresh acquires its declared scope. SSE or reconnection cannot mint a board read.
13. **Broader product and writer closure:** Correct Claim plus visible Unclaim/Reassign/other Part VIII positives and qualified non-HTTP writer coverage count as independent gates; a Claim-only or reject-all source catalog is not whole-product acceptance.

Each case requires a predeclared original source, exact actor/target,
command/attempt identity, actual backend model authority, current
route/asset/owner generation, first failing source or physical
boundary, qualified independent data/history/DOM observation, and
an eligible positive neighbor. Where an effect is unobserved,
the result is unknown or incomplete, not a passed stronger
physical-refinement theorem. Counterexamples from a
generated formal model must be labeled abstract until a
qualified real physical witness shows corresponding execution.

## Editorial result and next owner

This revision preserves the preferred R5's genuine public-model Claim,
the R4 admission/execution distinction, correct command-first
branching and typed four-outcome semantics, and Part IX's
separate full application and product obligations. It
expands the source into a falsifiable vertical production
correspondence with accurate actor/target/tenant binding,
current transaction predicates, complete primary
assignment writer scope, historical C42 uncertainty,
installed route and browser target adoption.

**Nonclaims:** No full Gesso implementation correctness,
HumanHelp production deployment, authenticated XTDB
transaction causality, complete physical writer
confinement, universal Claim theorem, browser/HTMX
all-schedules refinement or Part VIII product completion
is established by this documentation revision.
