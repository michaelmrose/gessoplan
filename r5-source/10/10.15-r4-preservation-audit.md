# R5.1 Part X — 10.15 Validation and Physical Failure Windows Preservation Audit

**Normative source:** `r5-source/10/10.15-validation-and-physical-failure-windows.org`.
**R4 baseline:** `main` Part X “Validation ladder” and “Evidence layers are complementary,” including distinct test categories, first enforcing boundary, exact assembly, expected network/console failures and repair ownership.
**Preferred R5 predecessor:** R5/R5.1 10.15, retaining its twelve mandatory mutation/positive-control pairs, physical Biff/XTDB concurrency, browser and host scenarios, and warning that tests do not establish universal refinement.
**Accepted design context:** R5.1 Parts I–IX, Part X 10.01–10.14. 10.13 qualifies backend premises; 10.14 requires real pre-effect admission, issuer and runtime trust. 10.16–10.19 own multi-process topology, durable rendezvous, two-host failures and distributed acceptance.
**Gesso reference:** `michaelmrose/gesso` `application-assurance` HEAD `1b5e10e71c00e7784b019dee7dc1198a96fd03f6` (v1622).
**Disposition:** 10.15 substantively reviewed as a timeless intended contract. It does not certify today's complete Gesso or HumanHelp application.
**Test execution:** No JVM, embedded XTDB, Node, Chromium, formal checker, multi-node or HumanHelp tests were executed during this editorial revision. The existing repository contains source for the test scenarios cited below; source inspection is not a passing result.

## Editorial decision

Preserve R5's stronger targeted negative-and-positive physical oracle matrix and R4's complementary validation ladder. Define a source-linked, independently observed case fixture and exact result classification; make real boundary reachability, nonvacuity, pre-effect rejection and *post-submission unknown* distinct. Retain separate proof, finite, JVM/Node, true Chromium/HTMX/SSE, real Biff/XTDB, real HumanHelp and multi-host validation. Neither a clean report nor a passed bounded test is promoted to production-wide correspondence or an unbounded theorem.

## Twenty-eight R4/R5 preservation and strengthening decisions

1. **R4 complete ladder retained:** Unit tests, property tests, exact finite exploration, JVM/Node/Chromium portability, real HTMX/SSE/EventSource, XTDB, HumanHelp, artifact freshness and multi-host scenarios are different evidence layers.
2. **Formal theorem differs from integration:** A proof concerns its specified semantic machine, while browser and provider tests challenge the realization and external assumptions.
3. **Source is canonical:** Original Gesso declarations supply operations, invariants and expectations; tests and generated formal models cannot silently narrow them.
4. **Independence of oracle:** A test cannot establish correctness by computing expected results through the same faulty adapter or by trusting caller-supplied success metadata.
5. **First enforcing boundary:** Negative cases reach the claimed actual protected gateway/endpoint/effect gate; an earlier test-only wrapper rejection is not production enforcement.
6. **Actually issued assembly:** Every case names the source, checked assembly, plan, loaded artifact, installed route and relevant provider/host versions within their qualified scope.
7. **Observed effect provenance:** Forbidden writes and browser effects require a credible observer, interval and covered universe. Empty logs and structural agreement alone are not proof of prevention.
8. **Nonvacuity:** Accepted positive controls must traverse the same production boundary; reject-all implementations, empty initial state, missing browser runtime and untriggered races cannot pass.
9. **Typed result classes:** Counterexample, refutation, rejection-as-designed, incomplete, unsupported, unavailable, timeout, observed success and commit-unknown are not collapsed.
10. **Finite bounds are exact:** A complete finite graph can establish its specific finite property, not general unlimited history without a sound abstraction/refinement bridge.
11. **Cross-runtime conformance:** Clojure and CLJS/Node comparison exercises the selected actual semantic functions, preserving the claim's explicit bounded coverage.
12. **Real browser shell:** Chromium must execute emitted application JS, HTMX/SSE, native EventSource, HTTP and DOM effects; adapter-only tests are narrower.
13. **Physical backend:** Tests use actual provider transaction/query semantics and selected production lowering; fake status maps do not qualify XTDB behavior.
14. **Command race:** Concurrent requests acquire distinct genuine prestates and then compete at the actual guarded submission, with a positive winning write and losing conflict.
15. **Authorization race:** Membership/Organization dependency changes between prior read and incorporation challenge transaction-current policy, not merely initial handler checks.
16. **Frame and uniqueness:** Outside-field writes, absent/nil, relationship changes, competing inserts and whole-document PUT challenge physical and logical footprints.
17. **Durable atomic incorporation:** Command record and domain write are checked under one qualified transaction; half-commit and duplicate command histories are unacceptable.
18. **Unknown outcomes:** A lost reply/exception after possible commit must not be classified as rejection; observation failure and sidecar failure cannot automatically resubmit.
19. **Historical replay:** Command identity, semantic arguments, principal and disclosure are rechecked independently of new incorporation; a different command is not same-intent replay.
20. **Publication recovery:** Required outbox/gap and dispatch replay are challenged across before/after commit, before dispatch, retry and acknowledgment windows where claimed.
21. **Browser stale ownership:** Reordered/delayed callbacks, abort failures, resource retirement, partial install and deferred effects must not resurrect obsolete states or grant new effects.
22. **Visible progression:** Advisory and canonical basis, explicit Refresh, local optimism, stability of live roots and continuity are observed in real DOM, not inferred from HTTP 200.
23. **HumanHelp breadth:** The production model lifecycle/authorization/board acceptance is a separate proving application gate from a toy Claim scenario.
24. **Request isolation:** Independent Biff requests cannot share one-shot writer, principal, target, permit, budget or result; thread-bound deferred calls reject clearly.
25. **Deployment adoption:** Inspecting a Biff system map is not proof the actual server listener uses the final handler or that another raw endpoint cannot write.
26. **Writer closure:** Surveys of registered writers do not exclude direct, worker, migration, admin or external XTDB writers; scope remains explicit.
27. **Test harness adversaries:** Missing provider, incorrect fixture, empty choice generation, untriggered race, missing asset or uncaught unrelated console error fail the claimed positive gate.
28. **Claim scope and safe repair:** Test failures are attributed to original rules, implementation, backend assumption, shell, build, model policy or application assembly without modifying a valid theorem merely to hide the defect.

## Concrete Gesso source/test evidence examined

- `bb.edn` separates full, quick, JVM, formal/Recife, Node, Chromium and generated-runtime test gates; their availability is not a record of execution in this turn.
- `test/gesso/assurance/proof/kernel_systematic_mutation_test.clj` uses a separate finite Boolean interpreter and mutates the seven-rule closed proof kernel. The file explicitly disclaims any general kernel metatheorem.
- `test/gesso/live/browser/refinement_exploration_parity_test.cljc` explores actual adapter choices and compares JVM/Node corpus signatures, with explicit generator/exhaustiveness limits.
- `test/gesso/live/browser/chromium_integration.clj` runs real Chromium controlled by Playwright, real HTMX 2.0.7, SSE extension 2.2.4, EventSource, HTTP/SSE sockets and built browser JS. It documents actual physical-shell coverage rather than injected events; this review did not run it.
- `test/gesso/assurance/proof/xtdb_gateway_biff_unified_race_test.clj` installs two separate checked Ring requests, independently acquires prestates and releases a barrier for a bounded physical CAS contention test.
- `test/gesso/assurance/proof/xtdb_gateway_biff_unified_conflict_recovery_test.clj` separately tests a consumed writer permit and a fresh authorized request after a guarded conflict.
- `test/gesso/assurance/proof/xtdb_gateway_biff_unified_unknown_outcome_test.clj` distinguishes known assertion rejection from an exception deliberately thrown *after* a successful physical submission and before HTTP response.
- `test/gesso/assurance/proof/xtdb_gateway_biff_parallel_request_context_test.clj` checks simultaneous real-Biff/embedded-XTDB request-scope writer isolation and off-thread/invalid-dispatch rejection.
- `test/gesso/assurance/proof/xtdb_gateway_backend_compatibility_test.clj` challenges the selected XTDB beta1 interface/version and query/write options with fail-closed test cases; it does not prove general backend semantics.
- `test/gesso/model/tx_refinement_internal_basis_xtdb_test.clj` verifies that a pinned external query snapshot is not a transaction-internal DML basis; it expressly excludes general serializability/refinement.
- Production `gesso.assurance.proof.xtdb-gateway-biff-request-mediation`, writer inventory and `gesso.assurance.proof.xtdb-gateway-command-outcome-bridge` remain bounded: local host identity and observed readback are not exhaustive physical writer control, authenticated response provenance or universal command causality.

The existence and design of these tests are meaningful current implementation precedents but do **not** establish that all tests pass, that production HumanHelp is complete, that the shipped server adopted this path, or that the R5.1 normative requirements are implemented.

## Eighteen paired positive/adversarial acceptance controls

| # | Positive case | Forbidden/adversarial companion |
|---|---------------|----------------------------------|
| 1 | Valid source-derived kernel derivation is accepted | Missing premise or altered rule cannot pass by report forgery |
| 2 | A closed exact-finite oracle completes its declared graph | Empty generator, depth cutoff or timeout cannot be reported exhaustive |
| 3 | Identical JVM/Node inputs produce the intended portable semantics | Actual semantic change or typed unsupported input cannot be masked by test-normalization |
| 4 | Production Chromium loads the checked application JS and performs a real HTMX swap | A fake event or missing asset cannot count as browser-shell conformance |
| 5 | Authorized checked Claim reaches a physical guarded submission | Stale principal, Membership change or pre-read race must not bypass the real guard |
| 6 | Exactly one competing guarded update incorporates | Two conflicting submissions cannot both commit on one asserted state |
| 7 | Qualified whole-document replacement preserves all unrelated frame fields | Concurrent insert, delete or absent/nil change exposes unguarded footprint |
| 8 | One domain write and durable command record incorporate atomically | Duplicate C42 or asserted failure cannot leave a partial history |
| 9 | Committed command with lost HTTP response remains recoverable | Observer exception or lost reply cannot turn it into rejection or automatic retry |
| 10 | Compatible historical record resolves under fresh disclosure | Different principal, operation, arguments or lost record cannot silently resubmit intent |
| 11 | Current Browser resource owns installation and cleanup | Delayed callback, abort failure, stale generation or partial installer cannot resurrect retired effect |
| 12 | Authorized fresh remote board state stays advisory until user Refresh | SSE duplicate or network race cannot silently adopt or overwrite local continuity |
| 13 | Checked Biff request owns its scoped writer and returns legitimate result | Concurrent or off-thread request cannot borrow another request's permit or result |
| 14 | Actual deployed HTTP listener uses the final checked handler | Retained prior closure/raw route bypass is not accepted as installed enforcement |
| 15 | Positive path observes intended physical mutation | Test-local empty counter or reject-all implementation cannot pass a negative-only gate |
| 16 | Required outbox notice is eventually delivered under its stated fairness/recovery | Kill after commit before dispatch cannot permanently lose required intent |
| 17 | Qualified provider/adapter behavior is observed within the selected version | Unsupported provider, altered options or wrong read basis cannot count as passing |
| 18 | Deliberately injected expected network failure is classified and contained | Unrelated console error, missing test fixture or untriggered fault must still fail |

The matrix is a prospective acceptance contract; it does not claim these cases ran or that all physical environments are covered.

## What remains separate

10.15 describes how to challenge the first actual enforcing boundary and classify failures without inflating tested evidence. It does not replace 10.13's claim-indexed provider qualification or 10.14's fail-closed production admission. The concrete distributed host, routing, durable rendezvous, publication/outbox and two-host fault schedules remain 10.16–10.19's responsibility; no two-process test is passed or implied here.

Whole-Part-X reconciliation must validate both the R4 preservation chain and the positive/adversarial cross-section matrix; editorial acceptance will not certify a deployed application.
