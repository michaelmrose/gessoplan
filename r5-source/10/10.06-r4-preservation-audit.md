## Reconciliation decision

Retain R5's concise central distinction and exact runnable *pure Clojure* lost-field witness. Strengthen the normative physical-to-semantic correspondence to recognize four footprints: original guard dependencies, abstract assigned/framed fields, actual physical mutation extent, and physical conflict/predicate protection. Make explicit which precise backend assumptions and source/deployment coverage would establish preservation, instead of confusing a syntactically checked source plan, a pinned external read, a process-local submit receipt, or a same-basis poststate with a verified transaction-internal frame.

Preserve R4's essential protected Claim requirement: one-primary RequestAssignment safety must hold for concurrent real writers under an actual qualified atomic boundary. The smaller R5 text did not fully separate absence/uniqueness predicates or counterfactual history requirements, so the rewrite expands those without narrowing supported future Gesso to current experimental gateway coverage.

## R4, R5 and accepted-section preservation decisions

1. **Four distinct footprints are normative.** Original semantic guards, abstract write/frame, physical mutation and conflict/predicate protection can differ. An abstract invariant cannot omit a persisted write side effect merely because the source delta names only other fields.

2. **Claim guard dependencies remain real public-model facts.** Request status, current Membership, Organization/Location association, assignment absence/uniqueness and command binding may all be needed. The actual write set may include Request, RequestAssignment, durable command result and outbox intent; reading Membership need not mean rewriting it.

3. **Simultaneous assignment and frame survive.** The source before-state and input evaluate every RHS, with unassigned fields preserved including presence/absence. Sequential evaluation or an added field is not justified by a mere map of the intended delta.

4. **A physical `:put-docs` is whole-document replacement.** A named-field or typed-projection list cannot reduce its possible mutation scope. Only the actual selected physical operation semantics and current document frame determine whether unrelated data may be overwritten.

5. **Original runnable witness is preserved.** The full Clojure `prepared-before`, `prepared-after`, `partial-guard?`, `complete-map-guard?` and `assert` example remains, including the concurrently corrected summary. It proves only the map-level contrast, not that a particular XTDB assertion/execution was performed.

6. **Presence, nil and SQL equality are qualified.** An absent field and existing nil differ. A SQL `NULL` predicate, nested value, model codec or missing/deleted row cannot be substituted for Clojure map equality. Fail unsupported or justify the actual representation bridge.

7. **All-field CAS has a new-field gap.** Comparing every previously present field can still allow an inserted field to be erased. For supported scalar top-level complete-guard SQL, additional field-count assertion plus correct values/semantics can close that specific gap; it does not automatically cover nested data, other documents or missing names under unsupported types.

8. **Revision is meaningful only with writer discipline.** One command incrementing a local revision is not physical monotonicity. All relevant writers must enforce exact predecessor/successor, nonwrap, provenance, identity evolution, migrations and exceptions at the true conflict boundary.

9. **Transaction-local derive-and-preserve is distinct.** A backend deriving from genuinely current transaction state may preserve frame safely; a pinned client read plus merge is external and not that proof.

10. **A narrow patch must really be narrow.** A library routine named update may lower to full-document PUT. Source declarations must inspect actual physical write forms, not names or syntactic differences.

11. **Pinned pre-read is external.** It records observed state at a named basis but cannot attest transaction-internal state or eliminate intervening writes. Only qualified backend assertion/isolation can supply that missing boundary.

12. **Submission and later readback are not causality.** Exact emitted operations, one owned API call, returned key and later same-basis domain state each have independent evidence owners. Another writer can intervene or restore identical bytes; observed match does not alone establish who wrote them.

13. **Absence and uniqueness need predicate conflict.** Two helper transactions inserting distinct active RequestAssignment documents can violate one-primary even if neither updates any previously read row. A shared atomic constraint/CAS/exclusive conflict must actually cover all candidates and relevant writers.

14. **Positive-row checks do not cover phantoms.** Checking an existing Request or assignment ID is not equivalent to protecting a negative query over every active primary assignment. Deletion, activation, migration or table-level writer may change the predicate.

15. **Current-state ABA and history ABA differ.** If the claim uses only current value, A→B→A may be harmless. A claim that nothing changed, that a lease stayed valid or that a particular command never incorporated needs a genuinely history-sensitive token/contract.

16. **Bounded revisions have explicit overflow/identity semantics.** Exact integer range, nonwrapping successor, delete/recreate epoch and no-untracked reset matter. A timestamp or source fingerprint is not necessarily a monotonic physical revision.

17. **Proof transfer remains directional and conditional.** Abstract guarded-transition induction depends on original source catalog and supported semantics. Strong installed frame safety additionally needs actual writer/guard coverage, backend isolation and current deployed source/route qualification.

18. **Source-side diagnostics are not runtime authority.** Shape checking, host-declared protection and frame report fields are copyable descriptions. They do not issue a transaction, certify a principal, prove deployed host adoption or grant retries.

19. **Writer coverage is independently owned.** A raw/admin/migration writer can break revision discipline or one-primary safety despite an admitted source catalog. 10.07 requires real physical entrypoint/credential coverage; a supplied enumerator's silence is unknown, not empty.

20. **Nonvacuous HumanHelp is mandatory.** Real eligible Claim must work under concurrency; Unclaim, Reassign, creator-local Create and independent Part VIII product gates cannot be replaced by a reject-all protected operation.

21. **The same semantics apply across nodes.** Multi-node node loss/routing/attempts do not invent new Claim meaning or enable ungranted reads. They add physical conflict and durable command/failover obligations under the same source policy.

22. **Observation classes must not be promoted.** Completed source check, correct abstract frame, finite physical sample, bounded same-basis readback and qualified universal physical-refinement evidence are distinct results. Unsupported/timeout cases must remain incomplete, not success.

## Twenty paired positive/adversarial conformance obligations

1. **Typed source frame:** Valid simultaneous assignment leaves unassigned fields/presence unchanged. Adverse: sequential RHS or absent→nil mutation passes.
2. **Original example:** Partial guard accepts corrected-summary conflict while complete Clojure map guard detects it. Adverse: call these map assertions an actual XTDB transaction test.
3. **Whole-document PUT:** Exact protected target declares entire physical replacement. Adverse: before/after changed keys alone are marked complete write footprint.
4. **Old-field CAS:** All pre-existing scalar guard fields match. Adverse: new field inserted between read and commit is erased without full field-count/other qualified protection.
5. **Nil/absence:** Supported missing and present-nil cases preserve actual decoder semantics. Adverse: SQL NULL equality or absent-as-nil broadening is called fully checked.
6. **Nested fields:** A backend-qualified nested preserving operation meets its frame. Adverse: top-level scalar equality is silently promoted to a nested-document theorem.
7. **External read:** Pinned original state is correctly recognized as a separate observed basis. Adverse: it is labeled transaction-internal prestate after another writer intervenes.
8. **Guard atomicity:** Supported verified XTDB assertion/PUT rejects a changed covered field at the atomic boundary. Adverse: client-side pre-read success is treated as sufficient.
9. **Exact lowering:** Complete canonical checked vector contains every supported mutation. Adverse: extra raw DELETE/SQL statement or reordered PUT bypasses footprint accounting.
10. **Narrow patch:** Real patch changes only admitted fields under proper guards. Adverse: a full PUT masquerades as a two-field patch.
11. **Primary absence:** Two eligible helpers racing for distinct assignment IDs yield at most one active primary. Adverse: each checks an earlier empty result but no shared conflict excludes both.
12. **Uniqueness evolution:** Deletion, terminal transition and manager Reassign obey the selected assignment invariant. Adverse: a bypass writer revives an active second primary outside guarded catalog.
13. **Revision successor:** Exact expected revision r advances to r+1 at guarded commit. Adverse: an unchecked/unchanged/overflowed revision is accepted.
14. **Closed writers:** All relevant writers participate in the monotonic revision protocol. Adverse: direct admin writer changes data without bump, then stale revision CAS is called universal protection.
15. **Object lifecycle:** Delete/recreate uses a new epoch or otherwise prevents stale revision reuse where required. Adverse: identity reset reopens old authorization/expected version.
16. **ABA policy:** Current-only property remains valid after safe A→B→A; adverse history-sensitive no-change guarantee is certified from current equality.
17. **Poststate provenance:** Actual qualified before/after observation supports its bounded field report. Adverse: a matching poststate after third-party writer is attributed as causality of selected submission.
18. **Failure classification:** Guard rejection before side effect is distinguished from after-effect detection and unknown backend result. Adverse: timeout/diagnostic read promoted to safe rejection or prevention.
19. **Installed authority:** Current real public model/route enforces membership, tenant and Request assignment protection. Adverse: caller-supplied node/role/report creates proof of protected physical authority.
20. **Nonvacuous product:** Genuine eligible Claim and other required HumanHelp actions have independently observed positive paths. Adverse: reject-all gateway or missing Unclaim passes whole-app acceptance.

Every case must predeclare the source/invariant, original and mutated
guard/write footprint, selected backend implementation and assumed
semantics, expected first failure boundary, positive control, and an
independent physical effect oracle when physical prevention is claimed.
A model-level source rejection does not establish that an actual
unmediated external writer was stopped. Do not expose Request,
Membership, SQL, snapshot or tenant details in copyable diagnostics.
