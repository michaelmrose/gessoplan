# Part XI 11.06 — Aggregate Status Is Not Admission: R4 Preservation Audit

**Normative source:** `r5-source/11/11.06-aggregate-status-is-not-admission.org`.
**R4 baseline:** `main` Part XI “Release gate” and “Root release report,” including independently fixed supported capability scope, all mandatory test/proof gates, current physical artifact applicability, partial-check classification and an explanatory but not authoritative root report.
**R5 starting design:** a deliberately pure Clojure `summarize-required-gates` that reduces a nonempty supplied set of already validated gate results to explanatory blockers; no proof, certification or release API is asserted.
**Accepted R5.1 context:** Parts I–X and reviewed 11.01–11.05, especially immutable original release intent, eight check statuses and four decision subjects, original checker provenance and the nonauthoritative claim/evidence root.
**Gesso implementation inspected:** `application-assurance` at `1b5e10e71c00e7784b019dee7dc1198a96fd03f6` (v1622).
**Editorial disposition:** 11.06 reviewed as a future-system normative example, not actual release or formal verification.
**Execution:** No live JVM, Node, XTDB, browser, HumanHelp, installed host or formal kernel tests were run in this editorial revision.

## Editorial decision

Keep R5's small pure Clojure helper, without pretending it can check original source, proof admission or physical deployments. Add direct executable *negative illustrations*: a fabricated all-passing map and a nonempty but incomplete required set both yield a superficially green summary. The behavior is not a defect in a correctly scoped *aggregator*: it illustrates why admission must occur upstream of the reducer. Preserve R4's nonvacuous complete-scope release gate, mandatory failed/missing classification, profile non-downgrade, physical test and installed artifact requirements, and the difference between command disposition and release checking.

## Twenty-eight R4/R5 preservation decisions

1. **R4 requires source-derived complete** — R4 requires source-derived complete original capability and gate inventories before checking outcomes.
2. **Nonempty required-gate sets are** — Nonempty required-gate sets are not by themselves proof of original requirement completeness.
3. **R5's small Clojure result** — R5's small Clojure result aggregator remains pure explanatory code rather than an issuer.
4. **An incomplete self-selected required** — An incomplete self-selected required subset can yield a green summary without fulfilling the original request.
5. **Fabricated green rows can** — Fabricated green rows can yield a passing summary without real proof, test or installed physical observations.
6. **Missing required result rows** — Missing required result rows are reported missing rather than absent from the report.
7. **Unknown or malformed check** — Unknown or malformed check statuses are not successful checks.
8. **Failed, incomplete, unavailable, unsupported,** — Failed, incomplete, unavailable, unsupported, skipped, stale and missing statuses remain distinct blockers.
9. **Additional unrelated passing rows** — Additional unrelated passing rows cannot satisfy missing required gate IDs.
10. **Original result/status vocabulary is** — Original result/status vocabulary is distinct from business operation disposition and model transition outcomes.
11. **Proof checker results require** — Proof checker results require actual original source, issuer, checker/profile and premise validity.
12. **Physical test claims require** — Physical test claims require real observed test execution and exact tested/installed subject.
13. **Accepted trusted premises are** — Accepted trusted premises are not automatically proved by green abstract derivations.
14. **A narrower approved release** — A narrower approved release carries explicit excluded capabilities and remaining full milestone debt.
15. **Exclusion is an applicability** — Exclusion is an applicability classification and not a ninth passed check result.
16. **Strict proof and qualification** — Strict proof and qualification gates cannot be silently downgraded to operational success.
17. **Timed-out or bounded-incomplete model** — Timed-out or bounded-incomplete model checking cannot be presented as an unbounded theorem.
18. **An expected invalid business** — An expected invalid business action counts as a passing negative test only at its specified boundary.
19. **Reject-all implementations are not** — Reject-all implementations are not sufficient evidence for valid positive business operations.
20. **An SSE notification send** — An SSE notification send is not proof that a user has adopted authoritative browser state.
21. **Candidate admission and host** — Candidate admission and host installation retain different subjects and evidence.
22. **Traffic activation and completion** — Traffic activation and completion retain additional current evidence beyond green candidate gates.
23. **Current physical provider, handler** — Current physical provider, handler and asset qualification cannot be inferred from a historical aggregate.
24. **A copied in-process report** — A copied in-process report or serializable EDN map cannot become a genuine proof or capability.
25. **R4's ordinary operational milestone** — R4's ordinary operational milestone does not imply later formal or multi-node completion.
26. **Release report read failure** — Release report read failure does not change an already committed or uncertain domain command to rejection.
27. **HumanHelp's unselected response-flow policy** — HumanHelp's unselected response-flow policy remains a product requirement and separate decision.
28. **Current Gesso v1622 reports** — Current Gesso v1622 reports explicitly retain non-authoritative limits and caller-reported tests.

## Implementation correspondence and open limits

- `src/gesso/assurance/report.clj`: bounded source/obligation-backed conditional accounting; test observations remain **caller-reported** and cannot authenticate actual execution or host deployment. Its `:full-success?` is explicitly false within the supported boundaries.
- `src/gesso/assurance/proof/application_assurance_report.clj`: current source-relative structural composition is recomputed without conferring certificate issuance, admission or runtime authority. It retains real open physical writer/kernel/browser correspondence obligations.
- `src/gesso/assurance/proof/certificate.clj`: genuine restricted JVM-local certificate handles require actual original source/checker admission and cannot be forged by copyable report maps.
- `src/gesso/live/application_preflight/assurance.clj`: whole-app reports explain checked canonical surfaces but do not independently authenticate physically installed server/asset adoption.
- `src/gesso/live/application_preflight/authoritative_coverage.clj`: an enumerated declared-route snapshot does not prove exhaustive real XTDB writer coverage or current deployed router adoption.

No deployed release issuer, complete original product capability certifier, current host certification or physical test attestor is inferred from these source modules.
