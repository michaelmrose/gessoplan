## Governing revision decision

Keep R5's stronger separation of command truth, browser execution,
current adoption and cleanup, while restoring R4's explicit
intent-versus-execution table and single worked C42 recovery path.
Strengthen post-release permission checks, ownership of transferred
debt, the distinction between known committed result and present
Request state, and the fact that unknown command incorporation
survives a lost response and browser execution retirement. Add
explicit non-disclosure and lack-of-evidence dispositions; recovery
cannot assume a historical record exists, infer noncommit from one
missing read, or allocate a new command identity on uncertainty.

For HumanHelp, preserve the product decision that remote lifecycle
changes remain advisory until user-granted Refresh. Incorporate
one-use scope, overlapping/newer advisory debt, separate page
initialization permission, current principal and query context,
and protection against stale callback regressions. The release
does not issue more user acquisition rights simply because the
browser loaded newer code.

Keep 11.10 focused on retiring execution and composing acceptance,
without creating another compatibility checker (11.08), retention
registry (11.09) or command-result authority (Part IV).

## R4/R5 preservation and improvement decisions

1. Retire semantic execution/effect rights before physical cleanup.
2. Treat cancellation and socket/worker cleanup as fallible work
   whose failure cannot revive semantic rights.
3. Distinguish old assembly, browser execution, resource incarnation
   and callback/effect identities.
4. A late response may contribute evidence without gaining
   permission to install its former DOM effect.
5. Preserve stable route/subject identity as possible intent, not
   a frozen old program counter or execution capability.
6. Local filters, options and drafts survive only if the new plan
   explicitly revalidates their types, meaning and ownership.
7. Historical observations may remain usable evidence, not current
   Membership, source basis or protected adoption authority.
8. Command-specific unresolved outcomes may outlive browser
   execution or transport timeouts under the declared horizon.
9. Keep the original typed command ID, operation, canonical arguments
   and binding immutable through permitted retry/reconciliation.
10. A new HTTP/transport request identity never creates a new
    logical command by itself.
11. Current Request state alone does not attribute a prior C42.
12. A missing external command record at one snapshot does not
    establish authoritative nonincorporation.
13. A historical record is admissible only with genuine origin,
    compatible binding and current result-disclosure permission.
14. Old mutation permission can retire while protected historical
    read-only lookup remains eligible.
15. Ineligible retry never silently creates C43 from uncertain C42.
16. Unknown/unavailable/nondiscloseable/blocked remain honest,
    distinct from authoritative business rejection.
17. Domain commit, publication recovery, current state read and
    actual browser adoption remain independent obligations.
18. Durable work/outbox debt requires admitted transfer rather
    than deletion during rollout.
19. Future progress is conditional on declared history retention,
    service availability, fairness and disclosure permissions.
20. HumanHelp creator-local Create and own-command settlement have
    scoped privileges distinct from remote board acquisition.
21. Remote lifecycle/Create advisory alone never authorizes full
    collection reread or current DOM adoption.
22. One-use Refresh cannot be duplicated on replacement/runtime
    restart or silently consumed by unrelated successor reads.
23. Acquisitions discharge only covered advisory/knowledge debt;
    newer or incomparable debt remains.
24. New-page initial baseline must be an explicit separate grant,
    not a disguised same-page Refresh replacement.
25. Authority-context changes can force protected content and
    interest retirement despite previously adopted observations.
26. Late board responses cannot regress newer authorized local card
    observations or act with a retired resource instance.
27. Genuine positive and negative physical histories must exercise
    the same actual installed route/guard, not a synthetic wrapper.
28. All reachable A/A, A/B, B/A, B/B directions and exclusions retain
    separately qualified tested subjects and required premises.
29. Old/new workers, schemas and migrations retain actual compatible
    readers, writers and persistent work formats.
30. Actual cleanup and leaked resources require separate failure
    accounting; no inferred "all stopped" from missing callback.
31. Selected release evidence can be missing, unsupported, stale or
    conditional without fabricating a passing stronger profile.
32. Substantive responsibility is partitioned: 11.07 activation,
    11.08 direction, 11.09 retention, 11.10 retirement and recovery;
    Part IV authority, Part VI browser actuation, Part VIII policy.

R4's explicit N/N+1 overlap, C42 unknown-command history and
recoverable route/draft intent survive. R5's improved command outcome
and HumanHelp Refresh boundaries remain. Neither an arbitrary
browser-machine migration nor durable suspended actor registry is
introduced as a universal baseline. No essential R4 requirement
was intentionally removed.

## Actual v1622 source evidence and limits

The supplied application-assurance source snapshot was inspected;
no runtime assertion is inferred from namespace or test-file presence.

- src/gesso/live/browser/adapter.cljc models execution and
  resource retirement, state/effect ownership, and explicit
  Live invalidation handling. This is a local browser semantic
  adapter, not proof that an actual sleeping browser retained
  a generation or installed a recovered authorized card.
- src/gesso/live/browser/continuity.cljs provides browser-local
  capture/restore/release of physical continuity resources,
  deliberately below the semantic adapter. It does not
  issue principal permission, track a global release generation,
  or migrate arbitrary obsolete state.
- src/gesso/model/command_resolution.clj constructs one canonical
  command record in the *same abstract model transaction plan*
  and checks exact binding for its declared recovery shape.
  Its docstring leaves physical XTDB correspondence, true
  authentication, domain guards and outcome disclosure to
  independent trusted boundaries.
- src/gesso/assurance/proof/xtdb_gateway_unknown_command_reconciliation.clj
  performs a pinned, read-only external record observation.
  The implementation explicitly denies causal attribution to
  the prior attempt and any retry permit, and identifies a
  currently unresolved physical atomic-record incorporation
  boundary. Absence of a record does not prove noncommit.
- src/gesso/live/application_preflight/biff.clj covers a
  particular local Biff handler/start interface, not all
  installed production routes or multi-host rollout traffic.
- src/gesso/live/browser/build.clj binds a generated
  browser manifest/stamp to exact artifact bytes within
  qualified build assumptions; it does not prove that a
  sleeping client actually loaded those bytes or has current
  ownership/adoption rights.

The source snapshot does not demonstrate an end-to-end
production-verified rolling release, real multi-node
directional routing admission, durable old command
reconciliation across all supported schema migrations,
complete current authorization at every deployed route,
or fully qualified HumanHelp one-Refresh recovery.
The design specifies those necessary future conditions.

No JVM/XTDB/Chromium/real HTTP/multi-host or HumanHelp
physical tests were run for this documentation revision.

## Twenty-two future positive/adversarial acceptance pairs

| # | Qualified positive | Forbidden nearby inference/failure |
|---|--------------------|------------------------------------|
| 1 | Old request finishes under retained admitted rights | Old callback looks up a new provider after retirement |
| 2 | Late C42 response contributes only genuine evidence | Response physically installs old card or rejects unknown |
| 3 | Current protected historical record supports C42 | Browser ID or current Request read is called attribution |
| 4 | Missing record leaves uncertain incorporation unresolved | Missing at one snapshot is claimed proof of no commit |
| 5 | Qualified compatible retry preserves C42 binding | New C43 issues duplicate business command |
| 6 | Historical read-only resolver survives old writer | Old mutation rights revived to look up result |
| 7 | A stream carries its compatible owner/guard | A stream silently switches to B's current provider |
| 8 | Current principal gates historical disclosure | Old stored session leaks protected result |
| 9 | Actual A/B and B/A permitted paths execute | Sticky routing conceals incompatible failover |
| 10 | Exclusion fails closed at genuine protected gateway | Test-only wrapper falsely certifies real writer coverage |
| 11 | Old browser assets retained to promised expiry | CDN purges A while sleeping clients have live rights |
| 12 | Expired A execution receives typed retirement | Missing JS file or decoder failure masquerades as protocol |
| 13 | Failed B leaves valid A but revoked A stops effects | Failed install lets known-unsafe A continue writing |
| 14 | Migrations preserve admitted pending work formats | Old compatible reader implies unsafe old writer permission |
| 15 | Scoped current acquisition installs under new owner | Old optimistic rollback undoes newer card |
| 16 | Bob receives advisory without board auto-adoption | Asset reload fetches unrelated remote changes |
| 17 | Valid one-use Refresh covers only justified debt | Refresh is duplicated or clears later debt |
| 18 | New page initial grant is explicitly separate | Same page reset fabricates another user Refresh |
| 19 | Cleanup leak is reported but has no effect rights | Physical failed cancel is interpreted as live permission |
| 20 | Rollback honors actual migrated state and workers | Historically passed code rolls back invalid schema |
| 21 | Real eligible Claim works at the protected route | Reject-all handler passes because tests are only negative |
| 22 | Multi-host failover retains truthfully scoped debt | One SSE write becomes proof of system convergence |

These are prospective tests and evidence requirements, not
observed successful Gesso release behavior. Positive and
negative cases must challenge the actual protected side
effect or installed physical boundary, not independent
report generation alone.
