## Editorial judgment

Keep R5's superior distinct semantic, proof, implementation, assembly-generation, asset and activation identities, its dependency-specific invalidation discipline and its honest pure worked Clojure example. Restore R4's exact versioned input determinism and *correctness before cache hit rate* as explicit requirements; make complete original-source and physical-dependency coverage open until independently established. Distinguish impact *reconsideration* from selective reuse, reconstruction, recompilation, qualification and installation/activation rechecking. A compact finite graph traversal is a useful algorithmic illustration but cannot check whether the real application dependency index is complete or whether its returned success is applicable. Cache trust and re-admission detail remains with 11.04.

## Twenty-eight R4/R5 preservation decisions

1. **R4 deterministic identities:** R4 deterministic identities remain stable only for the complete interpretation-specific inputs and relevant versions.
2. **Normalized semantic identity:** Normalized semantic identity and exact byte identity remain separate tracked claims.
3. **Diagnostic metadata changes:** Diagnostic metadata changes may preserve abstract theorem applicability where meaning truly stays unchanged.
4. **Compiler and byte-affecting:** Compiler and byte-affecting toolchain changes cannot inherit identical JavaScript artifact evidence without rechecking.
5. **Source path, Git:** Source path, Git commit, timestamp and human identity labels are provenance but not semantic or installed authority.
6. **R4 incremental source:** R4 incremental source dependency and proof identity cones remain the optimization goal rather than rebuild-everything behavior.
7. **Semantic interface and:** Semantic interface and original operation, invariant, role, model and required capability closure are canonical source-derived inputs.
8. **A correct declared:** A correct declared graph alone never proves absence of hidden direct XTDB writers or unmatched physical effects.
9. **Each proof, implementation,:** Each proof, implementation, provider, compiler, asset, host and activation dependency is recorded for the claims it affects.
10. **Structural subject hashing:** Structural subject hashing is not proof of arbitrary Clojure denotational equivalence, backend fidelity or complete lowering.
11. **A current checker:** A current checker must admit subject, proof, profile, premise and dependency compatibility before retaining an old derivation.
12. **Implementation A-to-B changes:** Implementation A-to-B changes requalify conformance even if the normalized semantic Claim contract is admitted unchanged.
13. **A changed semantic:** A changed semantic Claim eligibility rule invalidates its dependent contract, proof, plan and root, not unrelated search work.
14. **A later discovery:** A later discovery that search depends on Claim extends the graph and requires reconsidering search.
15. **A browser manifest:** A browser manifest binding implementation identity adds that edge and cannot reuse a simplified fixture's omitted edge.
16. **Reconsidered manifest does:** Reconsidered manifest does not necessarily entail changed emitted bytes; current stamp and actual receipt must still agree.
17. **An omitted, renamed,:** An omitted, renamed, removed or unsupported original requirement cannot disappear from the canonical release denominator.
18. **Unresolved graph edge,:** Unresolved graph edge, unacceptable cycle or invalid dependency subject is a typed admission failure, not a successful traversal.
19. **Runtime Membership, command:** Runtime Membership, command identity, protected read permission and current principal remain effect-time checks, not immutable build-time facts.
20. **Selected strict release:** Selected strict release gates remain unsatisfied after missing, stale, unsupported, unavailable or incomplete required rechecks.
21. **Physical installed host,:** Physical installed host, active listener, backend qualification and traffic exposure retain separate current requalification subjects.
22. **Cache lookup, serialization:** Cache lookup, serialization and corrupted evidence trust policies belong to following 11.04 and cannot substitute for current admission.
23. **R4's dependency invalidation:** R4's dependency invalidation can retain independent immutable conclusions without forcing unrelated reconstruction.
24. **The current source-derived:** The current source-derived dependency graph cannot assert its own complete writer/source universe merely by enumerating nodes.
25. **Negative and positive:** Negative and positive acceptance controls distinguish working supported operations from reject-all pseudo-coverage.
26. **Comment-only source changes:** Comment-only source changes can retain an abstract subject while still changing traceability, exact emitted bytes or physical evidence.
27. **Replaced provider, changed:** Replaced provider, changed credentials and mixed-generation activated hosts require separate live evidence even with stable semantic theorem.
28. **The R4 worked:** The R4 worked HumanHelp Claim example remains schematic, not a fictional deployed Gesso release/reconsider API.

## Gesso v1622 implementation correspondence and nonclaims

- `src/gesso/assurance/subject.clj` uses a versioned, bounded, canonical EDN-like serializer and SHA-256 structural subject identity. It explicitly does *not* prove arbitrary Clojure execution meaning or implementation equivalence; its output remains unadmitted.
- `src/gesso/assurance/dependency.clj` checks a declared identity-bound DAG with exact dependency fingerprints, bounded nodes/edges and genuine JVM-local checked handles. Its documentation explicitly states it is structural, not complete actual application route/writer discovery or current runtime authorization; consumer-provided current assembly sources remain trusted inputs.
- `src/gesso/assurance/proof/obligation.clj` derives source-relative and not-yet-proved invariant obligations, preserving full declared input conditions and open original source/initial-state/writer/refinement completeness assumptions.
- `src/gesso/live/browser/artifact.clj` derives pure BrowserArtifactStamp and plan registry correspondence from a particular manifest, not actual browser JS execution.
- `src/gesso/live/browser/build.clj` binds a specific emitted JavaScript file's bytes to an application manifest and receipt in supported build paths. Manifest/receipt equality does not prove arbitrary compiler correctness, installed host adoption or current physical browser effect.
- `src/gesso/live/application_preflight/authoritative_coverage.clj` freshly inspects host-provided entrypoint enumeration but expressly does not prove that enumerator exhaustive or that all extra XTDB writers are absent.

The current code supplies meaningful identity, structural dependency and artifact primitives, but no all-encompassing, certified dependency inventory spanning every original product requirement, external writer, actual deployment, selected release profile and current authorization. This section deliberately specifies stronger future obligations rather than claiming v1622 implements them.

## Fourteen paired positive/adversarial acceptance controls

| # | Positive supported test | Adversarial or nonconforming behavior |
|---|-------------------------|----------------------------------------|
| 1 | Normalized unordered maps yield the same supported semantic subject | Map iteration order generates spurious proof identity drift |
| 2 | Relevant Clojure primitive contract change requalifies affected proof | Old hash is treated as denotational equivalence of changed program |
| 3 | A comment-only change retains an applicable abstract theorem | Byte-changing code generation reuses stale JS artifact identity |
| 4 | Claim policy rule change reconsiders affected operation/plan/root | Unrelated search plan is forcibly rebuilt without dependency |
| 5 | A-to-B XTDB adapter change rechecks physical conformance | A's integration test certifies B using same semantic ID |
| 6 | Unchanged proof is re-admitted against fresh source and dependency closure | Copied success EDN/digest is taken as certificate |
| 7 | Current browser manifest matches actual emitted bytes and receipt | Changed compiled plan/manifest served with old receipt |
| 8 | Physical writer discovery updates corresponding release obligations | Complete declared graph is called complete deployed writer coverage |
| 9 | Required deleted operation remains visible as missing original requirement | Removed node silently reduces original milestone denominator |
| 10 | Invalid edge or cycle rejected by graph admission | Impact traversal called proof of valid source graph |
| 11 | New active host/provider has current own qualification | Old released host report certifies new runtime |
| 12 | Current protected Membership policy checked at Claim effect boundary | Build cache permanently freezes user's access |
| 13 | Independent file edit retains unaffected admitted evidence | Every source file/commit triggers global semantic rebuild |
| 14 | Unavailable strict checker keeps exact selected gate unmet | A weak operational check silently substitutes for missing formal proof |

All are prospective source/physical conformance checks. A source graph that does not faithfully cover the relevant original requirements and physical entrypoints cannot pass merely because the illustrative impact algorithm terminates.
