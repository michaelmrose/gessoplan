## Governing judgment

Keep R5's richer source-derived contract and its explicit asset/endpoint
retention. Restore R4's careful claim that equality proves only the
appropriate semantic identity, never physical installation or authority.
Strengthen normalization against under-approximate dependency catalogs,
unsafe presence-default collapse, stale provider implementations and
arbitrary opaque Clojure. Make directional refinement subject- and
implementation-bound and preserve proof-profile trust classifications.

The further new obligation is *joint retention*: the exact old browser
artifact, server/protocol pairing, old-state readers, Live reconnect and
authorized historical command resolver have independently stated owners
and potentially different horizons. This avoids the common invalid
inference that the last server request or most recent deployment
determines the end of sleeping-client or command-recovery obligations.
The release must not promise an old plan or original C42 result after
deleting the only compatible runtime or historical decoder.

## Thirty-two R4/R5 preservation and strengthening decisions

1. The original admitted business source, not a user-authored secondary
   compatibility catalog, determines relevant continuation semantics.
2. Unknown/opaque source dependencies are named premises or unsupported,
   not silently removed from the normalized contract.
3. Operation rule, placement and role/knowledge interfaces are included.
4. Presence-aware typed parameters, defaults and canonical argument
   binding affect compatibility whenever their interpretation changes.
5. Original command identity, canonical binding, deduplication and
   outcome/unknown reconciliation semantics survive as contract facts.
6. Protected authority and information-flow obligations are separate
   from serialized client assertions or stored snapshots.
7. Progression, scope, coverage, acquisition/adoption and one-grant
   Refresh policy affect the meaning of a client continuation.
8. Browser resource incarnation, deferred effects and cancellation
   rights are part of the continuation's admissibility.
9. Server route, transport, encoder, decoder and actual emitted
   HTMX/JS protocols are separately represented.
10. Persistent schema, pending durable work and historical result
    formats must be readable by every admitted target that needs them.
11. Normalization has a declared interpretation/version and a
    source-complete dependency closure before equality is meaningful.
12. Equal hash/route/operation names do not establish semantic
    equivalence absent qualified normalization and origin.
13. Equal semantic contracts do not automatically requalify changed
    adapters, browser bytes, providers or installed host.
14. Current Membership, credential, model state and disclosure remain
    checked at their actual runtime boundaries.
15. A directional adapter states exact origin/target scope and
    semantic/representation/refinement obligations.
16. A checked old-to-new relation does not imply new-to-old.
17. Trusted compatibility premises remain visible and cannot replace
    mandatory proof in a strict profile.
18. Actual serving/loaded asset and host binding differ from built
    artifact stamp, local system map and copyable status report.
19. Exact old asset URLs remain immutable for the admitted promise,
    including byte-affecting dependencies and cache/proxy effects.
20. Sleeping clients, service workers, in-flight requests, SSE and
    background durable work are possible overlap origins.
21. A build-artifact match does not prove compiler correctness or
    browser DOM installation.
22. Retain route, codec and endpoint support for every *permitted*
    A/A, A/B, B/A and B/B operation direction.
23. Local server reference counts do not exhaust remote sleeping-client
    retention obligations.
24. Client execution/asset, Live registration and command-result history
    have different declared retention and recovery horizons.
25. The joint promise is invalid if one necessary decoder or record
    expires earlier than the supported recovery path.
26. A typed early refusal may safely retire an expired origin, but
    deleting files alone is not the specified retirement mechanism.
27. Historical read-only reconciliation can outlive permission to
    execute an old mutation implementation.
28. Old command ID or current domain state alone does not authenticate
    historical incorporation or permission to disclose a result.
29. Missing/expired command evidence does not imply rejection or
    authorize a fresh logical command ID.
30. Actual migration state can permit an old reader while blocking
    an unsafe old writer.
31. HumanHelp reconnect/reload cannot grant unrelated remote
    authoritative adoption without explicit Refresh.
32. This section owns normalized/physical/retention guarantees rather
    than a second routing policy (11.08) or retirement machine (11.10).

R4's N/N+1 example remains a useful illustration of finite overlap
but not a numeric assembly identity. R5's sharper command/result,
client-asset and source-derived boundaries are retained. No essential
R4 continuation or resource-retention obligation is discarded.

## Inspected Gesso v1622 correspondence and nonclaims

- src/gesso/live/browser/build.clj relates a source-derived
  BrowserAssemblyManifest, BrowserArtifactStamp, SHA-256 and exact
  emitted-byte receipt. Its explicit contract does *not* prove an
  arbitrary emitter obeyed the manifest or that a browser actually
  loaded those bytes.
- src/gesso/live/browser/artifact.clj owns stamp/manifest shape and
  pure recognition; it does not establish deployed client identity,
  complete protocol or real installed behavior.
- src/gesso/live/application_preflight/biff.clj requires a current
  ApplicationAssembly and checks a native Biff local handler/response
  boundary, but expressly excludes later handler replacement,
  pre-serialized HTML and a server ignoring :biff.ring/handler.
- src/gesso/assurance/proof/xtdb_gateway_unknown_command_reconciliation.clj
  performs a separately pinned read-only command-record observation
  under specified binding/disclosure rules, not an authenticated
  multi-host original-attempt causality proof or retry permit.
  Its own docstring notes that a selected single-UPDATE gateway
  does not atomically write the canonical command record with the
  domain update; its readback cannot fill that production guarantee.
- src/gesso/assurance/proof/installed_route_provenance.clj establishes
  a restricted in-process Ring dispatch witness, not externally
  installed host/asset or cross-generation routing attestation.

These are source-relative pieces of evidence, not a complete active
generation registry, exact old-asset retention service, current
browser loaded-byte proof, continuously qualified cross-host decoder
set, guaranteed durable historical resolver or deployment release
certificate. Test files and declared acceptance cases cannot replace
actual executed physical observations.
