*** Multi-node production completion
:PROPERTIES:
:CUSTOM_ID: milestone-multi-node-production
:END:

This milestone realizes the same application meaning across actual independent
application processes under the qualified topology from
[[#req-multi-node-realization]]. Host identity does not confer semantic authority.

Completion requires all of the following for the stated production envelope:

| Area | Required evidence |
|------+-------------------|
| Physical topology | Actual independent hosts/processes, routing, qualified shared authority, and declared failure model |
| Command semantics | Stable binding, cross-host replay/disclosure, concurrent delivery, retention, and honest uncertainty |
| Publication recovery | Atomic durable intent where promised, dispatcher ownership, retry/acknowledgment semantics, duplicates, and crash recovery |
| Subscriber continuity | Initial and reconnect fence/replay/gap handling, including silent missed notices and retention expiry |
| Progression-safe reads | Another host obtains sufficient real provider evidence or reports insufficiency without false discharge |
| Selective adoption | HumanHelp remote changes remain advisory until permitted Refresh across reconnect and host replacement |
| Current authority | Replacement hosts enforce current authentication, Membership, scope, protected read, and command-result disclosure |
| Release overlap | Actual reachable client/server combinations, assets, workers, state formats, retirement, and recovery satisfy the selected bound |
| Resource envelope | Measured capacity, queue/debt/retention bounds, backpressure, and failure behavior under the declared load |
| Root evidence | Actual topology and provider assumptions enter the same obligation and release report |

The required fault schedule includes loss before submission, after possible
submission, after commit before publication, after publication before completion
recording, and during response delivery. The outcomes are not all equivalent.
A surviving authoritative commit remains incorporated even while a browser is
unknown. A later current-state read does not automatically attribute its command.

Advisory receipt, distribution acknowledgment, acquisition, physical installation,
and adoption are separately observed. At-least-once dispatch to a named boundary
does not establish delivery to every browser. Initial interest registration and
reconnect gaps require their own evidence even when no advisory was received.

Load testing must exercise relevant resource limits and recovery behavior, not
only maximum successful request rate. Independent concurrent requests must not
share a one-shot writer capability or leak invocation context. Where deferred
work is supported, its explicit ownership and assembly context are exercised.

Progress tests state when their availability, fairness, retention, authorization,
and user-action premises become satisfied. Under explicit Refresh, an inactive
user is not required to adopt remote state. After authorization is revoked, the
expected result may be nondisclosure rather than successful reconciliation.

A two-host demonstration or early prototype can expose valuable semantic defects
without satisfying this production milestone. The completion claim requires the
actual failure, resource, and compatibility envelope, not merely a load balancer
and a shared database.
