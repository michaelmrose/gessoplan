** Progress metrics and completion boundaries
:PROPERTIES:
:CUSTOM_ID: req-completion-boundaries
:END:

Progress measures coverage of required semantics, usable capabilities, enforced
boundaries, and honest evidence. Revision counts, source size, and raw passing
test counts do not establish completion.

*** Metrics have stable denominators and visible blockers

For each metric record the requirement-set identity, scope, numerator, denominator,
missing items, evidence class, and applicable assembly or implementation. A
change to the denominator is visible as a requirement change.

| Metric | Useful denominator | What it must not conceal |
|--------+--------------------+--------------------------|
| Required user capabilities exercised | Independent canonical capability set | Omitted controls, unavailable positive paths, unresolved product decisions |
| Declared assembly closure | All exposed managed affordances in the admitted source | Required capabilities absent from that source |
| Production-path enforcement | Relevant real entrypoint and effect-boundary classes | Undeclared writers, retained old handlers, test-only wrappers |
| Semantic judgment coverage | Required judgment/subject pairs for the selected profile | Unsupported forms treated as checked or assertions mislabeled as proofs |
| Required dependency closure | Obligations derived from original semantic sources | A structurally closed but incomplete caller-supplied graph |
| Mutation rejection quality | Predeclared relevant defect classes with positive controls | Wrong rejection boundary, trivial reject-all behavior, flaky diagnosis |
| Qualified substrate coverage | Actual provider/adapter/configuration envelopes used | Tests of a different backend, artifact, or shadow implementation |
| Formal correspondence coverage | Named formal-to-production transfer obligations | Formal theorems lacking a production relation |
| Recovery coverage | Required uncertainty, interruption, and retirement conditions | Happy-path reachability presented as eventual recovery |
| Incremental reuse | Applicable unchanged evidence and affected change classes | Speed obtained by omitting necessary dependency or environment checks |

Counts of accepted assumptions and trusted components are audit aids, not a
confidence percentage. Show which claims depend on each central premise. A small
kernel with an unqualified production boundary is a different result from an
end-to-end operation with qualified external premises.

Performance metrics report the hardware, concurrency, dataset, topology, resource
limits, and workload exercised. A fast local test gate is useful feedback but
cannot substitute for a required slower browser, backend, or fault scenario.
Parallel execution must preserve test isolation, exact intended inventory, and
complete result accounting; a missing worker result is not success.
