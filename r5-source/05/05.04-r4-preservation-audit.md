**Baseline:** R4 `main` Part V, `Continuity`, particularly `Continuity is

owner and instance identity`, and `Portable Choreo observes only effect
completion/failure`, with its Bob/R17 board replacement and I1/I2 examples.
**Candidate:** R5.1 `05.04-continuity-ownership-and-search.org`.
**Disposition:** focused sectional review. Part V has not undergone
whole-part reconciliation or reviewed-candidate acceptance; no backend or
browser proof is claimed here.

## R4 preservation audit

- Retained continuity as browser-local preservation of focus, caret,
  scroll, open details and selected local draft input. The snapshot is
  not authoritative domain state, knowledge, provenance or grant.
- Preserved R4's separation between installing an admitted projection
  and optional local continuity follow-up. Failure to restore focus
  must not undo a completed authoritative installation or reject
  a previously committed Request operation.
- Preserved the resource-instance/owner distinction: logical slot,
  capture I1, successor capture I2, replacement owner O1/O2 and target
  instance are different rights. A stale I1 callback cannot consume I2.
- A successful capture at schedule time is not permanent physical
  authority; the current owner and target are rechecked before each
  deferred DOM mutation. Semantic retirement precedes best-effort
  cleanup and leaves stale handles powerless.
- The capture is restricted to permitted local interaction data. No
  wholesale restoration of old server markup, protected operation
  bindings or now-undisclosable Request R17 is allowed.
- R4's illustrative browser functions are not an alternate
  application-author implementation or a machine-checked claim;
  R5.1 keeps opaque host resources behind a portable effect boundary.

## Specific improvements

1. **Current edits are separate from current captures.** A user can
   change a search field after capture without any new replacement.
   Current slot/owner, target instance, disclosure, and local edit
   generation are all required for the old value to be restored.
2. **Protected fields stay protected.** A generic all-input capture is
   not an admission policy for credentials, anti-forgery tokens,
   hidden command arguments, principals or operation bindings. A
   field's inclusion depends on declared local-data classification.
3. **Element identity requires compatibility.** Duplicate keys,
   missing identity or positional indexes over changed collection
   membership cannot silently redirect a restore into another
   Request control. Optional restoration can be skipped safely.
4. **Implementation binding is not authority.** Captured restore
   code/format is frozen or explicitly migrated, but the old
   implementation cannot override new semantic ownership rights.
5. **HumanHelp local versus server search.** Part IV's adopted board
   cohort is selected by Organization/Location, coverage, principal,
   visibility and temporal scope. Local text search, sorting,
   priority and terminal toggle can be presentation over that cohort.
   A truly server-side `cabinet` query is a different scope;
   relabeling its results `cabinet hinge` requires new admissible
   query evidence. Neither local edit clears Live/Refresh debt.
6. **Paired positive/adverse controls.** Added cases for authorized
   details preservation versus disclosure loss, later user edits,
   ambiguous element identity, local versus authoritative query,
   and completed installation versus failed optional focus.

## Gesso implementation inspected (not executed)

Gesso `application-assurance` head `1b5e10e7` (v1622):

- `src/gesso/live/browser/continuity.cljs` states that the adapter
  owns slot identity and generation, the shell owns opaque capture,
  and continuity realizes browser-local capture/restore/release.
- The implementation captures common inputs, including a positional
  fallback for controls without stable keys; `capture-inputs`
  defaults to `input, textarea, select`. These are implementation
  mechanisms, *not* a general proof of unique target identity or
  safe classification of every potentially protected field.
- `capture-box` freezes the restoring callback with the opaque
  capture; later registration does not reinterpret the old state.
- `release!` revokes a local delayed callback through a physical
  latch. `final-restore!` checks the latch before post-layout
  mutation; the shell/adapter still owns generation policy.
- Source-inspected tests include
  `full-capture-replacement-restore-preserves-user-state-not-server-structure-test`,
  `restore-resolves-target-again-after-layout-test`, and
  `release-revokes-delayed-restore-before-any-late-mutation-test`.
  A Chromium integration scenario addresses continuity restore
  failure without turning it into canonical swap failure.

These code paths show real implementation precedents but do not
establish that all local edit-generation, disclosure, ambiguous-key,
and query-scope obligations of the **finished** specification are
already enforced for every custom control. No Gesso tests were run.
