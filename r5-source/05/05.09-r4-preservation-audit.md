## R4 preservation and intentional improvement

- R4's example machine preserves one source-owned command identity
  and separate execution, timer, transport and physical target
  ownership. The preferred R5.1 representation uses the canonical
  projected `:local`/`:await`/`:return` vocabulary, not a second
  author-maintained transition-table language.
- R4's `Claim settled`, `timeout`, `rejected` and
  `authoritative acquired` histories never made arbitrary local
  DOM success evidence of server-side incorporation. R5.1's
  explicit install request/completion/adoption segment strengthens
  that point: a successful command is not the installed current card.
- R4 keeps normalization, actual source admission and owner-relative
  callbacks separate. Equivalent event names or a fabricated
  `:installation/completion-ref` cannot supply trusted host evidence
  or resurrect a retired execution.
- R4's timely timeout and delivery branches were explicit; R5.1
  retains distinct participant message versus environment timeout,
  completion buffering and declared interruption/fairness recovery
  instead of dropping a difficult branch from projection.
- R4's simplified `:request/helper-id` and optimistic
  `:request/status :claiming` are illustrative. Current domain
  truth belongs to guarded production RequestAssignment. Historical
  C42 Claim success can coexist with Bob's later primary assignment.
- R4's browser shell interpreted abstract effects, not another
  semantic machine. R5.1 keeps the shared coordinator responsible
  for adoption/Live debt while the role-local execution owns
  protocol progress, and the host interprets physical work.

## Normative corrections

1. **Source-qualified physical completion:** distinguish installation
   request, HTMX before-swap permission, transport success,
   after-swap-completed physical effect, and adopted authority. The
   completion must be bound to the actual effect instance, source,
   owner, target incarnation, scope and installed footprint.
2. **Ambiguous physical results:** the illustrative failed event
   carries a registered classified failure reference; partial and
   indeterminate effects cannot be silently mapped to wholly
   installed or wholly failed. Missing callbacks follow the declared
   deadline/owner-loss recovery path.
3. **Immediate completion registration:** bind and buffer or
   serialize a completion before the physical effect is allowed
   to finish; an event arriving before =:await= is armed cannot
   disappear, replay into a later effect or certify twice.
4. **Current coordinator reconciliation:** adoption rechecks newer
   independently adopted creator-local card/membership and
   invalidations/Refresh obligations accumulated after the request
   began. An older board install cannot discharge those
   obligations or clobber newer local facts.
5. **Partial installation recovery:** record per-target completion,
   physical uncertainty, compensation/repair, and successor owner
   separately from command outcome. Sequential HTMX swaps are not
   physically atomic without a declared mechanism.
6. **Terminal rejection/attempt distinction:** server-qualified
   terminal C42 exclusion differs from failed attempt; timeouts
   preserve unresolved attribution and a new owner must not
   inherit retired timer or target grants.
7. **Old Claim after Reassign:** historical success of Alice's
   C42 does not reinstall Alice after Bob's authoritative
   Reassign. Qualified current RequestAssignment observation
   independently controls current presentation.
8. **Six paired positive/adverse witnesses:** physical
   allowance/completion, immediate completion race, later
   invalidation/newer card, partial targets, old Claim/new
   Reassign, and timer/participant competition.

## Source-inspected Gesso implementation, not certified runtime

Gesso `application-assurance` branch at `1b5e10e7` (v1622):

- `src/gesso/choreo/machine.cljc` owns role-local protocol
  execution and its distinct `:await`/participant
  `:receive` contracts. `src/gesso/live/browser/adapter.cljc`
  owns browser event/resource generations, stale request
  rejection, fragment requirements and authoritative swap
  admission; it does not perform the actual DOM operation.
- In `adapter.cljc`, `before-swap` emits
  `:htmx/allow-swap` after checking request generation and
  permitted progression. Separately, `after-swap` uses
  current request correlation to record the basis and emit
  `:authoritative/installed` and optional continuity
  restoration. This source-level correspondence depends
  on the actual HTMX/host callback and does not by itself
  certify physical DOM evidence or all installed paths.
- `http-failed` preserves qualified inflight read
  requirements when queued successor work exists; it
  does not blindly declare read progress or fabricate a
  retry when no successor was queued.
- `src/gesso/live/browser/shell.cljs` interprets
  physical effects and copies issued generation fields
  into timer events. A failed provisional installation
  is a local presentation failure, not authoritative
  command failure. Some currently synchronous host
  effects are implementation choices, not proof that
  asynchronous admitted completion is impossible.
- `src/gesso/live/browser/optimistic.cljs` leaves a
  provisional DOM marker intact after `:await-authority`
  settlement until the canonical Live/HTMX presentation
  replaces it; semantic settlement never relabels
  provisional DOM as installed authoritative content.
- Source-inspected `test/gesso/live/browser/adapter_test.cljc`
  covers stale timeout generation, authoritative
  supersession, successful optimistic completion awaiting
  authority, physical fragment request/swap generation,
  and preservation of outstanding requirements.

These code and test examples do **not** certify generic
indeterminate multi-target DOM compensation, all callbacks
and host event-source truth, HumanHelp current assignment
eligibility, installed production write paths or formal
end-to-end Choreo refinement. The new normative obligations
are finished-system design, not an assertion of current
implementation completeness. No code or tests were changed
in Gesso; **no JVM/Node/Chromium/XTDB/browser integration,
Python assembly or formal proof tests were run**.
