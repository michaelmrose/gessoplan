## Material R4 requirements preserved

1. **Views own semantic intent rather than duplicating machinery.**
   A card supplies Claim/Reassign operation identity, Request and
   helper arguments, and presentation. Browser plan, transport,
   model authority and generated asset details derive from or
   are checked against the canonical assembly.
2. **Rendered action is not current authorization.** A positive,
   executable helper Claim or manager Reassign control can be
   validly rendered from current knowledge, but the trusted
   public model still checks authenticated principal, current
   Request, RequestAssignment, Membership/Organization and
   guarded transaction at execution.
3. **Enabled requires every applicable edge; unavailable retains
   semantic identity.** R4 rejects a visually disabled Claim
   whose form still submits a protected POST, and silent
   downgrade from a malformed Choreo operation to anonymous
   HTMX. Permanent unavailability does not fulfill HumanHelp
   positive product acceptance.
4. **Effective physical requests, not only a button attribute.**
   The normalized route matcher must cover concrete path
   parameters, method distinction, forms, inherited HTMX,
   detached submitter form ownership, relevant browser
   defaults and overrides for the selected profile.
   Conflicting duplicate Hiccup spellings and additional
   physical methods on a canonical control must not bypass
   checking.
5. **Dynamic output is checked at the last applicable structured
   boundary.** Static snapshots cannot enumerate all future
   cards. The emitted Hiccup value must be checked against the
   correct admitted assembly after component expansion and
   before serialization. An earlier view-model check or manual
   optional checker is not systemic production enforcement.
6. **Raw output is a genuine scope limit.** Pre-serialized Ring
   HTML, streaming, asynchronous responses, cached fragments,
   alternate servers and error/redirect paths require their
   own admitted boundary or an explicit exclusion. Merely
   naming an escape hatch does not satisfy a whole-managed-
   output promise.
7. **One checked occurrence, no untrusted re-evaluation.** R5's
   stronger treatment of lazy descendants, mutable component
   values and serializer-time code is retained and sharpened:
   sharing one Hiccup reference does not guarantee the second
   traversal emits the same effective request. A bounded
   immutable realization or equivalent qualified protocol is
   needed.
8. **A valid Claim can commit before a malformed *response*
   is detected.** R4's C42 example with incomplete Cancel
   arguments remains normative. The output guard blocks
   malformed delivery without retroactively rejecting or
   undoing the authoritative Claim. Correlated delivery may
   disclose known incorporation; a lost/incompatible error
   response leaves the client in an unknown state requiring
   admitted resolution.
9. **No false inference from errors or metadata.** Failed
   rendering does not prove no mutation; a current Request
   card does not prove historical command attribution; a
   browser-transmitted metadata or successful report map
   does not grant principal or command authority.
10. **Positive/adverse testing through the actual boundary.**
    A real eligible Claim and Reassign remain essential;
    seventeen concrete histories expose missing arguments,
    form bypasses, detached submitters, duplicate attributes,
    unrecognized implicit defaults, inherited host context,
    unstable lazy children, lost guard scope, cache disclosure,
    postcommit response failures, raw responses and legitimate
    plain HTMX reads.

R4 displayed illustrative `gesso.render/check-surface!`,
`gesso.render/effective-action` and `semantic-response`
functions. These were not imported as promised current APIs.
The desired properties are preserved using R5's source-owned
assembly and actual-response contracts. This also avoids
reverting to the longer R4 imperative example style where
the R5 semantics are clearer.

## Stronger R5 architecture retained

R5 07.07 already required exact final output checking,
a selected HTML/HTMX profile, inheritance/submitter/defaults,
DOM composition context, a single checked occurrence, systemic
synchronous/deferred/stream/cached/error response coverage,
explicit response cache partition and scope, and separate
postcommit settlement/recovery behavior. These were retained.

The focused 07.07 improvements:
- Explicit eligible Claim and manager Reassign positive paths
  without equating rendering to current model permission.
- Explicit native/HTMX concurrent action enumeration: one
  certified `:hx-post` does not whitelist a second physical
  operation on the same element.
- Host/form/base URL and target/fragment dependency treatment,
  with unsupported scope instead of silent green reports.
- Explicit distinction between one top-level Hiccup reference
  and one reproducibly materialized rendered occurrence.
- Synchronous dynamic-guard constraints from real Gesso source:
  missing propagation across async completion or raw HTML
  cannot be silently treated as covered.
- Split cache structural validity from authorization/freshness
  and principal-specific disclosure at each delivery.
- Preserve model historical incorporation versus client unknown
  under HTMX non-success response and loss; no fabricated
  command rejection or compensating write.
- Seventeen positive/adversarial histories tied to actual
  production response and browser boundaries.

## Actual Gesso v1622 correspondence and limitations

- `src/gesso/http.clj` provides a dynamically scoped
  `*html-response-preflight*` and
  `with-html-response-preflight` hook. It validates the
  supplied Hiccup value just before Rum serialization via
  `html-response`, retains the same top-level value and
  composes nested guards outer-first. With no guard installed,
  `html-response` retains its historical unguarded behavior.
  This dynamic scope alone does not capture after-return
  callbacks or prove that lazy descendants render identically.
- `src/gesso/live/application_preflight/biff.clj` and
  `src/gesso/live/application_preflight.clj` offer the
  canonical Biff wrapper/module/startup and
  `require-rendered-surface!`. They recheck the current
  application/artifact for responses on the wrapped canonical
  `gesso.http/html-response` path, but do not establish
  deployed server adoption, absence of later handler
  replacement or raw pre-serialized HTML coverage.
- `src/gesso/live/application_preflight/rendered_request.clj`
  enumerates explicit HTMX request methods, explicit native
  POST forms, form-associated submitters, implicit
  submit-button type and submitter overrides; it checks
  duplicate keyword/string attribute spellings. Its own
  docstring explicitly excludes unspecified form action
  defaults, JavaScript-initiated requests and unsupplied
  document/ancestor context. This must not be inflated into
  a complete browser behavior proof.
- `src/gesso/live/application_preflight/affordance.clj`
  checks canonical Choreo request identity, detects added
  actions on marked nodes and anonymous protected-route
  requests under a small literal plus colon-parameter
  route template vocabulary. It does **not** model arbitrary
  router precedence, wildcards or every browser rewrite.
- `src/gesso/live/application_preflight/rendered_surface.clj`
  shares the scanner between supplied static snapshots and
  actual per-response dynamic checks. The snapshot report
  does not establish producer completeness.
- Relevant regression tests are
  `test/gesso/live/application_preflight/rendered_request_test.clj`,
  `submitter_override_test.clj`,
  `rendered_response_test.clj` and `biff_test.clj`.
  They test concrete bounded cases including recognized
  submitter overrides, dynamic report rejection, nested
  guards and raw response scope. These were inspected as
  source; there is **no fresh Gesso test-suite pass** for
  this editorial revision.

Current implementation limitations in dynamic/implicit host
context, deferred responses, raw response bypass, exact
one-occurrence materialization and production adoption
remain genuine future end-state obligations. They do not
justify weakening Gessoplan's stronger contract.
