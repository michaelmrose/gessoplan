# R5.1 Part II — 02.07 Required Correspondence Checks Are Semantic Gates

**Baseline:** R4 `main`, Part II, “Required correspondence checks are semantic gates.”
**Candidate:** `r5.1` section 02.07.
**Status:** focused R4-preservation review, not an implementation certification,
proof of universal refinement, or cross-section Part II acceptance.

## R4 normative requirements preserved

- Correspondence categories are independent and operation-relative: resource,
  command, execution, plan/artifact, authority/basis, ownership, principal,
  authorization and continuity/provisional state.
- The checks are semantic admission gates, not debug assertions or one
  compulsory universal generation counter.
- An event class and its semantic owner determine which checks apply; not all
  asynchronous events are execution-private.
- Execution-private callbacks, shared fragment advisories, authoritative
  acquisitions and continuity completions retain their distinct owners.
- An idle board may admit a registered shared advisory, while a retired
  private callback cannot confer rights by asserting `:shared? true`.
- An admitted shared advisory cannot restore a private execution or directly
  install protected authoritative content.
- All supported paths that change semantic state require appropriate
  admission; no unchecked callback bypass is part of the supported contract.

## R5 improvements retained

- Resolve event class and owner from registered producer and admitted
  contract, not an untrusted event `:event/class` or free-form assertion.
- Register producer provenance separately from event-supplied correlation
  values. Recheck current applicability when a physical action runs.
- Retirement immediately removes semantic rights even while physical cleanup
  is pending. Command reconciliation remains separately admitted.
- Browser cooperation does not prove an adversarial browser complied; trusted
  authoritative security must be enforced by the server.

## Changes in this revision

1. **Specify the gate without demanding one function.** A common semantic
   gate is a coverage requirement across event classes, not a mandatory
   universal owner record or a single exported API.
2. **Keep evidence scoped.** Equality/correlation is not proof of producer
   origin, current permission, progression or business outcome. Browser
   callback rejection does not imply durable command rejection.
3. **Disallow downgrading via event data.** Required checks and allowed
   recovery paths come from admitted registrations, not caller-selected
   subsets or silent reassignment to shared ownership.
4. **Expand representative event classes.** Transport/local callbacks,
   timers, and optimistic settlement have distinct required correlations
   alongside the R4 examples.
5. **Require actuation-time applicability where asynchronous.** Earlier
   allowance cannot authorize a delayed DOM mutation after supersession.
6. **Add negative coverage matrix.** Reclassification, stale generations,
   missing subscriptions, inadequate observations, delayed physical effects,
   and missing command responses remain distinct failures and uncertainties.

## Correspondence to Gesso application-assurance

- `gesso.live.browser.adapter` already declares normalized event families,
  closed event keys, execution and request generation checks, Live refresh,
  continuity, optimistic settlement, and swap gating.
- `gesso.live.browser.shell` dispatches normalized transitions, installs
  adapter state before interpreting effects, and controls physical callbacks.
- Those source facts establish an implementation substrate, not automatic
  evidence of trusted producer registration, verified physical actuation,
  security against a hostile browser, or all possible event-path closure.
- In particular, the pure adapter accepts normalized event data; its value
  checks alone cannot authenticate the physical callback producer or
  establish a trusted authoritative command outcome.

## Deferred cross-part obligations

- 02.06 and 02.08: physical producer, resource and principal boundaries;
  the adversarial browser remains untrusted.
- Parts IV–V: durable command outcomes, authority progression and Live
  invalidation/advisory scope.
- Part VI: normalized events, shell interpretation, effect actuation,
  ownership retirement, HTMX swaps and browser refinement tests.
- Parts VII and IX–X: complete event-path coverage, physical correspondence,
  explicit trust premises, and reusable assurance evidence.

No normative R4 event-owner distinction has been intentionally discarded.
The `req-owner-relative-event-admission` anchor remains intact. This audit
does not assert the stronger checks already pass in the current Gesso runtime.
