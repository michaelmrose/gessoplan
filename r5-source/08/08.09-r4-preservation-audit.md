## R4 obligations preserved or strengthened

1. Missing optimistic basis never erases the semantic operation and never licenses an anonymous POST to a protected lifecycle route. Preserved from the R4 “Missing basis never erases operation identity” and “No anonymous fallback” passages (approximately lines 983–1002, 3474–3491).
2. Claim presentation eligibility is distinct from real Request/RequestAssignment and actor-dependent authorization. The browser's command envelope, target ID and optimistic CSS cannot confer production permission.
3. R4's pending presentation ownership and conditional rollback survive (approximately lines 3493–3523). The revised design distinguishes current execution, actual target instance, permitted rollback baseline, retirement, and a separate lingering unknown-command indicator.
4. R4's route/protocol safety (approximately lines 3525–3556) remains the responsibility of checked rendering and the trusted server. A route for Claim cannot execute a Cancel command or an operation for another Request.
5. The real Claim and lifecycle browser matrix (approximately lines 3718–3860) still requires an actual rendered click, generated command, production transaction, visible authoritative settlement and persistent reread; top-level browser acceptance cannot inject the command by hand.
6. R4's stale optimistic scenario (approximately lines 4594–4604) remains an essential negative case. The new section adds physical target generations and nested provisional snapshots so an implementation cannot pass by checking only its command ID.
7. R4's already-incorporated and connected recovery matrix (approximately lines 5060–5125) remains. An observed claimed card cannot be used to invent command-specific historical incorporation; late rejection or absent records do not mean the original write failed.
8. HumanHelp's real two-person and multi-operation acceptance is preserved. A synthetic fixture or successful button animation is not the independent product oracle.

## R5 architecture retained and refined

- Keep the preferred R5 distinction between portable semantic execution, browser physical effects, current authoritative facts and durable command uncertainty. Do not restore an independent R4 optimistic state machine.
- Treat C42 (user intent), E42 (local execution), H1/H2 (transport), T1/T2 (physical target) and G1 (provisional generation) as different lifetime and evidence domains.
- Specify a command historical outcome as source-bound, retention- and disclosure-qualified. A positive incorporation record and a complete current Request observation answer different questions.
- Spell out exactly which snapshot a rollback can restore. A provisional snapshot captured while another provisional generation is installed is not a later terminal baseline.
- Recover command uncertainty through a dedicated authenticated recovery owner after its card is retired; old browser effects cannot be resurrected by a stable command ID.
- Preserve independently outstanding advisory/Refresh obligations across one user's optimistic card success.
- State conditional liveness and record expiry without falsely interpreting exhaustion as rejection.
- Make useful adversarial histories mandatory independent of static assembly acceptance.

## Gesso source evidence inspected

- src/gesso/live/browser/optimistic.cljs delegates semantic ownership to the portable choreography and adapter. Its rollback checks physical ownership and a safe captured baseline. If rollback is missing, ownership is lost or its baseline was provisional, it requests authoritative refresh rather than installing an unsafe old snapshot.
- src/gesso/live/browser/optimistic_htmx.cljs attaches provisional execution to HTMX configRequest/beforeRequest/beforeSend and correlates settlement through XHR. It classifies transport/network failure without fabricating a failed semantic settlement. Its current bridge needs synchronous provisional derivation.
- src/gesso/live/optimistic/protocol.cljc defines distinct command-id and execution-id, optional observed basis, typed settlements and authoritative observations. Decoding those shapes is explicitly not trusted principal or provenance checking.
- src/gesso/model/command_resolution.clj offers experimental plan construction for an atomic command-result record, exact-binding comparison and a read/disclosure-dependent reconciliation decision. Its stated assumptions explicitly leave HumanHelp authorization, complete XTDB physical correspondence, durable publication and unknown-delivery liveness unestablished.
- src/gesso/assurance/proof/xtdb_gateway_command_outcome_bridge.clj has one bounded process-local reported-outcome/readback observation. It does not confer retry authorization, transaction causality, or a completed end-to-end settlement proof.
- src/gesso/live/browser/adapter.cljc, shell.cljs, and continuity.cljs provide scoped physical ownership mechanics. Inspecting these and their surrounding code is source evidence, not running an actual browser suite.

## HumanHelp implementation correspondence

- src/net/humanhelp/example/optimistic.clj binds decoded commands to the selected Request route and runs through a private prepared server. Its route binding is a meaningful guard, but it is not an authenticated, durable historical command lookup across browser reload.

Neither file by itself proves all browser/timeout/reload/record-retention behavior. These test files were read, not executed.

## Positive and adverse test histories to preserve

1. Real eligible Claim produces its command through the generated browser and persists a guarded Request/assignment result visible after reload.
2. Missing basis yields an admitted alternative or unavailable control, not a silently downgraded POST.
3. Lost response after commit leaves C42 unknown until disclosed exact historical incorporation is observed, without executing Claim twice.
4. Reuse of C42 with altered Request, operation, principal or arguments is rejected without result disclosure or new mutation.
5. Current R17 can be refreshed while C42 remains historically unresolved.
6. Later T2 authoritative installation defeats delayed E1 rollback of T1.
7. E2 cannot restore E1 provisional DOM as terminal authority; install-failure compensation is distinct.
8. Logout, disclosure revocation, browser reload and incompatible plan retirement do not let stale effects or recovery references grant authority.
9. Approved independent Request actions may overlap; conflicting commands honor declared dependency/conflict policy.
10. Absent/expired records, limited retries and publication crashes produce truthful diagnostics rather than invented rejection.
11. Browser-positive tests exist for every required lifecycle operation, not only synthetic plan tests.
12. Local optimistic adoption does not clear independent remote advisory or one-use Refresh debt.
