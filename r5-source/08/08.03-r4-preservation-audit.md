## R4 requirements retained

1. **Full independent HumanHelp product oracle.** Authentication;
   real Create and immediate local creator adoption; Claim,
   Unclaim, Mark on the way, Complete, Cancel and manager
   Reassign; local search/order/mine-first/unclaimed-first/
   terminal filtering; details/continuity; separately
   selected response flow; two-client advisory and explicit
   one-Refresh; rejection/unknown/reconnect recovery are
   separate requirements independent of the present operation
   catalog. A permanently disabled or omitted capability
   fails despite green structural preflight.
2. **One lifecycle realization mechanism.** The six semantic
   operations retain their original identity through actual
   rendered action, current generated browser plan, loaded
   JavaScript/HTMX, trusted route, production Request model,
   authoritative settlement/acquisition and physical DOM
   adoption. Missing observed basis, handler or plan cannot
   downgrade to anonymous mutable HTMX.
3. **Reassign is a real reachable capability.** It requires
   visible legitimate target selection, manager privilege,
   target eligibility and genuine positive success. A
   read-side target menu grants no current authorization.
   No automatic synonym is invented for "Take over".
4. **The Claim positive case begins at a real button.**
   The browser runtime, not the test, supplies
   `__gesso_live_optimistic_command`. Lower-level server
   tests that manually prepare a protocol command remain
   valuable but do not prove the client wire-generation
   edge. Accept only a real eligible production model
   commit and fresh persisted Request/primary assignment.
5. **Authority/knowledge separation.** XTDB observed basis
   X17 is scoped client knowledge, not a Request revision
   or unconditional stale veto; the actual trusted
   Request/Membership guard decides current eligibility.
   Provisional DOM state cannot establish authoritative
   Request ownership.
6. **Concurrency/uncertainty.** Two distinct competing
   Claims must not both create active primary ownership
   from the same open state. A possibly incorporated
   C42 remains unknown until correlated authoritative
   evidence, and replay must not create a second
   logical mutation. Postcommit rendering or SSE
   failure does not reverse the model commit.
7. **Different settlement interfaces.** Current model
   `:commit/status`, protocol-v3 `:confirmed`,
   future Part IV authoritative `:committed`/
   `:already-incorporated`/`:rejected`/
   `:commit-unknown`, and browser `:accepted`/
   `:rejected`/`:unknown` have typed mappings.
   A current card never proves which command caused it.
8. **Physical continuation and permitted adoption.**
   An initiator's successful Claim may authorize its
   bound card; a remote participant receives advisory
   until its separate acquisition grant. Late or
   superseded callbacks cannot resurrect provisional
   DOM or erase unrelated advisory/Refresh debt.
9. **Test ladder and no false acceptance.** Source
   model/Choreo, preflight, rendered-surface, HTTP
   integration and real Chromium are distinct
   gates. Browser acceptance checks actual
   browser-generated command, operation, route,
   authoritative outcome, post-acquisition DOM
   and persisted reload, with console/request
   faults identified. A manually injected
   protocol command proves only a server fixture.
10. **Positive and adversarial obligations.** Twenty-one
    explicit histories cover eligible Claim,
    disabled button, missing basis, racing Claim,
    stale Membership, unrelated basis advance,
    postcommit loss, same C42 replay, Reassign
    supersession, DOM-only success, lifecycle
    operations, manager target, remote advisory,
    consumed Refresh, stale callback, invalid
    authentication and bounded Chromium scope.

## Actual HumanHelp dev source correspondence

- `src/net/humanhelp/example/components/request_card/core.clj`
  renders actual lifecycle buttons through
  `live/post-button`, with source
  `:choreo/op` and binding from
  `board/optimistic-binding`. It keeps
  the Claim operation identity even
  when a justified basis is missing;
  the contract rejects instead of
  becoming an anonymous HTMX POST.
- `src/net/humanhelp/example/board.clj` exposes
  current production-backed affordances,
  source-scoped observed XTDB basis,
  and read-side manager-target discovery
  via public Membership/Organization/
  User models. A manager may see a
  legitimate Reassign menu of *other*
  eligible helpers; a read-side menu
  does not prove commit authority.
- `src/net/humanhelp/example/components/request_card/core.clj`
  includes a real Reassign dropdown,
  trigger and target-helper operation
  buttons. This is **not** merely a
  disabled future placeholder.
- `src/net/humanhelp/example/optimistic.clj`
  authenticates the production User
  identity, checks operation/route
  correlation and delegates through
  the production Request choreography
  registry to the public model.
- `test/net/humanhelp/example/app_integration_test.clj`
  contains real XTDB/production Request
  HTTP integration with a *manually
  constructed* valid optimistic command
  for the trusted route. That tests
  an important server seam but cannot
  certify the real rendered button.
- `test/net/humanhelp/example/components/request_card/core_test.clj`
  asserts the source-rendered Claim
  button preserves its semantic
  operation and fails closed on
  missing optimistic basis/binding.
- Critically,
  `test/net/humanhelp/example/chromium_acceptance.clj`
  is a **real Playwright/Chromium**
  acceptance source file, run through
  its explicitly invoked `-main`,
  not automatically in ordinary JVM
  tests. It contains browser-produced
  protocol-v3 commands, Claim ->
  Unclaim -> Claim -> Mark on the way
  -> Complete, independent Cancel,
  and manager Reassign using the
  rendered target dropdown. It
  verifies fresh model/reload states
  and browser network/console
  diagnostics for those selected
  scenarios. This was source
  inspection, **not a fresh passing
  Chromium test execution**.
- That existing browser coverage is
  meaningful and must not be erased
  by writing as though Reassign
  were still unavailable. It also
  does **not** establish all
  concurrent C42 replay/unknown
  scenarios, multi-client remote
  one-Refresh correctness, details,
  response-flow selection or every
  required product capability.

## Gesso correspondence and open proof boundaries

Gesso's `gesso.live.optimistic` browser
and server projection, `gesso.live.ui`
and application-preflight functions
supply the generic structural and
execution substrate exercised by
HumanHelp. Real Claim model mutation
uses production Request/RequestAssignment
guards and Gesso model transaction
mechanics. The separate
`gesso.model.command-resolution` helper
is experimental and does not
certify full HumanHelp durable
same-command incorporation, runtime
retention, authenticated replay or
unbounded distributed contention.
A generated browser asset/semantic
admission result is not a trusted
runtime principal or proof of
current Membership. Physical XTDB
and browser-deployment contracts
remain qualified evidence classes.
