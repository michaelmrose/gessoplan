## R4 requirements recovered and correctly located

1. **The test ladder is not a single synthetic oracle.** R4 separately owns production-model checks, Request Choreo checks, assembly/preflight, concrete Hiccup/render tests, lower-level server integration with manufactured commands, and real Playwright/Chromium. R5 added backend, physical adapter and installed-host distinctions. This revision retains them and explicitly states the proof each layer cannot supply.
2. **Claim must originate from the rendered control.** R4's genuine Chromium Claim sequence (lines 3718 onward) requires a real authenticated page, generated runtime command, real HTMX route, public Request operation, authoritative mutation/settlement, final DOM and persistence after reload. Top-level tests may not inject `__gesso_live_optimistic_command`; a lower-level server fixture may legitimately inject it only to test its narrower seam.
3. **Independent lifecycle capability oracle.** R4's Claim, Unclaim, Mark, Complete, Cancel, Reassign positive matrix is not computed from exposed operations. The current model's persisted `:done` and `:cancelled` statuses are retained; a historical R4 illustrative JS row used `completed`, which is not promoted to production vocabulary. Reassign target-selection and ended previous primary remain explicit.
4. **R4's 28 rich-board requirements survive by behavior.** Authentication, immediate creator Create, remote-only advisory, visible one-use Refresh signal and click, remote/local selective adoption, advisory debt, Refresh races, search, both sort priorities, terminal filtering, details/continuity, correct terminal presentation, lifecycle actions, response flow, reconnect, stale optimistic callbacks, malformed protocol and already-visible remote lifecycle policy remain independent acceptance scenarios. The previously selected *advisory-only* remote lifecycle policy in R5.1 is used; R4's former open decision is not reinstated as an undecided policy.
5. **The response-flow product decision is still open.** Part VIII `decision-humanhelp-response-flow` remains a specific independent acceptance blocker; a working model route or generic form cannot be counted as selected and accepted response interaction.
6. **R4's concurrent two-user scenario cannot be reduced to two clicks.** R5's controlled backend preparation/submission barrier is retained and sharpened: prove that the same protected prestate was contested at the real guarded boundary, not only that browser actions overlapped in wall time.
7. **A negative adoption claim needs a causal milestone.** R4 remote R absent before explicit Refresh must be tested after R's actual commit and the relevant advisory has reached/qualified B; a one-frame count before delivery is vacuous. Source/adapter event traces and absence of prohibited reads/installs are better than arbitrary sleeps.
8. **Controlled malformed fixtures must use production construction.** Preserve R4's controlled bad operation, missing plan/route/capability, stale artifact, anonymous form and malformed protocol distinctions, but leave their detailed shape to 08.13. Each bad candidate has a valid counterpart; rejection of every control cannot pass.
9. **Real outcomes remain authoritative.** UI-only Claimed/Done and a green toast cannot replace persisted Request/assignment readback. Failed postcommit rendering does not revoke an already committed Request transition.
10. **Recovery scope is explicit.** R4's lost outcome, crash-before-publication, incomplete Refresh, reconnect and stale callback cases survive. R5's unknown/not-rejected and bound command recovery are preserved without declaring the current HumanHelp implementation crash-resumable.

## R5 architecture retained and revised

- Separate source-owned production rules, semantic-machine oracles, backend transactions, application/structured-render checks, browser adapter, installed host and independent user acceptance.
- Use authentic production fixtures and qualified exception fixtures; distinguish a public seam-mocked test from connected cross-model persistence evidence.
- Preserve R5 lifecycle and board matrices; add the selected HumanHelp remote advisory policy, exact command/presentation provenance, and real generated-asset/handler evidence.
- Preserve deterministic backend barriers, but require that the instrumentation does not change the guard semantics or serialize away the attempted race.
- Preserve positive model assertions and negative evidence gaps: fault-free outcomes versus intentionally lost delivery, historic command attribution versus current card state, physical installation versus authorized adoption.
- Keep fault/qualification and backend version invalidation separate from structural check failures and ordinary model rejections.
- Require a proposition-specific source/version/evidence ledger; no receipt alone is an end-to-end certificate and no failure suppression is an acceptance mechanism.

Its explicit caveats include absent deployment-wide writer closure, causation and universal refinement. It is not a complete concurrent HumanHelp Membership/Claim proof.
- `test/gesso/assurance/proof/xtdb_gateway_unknown_command_reconciliation_test.clj` checks read-only command-record outcomes and refuses to infer retry authority or historical causality from a matching record or absent record; independently seeded records are explicitly not atomic incorporation proof.

## Required paired acceptance examples

1. Genuine successful Claim from real rendered control versus a valid server-side command manufactured by a narrow integration fixture.
2. Reassign with a legitimate different target helper and preserved state versus forged/expired target Membership.
3. Real guarded two-helper race over one Request prestate versus simultaneous clicks without contested guard evidence.
4. Creator's local S visible after Remote R advisory, while R and its debt remain outside adopted membership.
5. Advisory delivered, B has not adopted R, and explicit one-use Refresh later adopts R; no vacuous pre-delivery absence.
6. Remote lifecycle changes to an already-visible R remain advisory-only until permitted Refresh/local read.
7. Search/sort/terminal visibility operate on adopted data without mutating Request or secretly expanding authoritative query membership.
8. Details/focus and scroll survive only legitimate same-identity replacement; lost disclosure retires protected DOM.
9. Unknown C42 after a deliberately lost result remains recoverable without inferred rejection, new C43 retry or DOM-only confirmation.
10. Known commit followed by output failure is not undone; non-delivery is reconciled from permitted authority.
11. Crash-after-commit publication gap must use actual durable/alternative recovery, not a test that merely invokes a publish function.
12. Mixed A/B assets, retired effects, and wrong installed Biff module/handler do not gain protected execution rights.
13. Two real authenticated sessions cannot share a principal fixture accidentally or leak tenant identity through Live metadata.
14. No blanket suppression of unrelated console, page, HTTP and network errors makes a fault test green.
15. Required response flow remains an explicit not-yet-accepted product obligation until a chosen implementation and test are provided.
