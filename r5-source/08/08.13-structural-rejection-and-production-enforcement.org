** Structural rejection and production enforcement

Controlled defects are introduced before admission or at an explicitly tested
runtime replacement boundary. A copied inspection report is not a credential;
associating new values into a report must not manufacture a current application.
Each negative case has a paired valid path through the same enforcing boundary.

| Defect | Required enforcing boundary and evidence |
|--------+-------------------------------------------|
| Unknown semantic operation in a view | Preparation/construction rejects it with operation and source context; no fuzzy execution. |
| Missing required browser plan | Assembly rejects the missing realization edge; no ordinary HTMX fallback. |
| Missing physical route | Closure reports the required transport and unresolved dispatch binding. |
| Route bound to a different operation/executor | Construction or installed-dispatch guard rejects the mismatch before the prohibited model invocation. |
| Missing trusted capability | Construction rejects a statically known omission; runtime capability failure follows its typed path without unauthorized submission. |
| Missing initial acquisition or recovery path | Admission rejects the incomplete managed scope even though it cannot predict whether a future dynamic failure occurs. |
| Enabled render lacks basis required by its selected plan | Concrete preparation/render rejects it; it cannot drop semantic identity. |
| Anonymous action on a lifecycle route | Actual served-output guard rejects it and identifies the semantic route collision. |
| Stale manifest or wrong asset bytes | Build/startup/serving rejects the mismatched subject under the selected receipt contract. |
| Forged build labels without qualified production | The application does not accept copied labels as compiler correspondence. |
| Malformed command protocol or forbidden actor field | Trusted input boundary rejects it before mutation, with the exact selected typed outcome. |
| Browser advisory used as an installation grant | Coordinator/effect admission rejects the unauthorized read or adoption. |
| Retired target, request, or continuity slot | Final effect admission denies the stale physical act. |
| Handler checked but a different handler installed | Host adoption evidence fails; a green constructor report cannot satisfy the gate. |
| Unclassified relevant writer | The applicable coverage claim is blocked or retains the explicit accepted premise; the writer does not disappear from the report. |
| Required user capability removed from an otherwise closed assembly | Independent acceptance fails. |

Diagnostics use stable structured fields for category, subject, source location,
expected/actual binding where safe, and first enforcing boundary. Tests assert
those fields rather than depending only on an English exception-message regex.
Diagnostics redact credentials, protected content, and complete command payloads
unless the relevant diagnostic audience is explicitly authorized.

Static preflight need not predict dynamic facts. It must still require declared
handling and recovery paths for dynamic conditions that can strand an operation:
unknown outcome, failed acquisition, denied disclosure, lost subscription,
obsolete plan, exhausted retry budget, and unavailable provider. A structurally
valid “send” with no permitted continuation after uncertain delivery is incomplete.
