## Principal editorial decisions

1. **One source of physical route truth.** Preserve R4's ownership split: production Request Choreo owns semantic operations, example.routes owns actual route identities and specifications, example.app owns handlers, example.application-preflight owns composition, and Gesso owns the generic checker. Do not turn the charter into an independent route inventory that can drift from the real Reitit router.
2. **Operation, route, and physical writer coverage are not synonymous.** Preserve R4's separation of operation supported by server, operation exposed to user, and eligible positive product capability. Explicitly classify Create, initialization, external callbacks, jobs and all physical writers. A missing inventory is unknown, not no-interference proof.
3. **Real rendering is a checked physical edge.** Preserve R4's structured response and anonymous lifecycle POST constraints. Expand them to effective HTMX coordinates, native form owners and submitter overrides, disabled state, deferred/serialized content, cached/OOB/error responses and read/disclosure. This is a qualified supported-language contract, not an impossible promise to statically inspect arbitrary JavaScript.
4. **No post-commit retroactive rejection.** Render or DOM failure after the model has committed cannot undo domain truth. The client needs separately qualified recovery; a static scanner does not establish physical installation.
5. **Build artifact identity is not sufficient.** Preserve R4's current-browser requirement and R5's generated-source/receipt approach; require actual shipped bytes, dependencies, serving URLs, immutable publication set and client load compatibility. A hash binds bytes but does not prove arbitrary compiled program semantics.
6. **Deployment compatibility has explicit generations.** A/B mixed routes, plans, clients, assets and callbacks cannot acquire the same admission merely by sharing an artifact filename or command ID. C42 durable resolution is not license to resume retired E42/target/plan effects.
7. **Actual Biff/Aleph lifecycle joins are mandatory.** Biff native module and start order, checked Ring handler installation, Aleph traffic exposure, initialized Live/XTDB providers and FX prerequisites must be verified against a named supported host version. Current Gesso's caveats are preserved honestly rather than rebranding them as universal protection.
8. **Multi-client ability is independent.** Request-scoped ownership and production XTDB exclusion must permit independent authorized clients; a global single-flight wrapper cannot pass the HumanHelp acceptance oracle.
9. **Formal limits are qualified.** Commit atomicity, command outcome, query/absence visibility, compiler, runtime, source-to-serving asset identity and backend assumptions need their own versioned evidence. This section never certifies every XTDB execution.
10. **Positive fixtures remain mandatory.** Preserve R4's insistence that rejecting all malformed requests is not sufficient; independent Claim/Create/other lifecycle good paths and actual Chromium HTTP/DOM/DB execution must still work.

## Gesso implementation correspondence (source inspected; tests not executed)

- src/gesso/live/application_preflight.clj exposes check-application-assembly, require-application-assembly!, check-rendered-surface, checked-rendered-response!, application-handler-module and start-biff-application!. Its own docs make clear that verified current assemblies do not establish every producer/entrypoint was guarded.
- src/gesso/live/application_preflight/biff.clj enforces the **canonical application-handler module** in the supplied modules Var and requires its qualified ID to be the first lifecycle start-order item. The installed wrapper operates on :biff.ring/handler. It explicitly excludes direct biff.core/start, handler replacement and pre-serialized responses.
- src/gesso/http.clj binds a dynamically scoped pre-serialization guard around canonical html-response, composes nested guards outer-first and rejects nil/false or thrown validation. It cannot prove that callers use this renderer or that deferred work outside its dynamic scope remains guarded.
- src/gesso/live/application_preflight/rendered_request.clj scans canonical Hiccup HTMX requests, native POST forms and submitted form overrides. Its docstring explicitly excludes JavaScript-initiated requests, some form/default cases and markup outside the supplied tree; presence of a scanner is not a complete HTML/physical-transport proof.
- src/gesso/live/application_preflight/rendered_surface.clj composes request-coordinate and canonical affordance scans against operation-summary, but the current pipeline is finite in inspection scope and carries actual source limitations.
- src/gesso/live/browser/entrypoint.clj and build.clj generate a browser manifest/entrypoint, compile CLJS and verify receipt/byte hash/size. build.clj distinguishes its lower-level arbitrary-emitter API from supported generated application build. Compiler correctness, transitive deployed assets and actual loaded script behavior remain independent claims.
- src/gesso/live/browser/artifact.clj verifies manifest/stamp correspondence; not a certificate of the deployment publication set.
- Gesso source provides no basis to claim a universal native-form/HTMX/JS runtime guard, globally atomic deployment or full XTDB backend proof merely from these functions.

## HumanHelp implementation correspondence and concrete mismatch

- src/net/humanhelp/example/routes.clj owns route specs, route IDs, Reitit route-table and handler binding; required IDs are checked, while some optional handlers can be omitted. Physical route facts are not simply constructed from a second handwritten preflight table.
- src/net/humanhelp/example/application_preflight.clj derives operation→route IDs from that route catalog, derives browser declaration from production Request browser plans and composes trusted server/Live/fragment assembly. Its namespace explicitly says dynamic rendering and native Biff startup are separate boundaries.
- src/net/humanhelp/example/app.clj provides real handler mapping for Create, fragments, streams and lifecycle operations. src/net/humanhelp/example/browser_realization.cljs supplies physical realization options to Gesso's generated entrypoint rather than creating a second semantic plan.
- src/net/humanhelp.clj currently calls application-preflight/start-biff-application! with initial-system, #'modules and components. Its modules Var contains Biff/Fx/Graph/XTDB, model transaction, app and other modules **but not the exact** application-preflight/application-handler-module object. Its components sequence consists of init/start functions (config/XTDB/Live/Aleph), not a qualified module-ID start order beginning with the Gesso handler ID.
- Compared to the checked Gesso v1622 startup implementation, that is a **concrete source-level API/assembly incompatibility**: the canonical Gesso check would reject this composition before ordinary service. It does not establish whether the particular archived HumanHelp deployment ran, how any other branch was started, or a production exploit. The plan should require a correct positive startup and deterministic rejection of this mismatch, not merely a negative fixture.
- net.humanhelp/app.clj routes /app to the example application during the proving phase, distinct from unfinished site UI. Positive HumanHelp capability acceptance is still a requirement independent of assembly closure.
- Existing HumanHelp application-preflight tests in test/net/humanhelp/example/application_preflight_test.clj check source-owned route/server/acquisition construction and controlled missing-route failures; they do not alone certify the real startup module order, Aleph serving handler, generated bytes delivered to browser, deferred responses or a complete two-client acceptance.

## Positive and adversarial verification matrix

1. Real canonical module and qualified Biff start order install the inspected handler before Aleph serves protected responses.
2. Absent/duplicate/incorrect module, non-ID start order, and later replaced handler fail before the associated claim is granted.
3. A real eligible rendered Claim produces a Gesso semantic command, reaches the selected trusted Request route and persists a guarded model transaction.
4. Native submitters, detached form owners and inherited/effective HTMX attributes cannot silently reach a reserved semantic route without protocol.
5. An ordinary read-only path succeeds without inventing a Choreo operation, while a deliberate ordinary writer has declared protected coverage.
6. Create, asynchronous jobs and external writers cannot bypass declared model rules under the configured assurance policy.
7. A deferred/streamed/partial OOB response after handler return receives actual final-output checking, or the selected profile refuses that output path.
8. Browser build source, manifest, compiler, emitted bytes and receipt match; stale manifest and forged receipt fail distinct evidence checks.
9. The script and all required assets actually served to the browser match the admitted immutable A publication set.
10. Deploying B while old A clients persist either pins compatible A assets and server operation contracts or forces qualified reload, with no stale A callback actuation.
11. Failed B build/preflight/start does not expose a half-activated application or leak owned live/db/HTTP resources.
12. Concurrent independent authenticated clients execute permitted operations; same-Request conflicts obey atomic guard/exclusion, not a global one-use lock.
13. Backend qualification explicitly covers the observed guard, uniqueness, query and command evidence required by the positive cases.
14. Actual browser HTMX/DOM/XTDB tests confirm persistence after reload and reject DOM-only success, without hand-injected top-level command wire data.
15. All six lifecycle operations remain independently eligible and testable despite the existence of structural rejection fixtures.
