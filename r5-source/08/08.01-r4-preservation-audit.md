## R4 obligations retained and sharpened

1. **Selected real proving application:** HumanHelp's `/app` is
   the production-backed `net.humanhelp.example.app` during this
   milestone. The unfinished eventual site UI is a separate work item;
   tests do not make it the hidden actual integration target.
2. **No parallel example model:** persistent Request and
   RequestAssignment, User, Organization and Membership state and
   policy come from the real `net.humanhelp.site.model.*`
   owners. An example-only store or simplified eligibility
   policy cannot replace a missing production model operation.
3. **Production-model migration before workaround:** an invalid
   Request/assignment/authorization transition belongs to
   production model code. A browser or UI shim that produces
   plausible cards does not qualify as the implementation fix.
4. **Model-owned Choreo:** `request.choreo` coordinates
   public `request.core` operations and the Gesso
   protocol. A physical `:helper` browser participant
   is not Membership authority, nor proof of requestor
   or manager permission. Trusted actor, target
   helper, physical server and role are distinct.
5. **One canonical assembly:** real browser declaration,
   semantic operation capability, issued server
   executor, route map, fragment acquisition,
   publication, generated artifact and rendered
   surfaces are joined without a test-only
   shadow registry. Builder outputs are
   not trusted model capabilities by themselves.
6. **Separate Create and lifecycle:** source-owned
   Request Create, authentication, protected
   reads, raw writers and fixtures are not
   automatically closed by a six-operation
   lifecycle browser plan registry. Complete
   product acceptance is independently selected.
7. **Real installed service:** a checked
   `:biff.ring/handler` slot alone does not
   prove an Aleph listener consumed it.
   Biff 2 can run `:init` before ordered
   `:start`, so protected workers/listeners
   need actual no-exposure fencing.
8. **Structured rendering and no silent
   downgrade:** a missing optimistic
   basis cannot transform a managed
   Claim action into an anonymous HTMX
   mutation, and early raw serialization
   must not bypass required response checks.
   Valid operations that already committed
   remain committed despite render errors.
9. **Source responsibilities:** example
   `application-preflight`, routes,
   board, Live, optimistic integration,
   components and views own concrete
   realization, not business policy.
   Production cross-model calls use
   the owning model public `*.core` API.
10. **Full application evidence:** closure,
    actual production enforcement and
    positive user behavior remain independent.
    Twelve positive/adversarial histories
    cover Create, Claim, role/actor separation,
    example-only writes, fixture permission,
    partial checked slice, shadow
    test registries, handler mismatch,
    early init effects, uncertain
    settlement, broken browser control
    and stale-generation callbacks.

R4's long illustrative source sketches and helper names
are preserved as *architectural obligations*, not asserted
to be current public APIs or evidence that the final
application is already complete. The stronger R5
source/physical/authority vocabulary is retained.

## Verified HumanHelp `dev` source correspondence

- `src/net/humanhelp/app.clj` selects
  `net.humanhelp.example.app/module`
  as the real `/app` entrypoint; the
  unfinished production site UI is not the
  selected proving surface.
- `src/net/humanhelp/site/model/request/core.clj`
  owns the public Request and RequestAssignment
  interfaces; other models expose their own
  public `*.core` APIs.
- `src/net/humanhelp/site/model/request/choreo.clj`
  exports the six lifecycle semantic operations
  Claim, Unclaim, mark-on-the-way, Complete,
  Cancel and Reassign, with one physical
  `:helper` browser participant and a
  trusted Request-authority projection.
  Its own documentation keeps current
  authorization in production `request.core`.
- `src/net/humanhelp/example/application_preflight.clj`
  derives lifecycle browser plans from
  `request.choreo/browser-plans`, route
  capabilities from `example.routes`,
  execution from the exact prepared server,
  Live acquisition through the two
  managed board fragments, and artifact
  correspondence through Gesso's canonical
  assembly preflight. It explicitly calls
  this the **Request browser application
  slice**, not a universal all-product
  validator.
- `src/net/humanhelp/example/app.clj`
  contains both the distinct production
  Request creation route and the six
  lifecycle route handlers. It uses
  production User and Request public
  model APIs and composes browser-plan
  middleware; it also references
  fixed model-backed Organization/Location
  fixtures. Their presence is not
  proof of all tenant/authentication cases.
- `src/net/humanhelp.clj` creates the
  canonical assembly with the selected
  actual browser artifact path and calls
  Gesso's `start-biff-application!`
  with Biff modules and infrastructure.
  This source establishes an intended
  checked startup, not independent
  physical deployed Aleph adoption.
- `test/net/humanhelp/example/application_preflight_test.clj`
  consumes the production assembly and
  exercises missing issued server
  operation, route and acquisition
  failures rather than inventing a
  parallel checked registry.
  `test/net/humanhelp/example/app_integration_test.clj`
  contains disposable clean-XTDB tests
  involving actual production entities,
  Create and Request lifecycle operations.
  Source inspection is not a fresh
  runtime pass or real Chromium
  product acceptance.
- The full HumanHelp product still
  needs positive authenticated
  Create/Claim/Unclaim/on-the-way/done/
  cancel/Reassign, board, details,
  selected response-flow, remote
  advisory/Refresh and unknown/reconnect
  tests against real production
  semantics. A green lifecycle
  structural checker is not that evidence.

## Gesso correspondence and retained open premises

Gesso `src/gesso/live/application_preflight.clj`
and its Biff, operation-acquisition and
optimistic execution components provide
source-relative structural closure and
a canonical guarded output/startup
entrypoint. They are *bounded* claims:
they do not prove an alternate Aleph
server adopted the installed handler,
all raw/request/background writers are
covered, arbitrary opaque callbacks
are sound, XTDB physically refines every
abstract guard, source JavaScript is
served/loaded correctly in every client,
or every HumanHelp capability works.
That is why the R5.1 finished-system
design retains stronger physical,
security and positive-acceptance
obligations without falsely representing
the current implementation as complete.
