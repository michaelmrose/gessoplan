## R4 preservation and normative improvements

1. **Adopted-cohort search:** search applies to already permitted
   adopted Request/User projections; a query returning zero
   matches proves no matching currently adopted member, not
   absence of Request from the database. Fresh remote membership
   must not be adopted as a side effect of changing search
   or board options.
2. **Declared host-portable normalization:** trim, case
   normalization, substring behavior and Unicode semantics
   must agree between server/client implementations,
   with explicit limits rather than assuming JVM and
   JavaScript case folding behave identically for
   every input. Opaque progression/basis is never
   a search or ordering key.
3. **Search disclosure:** only viewer-permitted Request
   and User display fields enter indexes, hidden
   attributes, search-match outcomes and debug
   presentation. Private email/phone cannot become
   discoverable simply because the visible card
   omits it. Revocation can retire a previously
   admitted index under applicable current policy.
4. **Complete deterministic sort:** mine-first primary,
   unclaimed-first secondary, chosen newest/oldest
   time then stable Request ID. Mine uses real
   requestor or active primary assignment and
   never authorizes a mutation. Unclaimed means
   model-open/unassigned, not terminal.
   Missing viewer identity never means nil=nil
   is "mine".
5. **Malformed time is an error:** the canonical
   date-order projection must validate its
   timestamp and portable comparison contract;
   silently substituting zero/Unix epoch for
   an invalid timestamp is forbidden.
6. **Options drafts, Cancel and live input:** defaults
   remain empty search, newest first, priority
   toggles false, terminal hidden. Dialog Cancel/
   Escape preserve applied state, while Done applies
   a valid draft as one local update. Search
   scheduling and HTML responses are resource/
   generation-bound; slow earlier input cannot
   overwrite newer text.
7. **Details and continuity:** native Gesso
   accordion reveals already authorized
   current *adopted* Request details. Scroll,
   focus/caret and open/selected details may
   survive compatible same-Request replacement;
   a removed or unauthorized card is retired
   with a safe focus fallback. Old provisional
   action rights or protected details cannot
   be resurrected by continuity.
8. **Current-details action distinct:** any separately
   labelled current-details read needs its own
   authenticated Request-scoped acquisition
   and cannot auto-adopt unrelated board cohort
   members or erase outstanding advisory.
   Unauthorized absence/deletion distinctions
   use the selected non-disclosure policy.
9. **Accessible feedback:** meaningful labels,
   keyboard interaction/focus, text status
   beyond color, bounded polite advisory,
   pending/unknown/retry and screen-reader
   announcements are positive browser
   obligations. A technical XTDB basis
   or proof error is not user-facing recovery.
10. **Response flow remains unselected:** R4 and R5
    record `decision-humanhelp-response-flow`
    as unresolved product semantics. The
    framework may not invent a message
    entity/provider or claim that a
    working Claim automatically counts as
    response-flow success. HumanHelp must
    choose an explicit model/UI/UX contract
    and independently exercise its eligible
    and negative outcomes before whole
    product acceptance.
11. **Positive/adversarial histories:** twenty-four
    examples cover remote-only search, Unicode/
    disclosure, late responses, combined ordering,
    terminal, malformed timestamp, Cancel
    and Done, details persistence/retirement,
    current detail read, accessibility
    and each response-flow selection branch.
    An unchosen response flow remains
    a *product acceptance blocker*, not
    a Gesso framework defect or pass.

## HumanHelp `dev` source observations

- `src/net/humanhelp/example/board.clj` defines
  `normalize-view-state`, `search-match?`,
  `visible-rows`, `row-sort-key` and
  source-owned Request/User display
  projections. The current sorter is
  lexicographic by selected priority
  groups, created time and Request ID.
  `mine?` checks requestor or
  active primary helper; it is not a
  trusted operation capability.
- `searchable-row-text` includes Request
  ID/status/title/details/location
  details and display User names,
  email and phone, so the finished
  projection needs authorization
  for every searchable field.
  This is a required disclosure
  review, **not a demonstrated
  privacy breach**.
- `created-sort-value` uses
  `instant-epoch-milli`; for a
  non-`Instant` timestamp that
  helper returns 0. The current
  source therefore does not meet
  the finished design's explicit
  invalid-date-as-error guarantee.
  The implementation needs a
  validation/portable sort fix.
- `src/net/humanhelp/example/views.clj`
  renders labeled search field,
  GET route with 250ms keyup
  trigger, board options dialog
  with newest/oldest and priority/
  terminal controls, and details
  accordion over Request cards.
  `src/net/humanhelp/example/app.clj`
  `search-requests` and
  `apply-board-options` invoke
  fresh production-backed
  fragment queries; they do
  **not by themselves** satisfy
  R5.1's stricter adopted-only
  no-remote-acquisition policy.
- `src/net/humanhelp/example/live.clj`
  defines `request-list-client-continuity`
  with scroll anchor, focus
  and native `<details>` key
  preservation. That demonstrates
  a meaningful configured
  Gesso physical mechanism,
  but no fresh browser test
  of open state, caret/scroll
  after real re-render and
  missing-card retirement
  was executed here.
- `src/net/humanhelp/example/components/request_card/core.clj`
  renders a real Gesso accordion
  with model-backed Request
  details and semantic operation
  actions. Opening the accordion
  is non-mutating. It is not
  a source-owned production
  response-flow operation.
- `test/net/humanhelp/example/board_test.clj`
  has real source-level fixtures
  for normalized view state,
  search/newest/oldest,
  mine-first/unclaimed-first
  and terminal visibility.
  `test/net/humanhelp/example/views_test.clj`
  verifies card/render delegation
  and fragment observed basis.
  These tests do not establish
  full real-browser acceptance
  or portable JS/JVM search
  correspondence.
- The current
  `test/net/humanhelp/example/chromium_acceptance.clj`
  exercises browser-generated
  lifecycle Claim/Unclaim/
  On-the-way/Complete/Cancel/
  Reassign. Its existence
  cannot be promoted to evidence
  of the new rich-board interaction
  matrix or an independently
  chosen response-flow outcome.
  This was source inspection,
  not execution of the suite.
