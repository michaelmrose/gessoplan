## Editorial finding

Preferred R5 provides a better contract than R4's broad
early “authoritative foundation”: it separates a model-owned
operation and durable *logical command* from the actual
XTDB physical attempt and from any later observation.
The revised text restores R4's atomic preparation/commit/
postcommit, current trusted identity, FX capability, command
retry/uncertainty and real model consistency guarantees
without reimposing R4's old stage numbering.

The core risk is **semantic conflation**: treating a pre-read
as an atomic guard; treating failed HTTP delivery as command
rejection; treating a syntactically lowered transaction as
actual admitted physical authority; treating pinned poststate
agreement as causal proof; or treating a known local writer
list as complete physical closure. All must remain separate
until independently qualified evidence connects them.

The original HumanHelp Claim is a multi-record and historical
command problem: protected Request and RequestAssignment,
authenticated helper Membership and Organization association,
one-primary safety, command result and required durable notice
intent have distinct roles in one authoritative effect. A
toy one-document update does not satisfy it. Genuine eligible
positives are required alongside the expected rejection
paths, without shrinking product capability requirements.

## Real Gesso v1622 implementation correspondence (bounded)

The actual local `application-assurance` source was inspected,
not run, for these relevant modules and their precise claims:

- `src/gesso/model/command.clj` defines generic create/update
  command and optimistic-version mechanics. Its namespace
  explicitly declines to attach authorization to version
  guards. A command shape alone does not authorize Claim.
- `src/gesso/model/tx.clj` constructs `:commands`,
  `:guards`, `:assertions`, `:changes` plans, XTDB
  assertions, Biff-compatible formatting and a Gesso Live
  postcommit seam. It does not own domain policy, trusted
  Graph inputs or complete multi-node durable publication.
- `src/gesso/model/command_resolution.clj` constructs
  a typed binding and same-transaction canonical outcome
  record with absence guard and disclosure predicate.
  Its scope explicitly leaves domain authorization,
  complete guards, real XTDB contention, durable notice,
  external writer closure and lost-delivery liveness open.
- `src/gesso/model/tx_refinement_prestate.clj` checks
  an ASSERT-before-write lowering prerequisite while
  retaining provider behavior and transaction-internal
  prestate correspondence as named external premises.
- `src/gesso/assurance/proof/xtdb-conditional-guard-admission.clj`
  describes restricted ASSERT/PUT and field-count guard
  shapes. A syntactically complete guard is not an observed
  backend execution or a general nested/other-document
  frame guarantee.
- `src/gesso/assurance/proof/xtdb-restricted-submission-gateway.clj`
  owns a bounded real `xtdb.api/execute-tx` one-shot call
  with guarded source-derived operations; its process-local
  receipt/journal, pinned readback and ledger comparisons
  are observations, not durable causal attestation.
- `src/gesso/assurance/proof/xtdb-internal-prestate-capability.clj`
  reports version-scoped XTDB API/prestate limits and
  bounded experiments; it explicitly rejects the inference
  that a snapshot token or `xt.txs` record proves the
  internal state in a subsequent DML transaction.
- `src/gesso/assurance/proof/xtdb-gateway-writer-coverage.clj`
  binds exact locally issued callbacks to enumerated
  host registrations and has opt-in request-scoped
  plan-bound variants, while expressly leaving external
  writers, deployed handler adoption and physical causality
  unproved.
- `src/gesso/assurance/proof/physical-writer-inventory.clj`
  inventories host-observed potential writers without
  proving its enumerator closed-world or the absence of
  direct/external XTDB clients.
- `src/gesso/assurance/proof/xtdb-gateway-atomic-submitted-readback.clj`
  locally correlates original return and same-node/same-
  basis poststate/command/ledger observations; it cannot
  authenticate a writer or establish universal causality.
- `src/gesso/assurance/proof/xtdb-gateway-command-outcome-bridge.clj`
  is v1622's opt-in read-only join from exact one-shot
  process-local submission/readback to canonical command
  reconciliation and caller-reported request outcome.
  It is *not* evidence that the Biff production handler
  universally uses that gateway or that all requests
  have safe replay/authorization and Live settlement.

Relevant source tests exist, including
`test/gesso/model/command_resolution_test.clj`,
`test/gesso/model/tx_refinement_prestate_test.clj`,
`test/gesso/model/tx_refinement_xtdb_test.clj` and
`test/gesso/assurance/proof/xtdb_gateway_writer_coverage_test.clj`.
No JVM, XTDB, Biff, Chromium, real-HumanHelp, distributed,
or external formal test was executed in this revision.
Source presence and prior described bounded experiments
are not current production correspondence evidence.
