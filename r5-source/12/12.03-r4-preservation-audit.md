## Core editorial decisions

R5 correctly separates the permanently executable semantic core,
a *small propositional checker*, and the guarded/initial/inductive
proof mechanisms. R4's ambition for a compact trusted kernel and
proof-producing elaboration survives, but its early chronology
does not force full proof formalization before a usable application.
The checker must independently reparse original source; a proof
generator cannot self-validate its output. Source obligation coverage
is distinct from internal proof-tree completeness.

The exact R5.1 initial propositional system has seven rule families.
It does not include classical excluded middle, atomic facts as
axioms, arbitrary host evaluation, general arithmetic reasoning or
hypothetical-premise discharge. The latter is especially easy to
overstate: a conclusion conditional on an open premise is not an
unconditional proof of that premise or a current runtime fact.

R4's coverage of real Biff lifecycle and model FX is restored
in the new Stage 4 without introducing a second domain-policy
owner. Its named *effective* integration and actual installed
handler matter, not merely its dependency label or a locally
constructed ApplicationAssembly. The accepted Part VII refines
an important failure window: if Biff runs all `:biff.core/init`
callbacks before its ordered `:biff.core/start` phase, start
order alone does not fence physical initializer effects.
The host must therefore own private/fenced construction and
separately qualify early effects, before it advertises the
required preflight-sealed serving guarantee.

## Gesso v1622 source evidence and nonclaims

The user-supplied `application-assurance` archive contains the
following *actual* Clojure source and test namespaces; their
docstrings delimit the interpretation:

- `src/gesso/assurance/proof/kernel.clj` defines
  `check-derivation!`, seven initial propositional rules,
  nominal subject/variable checks, restricted source premises,
  step references and goals. It describes outputs as copyable
  unadmitted evidence and makes **no meta-soundness theorem**.
- `src/gesso/assurance/proof/derivation.clj` defines
  `check-transition-derivation!` over a closed guarded
  transition and matching-relation premise; it does not
  prove that a physical transition matched.
- `src/gesso/assurance/proof/operation_set.clj` checks an
  original declared operation/invariant catalog. It cannot
  discover all independent external/physical writers.
- `src/gesso/assurance/proof/induction.clj` defines
  `check-induction!` across initial and per-operation
  preservation obligations; a complete declared abstract
  induction result is conditional on original-source,
  operation completeness and realization assumptions.
- `src/gesso/assurance/proof/initial_cases.clj` reports
  finite declared initial constructor case checks, not
  universal physical constructor or initializer coverage.
- `src/gesso/assurance/proof/certificate.clj` rechecks
  source and graph before issuing opaque JVM-local
  handles for propositional, guarded-transition and
  conditional-induction claims. It does not issue signed
  deployment permission or prove checker soundness.
- `src/gesso/assurance/proof/propositional_semantics.clj`
  supplies an independent bounded truth-functional oracle
  for abstract Boolean atoms. Exhaustion is not a theorem
  about a current typed rule or XTDB implementation.
- `src/gesso/live/application_preflight.clj` exposes
  `check-application-assembly`, `wrap-application-handler`
  and `start-biff-application!` for canonical covered
  startup and HTML/Ring paths, with documented bypass
  and deployment limits.
- `src/gesso/live/application_preflight/biff.clj`
  implements native Biff application handler/startup
  wrappers, explicitly noting that all module
  `:biff.core/init` entries execute before the start
  phase. A successful module/handler shape check cannot
  observe all external host adoption, early effects or
  later handler replacement.
- `src/gesso/live/application_preflight/assurance.clj`
  describes the current coordinator report and open
  obligations without acting as a new issuer.
- `src/gesso/model/core.clj` and
  `src/gesso/model/tx.clj` distinguish generated
  Biff/model plumbing from complex application Graph/FX
  and actual transactional domain meaning. A generic
  version/guard fragment by itself does not prove current
  actor authorization.
