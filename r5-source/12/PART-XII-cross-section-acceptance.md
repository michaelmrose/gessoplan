## Independent gate-by-gate admissibility challenge

The eighteen revised stages, five dependency classes and worked examples
must remain subject to the **sixteen original R4 acceptance gates**.
Each current gate has a distinct named heading and its own written
positive/adversarial oracle. The gate's object is not an already
executed test, and all applicable real evidence still belongs
to the owning part/runtime/issuer.

boundary*, not a second universal policy engine or single final report.

the selected profile demands both, and the test must actually reach
the claimed boundary. This independent review found no gate that
requires hiding a missing mechanism to make the narrative coherent.

## Independently challenged cross-section failure histories

1. **Alice's C42 commits, A fails, C recovers.** A valid existing
   guarded multi-document Claim can incorporate and persist original
   C42 without the HTTP response reaching Alice. The client remains
   `:commit-unknown`; the historical resolver on C needs exact
   compatible binding, retained canonical record and current
   authorized disclosure. R's later state is not proof of the old
   command; C43 is not C42. A later publish/renderer failure
   neither undoes C42 nor proves a new command rejected.
2. **Bob's O1/O2 one-use Refresh.** Under the selected HumanHelp
   ordinary remote policy, O1 creates advisory debt. Bob grants
   G1: one current, scoped logical acquisition with default one
   physical read, no automatic successor. O2 arrives while A1
   is pending. Only provider-qualified progression/scope plus
   *actual complete installed coverage* can discharge both.
   Otherwise O2 remains and a second user grant or separately
   admitted recovery entitlement is required. No SSE wakeup
   creates new read authority.
3. **Two valid helpers contend for RequestAssignment.** Only the
   actual selected guarded transaction and all relevant writer
   paths can establish one-primary cardinality, absence,
   current Membership/Organization policy, frame/presence and
   history-sensitive exclusion. A successful abstract safety
   proof with a missing Reassign transition is not complete.
   Independently qualified physical negative and positive
   cases remain required.
4. **C42 committed, publisher/router fails after the commit.**
   Strong selected durability couples domain/command result
   to notice intent. Replacement dispatch can conservatively
   redeliver duplicate advisories under bounded
   disclosure/resource contracts; initial/late interest
   requires actual fence/replay/gap recovery or a selected
   weaker qualified independent acquisition path. No
   recipient-completed-delivery ledger is mandated solely
   for duplicate-tolerant notice delivery.
5. **HTMX success with stale physical owner.** HTTP 200,
   response parse or pre-swap callback does not authorize
   DOM adoption. A retired resource cannot mutate a
   new instance sharing a logical target ID. Shared live
   resource rights, one-use grants and partial OOB debt
   remain separately owned.
6. **P23 proof/build used as P24 evidence.** Sound abstract
   theorem may stay true, but new actual Biff handler,
   served/loaded artifact, issuer interpretation and
   XTDB physical writer need current qualification.
   A copied report or old Chromium result is not a
   production-installed certificate or an authorized
   model operation.
7. **Green-looking stopped candidate.** Original full
   HumanHelp/selected external formal intent includes
   current clock/provider, real enabled actions,
   Reassign, selected Response, full source/writer
   catalog, no ungranted remote adoption, real
   command recovery and mandatory physical proof.
   The candidate is rejected at each owning boundary
   as independently testable mutations, not because
   a wrong early exception masks all other negative
   oracles. Source/physical repairs create a newly
   qualified candidate, not edited status fields.
8. **Real developer workflow and optional exploration.**
   A useful single-node Claim slice can be admitted
   under an explicit narrower product profile without
   independent S0–S4 formal completion. Small independent
   kernel formalization and two-host experiments may
   proceed before finished product or production
   multi-node qualification. Business rules remain in
   ordinary source-owned Clojure; no separate
   handwritten formal HumanHelp application or
   mandatory Rust router is introduced.

All eight histories are specifications of acceptance
or falsification cases, not reports of actual fault
injection, live participant sessions or verified
physical effects. A correct outcome under a
source-only check is not independently observed
production correctness.

## Cross-part ownership and four kinds of completion

- **Part I:** semantic/source claims, actual physical
  realization and product acceptance are separate
  assurance dimensions. The final principle
  preserves usable application behavior and truth
  about incomplete evidence rather than one
  unconditional `:proved` flag.
- **Part II:** the original model and independent
  product requirement owner determine business
  meaning and the full obligation denominator.
  Host-Clojure opaque predicates are not silently
  checked by mere source availability.
- **Part III:** Choreo global/local projections
  and role-local knowledge are not new model
  policy owners. The browser cannot send a
  global observation it never legitimately
  acquired.
- **Part IV:** authoritative current guards
  and immutable original logical command
  history are distinct from transport attempts
  and later browser-presented status.
- **Part V:** provisional optimism/continuity
  cannot become authoritative incorporation
  and does not justify remote board adoption
  or post-retirement effects.
- **Part VI:** HTMX and the narrow browser shell
  implement current exact resource permissions,
  one-physical-read ordinary Refresh budgets,
  qualified progression and actual installed
  OOB/DOM effects; a lost SSE event does not
  forbid an independently permitted manual read.
- **Part VII:** preflight/closed source assembly
  and the physically adopted Biff handler,
  protected writer, current emitted/served
  browser bytes and actual rendered paths
  are separately qualified.
- **Part VIII:** the selected HumanHelp
  remote lifecycle policy is advisory until
  explicit one-use Refresh. Product-owned
  Response remains a distinct unresolved
  decision; six lifecycle actions,
  current Membership/RequestAssignment,
  a rich board and fourteen independent
  real acceptance gates remain the
  full product's denominator.
- **Part IX:** source-derived proof/induction,
  issuer-controlled certificates, premise
  substitution, nonvacuity and the true
  original operation catalog are separate
  from application/physical completeness.
- **Part X:** S0/S1 mathematical kernel
  soundness, S2 Clojure checker semantics,
  S3 typed source atom evaluation and
  S4 production transfer remain five
  separately assessed objectives,
  with actual XTDB and multi-node
  premises carried to the selected host.
- **Part XI:** four release decisions
  (candidate, installation, activation
  and completion) differ from four
  independent milestone subjects:
  operational HumanHelp,
  compositional certification,
  external formal verification and
  production multi-node realization.
  An original stricter release intent
  cannot shrink after tests fail.

The eighteen stages are *construction and
implementation contract navigation*,
not a total order on proofs, an
application maturity percent, or
permission to defer early host
safety. The five dependency kinds
are semantic prerequisites,
implementation priorities,
exploratory feedback,
optional early hardening
and completion dependencies.
The stronger original profile
remains mandatory whenever it
was selected, while valid
conditional smaller results
retain their own truthful value.
