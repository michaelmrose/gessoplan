*** Stage 17 -- Formal-to-production transfer and release-bound evidence

Connect the external results to the actual checker and runtime subjects that
consume them. The correspondence direction, observable behavior, representation,
and remaining trust must be stated for each claim.

Deliver:

- production-admission-to-formal-validity correspondence for the declared checker
  scope, with actual implementation and decoding/normalization identities;
- execution refinement where claimed, separately from admission soundness;
- progress/fairness/divergence conditions for any transferred liveness result;
- complete formal-assumption-to-production-obligation traceability;
- checked or explicitly trusted translation/extraction mechanisms under the
  selected profile;
- finite bounds or sound abstraction transfer, with incomplete results preserved;
- source-level counterexample explanation exercised through the actual backend
  where the release claims that capability;
- release import, cache applicability, invalidation, and installed-subject binding
  for the resulting evidence.

Acceptance substitutes an outdated theorem, different production checker, altered
subject, omitted obligation, or incompatible build and verifies the appropriate
rejection. A trusted translation premise remains visible; it cannot satisfy a
profile requiring that translation to be proved. Tests and conformance vectors
alone cannot discharge a required universal transfer theorem.

An atomic action in a model creates an atomic production obligation. Proof of the
model cannot establish that unguarded pre-reads and ordinary writes implement it.
A provider contract may legitimately remain qualified and trusted without claiming
a proof of all XTDB. A violated premise invalidates dependent applicability even
if the abstract theorem remains true as a conditional statement.

This stage strengthens the release machinery from Stage 11. It does not make
artifact freshness, installed enforcement, or real-browser acceptance optional
before external formal work is complete.

*** Stage 18 -- Qualified multi-node realization

Realize the existing authority and command semantics across actual independent
application processes. The baseline topology and acceptance scope are those of
[[#req-multi-node-realization]] and [[#milestone-multi-node-production]].

Deliver:

- at least two application processes, actual routing/failover, and a qualified
  shared authoritative backend;
- durable publication intent and a dispatcher with explicit distribution-boundary
  acknowledgment, retry, retention, and duplicate semantics;
- authorized distributed interest delivery with registration/reconnect fence,
  replay, or conservative gap handling;
- cross-host command lookup and compatible retry under the original binding;
- progression-safe coherent reads through another host;
- qualified session, principal, scope, assembly, asset, and protocol compatibility;
- measured resource/load bounds and declared recovery behavior;
- actual host-loss, publication-loss, silent-gap, reorder, retention-expiry, and
  rolling-release scenarios in the root evidence.

Acceptance preserves authority, command identity, selective adoption, and honest
uncertainty through host replacement. A later matching Request state does not
attribute the originating command. Outbox publication does not prove receipt by
every subscriber; live interest filtering does not itself close a registration gap.

HumanHelp's remote board still waits for permitted Refresh. A lost advisory does
not eliminate the user's independent authorized acquisition path. Current
Membership loss may require nondisclosure rather than eventual result lookup.
Progress claims name availability, fairness, retention, permission, and user action.

A small real topology can provide exploratory feedback before external proof or
full HumanHelp completion. It is then a prototype under an explicit narrower
scope. Production completion requires the actual fault and resource envelope.
Direct participant routing and persisted suspended workflows remain separate
capabilities, not prerequisites for ordinary authoritative rendezvous.
