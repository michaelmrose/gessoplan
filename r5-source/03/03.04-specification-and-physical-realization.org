*** Choreography is specification, not a hidden coordinator

The global choreography is the semantic specification of allowed distributed
behavior.  It is not a requirement that Gesso run one omniscient global state
machine alongside every projected role.

The implementation must therefore preserve two complementary truths:

- the global description is authoritative for what behaviors are admitted;
- projected actors execute locally and independently using only the knowledge,
  resources, and authority available to them.

A runtime architecture that requires every local step to consult a central
choreography interpreter solely to rediscover projected control flow would
defeat an important purpose of projection. This does not prohibit a declared
authoritative operation from consulting its centralized model authority or
checking a trusted runtime premise. The prohibition concerns an unnecessary
global control interpreter, not model-owned coordination whose semantics the
application actually requires.

Conversely, independently executing local machines do not become semantically
independent programs.  Their combined traces remain constrained by the global
description.

The executable global semantics may still run as a reference oracle in a
checker, simulator, or deterministic test harness. Such a harness may schedule
several projected roles and compare a supplied execution with the global
machine. This is not a second production coordinator, nor is one successful
witness a proof that every admitted distributed schedule refines the global
specification. Actual production participants must obtain their needed local
knowledge and satisfy their own message, owner, environment, and authoritative
operation contracts without consulting a hidden global control state.

The intended relationship is:

| Stage | Product and obligation |
|-------+------------------------|
| Global specification | Declares the allowed distributed behavior |
| Verification and projection | Derives admitted role-local plans with explicit premises |
| Independent local execution | Produces concrete interactions under the realization contracts |
| Refinement judgment | Relates those interactions to the admitted global behavior and stated observation alphabet |

The absence of a central runtime machine is therefore not a weakening of the
global specification.  It is the point of a successful projection.

The *observation alphabet matters* when the choreography carries
externally significant effects. A coarse distributed semantic trace
may omit ordinary =:local= steps; this does not authorize hiding a
notifier's real external delivery, a charge, a protected disclosure,
or an actual DOM installation from a claim whose postcondition
includes it. A checked local action exposes its effect contract and
the relevant issued/fulfilled/failed boundaries to its realization.
An assurance claim about the physical effect uses a corresponding
physical observation and owner/effect identity relation, even when a
different semantic trace intentionally abstracts that action away.

The return condition is property-specific: "command incorporated",
"required publication intent persisted", "notifier consumed the
message", and "recipient was actually notified" are distinct
postconditions. A global terminal outcome cannot establish a
stronger physical postcondition merely because a weaker semantic
trace reached =:return=. Durable handoff can discharge a
*work-recorded* obligation if the authored terminal permits it,
while retaining a separate future fulfillment obligation and any
named environmental progress premises.

*** Semantic behavior versus physical realization

A choreography describes semantic behavior.  Physical realization is permitted
to vary when that variation does not change the semantic trace.

For example, the semantic statement:

#+begin_example
:request-authority establishes the result of :request/claim
#+end_example

does not require:

#+begin_example
one fixed Aleph process
one fixed HTTP connection
one fixed DOM node
one fixed browser tab
one fixed database connection
#+end_example

The authority may be realized through different physical resources at different
times.  A retry may reach another host.  A fragment may be replaced by a new DOM
node.  A browser may reconnect.  None of these physical substitutions creates
a new semantic authority or silently changes the meaning of the operation.
Neither does their mere occurrence establish that continuation is safe:
admission must preserve or re-establish the relevant command binding, qualified
authority/incarnation and basis, role/principal rights, execution or physical
resource ownership, and permitted artifact/projection correspondence.

A host restart or changed transport attempt cannot manufacture command
nonincorporation or authorize retry after an unknown outcome. A new DOM
resource cannot inherit the old resource's pending effect permissions merely
because its logical target name is equal. A database with the same authority
label but a different unqualified incarnation cannot be treated as the same
authoritative history. The exact checks are owner- and operation-relative,
not a demand to attach every identity to every semantic event.

This end-state design therefore requires every layer that crosses a
replaceable physical boundary to preserve the logical identities needed by the
semantic layer rather than reconstruct them from physical coincidence.

Detailed multi-node routing belongs to its separately scoped realization
contract.  The semantic requirement established here is only the stronger
and more durable one:

#+begin_quote
A host may realize a role or authority for an execution, but physical hosting
does not create semantic authority.
#+end_quote

*** Physical realization correspondence cases

| Proposed realization | Required evidence or prohibited inference |
|----------------------+--------------------------------------------|
| A deterministic test harness advances all roles together | Useful bounded witness; it does not require a production lockstep coordinator or prove all schedules |
| A command is retried through a different HTTP host after a lost response | Preserve command identity and unresolved incorporation; host replacement does not authorize a duplicate write |
| An HTMX target is replaced before a delayed effect completes | The retired resource loses actuation rights; matching logical target IDs alone do not admit the stale effect |
| A replacement authority reports the same semantic name with different database lineage | Re-establish qualified authority continuity and admissible observations before relying on the old history |
| A projected executable plan is repackaged or deployed elsewhere | Check the admitted artifact/assembly compatibility, principal context and actual execution correspondence; equal plan labels do not suffice |
| A coarse semantic trace hides the notifier's effectful local action, yet an assurance result claims successful external delivery | Require qualified physical issue/fulfillment evidence and an observation alphabet that preserves the asserted effect; global terminal alone does not prove delivery |

These cases define realization and assurance obligations. Listing the
cases is not a proof that physical transport and browser effects refine
the abstract Choreo machine; that stronger judgment requires its own
property, premises, and correspondence evidence.
