# R5.1 Part III — 03.11 Full-Language Knowledge and Plans

**Baseline:** R4 `main` Part III, especially “Operation declarations
should remain inspectable data,” “Projection is a semantic compilation
boundary,” “Projection cannot create knowledge,” “Local executable guards
belong in the executable projection,” and “Host-language callbacks may not
bypass projected semantics.”
**Candidate:** `r5.1` source unit 03.11.
**Status:** focused R4 preservation audit, not whole-Part-III acceptance,
arbitrary-Clojure verification or proof of a deployed browser/runtime.

## R4 obligations preserved

- Ordinary Clojure effects remain available behind explicit semantic action
  interfaces; declarative syntax cannot become a second opaque semantics.
- Elaborated declarations retain inspectable owners, inputs, outputs,
  contracts, semantic identity and source explanation without treating
  source-only diagnostic coordinates as semantic identity.
- Role-local required facts must have actual communication, entry,
  derivation or authorized observation paths; projection cannot manufacture
  knowledge or promote asserted facts into authoritative provenance.
- The executable role-local projection retains required message contracts,
  correlation, guards, local knowledge boundaries, failure/terminal behavior
  and resources, while omitting unrelated global information.
- The production machine must not depend on a diagnostic proof sidecar, yet
  a runtime-semantic guard cannot be deleted merely because a proof explains it.
- Host-language callbacks realize declared effects and return normalized
  completions; they must not mutate protocol state or directly bypass the
  projected machine's event admission.
- Projection failures need actionable, subject/role-specific diagnostics
  rather than unexplained “projection failed” reports.

## R5 improvements retained

- The interface explicitly distinguishes target placement, effect footprints,
  outputs, failure/uncertainty, resources and nontermination assumptions without
  claiming unrestricted Clojure code can be fully statically understood.
- Value availability, role-local knowledge, provenance, presence refinement
  and causal eligibility remain separate judgments.
- Must-analysis joins retain premises from every reachable path; versioned
  bindings prevent stale/optional-value and cross-subject laundering.
- Required fields and actually transmitted optional fields are checked;
  authority is not inferred from the payload shape alone.
- Loops need fixed-point analysis or reported bounds; terminal reachability
  is not liveness and unsupported extensions cannot bypass checking.
- Compact executable locators are distinct from exact plan identities,
  diagnostic coordinate maps and continuation compatibility.

## Focused changes in 03.11

1. Make the host-effect boundary explicit: completions belong to the pending
   declared effect, pass owner-relative admission and applicable identity,
   provenance and guard checks, and cannot directly select continuations.
2. Preserve post-effect uncertainty and original-command reconciliation;
   callback timeout is neither a negative domain fact nor a license to
   re-incorporate a potentially committed operation.
3. Reaffirm executable guards versus sidecar proofs with the concrete case
   of delayed callback/message completions.
4. Add nine counterexamples covering overly broad entry fixtures,
   optional-field reuse, cross-subject provenance, optional sender knowledge,
   host callback bypass, retired effects, uncertain commit, unjustified
   liveness and copied/stale proof sidecars.

## Current Gesso correspondence and limits

- `gesso.choreo.verify` implements definite value, role-local knowledge and
  definite-authoritative must-analyses with edge-sensitive await handling.
  Its documentation explicitly excludes optional sender-field proof,
  arbitrary liveness, runtime resource ownership and physical realization.
- `gesso.choreo.machine` accepts declared local/authoritative completions and
  enforces closed output keys; `complete-authoritative` explicitly delegates
  authentication, business authorization, physical incorporation and true
  command disposition to the trusted endpoint and public model contract.
- `gesso.choreo.project` emits compact role-local ExecutablePlans and separate
  compiler-only semantic-location provenance; a structurally valid plan
  does not itself establish refinement or browser actuation.
- `gesso.choreo.artifact` packages executable plans and an exact-digest-bound
  diagnostic proof sidecar, which is not a runtime dependency.
- These are existing boundaries and partial evidence, not a demonstrated
  proof of universal semantic refinement or admission of arbitrary Clojure
  callbacks on a production host.

## Open cross-part obligations

- Parts IV and VII: qualified authoritative incorporation, durable command
  outcomes, actual installed handlers and trusted effect-origin evidence.
- Parts V–VI: browser effects, retired resources and cancellation/installation
  boundaries without inventing successful adoption.
- Parts IX–X: the supported typed-rule subset, proof/assumption closure,
  sound fixed-point analyses and physical realization correspondence.
- Part III later units: Malli boundaries, branch-knowledge projection,
  optional transmitted fields, host-local guard implementations and
