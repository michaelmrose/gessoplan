# R5.1 Part III — 03.02 A Concrete Coordination Vocabulary

**Baseline:** R4 `main` Part III global choreography, operation types,
projection and construction requirements.
**Candidate:** R5.1 section 03.02.
**Status:** focused preservation audit; not whole-Part-III acceptance,
proof of complete source closure, or runtime certification.

## R4 requirements retained

- One global choreography describes permitted distributed behavior and is
  projected into independently executable role-local semantics.
- Local computation, authoritative effects, communications, environment
  events, branching and completion must remain distinct.
- Statically knowable contradictions should fail early, while dynamic
  authorization, business outcomes and transport uncertainty retain their
  explicit runtime obligations.
- Possessing a map/message and matching schema do not by themselves convey
  knowledge or trusted authority.
- Authoring syntax and operation metadata are not independent executable
  workflows or proof that illustrated helpers already exist.

R4 does not require an exact six-opcode low-level table in its introduction.
R5's closed portable six-operation representation is the stronger design,
retained rather than incorrectly attributed verbatim to R4.

## Superior R5 semantics preserved

- Six global node kinds: `:local`, `:authoritative`, `:branch`,
  `:communicate`, `:await`, `:return`. Projected `:send` and
  `:receive` realize separate endpoints of semantic communication.
- Closed interpreted fields and explicitly inert metadata; unknown executable
  options are not silently ignored by checked construction.
- Hidden local work cannot conceal protected effects, and an authoritative
  result need not mean a committed write.
- Participant messages cannot impersonate environment events and vice versa.
- Authoritative acquisition need not be a new global operation opcode.
- Selectors distinguish missing values, nil and false where supported;
  a recognized branch depends on actually established local knowledge.
- Checked elaboration, provenance and required operation effects survive
  projection rather than being supplied by untrusted runtime context.

## Changes in 03.02

1. Distinguish source-level admitted semantic closure from a raw structural
   normalizer accepting a map; misspelled semantic fields require a failure
   at the claimed checked construction boundary.
2. Clarify the example's entry and nominal output-type obligations; a
   two-valued enum claim about opaque Clojure is not established by the
   graph's branch case map or by definite-value must-analysis.
3. State present nil branch cases are unsupported by the current core,
   requiring explicit extension for any future typed nil case.
4. Add six acceptance cases for unknown fields, nonexhaustive selection,
   environment/message confusion, open payload extras, hidden protected
   effects and role-local versus global completion.

## Current Gesso implementation correspondence

- `gesso.choreo.semantics` recognizes these six global operations and
  checks structural shape and successors. Its `->program` does not apply
  a complete state-key whitelist. For local/authoritative states,
  absent `:outputs` can default to the empty set. Thus raw
  normalization does not itself certify fail-closed source semantics.
- `gesso.choreo.core` exposes constructors and retains additional
  top-level fields without granting semantic meaning; branch constructors
  reject nil case values.
- `gesso.choreo.verify` implements definite-value and role-local
  knowledge analyses, not a proof that arbitrary opaque functions have
  the promised enum range or authorization properties.
- `gesso.choreo.project` distinguishes projected send/receive from
  await events; it does not establish physical message delivery.

## Deferred obligations

- 03.03 and 03.07–03.14: expense policy, nominal value typing,
  typed source elaboration, schema and exact result alternatives.
- 03.15–03.21: projection correctness, message provenance, branch
  knowledge, guarded effects and terminal correspondence.
- Parts IV, VI–VII, IX–X: actual authoritative/physical effects, complete

No R4 normative distributed-coordination requirement is intentionally
lost. The six Part III headings and existing anchors are preserved.
This audit records gaps, not claims of already proved behavior.
