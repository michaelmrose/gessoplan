# R5.1 Part III — 03.14 Runtime Validation and Schema Compatibility

**R4 baseline:** `main` Part III, “Runtime validation preserves static
premises,” “Validators should be reusable and diagnostic failure should be
rich,” and “Schema changes participate in semantic compatibility.”
**Candidate:** R5.1 section 03.14.
**Status:** focused R4 preservation audit and implementation correspondence
notes. The canonical Org text is the timeless specification of finished Gesso.

## R4 requirements retained

- Static checking depends on runtime premises actually enforced at untrusted
  and dynamic boundaries; passing a static verifier does not replace checks.
- Browser commands, authorized external reads, FX completions, and settlements
  have distinct checks before being interpreted as admitted transitions.
- Failed runtime premises reject or recover by declared protocol and may not
  be bypassed by an apparently successful shape check.
- Reusable/precompiled validators serve the common path, and a failed check
  must retain semantic/operation context for useful diagnostics.
- Schema changes to enum sets, required/optional fields, cardinality,
  nominal types and closed variants may invalidate dependent artifacts.
- Semantic identity follows normalized contracts rather than filenames or
  source-location-only metadata.

## Stronger R5 design retained

- The R5 table maps each physical input to its layered admission obligations,
  including trusted command/caller binding, acquisition/provenance and
  owner-relative settlement. This replaces R4's schematic step diagram.
- Error explanations remain governed by disclosure restrictions; private
  content is not automatically safe to report in a diagnostic.
- Compatibility and proof validity are qualified judgments, not by-products
  of successful runtime schema checks.

## Improvements in 03.14

1. Distinguish check availability from actually installed, applicable
   enforcement. A detached fixture or obsolete validator cannot discharge
   production route or effect closure.
2. Restore R4's explicit sequence from admitted read envelope through
   authorized acquisition to justified knowledge, and from settlement
   correlation to the admitted browser transition.
3. Require cached/deferred/reused admissions to remain valid for their
   original subject, principal, scope, assembly and consumer.
4. Cover diagnostic disclosure at exception construction, logs, traces,
   persistence and responses; redaction in only one output channel is
   insufficient.
5. Define schema compatibility as directional and consumer-relative,
   including old/new producers and readers, in-flight continuations and
   proof reuse; require actual semantic dependency evidence.
6. Add nine adversarial cases for bypassed routes, scope substitution,
   retired effects, false command rejection, diagnostic leakage, new
   variants, changed predicates, stale assembly evidence and writer
   authorization changes.

## Gesso implementation observations (audit only)

- `gesso.choreo.type` contains compiled Malli schema/validator tables
  and on-demand `explain-data`; `validate!` includes the raw rejected
  `:value` and Malli `:explanation` in exception metadata. This is not
  automatically a vulnerability: it establishes that logging/response
  callers require a separate qualified disclosure policy.
- `gesso.choreo.machine` checks declared local/authoritative completions
  and explicitly does not own principal authentication or transaction truth.
- `gesso.live.browser.adapter` delegates host effects to the imperative
  shell and rejects stale callbacks relative to its owned generations.
- `gesso.assurance.dependency` binds exact declarative dependency
  fingerprints but expressly claims structural checking only, not
  deployment authorization, assumption discharge or a proof.
- `gesso.live.browser.artifact` compares generated artifact stamps against
  current assembly/plan facts; this is concrete drift detection, not a
  universal physical refinement theorem.

## Remaining cross-part obligations

- 03.12–03.13: admitted registry/predicate semantics, semantic closure,
  and nonpromotion of shape into trust.
- Parts II, IV, V–VII: qualified observations, runtime ownership,
  authoritative command/read correlation, all installed routes and writer
  guards, browser installation and disclosure.
- Parts IX–X: issuer and assumption soundness, compositional invalidation,
  versioned proofs and physical refinement evidence.
- Part XI: end-to-end negative cases and release gates must distinguish
  document integrity from deployed/runtime acceptance.

No R4 normative requirement in the compared unit was intentionally
discarded. Canonical R5.1 remains a statement of completed Gesso, not of
the implementation version inspected for this audit.
