** Semantic acceptance obligations

The definitions above require executable judgments and focused conformance
cases. Part IX owns the certification rules; Part X owns soundness and
implementation correspondence. The semantic definitions used by construction,
projection, the portable machine, and evidence tools must agree on these cases:

| Case | Required result |
|------+-----------------|
| Valid opaque Clojure action with a complete admitted interface | Admit under the selected assurance policy; retain asserted functional/effect premises |
| Missing operation binding or malformed continuation | Reject; an assertion cannot supply the absent structural edge |
| Role uses a value known only to another role | Reject or report the exact missing knowledge obligation |
| Optional message field absent on one path | Do not treat it as definitely present at the join |
| Optional field actually sent without sender knowledge | Reject that semantic send |
| New asserted output overwrites an authoritative binding | Do not inherit the old provenance or dependent applicability |
| Ordinary environment event matches a participant message name | Do not cross the event-class boundary |
| Two receive alternatives accept the same correlated message with different behavior | Reject ambiguity or require an explicit discriminator/equivalence justification |
| Role has equivalent local continuations under the supported relation | Omit an unnecessary discriminator without disclosing private data |
| Role must wait in one branch and return in another | Require a distinguishing path or an explicit conditional-participation contract |
| Unrelated authoritative read follows a foreign commit | Do not discharge a command-specific causal dependency |
| Timeout after submission | Preserve command uncertainty; do not infer a rejected commit |
| Compatible replay returns permitted recorded success | Use the accepted continuation without incorporating again |
| Old resource completion matches the command but not current owner | Reject its stale local effect; separately admit useful reconciliation evidence when permitted |
| Required notification is lost after commit | Preserve the command result and its declared delivery/recovery obligation |
| Old typing timer or duplicate report arrives after replacement | Do not hide the new indicator or extend its expiry |
| New valid artifact has different runtime locators | Require exact sidecar correspondence and a separate continuation-compatibility decision |
| Finite graph has a path to return but can loop forever | Report the structural result without a universal termination claim |

Tests exercising these cases are conformance evidence for the tested subjects
and profiles. They do not replace a proof of the general projection relation,
prove arbitrary host callbacks, or establish every external-system premise.
Negative and mutation cases must reject for the intended semantic reason, not
merely because the fixture became malformed in an unrelated way.

Acceptance also includes positive cases: ordinary opaque functions, declared
open extensions, valid retries, supported partial orders, and privacy-preserving
observations must remain usable under their contracts. A system that rejects
every interesting application would not meet Gesso's construction goal.
