# R5.1 Part III — 03.04 Choreography Is Specification, Not a Hidden Coordinator

**Baseline:** R4 `main`, Part III “Choreography is specification, not a
hidden coordinator” and “Semantic behavior versus physical realization.”
**Candidate:** `r5.1` source unit 03.04.
**Status:** focused preservation review, not full Part III acceptance or
physical execution/refinement certification.

## R4 requirements preserved

- The global choreography determines permitted distributed behavior but need
  not run as a central production control interpreter beside every role.
- Projected role-local executables run independently with their own knowledge,
  resources, authority and admission constraints; they remain jointly
  constrained by the global specification.
- Calling a trusted public model authority is legitimate and is not the same
  as asking a hidden global choreography controller to choose each local step.
- Global-to-projected behavioral correspondence is a separate proof or
  assumption-qualified assurance claim, not an inference from creating plans.
- Semantic operation identity, role, authority and workflow are independent
  of particular Aleph/HTTP processes, DOM nodes, browser tabs and connections.
- Physical substitution does not confer semantic authority or change the
  meaning of an operation merely by changing where it executes.
- Logical identities and guarded transitions survive or are re-established
  across replacement boundaries under the applicable admission contract.
- R4's detailed multi-node topology discussion remains deferred; this
  section asserts only the semantics of hosting and authority.

## Superior R5 design retained

- A four-stage relationship distinguishes global specification, verification
  and projection, independent local execution and the refinement judgment.
- A centralized *model* authority or explicitly required coordination is
  permitted; the design forbids only an unnecessary global program counter
  controlling every projected local step.
- Trusted authority continuity, actor/principal scope, command semantics,
  physical resource instance ownership and executable artifact correspondence
  remain separate dimensions, as defined by Part II.
- The observation alphabet and hiding rules are part of the stated
  correspondence claim; structural checks, replay and actual deployment
  do not silently become the same kind of evidence.

## Changes in 03.04

1. Explicitly allow a reference global machine to run within deterministic
   tests or witness checkers without treating that machinery as production
   global coordination.
2. State that a successful single concrete witness does not prove
   all-schedules projection correctness or universal liveness.
3. Clarify physical replacement as conditional safe realization: commands,
   authority incarnation/basis, principal rights, resource generations,
   artifact/assembly applicability and execution ownership must retain
   their relevant qualified correspondence.
4. Add five negative cases covering harness versus production, host retry
   after uncertain incorporation, delayed DOM effects, authority
   reincarnation and artifact/deployment substitution.
5. Keep the necessary checks owner/operation relative; the end-state model
   does not require every possible identity on every event.

## Current Gesso implementation and limits

- `gesso.choreo.semantics` implements the global reference transition
  machine; `gesso.choreo.project` produces independent role-local
  executable plans with closed runtime representation.
- `gesso.choreo.realization` explicitly runs independently projected roles
  together with an in-memory queue under selected test schedules. It has
  no browser, HTMX, live network, database or production scheduler.
- `gesso.choreo.correspondence` checks concrete lockstep and weak
  replay witnesses, and disclaims an all-schedules refinement theorem.
- `gesso.assurance.proof.xtdb-gateway-command-outcome-bridge` limits its
  physical report to process-local co-observation and value agreement.
  It does not authenticate physical request arguments, prove transaction
  causality, authorize retry or establish Live/browser settlement.
- None of these components makes a replacement host, DOM target or
  authority incarnation safe solely by label equality.
